# サブエージェントのモデル選択

## 選択可能な範囲を確かめる

依頼された仕事の成果、必要な独立性、失敗時の影響、完了を判定する方法を確認する。小さな作業で委譲の準備・待機・結果確認が本作業を上回るなら、自分で行う選択も含める。独立レビューが契約上必要な場合は省略しない。サブエージェント禁止や委譲範囲の制限をこのSkillで解除しない。

ユーザーのモデル指定・予算・利用制限と、現在のHostが提供するモデル一覧・起動オプションを照合する。利用可能であることと利用を許可されていることを分ける。親が使っているモデルの継承を許可と推定せず、明示指定が必要なモデルを自律的な候補から除く。選択肢が不明ならモデル名や能力を推測で作らない。

Hostがモデルや推論設定を変更できない場合は、その制約を明示する。固定された設定で要求を満たせるならそのまま進め、満たせない場合は不足を報告する。モデルを選ぶために別Hostへの移動、権限拡大、新規契約を暗黙に行わない。

## 仕事に必要な能力を選ぶ

| 仕事の性質 | 選択で確かめること |
| --- | --- |
| 範囲が狭い検索・抽出・定型変更 | 出力を容易に照合できるなら、低遅延・低費用の候補で十分か確認する |
| 複数箇所にまたがる実装・原因調査 | 関連経路を保持できるcontext、利用可能なtool、対象言語・テストを扱う能力を重視する |
| 不確実な設計・反例探索・高影響なレビュー | 複数の制約や失敗経路を比較する推論能力を確保する。高価な名前だけを保証としない |
| 独立レビュー | 実装者の会話・自己評価から分離したcontextで、要求と実体を確認できる起動方法を選ぶ。別モデルだけでは独立性は成立しない |

必要な能力を満たす候補から、入力規模・予想出力・遅延・費用・再試行の見込みを比較する。工程名で高価なモデルを固定せず、最安の候補へ難しい作業を無条件に割り当てない。モデル価格やcontext上限を具体的に比較する必要がある場合は、現在のHost情報や公式情報で対象版を確認する。特定モデルの順位表や古い価格をSkillへ固定しない。

## 起動と見直しを対応付ける

委譲時に、目的・変更範囲・完了条件と、選択したモデル・指定できる推論設定・短い選択理由を既存の実行記録へ残す。Hostの実際の引数へ反映し、指定した値と実際に使われた値を確認可能な範囲で区別する。選択のためだけの台帳やAgentは追加しない。context継承とモデル変更を併用できない等の制約があれば、必要最小限の根拠を新しいcontextへ渡す。

期待する成果物・反例・検証結果で完了を確認する。モデルの自己申告や選択名を品質の証拠にしない。能力不足を示す具体的な見落としがあれば、問いを狭める、必要な根拠を追加する、許可された範囲でモデル・推論設定を変更する、を比較する。権限拒否・通信障害・利用上限は能力不足と分け、モデル変更で回避しない。

再試行は残予算と実行上限、前回から変わる条件を明らかにして行う。同じ条件で失敗を繰り返さず、改善根拠がなければ不足と次の判断を返す。この手順は進行役の判断を支援するもので、自動モデルルーティングの実装ではない。
