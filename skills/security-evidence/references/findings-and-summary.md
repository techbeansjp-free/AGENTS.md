# 原始結果・非該当・Summary

## 証拠の照合

同一runかどうかだけで採否を決めず、対象・生成来歴・検査条件・鮮度を照合する。別runのSBOMやscan結果を組み合わせる場合は、不変の成果物IDと信頼できる来歴で同じ対象へ結び付け、対象の変更と鮮度の条件を確認する。確認できなければ不足として扱う。source変更、image差替え、OS/CPU相違、出力不正、symlinkによる別file参照、過大な入力、必要な結果の欠落は明示的に失敗にする。画像tagや同じfilenameだけで実体一致としない。対象の同一性をhashだけで主張せず、どの入力・実行から取得したかを追跡する。

raw結果は変更せず、評価を別に保存する。対象ごとの出現数とunique advisory数を混同せず、severityを返さないscannerから勝手に深刻度を推定しない。必要なinventoryが空ならその理由を確認する。

## 非該当とリスク受容

非該当は対象advisory、binary/image版とhash、該当コードや構成の有無、解析方法と限界を示す。別版・別advisoryや将来のbuildへ一括適用しない。実際の脆弱性を残して受容する判断は、責任者・期限・代替防御を持つ別の承認として扱う。

## Summaryの失敗経路

成功、setup失敗、scan失敗、中断、不正JSON、未対応、欠落の各状態を表示する。Summaryのために未導入runtimeや新しいネットワーク照会を必須にしない。監査・描画・保存の終了値をそれぞれ保持し、必須gateの失敗を消さない。

package名、message、追加check名等は未信頼文字列としてescapeする。HTML・Markdown表・リンク・コード囲みへの注入を検査する。生ログ、環境変数全文、認証URL、container Config全文をそのままartifactへ入れず、必要な非秘密fieldだけを選ぶ。共有前に公開範囲を確認する。
