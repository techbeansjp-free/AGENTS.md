# 確認する項目

保証範囲の案を作るときに、抜けを探すための一覧である。核はすべての案件で扱い、任意の項目は案件で選ぶ。扱わないものは理由を残す。

## 必ず扱う核

書く場所は`details/02_要件/03_品質保証範囲.md`の節である。契約書に同種の定めがあれば、条項の参照だけを書く。

| 項目 | 節 |
| --- | --- |
| 保証の基準時点（納品物の版・環境・適用する基準の版と基準日、文書の優先順位） | 保証の基準時点 |
| 検収合格の扱い（検収後に判明した差異を含む） | 保証の基準時点 |
| 検収が引き延ばされた場合の扱い（みなし検収等。可否・有効性は法務の論点として示すだけ） | 保証の基準時点 |
| 無償で対応する期間と保守契約への切替え、契約上の責任期間・通知期間 | 保証の基準時点 |
| 責任分界（外部サービス、OSSの脆弱性・サポート終了・パッチ適用、設定変更・第三者による改修、移行元・外部データの正確性） | 責任分界 |
| 条件が変わったときの分類 | 条件が変わったときの分類 |
| 調査を始める条件と修正の完了条件（調査の範囲と費用、修正・テスト・リリース、再発の扱い） | 調査を始める条件と修正の完了条件 |
| 合意の記録 | 合意の記録 |

## 任意の項目

値の置き場は、仕様書雛形の`00_利用案内.md`「置き場の表」に従う。表にないものだけを「表にない」と書き、その正本は置き場の表の規則で案件ごとに決める。

- 動作環境：ブラウザ、クライアントOS、デバイス、画面サイズ、拡大率、ブラウザ設定（Cookie・JavaScript・ストレージ）、拡張機能、言語・ロケール、タイムゾーン、ネットワーク（速度・遅延・切断）、アクセシビリティ（規格・版・適合レベル）
- 構成・実行環境：サーバーOS、言語ランタイム、フレームワーク、ライブラリ（直接・間接）、DB、ミドルウェア、インフラ、クラウド、外部API・外部サービス（プラン・制限・障害時の扱い）
- 機能・業務：対象・対象外の機能、業務フロー、業務規則、日付処理（うるう年・月末・年度末）、数値処理（丸め・桁・精度）、操作（正常・異常）、状態遷移、排他制御、二重操作、エラー処理、権限、適用法令と基準日。業務系の案件では日付処理と数値処理を外さない
- 性能・拡張性：同時利用者数、登録ユーザー数、リクエスト数、レスポンス時間（測定条件）、データ件数・容量、スケーリング、性能測定の環境・方法、ファイルアップロード、検索、帳票、バッチ、外部APIのレート制限
- データ：入力文字数、対応文字（絵文字・外字）、文字コード、数値範囲、不正データ、ファイル形式、整合性、保持期間、復旧範囲、データ移行の移行元の品質（表にない）
- セキュリティ：準拠する基準と版（OWASP ASVS等）、脆弱性対策の判定基準、想定する脅威（不正アクセス・DDoSの規模と対策範囲）、診断の範囲・方法・合格条件、合意した残存リスク、認証、認可、セッション、暗号化、通信、脆弱性監視の有無
- 可用性・信頼性：稼働率と測定条件、提供時間、計画停止、RTO、RPO、想定する障害、災害対策、バックアップ、リストア、冗長化、外部サービスの障害時の振る舞い、通信障害（タイムアウト・リトライ）
- UI・UX：承認済みデザインとの一致の基準、印刷、アニメーション、ブレークポイントとフォント・代替フォント（表にない）、画面崩れと判定する条件、OS間・ブラウザ間の許容する差異、操作性、主観的な評価と客観的な不具合の区別
- 運用・保守：運用手順、障害対応の時間・優先度、ログ、監視、納品物・仕様・テスト結果の保存（品質保証範囲「証跡の保存」）
