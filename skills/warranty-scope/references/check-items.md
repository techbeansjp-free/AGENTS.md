# 確認する項目の分類

保証範囲の案を作るときに、抜けを探すための分類である。全項目を必須にしない。案件ごとに、適用する項目と適用外の項目（理由つき）を選ぶ。

「値の置き場」は、仕様書雛形の`00_利用案内.md`「置き場の表」の「情報の種類」の名前（括弧の補足は省くことがある）で示す。pathとIDの接頭辞は置き場の表を正本とし、ここに書き写さない。置き場の表にない種類は、置き場の表の規則（話題が最も近い1ファイルを正本に決める）に従う。「品質保証範囲」とあるものは、`details/02_要件/03_品質保証範囲.md`の節に書く。

| 分類 | 確認する項目 | 値の置き場 |
| --- | --- | --- |
| 動作環境 | ブラウザ、クライアントOS、デバイス、画面サイズ、拡大率、ブラウザ設定（Cookie・JavaScript・ストレージ）、拡張機能、言語・ロケール、タイムゾーン | 保証する利用・実行環境 |
| 動作環境 | ネットワーク（速度・遅延・切断） | 対象・対象外・制約・前提 |
| 動作環境 | アクセシビリティ（規格・版・適合レベル） | アクセシビリティ・UI/UX・後方互換・保守性・テスト容易性の基準 |
| 構成・実行環境 | サーバーOS、言語ランタイム、フレームワーク、ライブラリ（直接・間接） | 保証する利用・実行環境 |
| 構成・実行環境 | DB、ミドルウェア、インフラ、クラウド | 配備環境 |
| 構成・実行環境 | 外部API・外部サービス（プラン・制限） | 対象・対象外・制約・前提。障害時の扱いは外部の依存先ごとの障害時の縮退 |
| 構成・実行環境 | 保証する納品物のリリース・commit | 品質保証範囲「保証の基準時点」 |
| 構成・実行環境 | OS・ランタイム・ライブラリのサポート終了（EOL・EOS）の責任 | 品質保証範囲「責任分界」 |
| 機能・業務 | 対象・対象外の機能 | 対象・対象外・制約・前提 |
| 機能・業務 | 業務フロー、業務規則、日付処理（うるう年・月末・年度末）、数値処理（丸め・精度） | 業務規則。機能固有のものは機能の目的と詳細 |
| 機能・業務 | 操作（正常・異常）、状態遷移、排他制御、二重操作、エラー処理 | 機能の目的と詳細、受け入れ条件 |
| 機能・業務 | 権限 | 操作ごとの必要な権限 |
| 機能・業務 | 適用法令と基準日 | 対象・対象外・制約・前提 |
| 機能・業務 | 文書の間で食い違うときの優先順位、定めのない事項の判断方法 | 品質保証範囲「保証の基準時点」 |
| 性能・拡張性 | 同時利用者数、登録ユーザー数、リクエスト数、レスポンス時間（測定条件）、データ件数・容量、スケーリング、性能測定の環境・方法 | 性能・容量・スケーラビリティ・可用性・システムのRTO/RPOの目標値と測定 |
| 性能・拡張性 | ファイルアップロード、検索、帳票 | 機能の目的と詳細。閾値は性能の正本 |
| 性能・拡張性 | バッチ | ジョブの起動・入出力・完了期限と詳細 |
| 性能・拡張性 | 外部APIのレート制限 | 対象・対象外・制約・前提 |
| データ | 入力文字数、対応文字（絵文字・外字）、文字コード、数値範囲、不正データ | データ項目の型・制約・マスキング |
| データ | ファイル形式 | ファイル・イベント連携の契約 |
| データ | 整合性 | データの所有者・正本・識別子（データ単位）・機密区分・完全性・可用性 |
| データ | 保持期間 | 業務データの保持・削除・法的根拠・Privacyの検証 |
| データ | 復旧範囲 | バックアップ対象ごとの方式・保持・達成するRPO/RTO |
| データ | データ移行（移行元の品質） | 置き場の表にない。移行計画を正本にする |
| データ | 移行元のデータ・外部データの正確性の責任 | 品質保証範囲「責任分界」 |
| セキュリティ | 準拠する基準と版（OWASP ASVS等）、脆弱性対策の判定基準、想定する脅威（不正アクセス・DDoSの規模と対策範囲）、診断の範囲・方法・合格条件、合意した残存リスク | セキュリティの脅威・対策・合格基準、監査する操作と証拠 |
| セキュリティ | 認証、認可、セッション | 操作ごとの必要な権限、セキュリティの脅威・対策・合格基準 |
| セキュリティ | 暗号化、通信 | セキュリティの脅威・対策・合格基準 |
| セキュリティ | 検収時点で適用する基準の版 | 品質保証範囲「保証の基準時点」 |
| セキュリティ | 既知・未知のOSS脆弱性の責任、脆弱性監視の有無と責任者、納品後のパッチ適用の責任 | 品質保証範囲「責任分界」。監視の信号は監視の正本 |
| 可用性・信頼性 | 稼働率と測定条件、提供時間、計画停止、RTO、RPO、想定する障害、災害対策 | 性能・容量・スケーラビリティ・可用性・システムのRTO/RPOの目標値と測定 |
| 可用性・信頼性 | バックアップ、リストア | バックアップ対象ごとの方式・保持・達成するRPO/RTO |
| 可用性・信頼性 | 冗長化 | 配備ノードの台数・スケール・冗長化・障害分離の境界・障害影響・復旧 |
| 可用性・信頼性 | 外部サービスの障害時の振る舞い、通信障害（タイムアウト・リトライ） | 外部の依存先ごとの障害時の縮退。共通の規則はHTTP API・CLIの共通契約 |
| 可用性・信頼性 | 外部サービスの障害時にどこまで保証するか | 品質保証範囲「責任分界」 |
| UI・UX | 承認済みデザインとの一致の基準、印刷、アニメーション | 画面の目的と詳細 |
| UI・UX | ブレークポイント、フォント・代替フォント | 置き場の表にない。デザイントークン・レイアウトトークンを正本にする |
| UI・UX | 画面崩れと判定する条件、OS間・ブラウザ間の許容する差異、操作性、主観的な評価と客観的な不具合の区別 | アクセシビリティ・UI/UX・後方互換・保守性・テスト容易性の基準 |
| 運用・保守 | 運用手順、障害対応の時間・優先度 | 運用ごとの初動・エスカレーション・復旧の確認条件 |
| 運用・保守 | ログ、監視 | 監視の信号・閾値・ログの保存期間・検知の合格基準 |
| 運用・保守 | 設定変更の範囲と責任者、第三者による改修後の責任、アップデートの責任者 | 品質保証範囲「責任分界」 |
| 運用・保守 | 原因調査の範囲と費用の負担、瑕疵の修正の範囲（修正・テスト・リリース） | 品質保証範囲「調査を始める条件と修正の完了条件」 |
| 運用・保守 | 納品物・仕様・テスト結果の保存 | 品質保証範囲「証跡の保存」 |
| 運用・保守 | 保守の終了、契約上の責任期間・通知期間 | 契約書（品質保証範囲には条項の参照だけを書く） |

条件が変わったときの区分（瑕疵対応・互換性対応・保守・改修・仕様変更等）と判定の流れは、`details/02_要件/03_品質保証範囲.md`の「条件が変わったときの分類」と「調査を始める条件と修正の完了条件」を正本とする。
