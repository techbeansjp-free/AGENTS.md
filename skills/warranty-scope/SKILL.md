# 受託開発の保証範囲の合意

受託開発で瑕疵対応が無制限に広がらないように、保証の対象・条件・対象外と、瑕疵対応の始まりと終わりの条件を、顧客と合意する前に揃える。合意した内容は仕様書の品質保証範囲に残し、後で来た不具合や依頼が瑕疵対応か、保守・仕様変更・追加開発かを、合意と証跡で判定できるようにする。

中心の考え方：責任期間の長さと、保証の対象・条件・範囲を分けて扱う。責任期間が無期限でも、対象・条件・範囲は無制限にしない。顧客が期間の延長を求めた場合も、期間は法務・契約の判断に残し、対象・条件・範囲を限定する案を出す。

作るのは案までとする。顧客への送信と合意の確定は権限を持つ担当者が行い、説明文の作成は送信の許可ではない。契約書の雛形や条文は作らない。法的な有効性（責任期間を契約で変えられるか、免責の定めが有効か等）は断定せず、論点と判断者（法務）を示す。用語は、実務上の対応を「瑕疵対応」、法律上の責任を「契約不適合責任」（2020年施行の改正民法で、「瑕疵担保責任」に代わり定められた）と書き分ける。

顧客に納品して保証範囲の合意が必要な案件で使う。合意の相手がいない案件（OSS・社内ツール等）や通常の開発の工程には挟まない。

## 材料と書く場所

仕様書、既存の決定（Issue・議事録等）、契約書のうち保証・検収・責任期間の条項の所在を確かめる。既存の書式・ID・置き場があればそれに従う。

仕様書雛形を使う場合、列・節は雛形の`details/02_要件/03_品質保証範囲.md`を正本とし、値の置き場は`00_利用案内.md`の「置き場の表」で決まる。雛形は`project-assets`の配布先では`.agent-skill-chain/templates/specs/`、パッケージ内では`v05/templates/specs/`にある。このSkillは別の書式を持たない。

## 項目を選ぶ

[確認する項目の分類](references/check-items.md)から、案件で適用する項目を選ぶ。全項目を必須にせず、適用外にした分類は理由を残す。業務系の案件では、機能・業務の分類の日付処理と数値処理の行を外さない。

## 値は正本に置き、IDで参照する

保証する値（対応環境の版・性能の閾値・稼働率・セキュリティの合格基準・受け入れ条件等）は置き場の表の正本に書き、品質保証範囲と説明文には正本のIDと場所だけを書く。同じ値を二か所に書くと、片方だけが更新されて食い違うためである。IDに値やラベル（ブラウザ名等）を括弧で添えない。未決事項の文にも値を書かない。添えてよいのは正本の場所（ファイルと節）だけである。正本に値がまだなければ、正本への追記を提案するか、未決（OPEN ID）にする。

## 雛形の節を埋めたら確かめること

雛形の各節（節の名前と列は雛形が正本）が、案件の値ではなく正本のIDと合意の事実で埋まっているかを確かめる。特に次の三つは抜けやすい。

- 保証の基準時点：検収時の版・環境・適用する基準の版と基準日が特定できるか。
- 調査を始める条件と修正の完了条件：瑕疵でなかった場合の調査の費用と、何をもって修正が完了するか（修正・再検証・リリース）が決まっているか。
- 合意の記録：版・合意者・合意日・根拠があるか。

合意できていないものは未決にする。

## 未決事項に判断者を付ける

未決事項は置き場の表の「未決事項」の正本にOPEN IDで書き、判断者を付ける。対象プロジェクトの体制を優先し、次は既定の目安とする。

| 論点 | 既定の判断者 |
| --- | --- |
| 責任期間・通知期間・免責の定めの有効性、契約不適合責任の扱い | 法務 |
| 保証の範囲・費用負担・保守契約との切り分け | 契約・営業の権限を持つ担当（提供側）と、顧客の契約担当 |
| 保証する値・測定方法・技術的な実現性 | 技術の担当 |
| 業務上必要な範囲・受け入れる残存リスク | 顧客の業務の責任者 |

判断者が決まっていない論点は、それ自体を先頭の論点にする。

## 顧客への説明文の案を作る

送信はしない。何を保証し何を保証しないか（WAR IDと正本の参照）、条件が変わったときの扱いと瑕疵対応・保守・追加開発の分かれ目、顧客に決めてもらう未決事項と回答の期限、法務の確認が必要な論点（結論は書かない）を含める。

## 出力

既存の記録先と書式があればそれに従う。なければ、品質保証範囲の案（雛形の節に沿う）、正本へ追記を提案する値とその文書、未決事項と判断者、説明文の案を返す。

## 扱わないこと

合意の後に来た依頼の判定と見積は[estimate-and-scope](../estimate-and-scope/SKILL.md)、保証範囲に関係しない未決事項の整理は[decision-ownership](../decision-ownership/SKILL.md)、開発基盤の先行決定は[project-foundation](../project-foundation/SKILL.md)が扱う。個別の案件の値（ブラウザの版・稼働率等）は決めない。
