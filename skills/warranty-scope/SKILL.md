# 受託開発の保証範囲の合意

受託開発で、瑕疵対応が無制限に広がらないように、保証する対象・条件・対象外・条件が変わったときの扱い・瑕疵対応の開始と終了の条件を、顧客と合意する前に揃える。合意した内容は仕様書の品質保証範囲に残し、後で不具合や依頼が来たときに、瑕疵対応か、保守・仕様変更・追加開発かを、合意と証跡に照らして判定できる状態にする。

作るのは案までとする。顧客への送信と合意の確定は、権限を持つ担当者が行う。回答案や説明文の作成は送信の許可ではない。契約書の雛形や条文は作らない。

法的な有効性は断定しない。例えば、契約不適合責任の期間を契約で変えられるか、免責の定めが有効かは、論点と判断者（法務）を示すまでとする。用語は、実務上の対応を「瑕疵対応」、法律上の責任を「契約不適合責任」（2020年の民法改正で「瑕疵担保責任」から改称）と書き分ける。

顧客に納品して保証範囲の合意が必要な案件で使う。OSS・社内ツールなど合意の相手がいない案件や、通常の開発の工程には挟まない。

## 材料を集める

対象プロジェクトの仕様書、既存の決定（Issue・議事録等）、契約書のうち保証・検収・責任期間に関わる条項の所在を確かめる。既存の書式・ID・置き場があればそれに従う。

仕様書雛形を使う場合、書く場所は雛形の`details/02_要件/03_品質保証範囲.md`（品質保証範囲）と、`00_利用案内.md`の「置き場の表」で決まる。雛形は`project-assets`の配布先では`.agent-skill-chain/templates/specs/`、パッケージ内では`v05/templates/specs/`にある。このSkillは別の書式を持たない。

## 項目を選ぶ

[確認する項目の分類](references/check-items.md)で、動作環境から運用・保守までの分類ごとに、案件で適用する項目と適用外の項目を選ぶ。全項目を必須にしない。適用外にした分類も、理由を残して状態を「適用外」にする。

## 値は正本に置く

品質保証範囲には、項目ごとに次の6つを揃える：保証する値と測定条件（正本のID）、対象外（CON ID）、条件が変わったときの分類、証跡、合意の版（合意者・合意日は合意の記録の表）、状態（合意済み・未決・適用外）。

保証する値（対応環境の版・性能の閾値・稼働率・セキュリティの合格基準・受け入れ条件等）は、置き場の表の正本に書き、品質保証範囲には正本のIDだけを書く。正本に値がまだなければ、正本の文書に提案として書くか、未決（OPEN ID）にする。品質保証範囲や説明文に値を書き写さない。

## 無制限に広がらないための取り決め

次を、品質保証範囲の該当する節に案として書く。合意できていないものは未決にする。

- 保証の基準時点：検収時のリリース・commit、保証する環境、適用する基準とその版・基準日。
- 検収で合格したものの扱いと、文書の間で食い違うときの優先順位。
- 調査を始める条件：報告の形式（再現手順・環境と版・期待した結果と実際の結果）と窓口。
- 原因調査の費用の扱い：瑕疵と判明した場合・しなかった場合・判定できない場合。
- 修正の完了条件（修正・テスト・リリースの範囲）と、同種の不具合が再発した場合の扱い。
- 責任分界：第三者による改修、顧客側の設定・インフラの変更、外部サービス、OSSの脆弱性・サポート終了、納品後のパッチ適用。
- 条件が変わったときの分類：雛形の区分を出発点に、案件で合意する区分と扱いに置き換える。

## 未決事項に判断者を付ける

未決事項は、置き場の表の「未決事項」の正本にOPEN IDで書き、判断者を付ける。対象プロジェクトの体制を優先し、次は既定の目安とする。

| 論点 | 既定の判断者 |
| --- | --- |
| 責任期間・通知期間・免責の定めの有効性、契約不適合責任の扱い | 法務 |
| 保証の範囲・費用負担・保守契約との切り分け | 契約・営業の権限を持つ担当（提供側）と、顧客の契約担当 |
| 保証する値・測定方法・技術的な実現性 | 技術の担当 |
| 業務上必要な範囲・受け入れる残存リスク | 顧客の業務の責任者 |

判断者が決まっていない論点は、それ自体を先頭の論点にする。

## 顧客への説明文の案を作る

顧客に合意を求める説明文の案を作る。送信はしない。次を含める。

- 何を保証し、何を保証しないか（品質保証範囲のWAR IDと正本の参照で示し、値を書き写さない）。
- 条件が変わったときの扱いと、瑕疵対応と保守・追加開発の分かれ目。
- 顧客に決めてもらう未決事項と、回答の期限。
- 法務の確認が必要な論点（法的な結論は書かない）。

## 出力

既存の記録先と書式があればそれに従う。なければ次を返す。

- 品質保証範囲の案（雛形の節に沿う）。
- 正本の文書へ追記を提案する値と、その文書。
- 未決事項と判断者。
- 顧客への説明文の案。

## 扱わないこと

合意の後に来た依頼が瑕疵対応か保守・追加開発かの判定、見積・費用は[estimate-and-scope](../estimate-and-scope/SKILL.md)を使う。保証範囲に関係しない未決事項と判断者の整理は[decision-ownership](../decision-ownership/SKILL.md)、開発基盤の先行決定は[project-foundation](../project-foundation/SKILL.md)が扱う。個別の案件の値（ブラウザの版・稼働率等）は、このSkillでは決めない。
