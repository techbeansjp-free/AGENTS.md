# 抜け道と反例

必要な行だけ選び、実際の言語・規約へ落とす。すべての製品に全検査を追加する一覧ではない。

| 対象 | 調べる迂回・境界 | 証拠 |
| --- | --- | --- |
| 型・入力 | any相当、型断定、抑制、別名、raw値の再読取り、未検証deserialize | 許される型の成功、違反の失敗、入力境界での実拒否 |
| 依存方向・循環 | alias、再export、型参照、dynamic import、生成物、初期化順 | 実解決に合わせたgraph、合法な参照と禁止cycleの反例、未対応構文の扱い |
| schema・生成 | 古い生成物、手編集、別のschemaコピー、失敗後の旧成果物 | 正本から再生成した差分、互換性検査、生成失敗の終了値 |
| UI token・部品 | 値の直書き、inline style、変数経由、共通部品の迂回、例外領域 | AST等による許可/拒否例と実画面の確認。数値の存在だけで全違反にしない |
| 規約・実装の照合 | 対象収集漏れ、空集合、unknown設定、例外の肥大化 | 対象一覧、設定破損の反例、実CLI・CI入口での不合格 |

正規表現だけで扱える境界とAST・型情報が必要な境界を分ける。解析できない構文を黙って無視せず、対応範囲と停止・手動確認の扱いを定める。コメントや文字列内の例を実コードと誤認しない。

静的な非循環と、event/retry/stateの進捗は別問題である。後者は上限・中断・状態遷移を実仕様から確認する。guardを外す反例は専有の合成fixtureで行い、成功するだけの自己参照したテストで検査能力を証明しない。
