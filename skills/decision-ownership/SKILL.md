# 未決事項と判断者の整理

依頼や記録を、判断する人が自分で決められる形に整える。出すのは問い・判断者・判断材料・仮置き案までであり、判断そのものは判断者に残す。判断者が自分で決めた判断は理由と一緒に残り、後の変更や引継ぎで説明できる。代わりに決めた判断は残らない。

事実で答えられること（既存機能で実現できるか、過去に何を決めたか、記録に何があるか）は、確認した範囲で答える。確認できないことは未確認と書き、推測で埋めない。材料が少なく判断に進めない場合は、判断に必要な最小限の問いだけを返す。

回答案や依頼文の作成は、送信・起票・公開の許可ではない。対象プロジェクトの権限・連絡経路・既存の記録先に従う。

## 依頼の背景と要否を確かめる

依頼の言葉どおりに受け取らず、誰の要望か、何のために必要か、今はどう対応しているかを押さえる。分からなければ、それ自体を最初の論点にする。主な窓口以外から来た要望は、出どころと優先度の根拠を確かめてから扱う。

新しく作る前に、既存の機能・運用・別の対応で目的を満たせないかを確かめる。要否が未確認の依頼・追加要望・対応漏れでは、「やらない」も選択肢に含める。合意済みの必須要件や不具合の是正で要否を蒸し返さない。

## 確定と未確定を分ける

決まっていること、未決のこと、できれば入れたいことを混ぜない。口頭や会話だけで決まったことは、記録先に残っているかを確かめ、残っていなければ記録を論点にする。未決に依存する部分を実装担当へ渡さず、依存しない作業は進める。不確かなものは後回しにする判断も選択肢に入れる。

## 判断者を割り当てる

未決事項ごとに、誰が決めるかを書く。対象プロジェクトの契約・体制・既存の決定権限を優先し、次は既定の目安として使う。

| 判断 | 既定の判断者 |
| --- | --- |
| やるか・リリースしてよいか・完了か・業務ルール | 発注者・業務の責任者 |
| 優先度・スケジュール・リスクの受容・体制 | プロジェクトの管理責任者 |
| 技術的な実現方法・調査の進め方 | 実装・技術の担当 |
| 契約・費用・請求の変更 | 契約・経営の権限を持つ担当 |

提供側が先に進める場合は、その理由を記録に残す。判断者が決まっていない事項は、それ自体を最優先の論点にする。進まない原因が手段ではなく判断者の不在であることが多い。

## 先に伝えるべきリスクを出す

起きてから伝えると選択肢が減るものを先に出す。対象に関係するものだけを使い、毎回全項目を並べない。

- 新しい業務や差込みを引き受けると、誰の工数が圧迫され、何が遅れるか。
- 依頼の総量が対応できる量を超えていないか。超えていれば優先度の付け直しを依頼する。
- 見積・予定が目安ではなく確定値として扱われていないか。
- 例外の扱いや緊急時の動き方が決まらないまま運用が始まっていないか。
- 判断や承認が一人に集中し、確認待ちが詰まっていないか。
- 顧客側の事情（社内調整・体制の変化・予算の不安）が要件や日程のリスクになっていないか。
- デモや外部の行事など、日付が動かせない予定が計画に入っているか。

リスクは、誰に・いつまでに伝えるかと一緒に書く。稼働や費用への影響は数値で早めに出し、提供側の内部で確認してから顧客へ伝える順にする。

## 仮置き案を添える

止まっている論点には、判断者が決めやすいたたき台を添える。仮置き案であることを明記し、採用は判断者が決める。判断材料は、工数の目安・影響範囲・やらない場合のリスクをそろえて出す。数が多い場合は全量を一覧にしたうえで、重要なものを絞って先頭に置く。一覧の列は固定する（例：区分〈不具合・改善要望・ルール未定〉、前提条件、再現手順、対応状況、結果）。

## 相手に合わせて渡す

- **実装担当**：判断を丸投げしない。窓口で返せるものは窓口で返し、実装を見ないと分からない問いだけを、再現条件をつけた明確な形で渡す。業務や利用者の観点を補う。
- **顧客・発注者**：選択肢と判断材料をそろえ、決めやすい形にする。顧客側の事情は要件のリスクとして扱い、押し通さない。
- **経験の浅い担当・後任**：作業の範囲と判断基準を先に渡す。期限と確認の重さを添え、迷ったときの相談先を示す。
- **進行役が別にいる場**：仕切らない。抜けている文脈（要望の出どころ、優先度、過去の経緯）だけを補う。

依頼には期限と負荷の重さを添える。判断を返すときは、その人が決める理由を一言添える。

## 出力の形

既存の記録先や返信の形式があればそれに従う。なければ次を任意の例として使い、該当しない項目は省く。

```text
要点：<この件で最も大きい論点を1〜2文>
先に確認したいこと：<背景・目的・現状で分かっていないこと>
未決事項と判断者：<未決事項> → <判断者>（<理由>）。判断者が決まっていないものを先頭に置く
先に伝えたいリスク：<リスク>（<誰に・いつまでに>）
仮置き案：<案>（工数の目安／影響範囲／やらない場合のリスク）
渡し方：<相手> へ <渡す内容>
```

条件によって判断が変わる事例や、運用の型をそのまま他案件へ持ち込みそうなときは、[適用条件と反例](references/conditions-and-counterexamples.md)を読む。

## 扱わないこと

人物の性格や能力を評価しない。見るのは案件と判断の構造である。特定の個人の口調や過去案件の運用を、他の案件の規則にしない。設計案の比較と反証は[engineering-judgment](../engineering-judgment/SKILL.md)、見積・保守範囲・費用の責任分担は[estimate-and-scope](../estimate-and-scope/SKILL.md)、確認事項の回答と反映の追跡や引継ぎ文は[work-coordination](../work-coordination/SKILL.md)、起票は[tracker-issue-writing](../tracker-issue-writing/SKILL.md)を使う。誤字修正や決定済みの機械的な作業に、このSkillの整理を挟まない。
