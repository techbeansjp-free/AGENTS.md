# 開発基盤と規約の構築

目的は、チームが同じ規約と再現可能な環境で開発・検証できる状態を作ること。依存導入や文書作成だけを環境構築完了としない。既存基盤は動く環境・未保存成果・秘密・データを保護して不足を補う。この本文とreferencesは他のAIでも利用でき、`agents/openai.yaml`は任意のCodex用表示情報として扱う。

## 要求と適用範囲を確認する

既存基盤の点検だけを依頼された場合は、適用する契約と現状を照合し、指摘・影響・整備案を返す。構築・整備・修正も依頼された場合だけ対象を変更する。referencesの是正手順もこの作業範囲に従う。

ユーザー要求、AGENTS等、規約・構築手順・CI・lockfile・既存コードを出発点にする。作業場所・レビュー・外部操作の権限は対象プロジェクトに従う。このスキル自体はASC、GitHub、特定IDE、クラウド、言語、フレームワークの導入や公開を要求しない。

製品形態、対応OS/CPU、稼働規模、配備先、データ/信頼境界、外部接続、今回の完了範囲を把握する。不足情報があっても依存しない調査・許可された可逆な整備は進め、必要な未決事項だけ確認する。過去案件の版・port・保持期間・CVE例外・完了実績を新案件へ持ち込まない。変わる製品情報は公式の一次情報で確認する。

## 手戻りが大きい決定を先に揃える

referencesの具体的な構成は採用候補として読み、既存の必須契約と区別する。非root等の安全策も実行基盤と役割に応じて適用し、契約で必須の条件は黙って緩和しない。

まず[先行決定一覧](references/foundation-decisions.md)を既存成果と照合する。関連する詳細だけを追加で読む。

| 今回の対象 | 読む詳細 |
| --- | --- |
| API、型、DDD、画面、部品、保存・検索 | [契約・型・画面・データ](references/contracts-and-ui.md) |
| 構築入口、コンテナ、PRD/STG/DEV、worktree、port、復旧 | [実行環境と並行開発](references/containers-and-worktrees.md) |
| テスト、CI、脆弱性監査、Summary、ログ、完了証拠 | [検証・セキュリティ・証跡](references/verification-and-security.md) |

各判断は既存の規約・ADR・Issue等へ集約し、「決定/理由・境界・検査・状態・未決の有効化条件」を対応付ける。追加の台帳や固定ファイル構成を一律に要求しない。

- **今決める**：後で変えると複数機能・保存データ・利用者操作の互換性を壊すもの。共通APIエラー、認可、識別、設定/生成の正本等を後回しにしない。
- **選択済み/未検証**：設定や仕様はあるが実接続・復旧・CI等が未確認のもの。
- **後続で具体化**：要件がまだない業務schemaや負荷依存の選択。有効化前の作業と受入を明示する。
- **適用外**：製品形態と今回の範囲による理由を残す。CLIへ画面や、DB不要の道具へDBを追加しない。

## 規約を実行可能な基盤にする

必須の契約はユーザー要求と対象projectの規約から特定する。型ファースト、スキーマ駆動、DDD、画面/利用者操作からの実装は設計候補として、既存方針・製品形態・保守費用に照らして採否を決める。採用していない方針を検査の必須条件にしない。対象言語と製品形態へ落とし、空の層や不要な抽象化を増やさない。ルールごとに許す境界と禁止する迂回を明示し、型・lint・契約差分・依存/循環・UI/token・テスト・audit等の適切な検査に接続する。検査除外や型抑制で不合格を消さない。

初参加者向けにMakefile等の短い共通入口とREADMEを用意し、既存scripts/タスクへ委譲する。Make利用可能環境は`make help/setup/check/up/down`等を初期値とし、合意済みの同等入口があれば合わせる。未導入runtimeをbootstrap自体の前提にせず、個人のグローバル環境を暗黙に変更しない。

アプリ・DB・保存・ログ等は必要なものを実接続する。通常起動に破壊的resetを含めない。失敗・中断・部分起動・再実行で、自分が所有する資源だけを整理する。規約変更は理由・影響・移行と検査を一致させ、定義と実装のずれを残さない。

## 計画と完了を対応付ける

先行決定・構築・検証・共有CIを、受入可能な実装粒度へ分けて計画する。Issue/Project運用がある場合は既存の粒度・依存・計画周期へ対応付ける。phase labelや週単位スプリントの新設を必須にしない。実装だけで稼働を埋めず、レビュー・再検査・復旧等の容量を取る。チーム規模や開始日を仮置きする場合は明示し、拡張した範囲で旧見積りが成立するか見直す。

同じ対象の実コマンドと結果を確認し、次を分けて報告する。

- 規約・設定・機械検査が一致した範囲。
- ローカルの構築・品質・実接続・セキュリティが成功した範囲。
- 新規checkout/runner、対応OS/CPUで再現確認できた範囲。
- 共有CI・保護設定・レビュー体制が実際に適用された範囲。
- 商用配備まで依頼された場合、その環境で運用・復旧を確認した範囲。

未確認は未確認とし、設定候補を適用済み、scan失敗をゼロ件、単一環境の成功を移植完了としない。是正が依頼範囲なら変更して影響範囲を再検証し、点検のみなら未是正事項として返す。許可外の外部操作・個人端末管理・公開まで拡張しない。
