# ASCの独立レビューと是正

元要求・受入条件・適用規約・確認済みworktree・base/HEAD・未commit差分・検証結果を渡し、[変更のレビューと是正](../../review-and-remediation/SKILL.md)を読んで実体を確認する。振る舞い・設計・セキュリティ・反例・指摘の根拠・Evidenceの更新はその手順と参照資料を正本とする。入口の相互参照だけでレビューを終えない。

ASCでは次の契約を維持する。

- 進行役は現在のHostの別Contextへ独立レビューを依頼する。起動時の必須tool制限を実際の設定で満たし、プロンプトの「read-only」で代用しない。詳細は[ASC入口](../SKILL.md)の「独立レビューと提出」を参照する。
- 指定された既存worktreeと依存環境を使い、レビューのためだけにworktreeやsnapshotを複製しない。対象を確認できない、必要なtool制限を満たせない、独立Contextが使えない場合は未完了として扱う。
- 原則1系統で行い、認可・データ損失・並行処理・サービス間契約等で未解決の不確実性がある場合だけ、問いを限定して追加Reviewerを選ぶ。

## 重要度別の是正と再レビュー

High・Mediumは是正後、指摘の解消と影響範囲の回帰を独立レビューで確認する。Lowは是正または非是正の根拠を既存の結果へ残す。commitが許可されたGit作業ではLowの是正を1 commitにまとめる。Git未管理なら1変更単位にまとめ、Git導入を強制しない。

Lowだけでも振る舞い・契約・権限が変わる、または影響を限定できなければ再レビューする。誤字等で影響しないと進行役が確認できる場合だけ再レビューを省略できる。必要な実検証と提出対象・Evidenceの一致は維持する。

起動権限の違反や必須観点の欠落があれば影響する合格Evidenceを保留し、対象・実際の操作・欠けた確認を照合する。適合する権限で必要なレビューを再実行する。「今後注意する」だけで是正済みとせず、未確認の操作や変更を断定しない。
