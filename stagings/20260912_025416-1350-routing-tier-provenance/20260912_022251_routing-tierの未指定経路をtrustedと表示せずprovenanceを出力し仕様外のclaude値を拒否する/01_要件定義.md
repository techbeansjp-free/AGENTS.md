## 1. システム・変更概要

- 対象利用者: 利用projectの進行役・reviewer（`routing tier`を実行し結果を証跡へ残す）、ASC maintainer
- 実現する価値: `routing tier`の出力だけで判定の信頼源と用途が分かり、working treeの互換検証をtrusted検査と誤読しない。受理値が仕様06と一致する
- 変更前の振る舞い: `--provider=claude`を受理し未指定と同じworking tree判定を行う。失敗診断は「trusted project choiceへmodel mappingを定義」「requiredAuthority: model mapping owner」と述べ、出力は信頼源を持たない
- 変更後の振る舞い: `--provider=claude`は`ASC-CLI-VALIDATION-001`で拒否。未指定経路は出力へ`provenance: {source: "filesystem"|"filesystem-legacy", ref}`と`usage: "compatibility-only"`を含め、失敗診断はworking treeへの定義を案内し`requiredAuthority`は「不要」。`codex`経路は判定不変で`provenance: {source: "git", ref: <trusted commit>}`と`usage: "codex-adoption"`を加える
- 対象外: `claude`経路のtrusted読み、`codex`経路の先行読み取り除去、別command分離、利用側の合成の防止（00 §2.2）

### 2.3 不変条件

- INV-02: `--provider`の受理値は仕様06の`codex`だけである
- INV-03: `codex`経路の判定と既存出力fieldは変わらない

## 6. 外部インターフェースとデータ

### 6.1 外部境界

| 境界 | 方向 | 契約 | 認証・承認 | 失敗・再試行 |
|---|---|---|---|---|
| CLI `routing tier` | 入力 / 出力 | `--provider`は`codex`または未指定。出力へ`provenance`・`usage`を追加 | 不要 | 非0で終了。再試行は入力修正後 |

### 6.2 データ要件

- データ項目と意味: `provenance.source`（policy loaderの語彙をそのまま写す。現在は`filesystem`／`filesystem-legacy`／`git`／`git-legacy`／`git-floor`の5値で、`src/domain/policy.ts`が唯一の発生源。**handlerで正規化しない**）、`provenance.ref`（file pathまたはcommit SHA）、`usage`（`compatibility-only`／`codex-adoption`）
- 検証・正規化: loaderが返した観測値をそのまま写す
- 保存期間と削除: 保存しない（利用側が証跡へ転記する）
- 個人情報・秘密情報: 含まない（pathとSHAのみ）
- 既存データとの互換性: 既存fieldは不変。fieldの追加のみ
- 識別子方針: 既存。新規scenarioは`SCN-UNIT-TIERPROV-<3桁>`

## 8. Zero Trustと権限要件

- 検証する入力: `--provider`の値
- 検証するリポジトリ・リモート同一性: 変更なし（`codex`経路の既存検証を維持）
- 認証確認: 不要
- 操作単位の承認: 不要
- 書き込み直前に再検証する状態: 該当しない（read-only）
- 不明時に拒否する条件: `--provider`が`codex`以外
- 権限を分離する後続操作: なし
- authority/evidence graphの正方向と自己参照・相互参照の拒否条件: 未指定経路の結果を認可へ流す辺を作らない（`usage: compatibility-only`）
- head変更で失効する下流証拠: 既存規則どおり

## 9. 受け入れ条件と実行可能な受け入れ例

| AC ID | 受け入れ条件 | 例ID | project選択test layer | 観測方法 |
|---|---|---|---|---|
| AC-01 | `--provider=claude`は終了値1で、`reasons`に`codex`だけを受理する旨と未指定の互換検証の案内を含む | SCN-UNIT-TIERPROV-001 | unit | CLI `main`の出力 |
| AC-02 | 未指定経路でworking treeへkeyを足した場合の成功出力に`provenance.source`（`filesystem`）と`usage: "compatibility-only"`が含まれる | SCN-UNIT-TIERPROV-002 | unit | CLI `main`の出力 |
| AC-03 | 未指定経路の失敗出力に`provenance`が含まれ、`next`に「trusted」の語が無く`requiredAuthority`が「不要」 | SCN-UNIT-TIERPROV-003 | unit | CLI `main`の出力 |
| AC-04 | `codex`経路の出力に`provenance`（`source`はpolicy loaderの語彙をそのまま写した値、`ref`はtrusted commit SHA）と`usage: "codex-adoption"`が加わり、既存field（`selector`、`observedAt`等）と判定が不変。**loaderの語彙を正規化しない。** 正規なproject directory構成では`git`、legacy monolithでは`git-legacy`、floor適用時は`git-floor`になる | SCN-E2E-AM-001（既存、公式観測stubつきの実CLI経路） | unit | 既存codex-launch fixtureでの終了値と出力 |
| AC-05 | `provenance.source`はpolicy loaderが返した値と**恒等**であり、特定の値だけを別の値へ読み替えない。`filesystem`／`filesystem-legacy`／`git`／`git-legacy`／`git-floor`のいずれを渡しても同じ値が返る | SCN-UNIT-TIERPROV-004 | unit | `tierProvenance`の戻り値 |

- project policyが選択した言語とrunner形式の実行可能な受け入れ例（`gherkinDialect: en`、cucumber-js、`test/features/unit/routing-tier-provenance.feature`）:

```gherkin
@unit
Feature: routing tierは判定の信頼源と用途を出力し仕様外のprovider値を拒否する

  Scenario: SCN-UNIT-TIERPROV-001 provider=claudeを拒否する
    Given trusted policyを持つ隔離repositoryがある
    When routing tierを--provider=claudeで実行する
    Then codexだけを受理する案内つきで拒否される

  Scenario: SCN-UNIT-TIERPROV-002 未指定経路の成功出力はfilesystemのprovenanceと互換検証の用途を持つ
    Given trusted policyを持つ隔離repositoryのworking treeへtierMappingのkeyを未commitで足す
    When routing tierをprovider未指定で実行する
    Then 成功出力はprovenance.source filesystemとusage compatibility-onlyを含む

  Scenario: SCN-UNIT-TIERPROV-003 未指定経路の失敗診断はtrustedを主張しない
    Given trusted policyを持つ隔離repositoryがある
    When routing tierを未定義のmodelでprovider未指定で実行する
    Then 失敗出力はprovenanceを含みnextにtrustedの語が無くrequiredAuthorityは不要である

```

## 10. 境界値、異常、悪用、回帰

| 観点 | 条件 | 期待する振る舞い | シナリオID |
