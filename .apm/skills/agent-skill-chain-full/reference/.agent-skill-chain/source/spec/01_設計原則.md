# 設計原則

本プロジェクトでは以下の設計思想を採用する。

---

## UNIX哲学

基本原則

- 小さく作る
- 1つのことをうまくやる
- シンプルに保つ
- 組み合わせ可能にする

---

## 単一責務

1モジュールは1つの責務のみ持つ。

複数責務が存在する場合は分割する。

---

## 明確な境界

コンポーネント間の責務を明確にする。

例

- UI
- API
- Domain
- Infrastructure

---

## CQRS

状態変更と状態取得を分離する。

- Command = 状態変更
- Query = 状態取得

---

## イベント駆動

ユースケース実行後にイベントを発行する。

イベントは **「起きた事実」** を表す。

例

- UserCreated
- OrderPlaced
- AudioUploaded

---

## AIフレンドリー設計

AIによるコード理解を容易にするため、以下を守る。

- 小さなファイル
- 明確な責務
- 意図が分かる命名
- 深すぎないディレクトリ構造
