# CONTEXT_EFFICIENCY.md — issue 起票時のコンテキスト効率（ISSUE_CREATION）の正本

**責務**: 大規模一括起票時のコンテキスト肥大を防ぐ汎用原理（ISSUE_CREATION）の正本を 1 か所に持つ。具体数値・タグ運用は混入させず `.agent-skill-chain/project/` に委ねる。規模比例で、単一/少数 issue は [CLAUDE.md §issue 作成タスク受領時の標準フロー](../CLAUDE.md) の軽量運用を保つ。

---

## issue 起票時のコンテキスト効率（ISSUE_CREATION）

- **作業単位 = 1 issue**。1 issue は **fresh サブ**で扱い、issue 間で文脈を持ち越さない（issue-persist 境界）。
- **仕様 inventory は一度だけ索引化**し、各サブには必要な**スライスのみ渡す**（全文を毎回渡さない）。
- **確定した起票順序を正本化**し、親は issue 区切りで /clear する。

---

## issue-persist 境界

親が issue 区切りで /clear してよい（＝次の issue 起票へ安全に進んでよい）のは、当該 issue について次の **4 条件がすべて充足**したときに限る。未充足のまま /clear すると、後続 fresh サブが親要点を再構築できず手戻りとなるため、必須のチェックリストとして扱う。

1. **00〜03 充足**: 当該 issue の要求定義・（必要な場合の）要件定義・設計・実装計画が、規約上必須の項目を欠落なく満たしている。
2. **レビュー指摘収束**: 当該 issue に対するレビュー指摘が 0 件に収束している（却下済み指摘の理由も含め収束状態にある）。
3. **書記記録**: 実施内容・変更点・完了判定が記録として残されている。
4. **親登録**: 当該 issue が親（束ねる側）の管理下に登録されている（束ねる親を持つ場合）。

具体の充足判定手順・記録先の様式等の実値は `.agent-skill-chain/project/` に委ねる。

---

## fresh サブ構造化ハンドオフ

1 issue = 1 fresh サブで起票を進める際、親は**前 issue の会話往復を引き継がせず**、次の**構造化ハンドオフの最小情報のみ**を渡す。

- **対象**: 起票する issue が何であるか（範囲の同定）。
- **親要点の抜粋**: 親が把握している背景・制約のうち、当該 issue の起票に必要な部分のみの抜粋（全文を渡さない）。
- **担当スライス**: 仕様 inventory 索引から当該 issue に対応する部分のみのスライス（後続節参照）。
- **既出確認結果**: 先祖・兄弟・子孫を走査した既出確認（dedup）の結果（新規起票か、既存への紐付けか）。

fresh サブ構成（文脈リセット）をまたいでもレビューの収束保証・退行防止が保たれるよう、継承すべき物の扱いは [REVIEW_DUAL_LENS.md §6 反復ループへの must-preserve 継承（退行検知）](REVIEW_DUAL_LENS.md#6-反復ループへの-must-preserve-継承退行検知) に委譲する（本節では構造化ハンドオフに含める最小情報のみを定め、継承の原則本文は再定義しない）。

---

## 仕様 inventory の索引化＋スライス渡し

「仕様 inventory は一度だけ索引化」を具体化する。

- **索引化は起票着手前に 1 回だけ**行う。既存の spec・docs 群を全文読み込むのではなく、各 issue が参照すべき箇所を指す**索引（見出し・対応範囲の一覧）**を先に作る。
- 索引化の後は、**各 fresh サブには対応するスライスのみ**を渡す（索引全体・仕様全文を毎回渡さない）。
- 索引と併せて**確定した起票順序を正本化**し、順序の再検討・往復をサブごとに繰り返させない。

具体のタグ運用・索引の保存形式等の実値は `.agent-skill-chain/project/` に委ねる。

---

## 適用のスケーリング

上記の各節は、起票対象の規模に応じて適用範囲を変える。過剰適用（軽量な起票にまで全機構を強制すること）は避ける。

- **単一/少数 issue（軽量運用）**: issue-persist 境界とフェーズ省略禁止原則**のみ**を適用する。仕様 inventory の索引化・確定起票順序表・fresh サブの構造化ハンドオフといった全機構は発動しない。
- **大規模一括起票（全機構発動）**: 上記の issue-persist 境界に加え、仕様 inventory の索引化＋スライス渡し、確定起票順序の正本化、1 issue = 1 fresh サブの構造化ハンドオフを**すべて**発動する。

単一/少数 issue の場合の軽量運用は [CLAUDE.md §issue 作成タスク受領時の標準フロー](../CLAUDE.md) に従う。
