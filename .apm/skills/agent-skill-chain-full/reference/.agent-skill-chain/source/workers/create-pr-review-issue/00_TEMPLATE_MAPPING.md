# 00_要求定義.md 生成 — PrReviewIssueDefinition とテンプレートのマッピング

90_issues 配下の PR 指摘対応 issue 用 00_要求定義.md は、**workflow/TEMPLATES.md の 00_要求定義** の必須セクションを満たしつつ、以下のセクションを **必ず** 含める。PrReviewIssueDefinition のフィールドを次のようにマッピングする。

---

## frontmatter

- **document_id**: 新規作成時に UUID を 1 回発行して付与。
- **issue_id**: 新規作成時に UUID を 1 回発行して付与（当該サブ issue の一意識別子）。

---

## 見出しとマッピング

| 見出し（必須） | PrReviewIssueDefinition の対応 | 記載内容 |
|----------------|--------------------------------|----------|
| **# 要求定義書: {サブ issue 名}** | title | 例: PR#4 指摘対応 |
| **## 1. 目的・背景** | — | 「本 issue は PR 指摘対応 issue である」ことを明示。PR URL（pr_url）と親 issue へのリンク（parent_issue_links）を記載。 |
| **## 2. 指摘一覧** | findings | ReviewFinding[] を表形式または箇条書きで展開。各項目に id / file / location / summary を記載。raw は要約の下に折りたたみまたは注記で参照可能に。 |
| **## 3. 各指摘の対応方針（案）** | strategies | finding.id をキーに、対応方針案テキストを記載。「案であり、人間レビューを前提とする」旨をセクション冒頭に注記。 |
| **## 4. 受け入れ基準** | — | 「全指摘が網羅されている」「各指摘に対応方針が一つずつ付与されている」「対応方針レビュー（人間）を経ること」を含める。指摘が 0 件の場合は「指摘一覧が 1 件以上埋まっていること」を追加。 |
| **## 5. 参照元** | pr_url, parent_issue_links | PR URL、親 issue・親 03_実装計画などへのリンク。 |
| **## 6. 次のステップ** | — | 「対応方針レビュー（人間）」を**必ず**含める。続けて 01_要件定義.md への流れを記載。 |

---

## 参照するテンプレート

- **00_要求定義の汎用テンプレート**: `.agent-skill-chain/runtime/templates/00_要求定義.md`（パッケージ内。プロジェクトに .agent-skill-chain/runtime/templates/00_要求定義.md が無い場合）。
- 上記テンプレートの「要求定義の全体像」「1. 目的・背景」「成功基準」「次のステップ」等の構成を尊重し、PR 指摘対応用に **指摘一覧** と **各指摘の対応方針（案）** を追加した形で 00 を生成する。
