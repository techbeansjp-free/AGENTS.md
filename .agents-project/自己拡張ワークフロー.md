# 自己拡張ワークフロー（このリポジトリ固有・最優先）

**目的**: 本リポジトリは「パッケージの正本」かつ「自己拡張（ドッグフーディング）する消費者」の二役を兼ねる。両者は git の扱いが逆になるため、名前空間を分離して二重管理・配布物汚染を防ぐ。

このファイルは `.agents-project/` 配下にあり、**`.agents/` および CLAUDE.md の標準フローより優先**される（[../.agents-project/README.md](README.md) §優先順位）。

## issue の作成場所（標準フローの上書き）

CLAUDE.md / `.agents/` の標準では issue を `.workflow/<timestamp>_<title>/` に作るが、**本リポジトリでは下記に作成する**。

| 種別 | 作成場所 |
|------|----------|
| 単一 issue | `docs/maintainer/workflow/<timestamp>_<title>/` |
| サブ issue（PR 指摘対応等） | `docs/maintainer/workflow/{parent}/90_issues/{ディレクトリ名}/` |

- `<timestamp>` は実行環境の現在時刻（JST）。例: `TZ=Asia/Tokyo date +%Y%m%d_%H%M%S`。
- ファイルセット（`00_要求定義.md`・`01_要件定義.md`・`02_設計.md`・`03_実装計画.md`・`04_review.md` 等）は `.workflow/templates/` の標準テンプレートに従う。
- これらは **git 追跡対象**であり、自己拡張の開発記録として残す。

## memo の作成場所（標準フローの上書き）

CLAUDE.md / `.agents/`（[../.agents/skills/agent/run_command.md](../.agents/skills/agent/run_command.md):57・[../.agents/workflow/TEMPLATES.md](../.agents/workflow/TEMPLATES.md):12-13）の標準では memo を `.workflow/{issue}/memo/` に作るが、これは**消費者ランタイムの既定**である。**本リポジトリの自己拡張 issue では下記に作成する**（issue 本体と同一名前空間に置き、記録分裂を防ぐ）。

| 種別 | 作成場所 |
|------|----------|
| 自己拡張 issue の memo | `docs/maintainer/workflow/<issue>/memo/`（`close` 後は `docs/maintainer/workflow/close/<issue>/memo/`） |

- ファイル名のプレフィックス（`YYYYMMDD_HHMMSS_`・JST）の取得規約（`TZ=Asia/Tokyo date +%Y%m%d_%H%M%S` または `.agents/scripts/memo-prefix.sh` の実行）は配布物側の正本（上記 run_command.md:57）に従う（重複再定義しない）。
- これらは **git 追跡対象**であり、issue 本体と同一名前空間に置く。

## 完了 issue の close 移動（上書き）

汎用ルールの**宣言は [../.agents/boot/CORE.md](../.agents/boot/CORE.md) §完了 issue の close 分離**、**ライフサイクル詳細は [../.agents/workflow/PHASES.md](../.agents/workflow/PHASES.md) §完了 issue の close 移動**にある。本リポでは**配置先のみ上書き**する（トリガー条件・完了判定の定義は重複させず上記を参照）。

| 種別 | 移動先 |
|------|--------|
| 完了したトップレベル issue（配下のサブ issue 含む） | `docs/maintainer/workflow/close/<issue>/` |

- 移動は**トップレベル issue が完了したときのみ**（PHASES のトリガー・完了定義に従う。サブ issue 単独完了では移動しない）。
- close 後も git 追跡対象（自己拡張の開発記録）として残す。04_review.md・workflow.db ログ等の証跡は移動後もそのまま保持する。

### close 移動時の相対リンク補正（必須手順）

`docs/maintainer/workflow/<issue>/` はリポジトリルートから **4 階層下**（`docs`/`maintainer`/`workflow`/`<issue>`）だが、`close/<issue>/` へ移動すると **5 階層下**（`docs`/`maintainer`/`workflow`/`close`/`<issue>`）になる。成果物（00〜04・memo 等）内の `.agents/` 等リポジトリルート配下へ向かう**相対リンクは 1 階層深くなる**ため、移動時に必ず補正する。

- **補正内容**: 成果物中の実 markdown リンク `](../../../../`（4 階層上）を `](../../../../../`（5 階層上）へ補正する。**バッククォート内・本文中の `../../../../` の文章上の言及（過去レビュー証跡等）は改変しない**（実リンクのみを対象とする）。
- **検証（必須）**: 補正後、各リンク先の実在を確認し、未解決 0 件であることを検証する。例:
  ```bash
  fail=0
  grep -rEon '\]\((\.\./){5}[^)]+\)' docs/maintainer/workflow/close/<issue>/ | while IFS=: read -r f n link; do
    rel=$(printf '%s' "$link" | sed -E 's/^\]\(//; s/\).*$//; s/#.*$//')
    target=$(realpath -m "$(dirname "$f")/$rel")
    [ -e "$target" ] || { echo "UNRESOLVED: $f:$n -> $rel"; fail=1; }
  done
  ```
- この手順により、以後の close で同じリンク切れ（深さ不足）が再発しないようにする。

## テストの tmp 隔離（必須）

何かをテスト/検証するときは、**一時ディレクトリ（`mktemp -d`）を作成してその中で検証**する。**いきなり自己インストール（本リポへの `setup.sh` 実行等）や本番ファイルへの実行をしてはならない。**

- **理由**: 破壊的影響の回避と、既存生成物との混同による「本当に正しいか分からない」状態の防止。
- **具体運用**: install / uninstall / setup / build 等の検証は `mktemp -d` ＋ `git archive HEAD | tar -x`（クリーン clone の再現）等で隔離環境を作って行う。本リポの `.agents/` `.claude/` `.cursor/` `.workflow/` `workflow.db` を**変更・破壊しない**こと。検証後は一時環境を片付ける（`rm -rf` 等）。
- 汎用のテスト方針は [../.agents/RULES.md](../.agents/RULES.md) §テスト隔離 を参照（重複させず相互参照）。

## 理由（名前空間の役割分担）

| パス | 役割 | git |
|------|------|-----|
| `.agents/`、`AGENTS.md`、`CLAUDE.md`、`.workflow/templates/`、`.claude-plugin/`、`.agents/scripts/` | パッケージ正本（配布物） | 追跡する |
| `test/` | 保守者自己テスト（自リポ検証用の runner / coverage / E2E / 各 test-*.sh。**非配布**＝`package.json` の `files` allowlist 外。`verify-npm-pack.sh` でも pack 混入を検知） | 追跡する |
| `docs/maintainer/workflow/` | 自己拡張 issue（保守者の開発記録） | 追跡する |
| `.workflow/<issue>`、`.workflow/workflow.db*` | 消費者ランタイム生成物 | **無視**（`.gitignore`） |
| `.claude/`、`.adapters/` | setup / build による各ツール向け生成物 | **無視**（`.gitignore`） |

参照: [../docs/maintainer/workflow/README.md](../docs/maintainer/workflow/README.md)、[../.agents/SETUP.md](../.agents/SETUP.md)、ルート `.gitignore`。
