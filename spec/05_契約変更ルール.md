# 契約変更ルール

契約とは以下を指す。

- API
- Event
- Message
- Schema

---

## 破壊的変更

以下は破壊的変更とする。

- フィールド削除
- 型変更
- 意味変更

---

## 非破壊変更

以下は非破壊変更とする。

- フィールド追加
- Optional追加

---

## バージョニング

破壊的変更はバージョンを上げる。

例: v1 → v2

---

## 廃止

古い契約は一定期間残す。運用を明確にするため、以下を守る。

- **保持期間**: 廃止した契約は **6 か月** または **2 マイナーバージョン分** のいずれか長い方まで残す。明示的に短縮する場合は理由をドキュメントに残す。
- **廃止通知**: 廃止を決めた時点で、変更履歴・CHANGELOG または docs に廃止予定を記載する。通知チャネルはプロジェクトの標準（issue・PR・Slack 等）に従う。対象者は当該契約を参照している開発者・利用者とする。
- **マイグレーションパス**: 移行手順（旧→新の対応、置換例）をドキュメントまたはツールで提供する。フォールバック期間は上記保持期間と同一とする。必要に応じてスクリプト・codemod で一括置換を支援する。
