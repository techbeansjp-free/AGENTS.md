#### 2.1.4 単体テスト仕様（BDD）（必須）

**BDD 形式のテストケース（高レベル仕様）**:

```gherkin
Feature: {テスト対象}
  Scenario: {テストケース名}
    Given {前提条件}
    When {実行する操作}
    Then {期待される結果}
```

**テストコード例（必須: インラインコメントで Given/When/Then を明記）**

プロジェクトで使用する言語・フレームワークに応じて記述してください（`typescript`、`python`、`php` など）。**重要**: テストコード内の各ブロックに `// Given:`、`// When:`、`// Then:` のインラインコメントを必ず記載すること（[テストコード_BDD形式.md](../../.agents/テストコード_BDD形式.md) §1）。

```typescript
// Given: {前提条件の説明}
// When: {実行する操作の説明}
// Then: {期待される結果の説明}
```

## 4. テスト計画

**重要**: テスト計画の詳細は [`02_設計.md`](./02_設計.md) の **§6 テスト戦略** または [**RULES のテスト戦略**](../../.agents/RULES.md#テスト戦略必須要件) を参照してください。

### 4.1 テストの優先順位

- クリティカルな機能は厚くテスト
- 影響範囲が広い箇所は回帰テストに必ず含める

### 4.2 単体テスト（必須: 単体 BDD 網羅）

各タスクの §2.x.3（テスト観点）で定義する 5 観点（正常系・異常系・境界値・回帰・結合）に従い、単体テストを実施する。詳細は [テストコード_BDD形式.md §5](../../.agents/テストコード_BDD形式.md) および [`02_設計.md`](./02_設計.md) §6 を参照。

### 4.3 結合/API テスト（必須: API ブラックボックス網羅）

- エンドポイント/契約ごとに正常・異常・境界をブラックボックスで検証

### 4.4 E2E/受け入れテスト（必須: 主要シナリオ E2E 網羅、未達時は理由記載）

- 主要ユーザーシナリオを E2E で網羅し、未達時は理由を記載

### 4.5 バリデーション系のテスト

- すべてのバリデーションルールを網羅的にテスト
- 境界値（最小値、最大値、0、NULL 等）を重点的にテスト
- エラーメッセージも確認
