## レビュー概要

### レビュー目的

従来の「main.ts の `stories` 配列で読み込み順を明示し、新規ストーリー追加時は該当ブロックの末尾にパスを追加する」という記載は、実装上 **保守性が低く検出漏れも発生していた**。今回、**glob による自動検出**と **preview.tsx の `parameters.options.storySort`** による連番ソートに変更したうえで、以下を整合させることを確認する。

- **本リポジトリ（AI）**: 汎用版 [`AGENTS_STORYBOOK_RULES.md`](../AGENTS_STORYBOOK_RULES.md) の「サイドバー表示順」セクション
- **別リポジトリ**: 各プロジェクトの AGENTS_STORYBOOK_RULES.md（プロジェクト版）および `.storybook/main.ts`・`.storybook/preview.tsx` の実装（本リポジトリ外のためパスは記載しない）

### レビュー対象ファイル（本リポジトリ内）

- [`AGENTS_STORYBOOK_RULES.md`](../AGENTS_STORYBOOK_RULES.md)（汎用版・サイドバー表示順の修正・汎用表現への統一）

**注**: プロジェクト版の規約および Storybook 実装（main.ts / preview.tsx）は**別リポジトリ**に属するため、本レビューでは「汎用版規約がそれらと整合する内容になっているか」を確認対象とする。別リポジトリ内のファイルパスは記載しない。

## 変更内容の概要

### 1. main.ts（各プロジェクトの実装・別リポジトリ）

- **変更前**: `stories` を各ストーリーファイルのパスで明示列挙（docs / components を分割）。
- **変更後**: `../src/**/*.mdx`, `../src/**/*.stories.@(js|jsx|mjs|ts|tsx)` の glob で一括指定。
- **効果**: 新規コンポーネント追加時に main.ts の編集不要。公式推奨パターンに合わせ検出漏れを防止。

### 2. preview.tsx（各プロジェクトの実装・別リポジトリ）

- **追加**: `parameters.options.storySort` で、各エントリの `title` または `id` から「NN_」（01_, 02_, …）を抽出し、01 → 02 → … の順でソート。
- **注意事項を実装で反映**: 外部の `getSectionOrder` は参照せず、コールバック内に `getOrder` を定義。型注釈は付けない（eval 時の SyntaxError 回避）。

### 3. AGENTS_STORYBOOK_RULES.md（プロジェクト版・別リポジトリ）

- 「サイドバー表示順」を次の内容に差し替え:
  - main.ts は glob で一括指定し、新規追加時は main の変更不要。
  - 並び順は preview.tsx の `parameters.options.storySort` で制御し、meta.title の「フロント（public）/NN_…」で連番順になる旨を記載。
  - storySort を書くときの注意（外部関数参照不可・型注釈不可）を追記。
- 最終更新: 2026 年 2 月 2 日（サイドバー順序設定の修正）。

### 4. AGENTS_STORYBOOK_RULES.md（汎用版・本リポジトリ）

- 冒頭に「**汎用版**」である旨の注記を追加。
- 上記と同様に「サイドバー表示順」を glob + storySort ベースに修正。
- title 形式は「&lt;ルート名&gt;/&lt;階層番号&gt;_&lt;階層名&gt;/&lt;コンポーネント名&gt;」の汎用表現とし、例として `フロント（public）/02_最小UI部品/Button` を括弧で記載。
- 最終更新: 2026 年 2 月 2 日（汎用版として記載）。

## レビュー結果サマリー

### ✅ 良好な点

1. **実装と規約の一致**: main.ts の glob、preview.tsx の storySort（コールバック内完結・型注釈なし）が、両 AGENTS_STORYBOOK_RULES の記載と一致している。
2. **プロジェクト版と汎用版の役割分担**: プロジェクト版は「フロント（public）/…」の具体例で記載、汎用版は「&lt;ルート名&gt;/…」と汎用表現で記載し、例を括弧で補足しており、使い分けが明確。
3. **storySort の制約の明文化**: 「別スコープで eval される」「外部ヘルパー参照不可」「型注釈不可」が両規約に書かれており、同様の不具合の再発防止になる。
4. **保守性の向上**: 新規ストーリー追加時は main.ts を触らず、meta.title を付与するだけと明記され、運用負荷が下がっている。
5. **前回レビュー（20260131）との関係**: 当時は「main.ts の stories で読み込み順を明示」としていたが、今回の修正で正しい実装（glob + storySort）に合わせて規約を更新できている。

## 詳細レビュー結果

### 1. ドキュメント間の整合性

- **プロジェクト版 vs 汎用版**: サイドバー表示順の「やり方」（glob / storySort / 注意事項）は同一。プロジェクト版は title 例が「フロント（public）/…」に固定、汎用版は「&lt;ルート名&gt;/…」とし例を括弧で示しており、齟齬なし。
- **規約 vs 実装**: 各プロジェクトの main.ts（glob 一括指定）・preview.tsx（storySort をコールバック内に完結・型注釈なし）が、本リポジトリの汎用版 AGENTS_STORYBOOK_RULES の記載と一致することを確認した。

### 2. 既存規約との整合性

- **Storybook 論理構造（固定）**: 01_～06_ の階層順は変更しておらず、「サイドバー表示順」は「その順で表示するための実装方法」の記載に限定されている。
- **他セクション**: 「プレビューでのテーマ」「ダークモード適用方法」「各階層の役割」などは今回変更しておらず、参照・アンカーも有効。

### 3. 汎用版の汎用性

- ルート名・階層名をプロジェクトごとに定義する旨が注記されている。
- title の形式を「&lt;ルート名&gt;/&lt;階層番号&gt;_&lt;階層名&gt;/&lt;コンポーネント名&gt;」と抽象化し、具体例は括弧内に留めており、他プロジェクトでも流用しやすい。

### 4. AI エージェントによる利用

- 新規ストーリー追加時は「main.ts を編集しない」「meta.title を所定形式で付与する」と明確なため、LLM が従いやすい。
- storySort を追加・変更する際の「コールバック内にロジックを書く」「型注釈を付けない」が規約に書かれており、実装時のミスを減らせる。
