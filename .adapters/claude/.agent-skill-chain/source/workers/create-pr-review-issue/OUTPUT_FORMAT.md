# create-pr-review-issue — 出力フォーマット（固定）

本 worker が指摘抽出・対応方針案生成で用いる**データ形式はコード上で固定**する。AI 補助で中身を生成するが、入出力の形はこの仕様に従う。

---

## 1. ReviewFinding（1 件あたり）

| フィールド | 型 | 必須 | 説明 |
|------------|-----|------|------|
| **id** | string | 必須 | 指摘ごとの一意 ID（連番 `finding-1` または PR 側 ID を流用） |
| **file** | string \| null | 任意 | 対象ファイルパス（分かる範囲で） |
| **location** | string \| null | 任意 | 行番号やセクション（分かる範囲で） |
| **summary** | string | 必須 | 指摘内容の要約（1 文程度） |
| **raw** | string | 必須 | 元のテキスト（トレーサビリティ用） |

- 複数件は配列 `ReviewFinding[]` で扱う。
- review_comments_raw を行単位またはコメント単位で分割し、明らかに指摘でない行は除外してから各要素を上記フィールドにマッピングする。

---

## 2. strategies（対応方針案）

- **型**: `map<string, string>`（key: finding.id、value: 初期対応方針案テキスト）
- **必須**: 各 finding.id に対応する key が少なくとも 1 つ存在すること。
- **value の内容**: 以下のいずれかの方向性を 1〜3 文で記述する。
  - **修正**: どのファイルのどのルール・記述をどう変更するか
  - **却下**: なぜ却下するのかの理由を 1 文で
  - **別 issue**: なぜ分離するのか、どんな issue を立てるべきかの概要

---

## 3. 00_要求定義.md への反映ルール

- **指摘一覧セクション**: ReviewFinding[] を表形式または箇条書きで展開する。各行に id / file / location / summary を記載し、必要に応じて raw を折りたたみで参照可能にする。
- **対応方針案セクション**: strategies を finding.id と対応づけて記載する。各指摘 ID ごとに「対応方針（案）: …」と明記し、**人間レビューを前提にしていること**を注記する。

---

## 4. エラー時フォーマット

- **指摘一覧が空**: ReviewFinding[] が 0 件の場合、00_要求定義.md の指摘一覧セクションに「指摘一覧が空です。手動で指摘を追加するか、review_comments_raw を再入力してください。」と記載する。strategies は空の map でよい。
- **PR URL 不正**: pr_url から PR 番号を抽出できない場合、00 の参照元に「PR を一意に特定できるか不明です。有効な PR URL を確認してください。」と記載する。ディレクトリ名のプレフィックスは「PR不明」等のフォールバックを用いてよい。
