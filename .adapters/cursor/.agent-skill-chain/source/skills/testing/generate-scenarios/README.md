# capability: generate-scenarios

**目的**: テストシナリオ・観点を整理し、04_review の「受け入れ基準の確認」に使える形にする。

---

## 手順

1. 入力（01_要件定義の BDD、02_設計、03_実装計画。実装成果物）を読む。
2. 01 の BDD シナリオを列挙し、各シナリオに対応するテスト観点を 1 行ずつ書く。
3. 03 のテスト仕様・単体テスト観点と突き合わせ、不足があれば追記する。
4. テストシナリオ一覧・観点一覧を 04_review 用の「確認項目」としてまとめる。
5. 次の capability（map-coverage）で受け入れ基準との対応を取る。

---

## 制約・禁止

- BDD シナリオに沿った観点を優先する。01 にない観点を無制限に増やさない。
- 観点は「検証可能な形」で書く。曖昧な表現は避ける。

---

## 成果物の形式

- **OUT**: テストシナリオ一覧。観点一覧。04_review の「実装内容の確認」「受け入れ基準の確認」に転記する形。
- map-coverage ではこの出力と 01 の受け入れ基準・実装の対応を表にする。
