# define-constraints

**目的**: 前提・制約候補を明確化し、受け入れ基準に落とし込み、00/01 に記載する内容を確定する。

## 手順

1. 入力（identify-assumptions の出力：前提一覧・制約候補）を読む。
2. 各制約を「誰が・何を・どう検証するか」が分かる形に書き換える。
3. 受け入れ基準として採用する項目を選び、00_要求定義の「受け入れ基準」と 01 の「受け入れ基準」の対応を整理する。
4. 出力を 00/01 のたたき台としてまとめ、write-bdd へ渡す。

## 制約・禁止

- 受け入れ基準は DoD と整合させる。PHASES の DoD を満たすのに必要な項目を欠かさない。
- 重複を避ける。00 と 01 で同じ基準を別表現で書く場合は、参照でつなぐ。

## 成果物の形式

- **OUT**: 明確化された制約一覧。00 用・01 用の受け入れ基準案（検証方法付き）。write-bdd ではこの出力を BDD シナリオ・ユーザーストーリーに展開する。
