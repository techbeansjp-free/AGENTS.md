# 01_要件定義: #171 CI/gate運用の本番導入

**作成日**: 2026年07月20日

---

## ユーザーストーリー1: `.github/`一式の本番導入

**As a** リポジトリメンテナ
**I want** `init`コマンドでこのリポジトリ自身に`.github/`一式を導入したい
**So that** CI/gate workflowが実際にこのリポジトリで稼働する

### 受け入れ基準（AC）

- AC1-1: `node bin/agents-md.js init`を実行すると、既存の`AGENTS.md`・`CLAUDE.md`・`.agent-skill-chain/`一式は`unchanged`（衝突なし）、`.github/`配下18ファイル（CODEOWNERS、ISSUE_TEMPLATE 7種、SECURITY.md、dependabot.yml、pull_request_template.md、workflows 4種）が`created`として作成される。
- AC1-2: `--dry-run`実行結果と実実行結果の作成対象ファイル一覧が一致する。

## ユーザーストーリー2: `review.adapter`のhumanへの変更

**As a** リポジトリメンテナ（実質1人開発）
**I want** gate判定のアダプタをAPIキー不要のhumanへ変更したい
**So that** APIキー未設定でもgate判定フローが非同期deferralとして機能する

### 受け入れ基準（AC）

- AC2-1: `.agent-skill-chain/config/agent-skill-chain.yaml`の`review.adapter`が`claude`から`human`へ変更されている。
- AC2-2: `config.schema.yaml`が`adapter: human`を許容する（`enum: [claude, codex, human]`に含まれることをスキーマファイルで確認済み）。

## ユーザーストーリー3: branch-name / 既存テストへの非破壊確認

**As a** リポジトリメンテナ
**I want** 変更後にbranch名検証と既存テストスイートを実行したい
**So that** 変更が既存の規約・回帰を壊していないことを実地確認できる

### 受け入れ基準（AC）

- AC3-1: `node bin/agents-md.js verify branch-name process/171-ci-gate-dogfood`がexit 0を返す。
- AC3-2: `npm test`が既存322件を実行し、可能な限りpassすることを確認する。fail が出た場合は原因を特定し正直に報告する（Issue本文が要求する成功基準そのものが「既存322件超のテストを破壊しない」であるため、fail発生時は本Issueの成功基準未達として扱う）。
