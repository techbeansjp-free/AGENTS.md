## 3. 各指摘の対応方針（案 → 確定）

- **finding-1（即時対応・確定）**: audit.sh `check_find_worktree_prune` を、ルート起点 unbounded find に対し `.worktree` 単純存在ではなく `-prune`＋`.worktree`＋`-o` の共起（実際の prune 構造）を検査する形へ強化。迂回ケース（`.worktree` を print 対象名/コメントに含むだけ）の非検知テストを追加。
- **finding-2（即時対応・確定）**: `_audit_valid_branch_ref` に `(( ${#name} > 200 )) && return 1` を追加し Tier1 と対称化。
- **finding-3（起票・確定・本ブランチ内で実装）**: `check_worktree_branch_naming` に `GITHUB_HEAD_REF`（GitHub Actions 標準）が設定されていれば列挙対象へ追加。既存ローカル branch 列挙への追加に留め、無差別 remote 全列挙は行わない。grandfather 機構（`_gf`）と整合。非 CI（未設定）は従来動作（fail-safe）。
- **finding-4（起票・確定・本ブランチ内で実装）**: `_wt_effective` に env の引数なしフラグ（`-i`/`--ignore-environment` 等）スキップを追加。`_wt_extract_creation` に `switch --create`・`branch --track` の作成形認識、`worktree add --detach` 時のブランチ名検証スキップを追加。単体テスト追加。
- **finding-5（起票・確定・本ブランチ内で実装）**: `validate_worktree_path` に呼び出し側解決のリポジトリルート（`git rev-parse --show-toplevel`）を渡し、`<root>/.worktree/` 直下一致を検証。02_設計 の該当 ADR/インターフェース記述（純関数の位置づけ）を「呼び出し側が git 文脈でルートを解決し引数供給」へ整合更新。root 未供給時は従来の構造チェックへ fail-safe フォールバック。
- **finding-6/7（起票・確定・最優先・本ブランチ内で実装）**: 既定 trash の解決先を削除対象（target）の外側（main worktree ルート）へ変更。正規化後 trash が target 配下に入る場合は安全な代替先へフォールバック、それも不能なら退避を fail-safe（allow・WARN のみ・原本を壊さない）で処理。単体テストに「`git clean -xfd` path 省略・CWD=target」ケースを追加し退避物生存を確認。
- **finding-8（即時対応・確定）**: enforcement/README.md の Line 257 単一レジストリ表と Line 305 失敗条件一覧の**両方**へ #39/#40 を実装状態・強制レベル・SKIP 条件付きで追記。
- **finding-9（即時対応・確定）**: `run_audit` を `AUDIT_RC=$?` 保存へ修正、FAIL ケース=1・SKIP/PASS=0 の assertion を追加。line 192 の空虚 grep をブランチ行の `grep -Fx` 厳密一致へ置換。
