# 実装計画書: audit.sh の worktree 誤 SKIP と close 除外漏れの既存バグ修正

## 1. 実装概要

### 1.1 実装方針（必須）

audit.sh の git ツリー判定を `git rev-parse --is-inside-work-tree` に統一（タスク A）し、#4/#5 の find ループに `/close/` 除外を追加（タスク B）する。いずれも既存の同一ファイル内の慣用形へ揃える最小差分とし、test-audit.sh に worktree 再現・close 除外の回帰テストを追加する。

### 1.2 実装順序（必須: 1 件以上）

1. タスク A: `-d .git` 判定の統一（#10・#18・#19・#25・#27、および #28 の先行ガード除去）。
2. タスク B: #4/#5 find ループへの `/close/` 除外追加。
3. タスク C: test-audit.sh へ回帰テスト追加（worktree フィクスチャ・close 除外）。
4. tmp 隔離検証 → run-all 非回帰 → 実 worktree ルートで `audit.sh .` 受け入れ確認。

## 2. タスク分解

### 2.1 タスク 1（タスク A）: git ツリー判定の統一

#### 2.1.1 概要（必須）

worktree で誤 SKIP する `-d .git` 判定を `git rev-parse --is-inside-work-tree` に置換し、監査の fail-open を除去する。

#### 2.1.2 実装内容（必須: 1 件以上）

- #10 `check_sqlite_sidecar`（audit.sh:413 付近）: `if [[ ! -d "$PROJECT_ROOT/.git" ]]; then return 0; fi` → `if ! git -C "$PROJECT_ROOT" rev-parse --is-inside-work-tree &>/dev/null; then return 0; fi`。
- #18 `check_review_file_has_verify_log`（:563）・#19 `check_artifact_change_has_implement_log`（:578）・#25 `check_25_main_did_real_work`（:602）・#27 `check_review_dual_lists`（:739）: 各先頭の `[[ ! -d "$PROJECT_ROOT/.git" ]] && return 0` を同じ `is-inside-work-tree` ガードに置換（直後の `rev-parse HEAD` ガードは維持）。
- #28 `check_issue_doc_in_gitignored_path`（:768）: 先行する `[[ ! -d "$PROJECT_ROOT/.git" ]] && return 0` を削除（:769 の正しい `is-inside-work-tree` ガードに一本化）。

#### 2.1.3 テスト観点（必須）

##### 単体（本タスクの具体ケース・必須 1 件以上）

- worktree フィクスチャで成果物変更＋証跡なしのとき #25 が実行され FAIL する（worktree で SKIP されないことの確認）。
- worktree フィクスチャで #28 の実行ログ `[audit] checking issue docs in gitignored paths (#28)` が出力される。
- 非 git ツリー（`make_min_tree`）では従来どおり SKIP し FAIL を出さない（非回帰）。

##### 結合/API（本タスクの具体ケース・該当時は必須 1 件以上）

- 該当なし（単一スクリプト内の変更）。

##### E2E/受け入れ（本タスクの具体ケース・未達時は理由記載）

- 本 worktree ルートで `audit.sh .` を実行し、worktree 判定が実行側に倒れること（実行ログの可視化）を確認する。

##### バリデーション（該当する場合の具体ケース）

- 通常（非 worktree）git リポジトリで既存挙動が不変（`make_git_tree` シナリオが非回帰）。

#### 2.1.4 単体テスト仕様（BDD）（必須）

## テスト観点

本 issue 全体のテスト観点は 2 軸。(1) バグ A: worktree で `-d .git` 系監査が SKIP されず実行され違反を FAIL すること、非 git ツリーでは従来どおり SKIP すること。(2) バグ B: close 配下 03/04 が #4/#5 で FAIL せず、close 外 in-progress は従来どおり FAIL すること。加えて run-all.sh 非回帰と、実 worktree ルートでの `audit.sh .` 受け入れ（close 由来 FAIL 0 件）を確認する。各タスクの §2.x.3 に具体ケースを記載した。
