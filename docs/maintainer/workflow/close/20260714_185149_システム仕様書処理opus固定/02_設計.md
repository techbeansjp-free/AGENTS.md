### 2.5 横断設計判断（ADR）

#### ADR-1: システム仕様書（docs/ 配下）の処理を常に opus に固定する

- **コンテキスト**: 対応表に仕様書処理の行が無く、委譲時に実装役割の既定（原則 sonnet）へ格下げされ得る。システム仕様書は横断的かつ重要で、誤りが後続の設計・実装全体へ波及する。
- **検討した選択肢**:
  1. 対応表に「システム仕様書処理 → opus（常に）」の 1 行を追加する（採用）。
  2. 実装行の但し書きで「仕様書は opus 格上げ可」と補足する（不採用: 「複雑時のみ格上げ」の逆順運用になり非裁量固定にならない）。
  3. `source/MODEL_SELECTION.md`（抽象原則）に具体行を書く（不採用: コア中立性・2 層境界を壊す）。
- **決定**: 選択肢 1。`project/MODEL_TIER_TABLE.md` の役割→ティア対応表に、1 行目（設計・レビュー・監査＝opus）の直後へ「システム仕様書（docs/ 配下）の処理 → opus（常に opus）」の行を追加する。
- **根拠**: システム仕様書は特に重要かつ横断的なため opus が適切、というプロジェクトオーナーの明示判断。`evidence_source: human_decision`（inference_only ではない）。対象定義は既存 `RULES.md §システム仕様書` / `LOAD_POLICY` に一致させ独自定義を作らない（`existing_code` に基づく整合）。
- **帰結**: 仕様書処理の委譲時に根拠 1 行が一意に引用でき、ティアが常に opus に固定される。既存 4 行と非交差で後方互換。RULES §高リスク操作には該当しない（ドキュメント 1 行追加）ため、本判断は自走継続してよい（要人間確認ではない）。

#### ADR-2: 既存「opus 要否先行検討」手順との関係整理（裁量禁止との整合）

- **コンテキスト**: 既存の実装行には「まず opus 要否を判定し、不要と確定した場合のみ sonnet を選ぶ」という opus 要否先行検討の選定手順がある。追加行の「常に opus」がこの手順と矛盾しないかを整理する必要がある。
- **検討した選択肢**:
  1. 追加行を「一律 opus・非裁量の固定ルール」と位置づけ、opus 要否判定の対象外（判定を経るまでもなく opus）と明記する（採用）。
  2. 追加行にも opus 要否先行検討を適用する（不採用: 「常に opus」と矛盾し、格下げ余地を残す）。
- **決定**: 選択肢 1。opus 要否先行検討は主に**実装役割**の非裁量手順であり、システム仕様書処理は既存 1 行目（設計・レビュー・監査＝常に opus）と同種の「判定を経ない一律 opus」ルールとして扱う。
- **根拠**: `MODEL_TIER_TABLE.md §裁量禁止との整合` の非裁量原則（「迷ったら上位」という裁量上振れと区別された、対応表の該当行の決め方そのもの）と整合する。「常に opus」は裁量ではなく対応表で固定された非裁量ルールである（`existing_code`: 既存 1 行目と同じ扱い）。
- **帰結**: 「システム仕様書処理は opus 要否の判定を経るまでもなく常に opus」という一律ルールであることが明文化され、既存の非裁量原則（§裁量禁止との整合）と矛盾しない。裁量下振れ（コスト都合の降格）も本行には適用されない。

## 3. 機能設計

### 3.1 機能 1: 役割→ティア対応表への 1 行追加

#### 3.1.1 概要

`.agent-skill-chain/project/MODEL_TIER_TABLE.md` の「役割 → ティア対応表」に §2.2.1 で確定した 1 行を、1 行目の直後（実装行の前）へ挿入する。既存 4 行・本文（opus 要否先行検討／品質最優先／裁量禁止との整合／参照）は変更しない。

#### 3.1.2 処理フロー

```mermaid
flowchart TD
    Start([開始]) --> Read[対応表を読む]
    Read --> Insert[1行目(設計・レビュー・監査)直後に新規行を挿入]
    Insert --> Check{既存4行・本文は無変更か}
    Check -->|Yes| Verify[書式・列数・非裁量整合を確認]
    Check -->|No| Fix[差分を修正]
    Fix --> Check
    Verify --> End([完了])
```

#### 3.1.3 入力・出力

- **入力**: §2.2.1 で確定した追加行（役割 / ティア / 選定手順・根拠）。
- **出力**: 5 行になった役割→ティア対応表（既存 4 行 + 追加 1 行）。

#### 3.1.4 エラーハンドリング

- 列数不一致（`| 役割 | ティア | 選定手順・根拠 |` の 3 列）や既存行の意図せぬ変更が生じた場合は差分を破棄し、追加行のみの挿入に修正する。
