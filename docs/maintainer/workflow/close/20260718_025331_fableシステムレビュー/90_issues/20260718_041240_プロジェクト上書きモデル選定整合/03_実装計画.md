- **F-6（grandfather ファイル）**: 実装前に `enforcement/ci/audit.sh` の `check_worktree_branch_naming()` の実装を確認したところ、grandfather baseline の各行を**完全一致のキー**としてブランチ名照合に使っていることが判明した（`_gf["$gl"]=1` → `_gf[$br]` の完全一致lookup）。設計時点の想定どおり「名前 \| 理由 \| 日付 \| PR」を1行に収める形式にすると、audit.sh の完全一致照合が壊れる（ブランチ名だけでなくメタデータ文字列全体がキーになってしまう）ため、**メタデータはブランチ名の直前のコメント行に置き、ブランチ名自体は単独行のまま残す**形式に設計を具体化した。audit.sh（非所有）は変更していない。実装後、既存25件のブランチ名すべてが変更前と同じキーとしてパースされることをシェルで検証済み（§4 参照）。
- **F-1／F-3**: チェックリスト該当observableを「1つでも該当なら opus」という非裁量の判定規則とし、要求・要件執筆／issue起票／調査／chore／デフォルトの5行すべてがこの共通チェックリストを参照する形にして、役割ごとに別基準を重複定義することを避けた。
