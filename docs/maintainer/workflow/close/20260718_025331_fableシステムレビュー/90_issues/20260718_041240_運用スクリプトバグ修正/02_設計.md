### E-1【high・確定】setup.sh の論理パス比較による symlink 経由 rm -rf

- **対象**: `setup.sh` 行 91 / 101-105 / 119-127（own 判定は `lib/package-manifest.sh` 行 51-52 が `pwd -P`）
- **欠陥**: own 判定は `pwd -P`（物理）で「自己適用」を確定させる一方、破壊的操作直前の同一パス判定（行 101・119）と cp 判定（行 91）は `pwd`（論理）で行う。`PROJECT_ROOT` が `PACKAGE_ROOT` への symlink 経由だと、own 判定は物理一致で通過するのに行 101 の比較は論理不一致で「別ディレクトリ」と誤判定し、物理的に正本 source と同一の `$ASC_SOURCE_DEST` を `rm -rf` する（cp 復元前に消える）。
- **変更方針（2段構え）**:
  1. **比較の物理統一**: 破壊的判定の両オペランドを `pwd -P` で解決し、own 判定（`pwd -P`）と一貫させる。
  2. **削除直前アサート**: `rm -rf` の直前で source と削除対象の物理パスを独立再解決し、一致したら削除せず `exit 1`（回帰時の防波堤・多重防御）。

変更前（行 100-105）:
```bash
ASC_SOURCE_DEST="$PROJECT_ROOT/.agent-skill-chain/source"
if [[ "$(cd "$AGENTS_SOURCE" && pwd)" != "$(cd "$ASC_SOURCE_DEST" 2>/dev/null && pwd)" ]]; then
  if [[ -d "$ASC_SOURCE_DEST" ]]; then
    rm -rf "$ASC_SOURCE_DEST"
    echo "既存の .agent-skill-chain/source を削除しました。"
  fi
```
変更後:
```bash
ASC_SOURCE_DEST="$PROJECT_ROOT/.agent-skill-chain/source"
src_phys="$(cd "$AGENTS_SOURCE" && pwd -P)"
dest_phys="$(cd "$ASC_SOURCE_DEST" 2>/dev/null && pwd -P || true)"
if [[ "$src_phys" != "$dest_phys" ]]; then
  if [[ -d "$ASC_SOURCE_DEST" ]]; then
    # E-1 削除直前アサート: 物理パスを独立再解決し、正本 source と一致するなら自己削除を防いで中止
    assert_dest="$(cd "$ASC_SOURCE_DEST" && pwd -P)"
    if [[ "$assert_dest" == "$src_phys" ]]; then
      echo "エラー: 削除対象 $ASC_SOURCE_DEST が正本 source と物理的に同一です。自己削除を防ぐため中止します。" >&2
      exit 1
    fi
    rm -rf "$ASC_SOURCE_DEST"
    echo "既存の .agent-skill-chain/source を削除しました。"
  fi
```
同型を行 116-127 の `WF_TEMPLATES` 削除にも適用（`WF_SOURCE`/`WF_TEMPLATES` を `pwd -P` 比較＋削除直前アサート）。行 89-98 の `AGENTS.md`/`CLAUDE.md` 自己 cp 判定も両辺を `pwd -P` に統一（rm は無いためアサートは不要、比較のみ物理化）。

- **理由**: own 判定（物理）と破壊的判定（論理）の**非対称**が欠陥の本体。全判定を物理へ統一すれば非対称が消える。アサートは 00_要求定義.md §3.2「削除操作前は必ず pwd -P で同一判定」と再発防止テスト（§2）を満たす保険。
- **副作用検討**: 比較のみを物理化し、書込み先パス（`PROJECT_ROOT` 等の実体）は変更しない。よって通常インストールの配置先は不変（§5-1で確認）。`|| true` は `dest` 未存在時に `pwd -P` が空を返す既存挙動を維持する。

### E-4【medium・確定（要設計判断→採用案確定）】close-move-issue.sh の原子性・ロールバック欠如

- **対象**: `close-move-issue.sh` 行 89-104（while ループ移動）
- **欠陥**: `git mv`/`mv` がループ途中で失敗すると `set -e` で即終了し、一部は close/ 側・残りは元位置の分裂状態が残る。ロールバック・再開案内なし。`find -type f` は symlink（`-type l`）を列挙せず取り残す。
- **検討した選択肢**:
  - (a) 事前検証のみ: index.lock・移動可否・書込み権限を前チェック。中途失敗は減るが完全には消えない。
  - (b) staging へ全移動→最終 rename: `git mv` は履歴保持のため staging 経由にできず、追跡/非追跡混在で単一 rename が成立しない。
  - (c) 失敗時レポート: 中途失敗を trap で捕捉し、移動済み一覧・未移動一覧を出力して人手解決に委ねる。
  - (d) 全自動ロールバック: 移動を記録し失敗時に逆再生。`git mv` の逆再生自体が失敗しうるため分裂を悪化させうる。
- **採用案 = (a)+(c)＋symlink 列挙修正**（(d) は不採用）:
  1. 移動前に `git -C "$main_root" rev-parse -q --verify HEAD` 等でツリー健全性を確認し、`ls "$issue_dir/.git/index.lock" 2>/dev/null` 相当の in-progress 検知（並行 worktree の index.lock 競合は git 自身がエラーを返すため、本スクリプトは失敗時に (c) のレポートで受ける）。
  2. `trap` で `ERR` を捕捉し、失敗時に「移動済みファイル一覧」と「残りファイル一覧」を stderr に出力してから `exit 1`。自動ロールバックはしない（fail-closed・人手解決可能な状態で停止）。
  3. 列挙を `find "$issue_dir" \( -type f -o -type l \) -print0` に変更し、symlink を取り残さない。
- **理由**: 本スクリプトの既存哲学は「バックアップ失敗＝上書き中止（`package-manifest.sh` 行 111 等）」の fail-closed であり、(d) の投機的自動復旧より (c) の「明確な失敗報告＋人手解決」が一貫する。並行 worktree の index.lock は本質的に外部要因で、原子性の完全保証はプロセス外ロックなしには不可能。(a)+(c) で「分裂を検知可能・復旧手順明示」まで担保する。
- **主要差分**（行 89-104 周辺）:
```bash

### E-11【low・確定】new-workflow-memo.sh の TOCTOU 上書き

### E-12【low・確定（要設計判断→採用案確定）】memo-prefix.sh の JST 保証欠如

    echo "エラー: バックアップ先が既に存在します（同一秒の再実行？）: $bak。中止します。" >&2

```

### E-19【low・確定】check-relative-links.sh の fence 判定が ``` と ~~~ を区別せずトグル

- **対象**: `check-relative-links.sh` 行 163-167（`extract_links` の python）、行 197-201（`check_anchor` の python）
- **欠陥**: `stripped.startswith("```") or stripped.startswith("~~~")` で単一フラグ `in_fence` を反転するため、```` ``` ```` ブロック内に現れた `~~~` 行が誤って開閉をトグルし、以降のファイル全体で誤検出が連鎖する。
- **変更方針**: 開始フェンスの記号種（`` ` `` / `~`）と長さを記憶し、**同種・同長以上**の行でのみ閉じる。両 python ヘルパーの同一ロジックを修正。
```python
# 変更後（両ヘルパー共通の fence 判定）
import re
fence_re = re.compile(r'^(`{3,}|~{3,})')
in_fence = False
fence_char = ''
fence_len = 0
# ... ループ内 ...
    stripped = line.lstrip()
    m = fence_re.match(stripped)
    if m:
        marker = m.group(1)
        ch, ln_len = marker[0], len(marker)
        if not in_fence:
            in_fence, fence_char, fence_len = True, ch, ln_len
            continue
        elif ch == fence_char and ln_len >= fence_len:
            in_fence, fence_char, fence_len = False, '', 0
            continue
        # in_fence かつ 別種/短いフェンス行はコンテンツ扱い（開閉しない）
    if in_fence:
        continue
```
