# 設計書: 配備済み hook と正本の乖離検知スクリプト

**プロジェクト名**: 配備済み PreToolUse.sh が正本より陳腐化しロックアウト既知バグ修正が未反映
**作成日**: 2026年07月14日
**最終更新**: 2026年07月14日

---

## 1. 設計概要

### 1.1 設計方針

`.agent-skill-chain/source/scripts/` 配下に新規スクリプト `check-hook-drift.sh` を追加する。既存の `sync-version.sh`（正本 vs 派生ファイルの一致検証・`--check` モード）と同型の read-only 検証スクリプトとして設計し、`.agent-skill-chain/source/enforcement/claude/`（正本）配下のトップレベル通常ファイルと、採用先 `<project_root>/.claude/hooks/`（配備物）配下の同名ファイルを sha256 で比較する。比較対象の列挙規則は `setup.sh` の `copy_owned_files`（トップレベル通常ファイル・`.gitkeep` 除外）と同一にし、二重管理を避ける。

同期（コピー）は一切行わない。同期は既存の `upgrade`（`setup.sh` 経由）の責務のままとし、本スクリプトは「同期が必要かどうかを知らせる」診断に徹する。

### 1.2 設計原則

- **単一責務**: 適用する。本スクリプトの責務は「正本と配備物の内容一致検証」のみ。同期・書き込みは行わない。
- **明確な境界**: 適用する。`.claude/` への書き込み・`upgrade` の実行は本スクリプトの責務外とし、混同しない。
- **単一正本**: 適用する。比較対象ファイルの一覧は `enforcement/claude/` ディレクトリの実体から動的に導出し、ファイル名のハードコード一覧を持たない（正本のファイル構成が変わっても追従する）。

### 2.2 スクリプト仕様（check-hook-drift.sh）

- **引数**: `[project_root]`（省略時 `pwd`）。
- **比較元（正本）**: `<スクリプト位置>/../enforcement/claude/` 配下のトップレベル通常ファイル（`.gitkeep` 除く）。
- **比較先（配備物）**: `<project_root>/.claude/hooks/` 配下の同名ファイル。
- **出力・終了コード**:
  - `<project_root>/.claude/hooks/` 自体が存在しない → `[INFO]` を出力し **0**（enforcement 未 opt-in は正常な状態のため乖離扱いしない）。
  - 各ファイルについて、配備先に同名ファイルが無い → `[DRIFT]`（`未配備`）、内容不一致 → `[DRIFT]`（`不一致`）、内容一致 → `[OK]`。
  - 1 件でも `[DRIFT]` があれば終了コード **1**、無ければ **0**。
  - 前提エラー（正本ディレクトリが見つからない等）は終了コード **2**。
- **ハッシュ計算**: `sha256sum` があれば使用、無ければ `shasum -a 256` にフォールバック。
- **書き込み**: 一切行わない（read-only）。

### 2.3 参照関係・影響範囲

- 既存の `setup.sh`（`copy_owned_files`）・`bin/agents-md.js`（`upgrade`/`doctor`）には一切変更を加えない。本スクリプトはそれらと独立して実行可能な診断ツールであり、将来的に `doctor` へ組み込む場合は別 issue とする（01 §3 除外要件）。
- 本スクリプトの実行は read-only であり、稼働中の他セッションの `.claude/`（メイン作業ツリー含む）を書き換えない。

## 3. CORE.md への追記要否の検討

00 の参考資料は `.agent-skill-chain/source/boot/CORE.md:125` を挙げているが、当該行および周辺（禁止事項節・ロックアウト復旧手順）を確認した結果、`upgrade` の実行契機・配備物同期の運用ルールを記載するのに適した箇所は **CORE.md ではなく enforcement/README.md**（配備・強制の正本ドキュメント）であると判断した。CORE.md は「実行契約の正本」（phase 遷移・command 選択・禁止事項）に責務を限定しており（CORE.md §境界「実行契約の正本は本ファイル 1 か所のみ」）、配備物同期という運用手順を追記すると責務が越境する。したがって本 issue では **CORE.md は変更せず**、enforcement/README.md 側に運用ルールを追記する。

## 4. テスト観点

- 正本・配備先ともに同一内容のファイルのみを配置した場合、全ファイルが `[OK]` となり終了コード 0。
- 配備先のファイル内容が正本と異なる場合、当該ファイルが `[DRIFT]`（不一致）となり終了コード 1。
- 配備先にファイル自体が存在しない場合、当該ファイルが `[DRIFT]`（未配備）となり終了コード 1。
- `.claude/hooks/` ディレクトリ自体が存在しない場合、`[INFO]` のみで終了コード 0。
- 正本ディレクトリが見つからない不正な呼び出しでは終了コード 2。
- 上記いずれも `mktemp -d` による隔離環境で検証し、本リポジトリの実 `.claude/`（メイン作業ツリー・他 worktree 含む）には一切書き込まない。
