# 要件定義書: review-docs の表外必須ゲートという自己矛盾

**プロジェクト名**: review-docs の表外必須ゲートという自己矛盾
**作成日**: 2026 年 07 月 14 日
**最終更新**: 2026 年 07 月 14 日

> **用語**: [.agent-skill-chain/source/CONCEPTS.md §用語規約](../../../../../../../.agent-skill-chain/source/CONCEPTS.md#用語規約) を参照。

---

## 1. 概要

### 1.1 システム概要

本 issue はコード実装を伴わない**規約ドキュメントの整合性修正**である。対象は `.agent-skill-chain/source/workflow/PHASE_COMMAND_MAP.md` と `.agent-skill-chain/source/workflow/PHASES.md` の 2 ファイルのみ。

### 1.2 用語集

| 用語 | 説明 |
| --- | --- |
| PHASE_COMMAND_MAP | phase → command の対応表を定義する正本ファイル |
| review-docs | 実装前ドキュメントレビューの command。全 issue 一律必須の横断的ゲート |
| 横断的必須ゲート | 特定 phase に紐づかず、複数 phase をまたいで一律に必須となるチェック（review-docs 等）というカテゴリ |
| but 書き | 原則の宣言に対する例外を、都度その場しのぎの注記として書き足す記述パターン（本 issue が解消する対象） |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 規約の一貫性

- **As a** 本フレームワークの regulations を読む AI エージェント・保守者
- **I want to** PHASE_COMMAND_MAP と PHASES を読んで review-docs の位置づけを矛盾なく理解したい
- **So that** 「表が唯一の経路」という原則と「review-docs は表外の必須ゲート」という実運用の両方を、but 書きに頼らず正しく解釈できる

**受け入れ基準**:

- PHASE_COMMAND_MAP.md に「横断的必須ゲート」という分類が正式な見出し付きの節として存在し、review-docs がその節に位置づけられている。
- PHASE_COMMAND_MAP.md の「本表にない command の起動は禁止」の文が、適用範囲（phase からの選択経路であること）を文中で明示している。
- PHASES.md 側は同内容を重複させず、PHASE_COMMAND_MAP.md の当該節への参照のみで完結している。

### 2.2 BDD ユースケース

#### ユースケース 1: PHASE_COMMAND_MAP を読んで review-docs の位置づけを確認する

**シナリオ 1: 表にない command の禁止規定を読む**

```gherkin
Feature: PHASE_COMMAND_MAP の禁止事項の適用範囲明示
  Scenario: 第三者が禁止事項を読む
    Given PHASE_COMMAND_MAP.md の禁止事項に「本表が唯一の経路」という文がある
    When 読者がその文を読む
    Then 「フェーズ遷移コマンドの起動経路としては本表が唯一」という適用範囲が文中で分かる
    And 横断的必須ゲート（review-docs 等）の呼び出しがこの禁止の対象外であることが同じ節または直後の参照で分かる
```

**シナリオ 2: review-docs の位置づけを確認する**

```gherkin
Feature: 横断的必須ゲートという分類の明示
  Scenario: 第三者が review-docs の位置づけを確認する
    Given PHASE_COMMAND_MAP.md に「横断的必須ゲート」の節がある
    When 読者がその節を読む
    Then review-docs が表に行を持たない理由（横断的必須ゲートというカテゴリに属するため）が分かる
    And 「表に載らない」ことが「省略可・任意」を意味しないことが明記されている
```

#### ユースケース 2: PHASES.md から review-docs の必須性を確認する

**シナリオ 1: PHASES.md 側の記述が重複していない**

```gherkin
Feature: 正本の一元化
  Scenario: 保守者が PHASES.md の review-docs 関連記述を読む
    Given PHASES.md §レビュー成果物の配置ルール に review-docs の記述がある
    When 保守者がその記述を読む
    Then PHASE_COMMAND_MAP.md の横断的必須ゲート節への参照が含まれている
    And PHASE_COMMAND_MAP.md と同じ説明文（but 書き）が重複再記述されていない
```

### 2.3 ビジネスルール

- 表（PHASE_COMMAND_MAP.md）＝フェーズ遷移コマンドの起動経路。横断的必須ゲート＝特定 phase に紐づかない横断チェックというカテゴリ。両者は概念上独立であり、片方に属さないことは矛盾ではない。
- 重複禁止・正本 1 か所（.agent-skill-chain/source/CORE.md §境界、既存原則）に従い、横断的必須ゲートの定義は PHASE_COMMAND_MAP.md 側に一本化し、PHASES.md は参照のみとする。
