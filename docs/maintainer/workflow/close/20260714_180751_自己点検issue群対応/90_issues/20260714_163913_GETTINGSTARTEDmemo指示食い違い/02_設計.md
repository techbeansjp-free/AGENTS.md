## 1. 設計概要

### 1.1 設計方針

本 issue は静的ドキュメント（`.agent-skill-chain/source/GETTING_STARTED.md`）の記述整合のみを対象とし、コード・スキーマ変更を伴わない。設計方針は「正本（scribe/CONTRACT.md・ledger/schema.md）の定義は変更せず、案内文書側の表現のみを是正して既存の非推奨方針と一致させる」の 1 点に絞る（01 §2.3 ビジネスルール準拠）。

### 1.2 設計原則（本プロジェクトで適用するもの）

- **単一責務**: 本 issue の変更範囲は GETTING_STARTED.md の「1 issue を回す流れ」節に限定し、他ファイル（scribe/CONTRACT.md・ledger/schema.md）には触れない（正本と案内文書の責務分離を保つ）。
- **明確な境界**: 「証跡の正本の定義」（scribe/CONTRACT.md・ledger/schema.md の責務）と「利用者向け手順の要約」（GETTING_STARTED.md の責務）の境界を保ったまま、後者の要約が前者の定義からズレないようにする。

本 issue はドキュメント整合のみであり、CQRS・イベント駆動・UNIX 哲学・AI フレンドリー設計は非該当（該当なし）。

### 2.5 横断設計判断（ADR）

#### ADR-1: GETTING_STARTED の記述修正範囲を「1 issue を回す流れ」ステップ 2・4 に限定する

- **コンテキスト**: 00_要求定義.md は「1issue を回す流れ」の記述整合を求めているが、GETTING_STARTED.md には他にも証跡・memo に触れる箇所（例: 「サブ（command を実行する側）がやること」ステップ 5、run_command.md 等の他ファイル）がある。修正範囲をどこまで広げるかの判断が必要。
- **検討した選択肢**:
  1. 「1 issue を回す流れ」ステップ 2・4 のみ修正する。
  2. GETTING_STARTED.md 全体で memo に触れる箇所をすべて洗い出し書き換える。
  3. run_command.md 等、GETTING_STARTED.md 以外の文書も含めて memo 関連の表現を横断的に是正する。
- **決定**: 選択肢 1（「1 issue を回す流れ」ステップ 2・4 のみ）を採用する。
- **根拠**: 00_要求定義.md §8 参考資料が明示する対象範囲は「GETTING_STARTED.md『1issue を回す流れ』step 2」であり、00 §4.2 は「既存の GETTING_STARTED 読者向けの分かりやすさを損なわないこと」、00 §5 除外要件は「対応方針の具体設計・実装（本 issue は課題の起票のみ）」に続く本対応 issue のスコープを課題定義に沿って絞ることを求める。GETTING_STARTED.md「サブがやること」ステップ 5 は既に write-workflow-log の実行を明記しており（「write-workflow-log を省略しない」）、非推奨方針との直接的な矛盾はステップ 2・4 の「1 issue を回す流れ」の記述に限定される（evidence_source: existing_code。実ファイル `.agent-skill-chain/source/GETTING_STARTED.md` の現行記述を確認）。run_command.md 等の他ファイルは 00 の対象ファイルリストに含まれず、本 issue のスコープ外とする。
- **帰結**: 変更対象は GETTING_STARTED.md の「1 issue を回す流れ」節（ステップ 2・4）のみに確定する。他の memo 言及箇所（run_command.md 等）の是正要否は本 issue のスコープ外とし、必要であれば別 issue とする。
