## 1. 実装概要

### 1.1 実装方針

02_設計の ADR-1（猶予期限は次回実質改修時）・ADR-2（契約見出しは既存内容を維持したまま再配置）に従い、対象ファイルをテキスト修正のみで是正する。コード実行時の挙動変更はない。

### 1.2 実装順序

1. `.agent-skill-chain/source/skills/` 配下の既存 skill 全件（15 件）を grep で棚卸しする。
2. IO_CONTRACT.md の運用節を、対象範囲・期限・監査基準・棚卸し表を含む記述に修正する。
3. `skills/agent/SKILL.md` に契約見出しを追加する（既存内容は維持）。
4. grep による検証。
5. 00_要求定義.md frontmatter の `branch` 記録。
6. verify-and-close（04_review 作成・write-workflow-log 記録）。

## 2. タスク分解

### 2.1 タスク 1: 既存 skill 全件の契約見出し棚卸し

#### 2.1.1 概要

`.agent-skill-chain/source/skills/` 配下の SKILL.md 15 件それぞれについて、Purpose/Inputs/Process/Outputs/Done/Forbidden の見出しの有無を grep で確認する。

#### 2.1.2 実装内容

- `find .agent-skill-chain/source/skills -name SKILL.md` で全件列挙。
- 各ファイルに対し `grep -nE '^#+\s*(Purpose|Inputs|Process|Outputs|Done|Forbidden)\b'` を実行し、対応状況を判定する。

#### 2.1.3 テスト観点

##### 単体（本タスクの具体ケース）

- 15 件全てが棚卸し対象に含まれている（`find` の件数と表の行数が一致）。

##### 結合/API・E2E/受け入れ・バリデーション

該当なし（Query のみ）。

#### 2.1.4 単体テスト仕様（BDD）

```gherkin
Feature: 既存 skill 全件の棚卸し
  Scenario: 15 件全ての SKILL.md が対応状況表に反映される
    Given find .agent-skill-chain/source/skills -name SKILL.md が 15 件を返す
    When 各ファイルの見出し有無を grep で確認する
    Then IO_CONTRACT.md の棚卸し表の行数が 15 件と一致する
```

**検証コマンド**:

```bash
find .agent-skill-chain/source/skills -name "SKILL.md" | wc -l
```

#### 2.1.5 依存関係

- なし（他タスクの前提）。

#### 2.1.6 見積もり

- **工数**: 小
- **優先度**: 高

### 2.2 タスク 2: IO_CONTRACT.md 運用節の是正・棚卸し表追加

#### 2.2.1 概要

IO_CONTRACT.md の「運用」節を、猶予の対象範囲・期限・監査基準を明記した記述に修正し、タスク 1 の棚卸し結果を表として追加する。

#### 2.2.2 実装内容

- 既存の 3 行の運用節を、対象範囲・期限（次回実質改修時）・機械チェック時の FAIL/PASS 判定条件（4 項目）を含む記述に置換する。
- 棚卸し表（15 行）を追加する。

#### 2.2.3 テスト観点

##### 単体（本タスクの具体ケース）

- IO_CONTRACT.md に「対象範囲」「期限」「監査基準」に相当する記述が存在する（目視確認）。
- 棚卸し表に 15 件全てが列挙されている。

##### 結合/API

該当なし。

##### E2E/受け入れ

- verify-and-close で 04_review.md に確認結果を記載する。

##### バリデーション

該当なし。

#### 2.2.4 単体テスト仕様（BDD）

```gherkin
Feature: IO_CONTRACT.md の猶予基準明文化
  Scenario: 運用節に対象範囲・期限・監査基準が明記される
    Given IO_CONTRACT.md の運用節が「既存は追って揃える」とのみ記載
    When 運用節を対象範囲・期限・監査基準を含む記述に修正する
    Then grep -c "既存 skill 契約見出し対応状況" IO_CONTRACT.md が 1 以上になる
```

**検証コマンド**:

```bash
grep -c "既存 skill 契約見出し対応状況" .agent-skill-chain/source/IO_CONTRACT.md
grep -c "次回実質改修時" .agent-skill-chain/source/IO_CONTRACT.md
```

#### 2.2.5 依存関係

- タスク 1（棚卸し結果）に依存。

#### 2.2.6 見積もり

- **工数**: 小
- **優先度**: 高

### 2.3 タスク 3: `skills/agent/SKILL.md` の契約見出し追加

#### 2.3.1 概要

`skills/agent/SKILL.md` に 6 見出しを追加し、既存の「委譲の形（共通）」「実行要領」の内容は変更せず `## Process` 配下に再配置する。

#### 2.3.2 実装内容

- `## Purpose`（既存冒頭文）、`## Inputs`（新規に簡潔記載）、`## Process`（既存 2 節をサブ見出しとして保持）、`## Outputs`（新規に簡潔記載）、`## Done`（新規に簡潔記載）、`## Forbidden`（新規に簡潔記載）を追加する。
- 既存の「## 参照」節は変更せず維持する。

#### 2.3.3 テスト観点

##### 単体（本タスクの具体ケース）

- `grep -c '^## Purpose$'` 等、6 見出しがそれぞれ 1 件ずつ検出される。
- 既存文言（「委譲の形（共通）」「実行要領」「command を実行するときは必ず本ファイルを読むこと」等）が変更なく残っている。

##### 結合/API・E2E/受け入れ・バリデーション

該当なし（ドキュメントのみ）。

#### 2.3.4 単体テスト仕様（BDD）

```gherkin
Feature: skills/agent/SKILL.md の契約見出し追加
  Scenario: 6 見出しが追加され既存内容が保持される
    Given skills/agent/SKILL.md に契約見出しが存在しない
    When 6 見出しを追加し既存内容を Process 配下に再配置する
    Then grep で 6 見出し全てが検出される
    And 既存の「委譲の形（共通）」「実行要領」の文言が変更なく残っている
```

**検証コマンド**:

```bash
for h in Purpose Inputs Process Outputs Done Forbidden; do
  grep -c "^## ${h}\$" .agent-skill-chain/source/skills/agent/SKILL.md
done
grep -c "委譲の形（共通）" .agent-skill-chain/source/skills/agent/SKILL.md
grep -c "実行要領" .agent-skill-chain/source/skills/agent/SKILL.md
```

#### 2.3.5 依存関係

- タスク 2 と独立して実施可能（同一 issue 内で並行に近い形で実施）。

#### 2.3.6 見積もり

- **工数**: 小
- **優先度**: 高（00 の成功基準に名指しされている優先対応対象）
