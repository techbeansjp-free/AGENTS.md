# 要件定義書: audit.sh #6 の PR_BODY 検査 regex が過検知・非 POSIX 依存

**プロジェクト名**: audit.sh #6 の PR_BODY 検査 regex が過検知・非 POSIX 依存
**作成日**: 2026年07月14日
**最終更新**: 2026年07月14日

---

## 1. 概要

### 1.1 システム概要

`audit.sh` #6（PR 本文の内部参照禁止チェック）は、外部サイトの絶対 URL（`https://example.com/docs/...`）まで誤検知し、かつ `\s`（GNU grep 拡張）を使用しているため BSD grep 等で挙動が異なりうる。ユーザー判断により**対応する**ことが確定した（00 参照）。

### 1.2 用語集

| 用語 | 説明 |
| --- | --- |
| enforcement #6 | `audit.sh` の PR 本文内部参照禁止チェック（`.agent-skill-chain/runtime/`・`docs/` へのリンクを検出）。 |
| POSIX ERE | POSIX 拡張正規表現。`[[:space:]]` 等の文字クラスは規定するが `\s`（Perl/GNU 拡張）は規定しない。 |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 外部 URL の誤検知解消

- **As a** PR を作成する開発者
- **I want to** PR 本文に外部サイトの `/docs/` を含む URL を書いても FAIL しないでほしい
- **So that** 内部参照禁止チェックの本来の目的（リポジトリ内部の作業用パスへの参照防止）を損なわずに PR を作成できる

**受け入れ基準**:

- PR 本文が `https://example.com/docs/page` のような絶対 URL のみを含む場合、enforcement #6 は FAIL しない。
- `.agent-skill-chain/runtime/` や内部の `docs/` パスへの markdown リンクは引き続き FAIL する（既存の検知目的を維持）。

#### ストーリー 2: POSIX 準拠化

- **As a** BSD 系環境（macOS 等）で `audit.sh` を実行する保守者
- **I want to** grep の実装差異（GNU 拡張 `\s` への依存）を無くしてほしい
- **So that** GNU grep・BSD grep のどちらでも同一の判定結果になる

**受け入れ基準**:

- `\s` を使用せず、POSIX 文字クラス `[[:space:]]` を用いる。

### 2.2 BDD ユースケース

#### ユースケース 1: PR 本文の内部参照検査

**シナリオ 1: 外部 URL のみ（誤検知しないこと）**

```gherkin
Feature: PR_BODY 内部参照禁止チェック
  Scenario: 外部サイトの /docs/ を含む絶対 URL
    Given PR_BODY が "See https://example.com/docs/page for reference." である
    When audit.sh の #6 チェックが実行される
    Then FAIL しない
```

**シナリオ 2: 内部パスへの markdown リンク（検知を維持すること）**

```gherkin
Feature: PR_BODY 内部参照禁止チェック
  Scenario: .agent-skill-chain/runtime/ への markdown リンク
    Given PR_BODY が "[detail](.agent-skill-chain/runtime/xxx/00.md)" を含む
    When audit.sh の #6 チェックが実行される
    Then FAIL する
```

### 2.3 ビジネスルール

- 検知対象はリポジトリ内部の作業用パス（`.agent-skill-chain/runtime/`・内部の `docs/` パス）に限定する。
- 外部 URL（`http://`/`https://` スキーム付き）の内側にある `/docs/` は誤検知しない。
