# 実装計画書: audit.sh #6 の PR_BODY 検査 regex が過検知・非 POSIX 依存

**作成日**: 2026年07月14日
**最終更新**: 2026年07月14日

---

## 1. 実装概要

### 1.1 実装方針（必須）

`audit.sh` #6 の判定直前に、`sed -E 's#https?://[^)[:space:]]*##g'` で `PR_BODY` から絶対 URL を除去した文字列を作り、その文字列に対して既存の内部パス検知 regex（`\s` を `[[:space:]]` に置換したもの）を適用する。

### 1.2 実装順序（必須: 1 件以上）

1. `audit.sh` #6 のチェックブロックを、URL 除去 → 内部パス検知の 2 段構成に書き換える（タスク 1）。

---

## 2. タスク分解

### 2.1 タスク 1: enforcement #6 の regex 修正（過検知解消・POSIX 準拠）

#### 2.1.1 概要（必須）

外部 URL 誤検知を解消しつつ、内部パス（`.agent-skill-chain/runtime/`・`docs/`）への参照検知を維持し、`\s` を `[[:space:]]` に置換して POSIX 準拠にする。

#### 2.1.2 実装内容（必須: 1 件以上）

- `.agent-skill-chain/source/enforcement/ci/audit.sh` の該当ブロックを以下のように変更:
  - `_pr_body_no_url="$(printf '%s' "$PR_BODY" | sed -E 's#https?://[^)[:space:]]*##g')"` を追加。
  - 判定対象を `$PR_BODY` から `$_pr_body_no_url` に変更。
  - `[^)\s]` を `[^)[:space:]]` に置換（2 箇所）。

#### 2.1.3 テスト観点（必須）

##### 単体（本タスクの具体ケース・必須 1 件以上）

- `PR_BODY="See https://example.com/docs/page for reference."` → FAIL しない（外部URL誤検知の解消）。
- `PR_BODY="See [external docs](https://example.com/docs/page) for details."` → FAIL しない（markdown リンク形式の外部URLも誤検知しない）。
- `PR_BODY="[detail](.agent-skill-chain/runtime/xxx/00.md)"` → FAIL する（内部パス検知の維持）。
- `PR_BODY="[detail](/docs/maintainer/workflow/xxx/00.md)"` → FAIL する（内部 docs パス検知の維持）。
- `PR_BODY="See .agent-skill-chain/runtime/xxx/00.md) for details."`（markdown リンク構文を伴わない直書き）→ FAIL する（既存の非 markdown 検知パターンの維持）。
- `PR_BODY="This PR fixes a bug. Closes #123."` → FAIL しない（内部参照が全く無い通常の PR 本文）。

##### 結合/API（本タスクの具体ケース・該当時は必須 1 件以上）

- tmp git リポジトリ上で `audit.sh` をフル実行し、上記各 `PR_BODY` パターンで #6 チェックの PASS/FAIL が期待どおりであることを確認する（他の enforcement チェックに回帰がないことも合わせて確認、詳細は 04_review.md §3.1）。

##### E2E/受け入れ（本タスクの具体ケース・未達時は理由記載）

- 実際の GitHub PR 上での CI 実行による確認は、本 PR 自体が実 PR として作成されるため、その CI 実行結果を実質的な E2E 確認として扱う（本 PR の本文には内部パス言及を含めないため #6 は PASS する想定）。

##### バリデーション（該当する場合の具体ケース）

- BSD grep 特有の挙動差は本環境（Linux/GNU grep）では直接検証できないため、`[[:space:]]` が POSIX 標準文字クラスであり GNU/BSD 双方の grep マニュアルで規定されていることを設計根拠とする（02_設計 ADR-2）。実機での BSD grep 確認は未実施（理由: 実行環境が Linux のみのため）。
