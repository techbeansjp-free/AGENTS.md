## 1. 概要

### 1.1 システム概要

`.agent-skill-chain/source/` は消費者環境（自己拡張元である本リポも含む）に配布される汎用パッケージ正本である。本正本は「コア＝抽象／project＝具体」の建付けを取り、消費者固有の具体手順は `.agent-skill-chain/project/` 側の上書きファイルへ委譲する設計になっている。しかし現状、`skills/agent/run_command.md`・`workflow/PHASES.md`・`CONTEXT_EFFICIENCY.md` の一部箇所は、project 側にその上書きファイルが存在することを前提とした参照（無条件のリンク）になっており、`init` 直後で project 未整備の消費者環境では参照先が存在せず、必須ゲートの「具体手順」が宙に浮く。

### 1.2 用語集

| 用語 | 説明 |
| --- | --- |
| project 未整備 | 消費者が `init` した直後など、`.agent-skill-chain/project/` 配下に当該コアファイルへの上書き・具体化ファイルが存在しない状態 |
| フォールバック条件分岐 | 「project 側に該当ファイルが無い場合はこの参照を適用しない」旨の条件分岐のみを記載し、具体値を書かずに宙づり参照を解消する対応方針（00_要求定義 §7.1） |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: project 未整備環境でもゲート参照が宙づりにならない

- **As a** 本パッケージを `init` した直後の消費者エージェント
- **I want to** `run_command.md` の GitHub Issue 起票ゲート・ブランチ紐づけゲート・PR 紐づけゲートの「具体手順」参照が、project 側ファイルが無くても破綻しない
- **So that** 存在しないファイルへのリンクを追いかけて手が止まる、という事態を避けられる

**受け入れ基準**:

- `run_command.md`（GitHub Issue 起票ゲート・ブランチ紐づけゲート・PR 紐づけゲートの 3 項目）に、`.agent-skill-chain/project/自己拡張ワークフロー.md` 等の project 側具体化ファイルが存在しない場合の条件分岐（適用しない旨）が明記されている。
- 条件分岐の追記後も、各ゲート本文に書かれている抽象要件（記録先 frontmatter・記録する値・declined 等の代替記録）自体は変更されていない（ゲートの強制力は維持する）。

#### ストーリー 2: issue 作成場所の上書き確認が CLAUDE.md 未整備環境でも破綻しない

- **As a** issue 作成タスクを受領したサブエージェント
- **I want to** `PHASES.md §一般的な issue 作成ステップ` の「作成場所の上書き」確認が、CLAUDE.md に該当節が無い環境でも読める
- **So that** 作成場所が決められず作業が止まる、という事態を避けられる

**受け入れ基準**:

- `PHASES.md` の「作成場所の上書き」項目に、CLAUDE.md 該当節が存在しない場合のフォールバック（一般的な既定の作成場所に従ってよい旨）が明記されている。

#### ストーリー 3: ISSUE_CREATION の汎用原理が project/CLAUDE.md 未整備でも自己完結する

- **As a** 大規模一括起票または軽量運用のいずれかを行うサブエージェント
- **I want to** `CONTEXT_EFFICIENCY.md` の project への委譲・CLAUDE.md への参照が、project/CLAUDE.md 側に該当がなくても読める
- **So that** 本ファイルの抽象原則だけで軽量運用まで完結できる

**受け入れ基準**:

- `CONTEXT_EFFICIENCY.md:7` に、`.agent-skill-chain/project/` への委譲・CLAUDE.md 参照それぞれについて、該当が無い場合のフォールバックが明記されている。
- `CONTEXT_EFFICIENCY.md:64` に、CLAUDE.md に該当節が無い場合は本ファイル自身の軽量運用の記載に従ってよい旨が明記されている。

### 2.2 BDD ユースケース

#### ユースケース 1: project 未整備の消費者環境で implement-feature に着手する

**シナリオ 1: 3 ゲートの具体手順参照が宙づりにならない**

```gherkin
Feature: run_command.md のゲート参照フォールバック
  Scenario: project 側に自己拡張ワークフロー.md が存在しない
    Given 消費者が本パッケージを init した直後で .agent-skill-chain/project/ に該当ファイルが無い
    When サブエージェントが GitHub Issue 起票ゲート・ブランチ紐づけゲート・PR 紐づけゲートの具体手順を確認しようとする
    Then run_command.md 本文だけを読めば「project 側参照は適用しない・本文の抽象要件に従う」と判断できる
```

**シナリオ 2: project 側に自己拡張ワークフロー.md が存在する場合は従来どおり**

```gherkin
Feature: run_command.md のゲート参照フォールバック
  Scenario: project 側にファイルが存在する（本リポ等）
    Given .agent-skill-chain/project/自己拡張ワークフロー.md が存在する
    When サブエージェントが具体手順を確認する
    Then 従来どおり project 側ファイルの具体手順に従う（フォールバック条件は発火しない）
```

#### ユースケース 2: issue 作成タスクの作成場所を決める

**シナリオ 1: CLAUDE.md に該当節が無い環境**

```gherkin
Feature: PHASES.md の作成場所フォールバック
  Scenario: project 上書きも CLAUDE.md 該当節も無い
    Given .agent-skill-chain/project/ の上書きも CLAUDE.md §issue 作成タスク受領時の標準フローも存在しない
    When サブエージェントが issue の作成場所を決めようとする
    Then command 実行主体が定める一般的な既定の作成場所に従ってよいと判断できる
```

### 2.3 ビジネスルール

- 「コア＝抽象／project＝具体」の建付け自体は変更しない（除外要件・00 §5）。
- フォールバック追記は「project に無い場合は適用しない」という条件分岐のみとし、project 側の具体値（コマンド例・title/body 形式等）をコア側に書き写さない（00 §7.1 リスク対策）。
- 164009・163447 issue で既に整理済みの run_command.md の他セクション（委譲の形の定義・バックグラウンド実行禁止項目・AGENT_CONDUCT 転記義務項目）には触れない。
