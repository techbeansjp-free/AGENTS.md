## 1. 設計概要

### 1.1 設計方針

正本（CORE.md）を単一の情報源とし、入口案内（AGENTS.md）はそれを要約・参照するのみとする方針に従い、AGENTS.md 側の表現を実態（CORE.md の記述・enforcement の有無）に合わせる。

### 1.2 設計原則（本プロジェクトで適用するもの）

- **明確な境界**: 正本（CORE.md）と入口案内（AGENTS.md）の役割を分離し、入口は正本を要約・参照するのみとする。

## 2. アーキテクチャ設計

### 2.1 責務・境界・参照関係

#### 2.1.1 責務一覧

| コンポーネント | 責務（1 文） |
| --- | --- |
| `AGENTS.md`（入口案内） | 正本への導線を示す。強度表現は正本と一致させる。 |
| `.agent-skill-chain/source/boot/CORE.md`（正本） | HEARTBEAT 読了の実際の強度（推奨/強制）を規定する唯一の正本。 |

#### 2.1.2 境界

- **入力**: `.agent-skill-chain/source/enforcement/` 配下の実装（HEARTBEAT 読了を機械検知するロジックの有無）。
- **出力**: `AGENTS.md:10` の文言（「推奨」に修正）。
- **他責務との境界**: enforcement の実装ロジック自体（audit.sh 等）の変更は本 issue の範囲外。

#### 2.1.3 参照関係

- `AGENTS.md` →（参照）→ `CORE.md §Heartbeat`。循環参照なし。

### 2.2 調査結果（根拠）

`.agent-skill-chain/source/enforcement/` 配下（README.md・ci/audit.sh・ci/check-comment-refs.sh・claude/PreToolUse.sh・claude/PostToolUse.sh）を grep したところ、"heartbeat"（大小文字不問）を検知する機械ロジックは存在しない（該当なし＝exit code 1）。README.md の失敗条件一覧（#1〜#36 相当）にも HEARTBEAT 読了に対応する項目はない。

- **結論**: HEARTBEAT 読了は現状、機械強制（runtime reject / CI FAIL）の対象ではなく、AI の自己確認・自律判断に委ねられている。したがって表現は CORE.md 側の「推奨」が実態と一致しており、`AGENTS.md:10` を「推奨」に合わせて修正する。

#### ADR-1: 表現統一の方向（AGENTS.md → 推奨 or CORE.md → 強制）

- **コンテキスト**: 「強制」「推奨」いずれかに統一する必要があるが、どちらに寄せるかは実態（機械強制の有無）に基づいて決めるべきである。
- **検討した選択肢**:
  1. AGENTS.md の表現を「推奨」に修正し、CORE.md（実態どおり）に合わせる。
  2. CORE.md の表現を「強制」に変更し、AGENTS.md に合わせる（ただし実態が伴わない）。
- **決定**: 選択肢 1（AGENTS.md を「推奨」に修正）。
- **根拠**: enforcement/ 配下に HEARTBEAT 読了を検知する機械チェックが存在しないことを実際に grep で確認した（evidence_source: existing_code）。実態が伴わない「強制」という表現を残すと、今後 CORE.md 側を確認しない限り誤認が継続する。
- **帰結**: `AGENTS.md:10` の文言を「推奨」に変更する。CORE.md 側（既に「推奨」）は変更不要。将来、HEARTBEAT 読了を機械強制化する場合は、その実装追加と同時に両ドキュメントを「強制」へ統一する。
