# 要件定義書: HEARTBEAT 読了「強制」（AGENTS.md）vs「推奨」（CORE.md）の記述矛盾

**プロジェクト名**: HEARTBEAT 読了強制推奨の記述矛盾
**作成日**: 2026 年 07 月 14 日
**最終更新**: 2026 年 07 月 14 日

> **用語**: [.agent-skill-chain/source/CONCEPTS.md §用語規約](../../../../../../../.agent-skill-chain/source/CONCEPTS.md#用語規約) を参照。

---

## 1. 概要

### 1.1 システム概要

`AGENTS.md`（入口案内）と `.agent-skill-chain/source/boot/CORE.md`（実行契約の正本）の間で、HEARTBEAT 読了の強度表現（「強制」/「推奨」）が食い違っている。本 issue はこの表現不一致を、実際の enforcement 実装（機械強制の有無）に即して解消する。

### 1.2 用語集

| 用語 | 説明 |
| --- | --- |
| HEARTBEAT | `.agent-skill-chain/source/HEARTBEAT.md`。orchestrator が自己確認するチェックリスト。 |
| 強制 | enforcement（audit.sh・PreToolUse 等）が違反時に検知し FAIL/reject させる強度。 |
| 推奨 | 機械検知されず、AI の自律判断・自己確認に委ねる強度。 |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 入口と正本の表現一致

- **As a** 本フレームワークの利用者・エージェント
- **I want to** AGENTS.md と CORE.md の HEARTBEAT 読了に関する強度表現が一致していること
- **So that** どちらのドキュメントを読んでも、HEARTBEAT 読了が enforcement 上どちらの扱い（FAIL 対象か否か）か誤認しない

**受け入れ基準**:

- `AGENTS.md:10` と `.agent-skill-chain/source/boot/CORE.md:111` の HEARTBEAT 読了に関する強度表現（「強制」/「推奨」）が一致している。
- 表現の一致は実態（enforcement/ 配下に HEARTBEAT 読了を検知する機械チェックが存在するか）に基づいて決定されている。

### 2.2 BDD ユースケース

#### ユースケース 1: 表現の実態確認と統一

**シナリオ 1: 機械強制が存在しない場合は「推奨」に統一する**

```gherkin
Feature: HEARTBEAT 読了の強度表現統一
  Scenario: enforcement に HEARTBEAT 読了の機械チェックが無い
    Given .agent-skill-chain/source/enforcement/ 配下（audit.sh・PreToolUse.sh 等）に "heartbeat" を検知するロジックが存在しない
    When AGENTS.md:10 の表現を確認する
    Then AGENTS.md:10 は CORE.md:111 と同様に「推奨」と記載されている
```

### 2.3 ビジネスルール

- 入口ドキュメント（AGENTS.md）の強度表現は、正本（CORE.md）および実際の enforcement 実装と常に一致させる（表現のみを合わせ、HEARTBEAT の内容・読了タイミング自体は変更しない）。
