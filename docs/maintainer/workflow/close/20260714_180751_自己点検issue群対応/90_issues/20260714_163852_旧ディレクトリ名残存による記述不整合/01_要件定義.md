# 要件定義書: 旧ディレクトリ名残存による記述不整合

**プロジェクト名**: 旧ディレクトリ名残存による記述不整合
**作成日**: 2026年07月14日
**最終更新**: 2026年07月14日

> **用語**: [.agent-skill-chain/source/CONCEPTS.md §用語規約](../../../../../../../.agent-skill-chain/source/CONCEPTS.md#用語規約) を参照。

---

## 1. 概要

### 1.1 システム概要

実ディレクトリは `.agent-skill-chain/source|project|runtime` へ改名済みだが、正本ドキュメントの一部箇所に旧名（`.workflow`／`.agents`）が字面として残っており、`audit.sh` の実装既定値（`WORKFLOW_DIR` 既定 `.agent-skill-chain/runtime`）と食い違っている。本 issue はコード側の既定値を変更せず、ドキュメント記載側を実装に合わせて是正する。

### 1.2 用語集

| 用語 | 説明 |
| --- | --- |
| WORKFLOW_DIR | audit.sh が走査する既定ディレクトリを指す環境変数。既定値は `.agent-skill-chain/runtime`（`audit.sh:133`）。 |
| 旧名称 | 改名前のディレクトリ名 `.workflow`（→ `.agent-skill-chain/runtime`）・`.agents`（→ `.agent-skill-chain/source`）。 |
| 意図的な後方互換記載 | `SETUP.md` のレガシー移行手順や `package-manifest.sh` の legacy パス変数等、旧名称を**参照対象として意図的に**残す記述。本 issue の是正対象外。 |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: enforcement/README.md の記載を実装既定値と一致させる

- **As a** 本フレームワークの保守者・消費者
- **I want to** `enforcement/README.md` を読んだときに、PreToolUse が拒否する対象パス・WORKFLOW_DIRS の既定リスト・TODO/FIXME 監査の対象パスが、実際の `audit.sh` の実装既定値（`.agent-skill-chain/runtime`）と一致していてほしい
- **So that** 既定値を誤認して運用ミス（誤った WORKFLOW_DIR 上書き判断等）を起こさない

**受け入れ基準**:

- `enforcement/README.md` の該当 3 箇所（Layer2 説明・WORKFLOW_DIRS 既定リスト説明・失敗条件 #7 の説明）が `.workflow` ではなく `.agent-skill-chain/runtime` を記載していること。
- WORKFLOW_DIRS 既定リストの説明文言が `audit.sh` の `resolve_workflow_dirs`（`audit.sh:138-165` 付近）の実装と矛盾しないこと。
- 同ファイル内の意図的な後方互換記載・本 issue の対象外セクションは変更しないこと。

#### ストーリー 2: CORE.md / LOAD_POLICY.md / AGENTS.md の issue 用ディレクトリ表記を現行名称に統一する

- **As a** 本フレームワークを読む AI エージェント・人間の保守者
- **I want to** CORE.md・LOAD_POLICY.md・AGENTS.md を読んだときに、issue 用ドキュメントの作成先ディレクトリ表記が現行の実ディレクトリ名で書かれていてほしい
- **So that** 旧名称を実在するパスと誤認して探索に失敗しない

**受け入れ基準**:

- `boot/CORE.md:74` 付近の「.workflow 配下の issue 用ドキュメント」が「.agent-skill-chain/runtime 配下の issue 用ドキュメント」に修正されていること。
- `boot/LOAD_POLICY.md:13` 付近の「.workflow 配下の新規 issue フォルダ作成」が「.agent-skill-chain/runtime 配下の新規 issue フォルダ作成」に修正されていること。
- `AGENTS.md:125` 付近の「詳細は .agents 配下を参照する」が「詳細は .agent-skill-chain/source 配下を参照する」に修正されていること（同ファイル内の他の `.agents` 記載＝概念上のフレームワーク呼称は対象外）。

#### ストーリー 3: self-enforce.yml のコメントを audit.sh の実装と整合させる

- **As a** 本リポジトリの CI 定義を読む保守者
- **I want to** `self-enforce.yml` の enforcement audit step のコメントが、`audit.sh` の実際の WORKFLOW_DIR 解決ロジック（既定値＋ `docs/maintainer/workflow` の実在時追加）を正しく説明していてほしい
- **So that** 「audit.sh が旧名称 `.workflow` を前提にしているため通らない」という誤った理由付けを読んで誤解しない

**受け入れ基準**:

- `.github/workflows/self-enforce.yml` の step 7 コメントから `.workflow` という誤った既定値の記載が除かれ、`audit.sh` の実際の `resolve_workflow_dirs` ロジック（`WORKFLOW_DIR` 既定 `.agent-skill-chain/runtime` ＋ `docs/maintainer/workflow` の実在時追加）に基づく説明に置き換わっていること。
- コメント外部参照禁止規約（章節番号・仕様ドキュメント名の直書き禁止）に抵触しないこと（`check-comment-refs.sh` で確認）。

### 2.2 BDD ユースケース

#### ユースケース 1: 旧名称の残存検知

```gherkin
Feature: 旧ディレクトリ名の残存検知
  Scenario: 対象ファイル群に旧名称が残っていないことを確認する
    Given 修正後の enforcement/README.md, boot/CORE.md, boot/LOAD_POLICY.md, AGENTS.md, .github/workflows/self-enforce.yml
    When grep -rn '\.workflow\b|\.agents\b' で対象ファイルを検索する
    Then 意図的な後方互換記載・フレームワークの概念呼称としての ".agents" 以外に、旧ディレクトリ名としての ".workflow" ".agents" が残っていない
```

### 2.3 ビジネスルール

- `audit.sh` の実装既定値（`.agent-skill-chain/runtime`）自体は変更しない（00 §2.1／§5 除外要件）。
- 意図的な後方互換記載（`SETUP.md` のレガシー移行パス、`package-manifest.sh` の `legacy_source`/`legacy_runtime` 変数、`build-adapters.sh` のコメント等）は変更しない。
- 本 issue の対象範囲は 00 に列挙された対象ファイルのみとし、他のファイルに存在する同種の旧名称残存は別 issue の対象とする（スコープ外）。
