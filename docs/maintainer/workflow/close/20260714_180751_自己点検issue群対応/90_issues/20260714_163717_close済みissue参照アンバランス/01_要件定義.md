# 要件定義書: アクティブ issue 不在下での close 済み issue 参照アンバランス

**プロジェクト名**: アクティブ issue 不在下での close 済み issue 参照アンバランス
**作成日**: 2026年07月14日
**最終更新**: 2026年07月14日

> **判断**: [00_要求定義.md](./00_要求定義.md) の成功基準どおり、`.agent-skill-chain/project/自己拡張ワークフロー.md` に「正本文書における close/ 参照の位置づけ」方針を明文化することで対応する。正本の参照自体を全廃するのではなく、「結論は正本内で完結・close/ 参照は補足情報」という条件を明記する方針を採る（既存の `MODEL_TIER_TABLE.md` の書き方が既にこの条件を満たす実例であるため、大規模な書き直しは不要と判断）。

---

## 1. 概要

全 issue が close/ へ移動済みのため、正本ドキュメントからの「検討経緯・ADR」参照は構造的にすべて deny 領域行きになる。「経緯はノイズ・現在の事実のみ」という既存原則と、正本自体が経緯参照を前提にしている記載が併存しており、参照先だけが読めなくなるアンバランスが生じていた。本 issue では、正本文書が close/ を参照する場合の位置づけ方針を明文化することでこのアンバランスを解消する。

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 正本執筆者が close/ 参照の妥当な書き方を判断できる

- **As a** `.agent-skill-chain/project/` 配下の正本文書を執筆・更新する保守者
- **I want to** close/ 配下（検討経緯・ADR）への参照を含めてよい条件（正本は結論のみで完結・参照は補足情報に限定）が明文化されている
- **So that** 「経緯はノイズ」原則と参照依存のアンバランスを毎回都度判断せずに解消できる

**受け入れ基準**:

- `.agent-skill-chain/project/自己拡張ワークフロー.md` に、正本文書における close/ 参照の位置づけ方針（結論・現在の事実のみを本文に記載、close/ 参照は補足情報、読めなくても本文理解に支障がないことが条件）が明記されている。
- 既存の `MODEL_TIER_TABLE.md` の close/ 参照箇所が、この方針に沿った書き方の実例として言及されている。

### 2.2 非機能要件

- **互換性**: close/ 配下 deny 設定・close 移動運用自体は維持する（00 §2.1）。
- **セキュリティ**: 該当なし。

## 3. 除外要件

- 正本文書中の既存 close/ 参照箇所を今回すべて監査・書き直しすることは対象外（00 §5 のとおり、方針明文化に留める）。

## 4. 成功基準

- 00 §6 の成功基準（正本ドキュメントの close/ 配下参照について方針が明文化されていること）を満たす。
