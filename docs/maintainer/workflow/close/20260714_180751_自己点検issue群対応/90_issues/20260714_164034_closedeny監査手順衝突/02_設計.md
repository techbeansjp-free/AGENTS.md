## 1. 設計概要

### 1.1 設計方針

`.agent-skill-chain/project/自己拡張ワークフロー.md` の新設セクション `## close/ 参照・deny 運用に関する方針（自己点検issue対応）` 内に、サブセクション「close/ deny 設定の推奨形態（監査・調査タスクとの両立）」を追加する（本 issue の主対応。同セクション内の他 2 サブセクションは姉妹 issue 20260714_163724・20260714_163717 が対応し、3 issue分は 1 回の編集でまとめて追加済み）。`.claude/settings.json` 自体は変更しない。

### 1.2 設計原則

- **単一責務**: 適用する。deny 設定の推奨案は該当サブセクション 1 箇所に集約する。
- **明確な境界**: 適用する。「推奨・提案」（本 issue の対応範囲）と「実際の `.claude/settings.json` 変更」（対象外）を明確に区別する。

## 2. 変更内容

### 2.1 対象ファイルと変更点

| ファイル | 変更内容 |
| -------- | -------- |
| `.agent-skill-chain/project/自己拡張ワークフロー.md` | 「close/ deny 設定の推奨形態（監査・調査タスクとの両立）」サブセクションを追加。Read のみ許可・Grep/Glob と Edit/Write は引き続き deny する推奨案、および audit.sh の find 走査との非対称の許容理由（機械監査＝決定論的プログラム／エージェントの Read 等＝自律判断を伴う読み取り、という性質差）を記載。 |
| 本 issue の `00_要求定義.md` | frontmatter `branch` を実ブランチ名に更新（実施済み）。 |

### 2.2 内容の要点（追加文の骨子）

- 推奨案: `Read` のみ許可、`Grep`/`Glob` および `Edit`/`Write` 系は引き続き deny。誤編集防止という主目的は Edit/Write 側の deny 維持で達成できる。
- Grep/Glob は close/ 内の大量ファイル横断検索という操作性ゆえ、当面 deny を維持する案とする。
- audit.sh の `find` 走査は、人間が事前レビューした固定ロジックのプログラムによる決定論的走査であり、エージェントの Read/Grep/Glob（内容を読んで自律判断する経路）とは性質が異なるため、非対称は意図的な設計判断として整理する。
- 本節の記載は推奨・提案に留まり、`.claude/settings.json` 自体の変更はこの節の範囲外（ローカル環境固有設定であり、変更可否は消費者・保守者の判断に委ねる）。

### 2.3 参照関係・影響範囲

- `enforcement/ci/audit.sh` の走査ロジックは変更しない（00 §4.2 のとおり不用意に変更しない）。
- 既存の close 移動時の相対リンク補正手順（移動前に完結・移動後は Read/Grep/Glob を行わない）との整合を保つ（本節は「今後の設定変更を検討する際の推奨」であり、現行手順を上書きしない）。

## 3. テスト観点

- 追加サブセクションが「推奨・提案」であり `.claude/settings.json` を実際に変更するものではないことが明記されていること。
- audit.sh の走査ロジックに変更が加えられていないこと（diff で確認）。
- `bash .agent-skill-chain/source/enforcement/ci/audit.sh .` を実行し、本変更由来の新規 FAIL が無いこと。
