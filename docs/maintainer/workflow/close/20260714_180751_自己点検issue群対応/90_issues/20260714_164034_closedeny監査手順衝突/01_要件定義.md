# 要件定義書: close/ deny 設定と監査・検証手順が恒常的な特殊手順を要求する

**プロジェクト名**: close/ deny 設定と監査・検証手順が恒常的な特殊手順を要求する
**作成日**: 2026年07月14日
**最終更新**: 2026年07月14日

> **判断**: [00_要求定義.md](./00_要求定義.md) の成功基準どおり、`.agent-skill-chain/project/自己拡張ワークフロー.md` に「close/ deny 設定の推奨形態」を明文化する。実際の `.claude/settings.json` 変更は行わず（00 §5 除外要件・除外条件どおり）、推奨案（Read のみ許可・Grep/Glob と Edit/Write は引き続き deny）と、audit.sh の find 走査との非対称の許容理由（機械監査＝決定論的プログラムと、エージェントの自律読み取りとの性質差）をドキュメント化するに留める。

---

## 1. 概要

close/ 配下 Read/Grep/Glob deny のため、close 移動は「移動前にすべての検証を完結させ、移動後は内容を一切読まない」という特殊 6 ステップ手順を要求しており、監査・調査系タスク（過去 issue の参照、リンク検証等）と根本的に相性が悪い。加えて audit.sh 自身は close/ を `find` で走査しており、エージェントには許されない操作をスクリプトが行うという非対称がある。本 issue では、deny 設定の意図（誤操作防止）を保ったまま、この非対称・相性の悪さについて方針を明文化する。

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 保守者が close/ deny 設定の見直し余地を判断できる

- **As a** `.claude/settings.json` の close/ deny 設定を将来見直すかもしれない保守者
- **I want to** Read のみ許可する緩和案が推奨としてドキュメント化されている
- **So that** 誤編集防止（Edit/Write deny）の目的を損なわずに、監査・調査タスクとの相性を改善する選択肢が明確になる

**受け入れ基準**:

- `.agent-skill-chain/project/自己拡張ワークフロー.md` に、close/ deny 設定の推奨形態（Read のみ許可・Grep/Glob および Edit/Write は引き続き deny）が明記されている。
- 実際の `.claude/settings.json` は変更しない旨が明記されている（本リポの当該ファイルは非追跡のローカル設定であり、このタスクでは変更不能）。

#### ストーリー 2: audit.sh の find 走査との非対称の理由が明確になる

- **As a** close/ deny の非対称（audit.sh は find 可・エージェントは Read/Grep/Glob 不可）を疑問視する保守者・レビュワー
- **I want to** 「機械監査（決定論的プログラム）とエージェントの自律読み取りの性質差」という許容理由が明文化されている
- **So that** 非対称が「未解消の矛盾」ではなく「意図的な設計判断」であると判断できる

**受け入れ基準**:

- `自己拡張ワークフロー.md` に、audit.sh の find 走査と Read/Grep/Glob deny の非対称についての許容理由が明記されている。

### 2.2 非機能要件

- **セキュリティ**: close 済み issue の意図しない変更防止という既存目的を損なわない（Edit/Write は引き続き deny を推奨）。
- **互換性**: audit.sh の close/ 走査ロジックは変更しない（00 §4.2）。既存の close 移動時の相対リンク補正手順との整合を保つ。

## 3. 除外要件

- `.claude/settings.json` の実際の変更・deny 設定緩和の実装（本 issue はドキュメント上の推奨案の提示に留める）。
- audit.sh の走査ロジック変更。

## 4. 成功基準

- 00 §6 の成功基準（close/ 配下を対象とする監査・調査系タスクについて、既存の特殊 6 ステップ手順に依存する範囲・依存しない範囲が明文化されていること）を満たす。
