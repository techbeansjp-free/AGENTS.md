## 1. 概要

### 1.1 システム概要

`.agent-skill-chain/source/skills/agent/` 配下の `SKILL.md`（Claude Code の Skill エントリ）と `run_command.md`（command 実行の共通 I/F 正本）の重複・矛盾記述を解消し、あわせて source 内 5 ファイルに残る実在しない `REBUILD_PLAN` 参照を除去する、ドキュメント修正のみのタスク。コードの実行時挙動には影響しない。

### 1.2 用語集

| 用語             | 説明                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| SKILL.md（agent） | Claude Code の Skill ツールから読み込まれる `skills/agent/SKILL.md`。command 実行の入口。 |
| run_command.md   | command 実行の共通 I/F・委譲の形の正本。`skills/agent/run_command.md`。                  |
| REBUILD_PLAN     | source 内 5 ファイルで参照されているが実体ファイルが存在しない語。                        |
| 委譲の形         | run_command.md が定義する Task / Constraints / OutputSpec のブロック構造。                |
| workflow.db 本則 | 証跡記録の正本を workflow.db（write-workflow-log 経由）とする方針（RULES.md 等）。         |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 委譲の形の一本化

- **As a** 本フレームワークの利用者（orchestrator/サブエージェント）
- **I want to** 「委譲の形」の定義を run_command.md の 1 か所だけ参照したい
- **So that** SKILL.md と run_command.md のどちらに従うべきか迷わず、矛盾した記述に従ってしまうリスクを避けられる

**受け入れ基準**:

- SKILL.md に Task / Constraints / OutputSpec の重複定義が残っていない。
- SKILL.md が「委譲の形の定義は run_command.md に一本化する」旨を明記し、run_command.md への参照のみを持つ。

#### ストーリー 2: 実在しない REBUILD_PLAN 参照の解消

- **As a** 本フレームワークの利用者
- **I want to** 実在しない `REBUILD_PLAN` への参照を除去したい
- **So that** 存在しないファイルを探しに行く無駄や、旧ポリシーの誤適用を防げる

**受け入れ基準**:

- `grep -rn REBUILD_PLAN .agent-skill-chain/source/` の結果が 0 件になる。

#### ストーリー 3: 証跡記述の workflow.db 本則整合

- **As a** 本フレームワークの利用者
- **I want to** SKILL.md の証跡記述が workflow.db 本則ポリシー（RULES.md 等）と矛盾しない状態にしたい
- **So that** 「証跡は memo または 04_review に残す」という旧記述に従って workflow.db への記録（write-workflow-log）が省略されるリスクを防げる

**受け入れ基準**:

- SKILL.md の証跡記述が「本則は workflow.db（write-workflow-log を使用する）。memo は過渡的・例外運用のみ」という趣旨に修正されている。

### 2.2 BDD ユースケース

#### ユースケース 1: SKILL.md の重複定義・REBUILD_PLAN 参照の是正

**シナリオ 1: 委譲の形の一本化**

```gherkin
Feature: SKILL.md と run_command.md の重複定義解消
  Scenario: SKILL.md が委譲の形を独自定義せず run_command.md を参照する
    Given SKILL.md に Task/Constraints/OutputSpec の重複ブロックがある
    When SKILL.md を修正し run_command.md への参照のみに置き換える
    Then SKILL.md 内に Task/Constraints/OutputSpec の重複定義が存在しない
```

**シナリオ 2: REBUILD_PLAN 参照の解消**

```gherkin
Feature: REBUILD_PLAN 不在参照の解消
  Scenario: source 内の REBUILD_PLAN 参照が全て解消される
    Given grep -rn REBUILD_PLAN .agent-skill-chain/source/ で 5 ファイルがヒットする
    When 各ファイルの REBUILD_PLAN 参照を削除する
    Then grep -rn REBUILD_PLAN .agent-skill-chain/source/ の結果が 0 件になる
```

**シナリオ 3: 証跡記述の整合**

```gherkin
Feature: 証跡記述の workflow.db 本則整合
  Scenario: SKILL.md の証跡記述が RULES.md の本則と矛盾しない
    Given SKILL.md に「証跡は memo または 04_review に残す」という旧記述がある
    When 証跡記述を workflow.db 本則（write-workflow-log 使用）に合わせて修正する
    Then SKILL.md の証跡記述が RULES.md §証跡の本則と矛盾しない
```

### 2.3 ビジネスルール

- 「委譲の形」の定義は run_command.md の 1 か所に集約し、SKILL.md 側で重複定義しない。
- REBUILD_PLAN は実体を作成せず、参照側の文言を削除する方針で統一する（00 の期待効果 2 に基づく判断）。
- run_command.md 自体の構成変更は対象外（既存の「委譲定義は本 run_command に一本化する」という原則を維持する）。
