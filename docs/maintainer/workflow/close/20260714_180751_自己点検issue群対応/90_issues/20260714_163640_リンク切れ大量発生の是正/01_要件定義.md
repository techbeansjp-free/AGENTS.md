## 1. スコープ確定（実測ベース）

00 の「約 97〜1,150 箇所」は fable の広域計測値である。本 issue のスコープ（`.agent-skill-chain/source/`・`.agent-skill-chain/project/`・リポジトリルート直下 `*.md`・`docs/maintainer/*.md` 直下、**`close/` 配下は除外**）に限定し、**設計フェーズで実測**したところ、対象集合の総 Markdown リンク 443 件中 **リンク切れ 29 件**を検出した。うち 1 件は inline code（バッククォート）内の `](...)` 誤検出であり、**実修正対象は 28 件**である。

- 00 に列挙された既知の指摘箇所（`CORE.md`・`RULES.md`・`PHASES.md`・`GETTING_STARTED.md`・`CONTEXT_EFFICIENCY.md`・`spec/ai/03_AIレビュー基準.md`・`project/自己拡張ワークフロー.md`・`project/COVERAGE_EXCEPTIONS.md`・`project/README.md`・`skills/requirements/write-bdd/SKILL.md`）は**すべて実測 28 件の中に含まれる**ことを確認済み。
- 00 の行番号（`CORE.md:140`・`RULES.md:46` 等）は現ファイルからドリフトしていた（例: `RULES.md:46` → 実測 `:48`）。**行番号ドリフトの実在は 164050（行番号相互参照の脆弱性是正）の裏付けでもある**ため、本 issue では行番号ではなく**リンク文字列パターン**で特定・修正する。
- 配備物 `.claude/skills/...`（00 が挙げた `.claude/skills/review__review-code/SKILL.md:29`）は生成物であり**本スコープ外**（配備後の階層深度問題は §4 の方針で扱う）。

## 2. 機能要件

- FR-1: 実測 28 件のリンク切れを、リンク元ファイルから見て**実在解決する相対パス**へ是正する。
- FR-2: リンク切れを機械判定する**再利用可能な検査スクリプト**を新設する（`.agent-skill-chain/source/scripts/check-relative-links.sh`）。
- FR-3: 検査スクリプトを CI（`self-enforce.yml`）に**非ブロッキング**で組み込む。
- FR-4: 配備後に階層深度が変わり相対解決できない参照は、相対パスに依存しない案内文言へ変更する方針を定める（該当有無を調査し、無ければ「該当なし」を記録）。

## 3. 非機能要件

- 検査スクリプトは既存 `.agent-skill-chain/source/scripts/*.sh` と同じ bash 規約（`set -euo pipefail`・日本語コメント・終了コード契約）に従い、既存 CI の `bash -n` 構文チェック対象に含まれること。
- fenced code block（```）および inline code（`` ` ``）内の `](...)` を検査対象から除外し、誤検出を出さないこと（§1 の 1 件の誤検出を再現しないこと）。

## 4. 受け入れ基準（BDD）

### Scenario A: 既知の指摘箇所が解決可能になる
- **Given** 修正前は 28 件の相対リンクがリンク元から実在解決しない
- **When** 本 issue の修正を適用する
- **Then** `check-relative-links.sh` を本スコープに対して実行すると**リンク切れ 0 件**（exit 0）になる

### Scenario B: 検査スクリプトが誤検出しない
- **Given** `project/自己拡張ワークフロー.md` の本文に inline code として `](...)` の記述がある
- **When** 検査スクリプトを実行する
- **Then** その行はリンクとして検出されず、リンク切れに計上されない

### Scenario C: CI が非ブロッキングで検査する
- **Given** `self-enforce.yml` にリンク検査 step を追加する
- **When** PR/push で CI が走る
- **Then** リンク検査は `continue-on-error: true` で実行され、検出結果を出力しつつ CI を赤くしない

### Scenario D: 配備後階層変化の扱いが記録される
- **Given** 正本・project 配下に、配備後 `.claude/skills/` 等で相対解決不能になる参照が存在するか調査する
- **When** 調査を完了する
- **Then** 該当があれば相対パス非依存の案内へ変更、無ければ「該当なし」を 03 の実行記録に残す

## 5. 除外要件

- `close/` 配下のリンク切れ（別 issue 対応済み）。
- 配備物 `.claude/`・`.cursor/`・`.adapters/`（生成物）。
