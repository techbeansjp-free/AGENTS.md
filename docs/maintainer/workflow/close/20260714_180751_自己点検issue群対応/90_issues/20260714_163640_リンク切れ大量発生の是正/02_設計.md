## 2. 検査スクリプト設計（`check-relative-links.sh`）

### 2.1 配置・規約

- 配置: `.agent-skill-chain/source/scripts/check-relative-links.sh`（既存 `check-hook-drift.sh` と同列）。
- 言語: **bash**（既存 `scripts/*.sh` 規約に合わせる）。`set -euo pipefail`・日本語ヘッダコメント・終了コード契約を持つ。CI の「Shell syntax check（`bash -n .../scripts/*.sh`）」step に自動的に含まれる。

### 2.2 判定ロジック（擬似コード）

```text
scope_dirs = 引数（既定: .agent-skill-chain/source .agent-skill-chain/project）
scope_globs = 引数（既定: 上記 + ルート直下 *.md + docs/maintainer/*.md 直下）
除外: パスに "close/" を含むファイル / .claude/ .cursor/ .adapters/ node_modules/

broken = 0
for each md_file in 対象集合:
    in_fence = false
    line_no = 0
    while read line:
        line_no += 1
        # 1) fenced code block を除外（``` トグル）
        if line が /^\s*```/ にマッチ: in_fence = !in_fence; continue
        if in_fence: continue
        # 2) inline code を除去（誤検出防止の要）
        line = sed 's/`[^`]*`//g' 相当で ` ... ` を空へ
        # 3) Markdown リンクを抽出: ](target)
        for each target in ( grep -oE '\]\([^)]+\)' → 中身抽出 ):
            target = trim(target)
            if target 空: continue
            if target が ^(https?|mailto|tel): にマッチ: continue   # 外部
            if target が '#' 始まり: continue                        # 同一ファイル内アンカー
            if target が '{' か '}' を含む: continue                 # テンプレプレースホルダ
            filepart = target を '#' で分割した左側
            if filepart 空: continue
            resolved = realpath -m "$(dirname md_file)/$filepart"
            if [ ! -e "$resolved" ]:
                echo "$md_file:$line_no\t$target\t-> $resolved"
                broken += 1
            elif --check-anchors かつ target に '#anchor' がある:
                anchor = target の '#' 右側
                if slugify(見出し群 of resolved) に anchor が無い:
                    echo "$md_file:$line_no\t$target\t-> [anchor missing]"
                    broken += 1

exit (broken == 0 ? 0 : 1)
```

- **終了コード契約**: `0`=切れ 0 件 / `1`=切れ検出 / `2`=実行前提エラー（対象ディレクトリ不在等）。
- **inline code 除去（2 の要点）**: これにより `project/自己拡張ワークフロー.md` の本文中 `` `](...)` ``（markdown 構文の説明）を誤検出しない。§4 の実測でこの 1 件が唯一の誤検出だった。
- **`realpath -m`**: 実体が無くてもパス正規化する（`-m` は存在しないパスも解決）。存在判定は `-e` で別途行う。`..` を含む相対パスの正規化に用いる。
- **`--check-anchors`**: 既定 ON。`#anchor` 付きリンクについて、リンク先ファイルの見出しを GitHub 準拠でスラッグ化した集合に anchor が含まれるかを検査する（164050 のアンカー参照を検証するため）。スラッグ化規則は [164050/02_設計.md](../20260714_164050_行番号相互参照の脆弱性是正/02_設計.md#アンカースラッグ化規則) に定義。

### 2.3 CI 統合方針（非ブロッキング導入）

- `self-enforce.yml` に step を追加する:
  ```yaml
  - name: Relative link check (non-blocking)
    continue-on-error: true
    run: |
      bash .agent-skill-chain/source/scripts/check-relative-links.sh . || echo "[link-check] non-blocking: 切れ検出（段階導入中のため CI は赤くしない）"
  ```
- **非ブロッキングの根拠**: 兄弟 issue 163129 で「audit 非ブロッキングは 163203 解消待ちの暫定」と決めた前例に倣い、**新規検査は非ブロッキング導入から始める**（穏当）。加えて、`docs/maintainer/workflow/**` 配下の issue ドキュメント群など**本スコープ外に多数の相対リンクが存在**し、既定スコープ拡大時に想定外の赤化を招くリスクを避ける。
- **ブロッキング昇格の条件（申し送り）**: 本 issue 適用後に既定スコープの切れが安定して 0 件であることを CI で数回確認できたら、`continue-on-error` を外してブロッキング化する（別 issue で判断）。

### 3.1 配備後階層変化への対応（FR-4）

- 実測 28 件はいずれも**正本リポジトリ内で完結する相対参照**であり、`.claude/skills/` 等の配備後階層で解決不能になるものは本スコープの切れには含まれなかった。00 が挙げた `.claude/skills/review__review-code/SKILL.md:29` は**生成物**であり正本ではない。
- 方針: **正本（`source/skills/**`）のリンクが、配備後 `.claude/skills/**` にコピーされた時点で相対解決可能か**を実装フェーズで確認する。配備後に深度が変わり解決不能な参照が見つかった場合は、**相対パスをやめ「リポジトリルートからのパス案内文言」または「同梱ドキュメント名での誘導」へ変更**する（リンクとして張らず本文で誘導）。該当が無ければ 03 の実行記録に「該当なし」と明記する。
