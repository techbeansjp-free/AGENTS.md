## 1. 設計概要

### 1.1 設計方針

`.agent-skill-chain/project/自己拡張ワークフロー.md` §5 の本文・見出しから、未確定を示す文言（「暫定ドラフト」「ユーザーの明示確認を得ること」「確定後は本節を更新し注記を除去すること」）のみを除去し、リトライ間隔・回数・エスカレーション運用の具体値は一切変更しない。00_要求定義.md「## ユーザー判断（記録）」に既に記録済みの決定をそのまま本文へ反映する、純粋な文言整理として設計する。

### 1.2 設計原則（本プロジェクトで適用するもの）

- **明確な境界**: 「確定した運用ルール」と「未確定のドラフト」を紙面上で一意に区別できるようにする。本 issue の対応範囲は §5 のみとし、他節（§1〜§4、§6〜§8）や参照先の他ドキュメント（02_設計.md ADR-4 等、GitHub Issue 起票ゲート機能自体の設計文書）は変更しない。

### 2.2 調査結果（根拠）

`.agent-skill-chain/project/自己拡張ワークフロー.md:104-111` の現物を確認した結果、以下の 3 箇所に未確定を示す文言が含まれていた。

1. 見出し: `### 5. API 一時障害・認証失効時の運用（要人間確認・ドラフト）`
2. 本文冒頭の引用ブロック（02_設計.md ADR-4 が `inference_only` と明示した未確定事項である旨、実運用適用前のユーザー明示確認を要求する旨）
3. 各箇条書き末尾の「（ドラフト）」「（ドラフト値）」注記、および末尾の「上記はドラフトのため、確定後は本節を更新し、この確認要求の注記を除去すること」という一文

一方、具体値（リトライ 30 秒間隔・最大 3 回、リトライを尽くしても解消しない場合または認証失効と判定した場合のユーザーへのエスカレーション、ロックアウトも黙認通過もしない旨）は 00_要求定義.md の「## ユーザー判断（記録）」で正式採用が決定済みであり、変更しない。

#### ADR-1: ドラフト注記の除去方法

- **コンテキスト**: §5 は具体値そのものは維持しつつ、確定/未確定の記述状態のみを整理する必要がある。除去範囲を「未確定を示す文言のみ」に限定するか、それとも節全体を書き直すかの判断が必要。
- **検討した選択肢**:
  1. 未確定を示す文言（引用ブロック全体・各行末尾の「ドラフト」注記・末尾の除去指示文）のみをピンポイントで削除し、具体値の記述はそのまま残す。
  2. §5 を全面的に書き直し、確定版として新規に文章を再構成する。
- **決定**: 選択肢 1（ピンポイント除去）。
- **根拠**: 00_要求定義.md の「## ユーザー判断（記録）」および本対応方針の指示が「内容（具体値）自体は変更しない」ことを明示している（evidence_source: user_provided、出典は 00 の「ユーザー判断（記録）」節）。全面書き直しは既存の確定済み具体値の文言を意図せず変えるリスクを高めるため、最小差分の選択肢 1 を採用する。
- **帰結**: 見出しから「（要人間確認・ドラフト）」を除去し「（確定）」に置き換える。本文冒頭の引用ブロック（未確定事項・ユーザー確認要求）を削除する。各箇条書き末尾の「（ドラフト）」「（ドラフト値）」を削除する。末尾の「上記はドラフトのため、確定後は本節を更新し、この確認要求の注記を除去すること」の一文を削除する。
