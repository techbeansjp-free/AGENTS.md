## 3. 各指摘の対応方針（案 → 確定）

- **finding-1（即時対応・確定・反映済み）**: 02_設計.md §3.1/§3.2/§3.3 の未 commit 判定コマンドを `git status --porcelain --untracked-files=all --ignored=no`（`-uall`）へ修正し、未追跡ディレクトリを畳まず個別ファイルまで展開することを明記。§3.2 責務に「畳み込み対策」の重要注記を追加、§6.2 にネストされた未追跡 00〜04 ファイルの検知テスト観点を追記。**本 PR ブランチ内で反映済み**（commit `66e74d0`）。
- **finding-3（即時対応・確定・反映済み）**: 02_設計.md §3.2 判定条件のファイル名パターンを「closed set: `0[0-4]_*.md` および `90_issues.md`」として `90_issues.md` を独立パターンで明示併記。§6.2 に未 commit の `90_issues.md` 検知テスト観点を追記。**本 PR ブランチ内で反映済み**（commit `66e74d0`）。
- **finding-4（即時対応・確定・反映済み）**: 02_設計.md §3.5 パスフィルタ表セルの `type=feature\|bugfix\|...` を「`type` は `feature`, `bugfix`, `hotfix`, `release`, `chore` のいずれか」とカンマ区切りへ変更し Markdown 表破壊を是正。**本 PR ブランチ内で反映済み**（commit `66e74d0`）。
- **finding-2（起票・確定・後続 design-feature で対応）**: 未 push 判定（§3.4 `_wt_record_unpushed`）に、未 commit 判定（§3.3）と同じ記録対象パスの scope filter を適用する設計変更を検討・確定する。
  - **対応方針案（strategies）**: (a) §3.4 の `git rev-list @{u}..HEAD` / `origin/<branch>..HEAD` に対し、対象コミットが §3.2 の記録対象パス（`docs/maintainer/workflow/**` の `0[0-4]_*.md` / `90_issues.md`）を **1 つでも変更しているコミットのみ**を未 push 対象としてカウントする述語を追加する（例: `git rev-list @{u}..HEAD -- <走査ルート>`、または各コミットの `git show --name-only` に scope 述語適用）。(b) §2.1.1「未 push 判定」責務記述を「記録対象パスに触れる未 push コミットのみを対象とする」へ更新し、未 commit 判定との対称性を回復する。(c) SC-3（未 push 検知）受入基準のセマンティクスを「記録ファイルを変更した未 push コミットがある場合に検知」へ精緻化し、記録に無関係なコード変更のみの未 push は block しないことを明記する。(d) fetch 非依存・fail-safe SKIP の既存契約（ADR-2）は維持する。上記を後続の design-feature（02_設計 の §2.1.1・§3.4・§6.2 と 01 の SC-3）で整合させる。
- **finding-5（起票・確定・後続 design-feature で対応）**: ADR-3 の「作成時期でグランドファザリング」という主張と、R7 命名規則パスフィルタ（作成時期を判定しない）の乖離を解消する。
  - **対応方針案（strategies）**: 次の 2 案のいずれかを設計判断として選択し、00/01/02 全体を整合させる。**案 A（baseline 機構導入）**: 本 issue 完了時点のタイムスタンプ等を baseline として記録し、それ以降に作成された worktree のみ検知対象とする真のグランドファザリングを実装する（ADR-3 の主張を手段側に合わせる。ただし新規 state を持つコストと、ADR-3 が「baseline は新設しない」とした判断の再検討を伴う）。**案 B（要件を手段へ整合）**: ADR-3・§3.5・00/01 の記述を「作成時期ではなく R7 命名規則準拠パス配下の worktree を対象とする」へ改め、「新規 worktree のみ」という時期ベースの表現を撤回する（実装最小・現行手段を追認するが、非準拠パスの新規 worktree・準拠パスの既存 worktree の扱いを明記する必要）。後続 design-feature でトレードオフ（保護範囲・実装コスト・親 issue B/C との一貫性）を比較し、ADR-3 を確定し直したうえで §3.5 契約・SC・BDD を更新する。
