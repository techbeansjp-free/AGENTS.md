# 要件定義書: audit.sh の worktree 誤 SKIP と close 除外漏れの既存バグ修正

**プロジェクト名**: audit.sh worktree 誤 SKIP・close 除外漏れ修正
**作成日**: 2026 年 07 月 13 日
**最終更新**: 2026 年 07 月 13 日

> **重要**: このドキュメントは「生きているドキュメント」として扱い、実装内容と常に同期させる。

---

## 1. 概要

### 1.1 システム概要

`.agent-skill-chain/source/enforcement/ci/audit.sh` は、証跡・CONTRACT 違反を検出する監査スクリプトである。本 issue は同スクリプトに存在する 2 つの独立バグを是正する。バグ A は git worktree 環境での「非 git ツリー判定」の誤りによる監査の偽陰性（fail-open SKIP）、バグ B は close 済み issue に対する 2 チェックの除外漏れによる永久 FAIL である。

### 1.2 用語集

| 用語 | 説明 |
| ---- | ---- |
| worktree | `git worktree add` で作られる作業ツリー。ルートの `.git` はディレクトリではなく gitdir を指す「ファイル」になる |
| fail-open | 判定不能・環境差で「通過（SKIP）」側に倒れること。監査では偽陰性となり危険 |
| close 済み issue | 完了して `docs/maintainer/workflow/close/<issue>/` へ移動された issue |
| `-d .git` 判定 | `[[ ! -d "$PROJECT_ROOT/.git" ]]` による非 git ツリー判定。worktree で誤って真になる |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: worktree でも監査が実行される（バグ A）

- **As a** 監査を実行する保守者（および CI）
- **I want to** worktree 環境でも `-d .git` 系ガードを持つ全監査が SKIP されず実行されること
- **So that** worktree 上での作業でも偽陰性（fail-open）が発生せず、証跡違反が確実に検出される

**受け入れ基準**:

- worktree を再現したフィクスチャで、対象監査（#10・#18・#19・#25・#27、および同型バグの #28）が SKIP されず実行され、違反があれば FAIL する。
- 非 git ツリーでは従来どおり SKIP し、偽 FAIL を出さない。
- 通常（非 worktree）git リポジトリの既存挙動を変えない。

#### ストーリー 2: close 済み issue が永久 FAIL しない（バグ B）

- **As a** 監査を実行する保守者（および CI）
- **I want to** close 済み issue の 03/04 が「テスト観点未記載」「docs 更新要否未記載」で FAIL しないこと
- **So that** 完了済み issue が in-progress 前提の記載要求で永久に赤くならない

**受け入れ基準**:

- `docs/maintainer/workflow/close/` 配下の 03_実装計画.md は #4（テスト観点未記載）で FAIL しない。
- `docs/maintainer/workflow/close/` 配下の 04_review.md は #5（docs 更新要否未記載）で FAIL しない。
- close 外の in-progress issue では従来どおり #4/#5 が FAIL する（過剰除外なし）。

### 2.2 BDD ユースケース

#### ユースケース 1: worktree 環境での監査実行（バグ A）

**シナリオ 1: worktree で成果物変更＋証跡なしが FAIL する（#25 経路の実行確認）**

```gherkin
Feature: worktree 環境で -d .git 系監査が実行される
  Scenario: worktree で成果物変更があり workflow ログが無い
    Given git worktree として追加された作業ツリーがある（ルート .git はファイル）
    And docs 配下の *.md が直近コミットで変更され workflow.db に証跡ログが無い
    When audit.sh をその worktree ルートに対して実行する
    Then #25（メインが実作業を直接行った）等の -d .git 系監査が SKIP されず実行される
    And 証跡が無い違反として FAIL する
```

**シナリオ 2: 非 git ツリーでは従来どおり SKIP する（非回帰）**

```gherkin
Feature: 非 git ツリーでの SKIP を維持する
  Scenario: .git が存在しない最小ツリー
    Given .git を持たない最小 issue ツリー（tmp 隔離）
    When audit.sh をそのツリーに対して実行する
    Then -d .git 系監査は SKIP され FAIL を出さず exit 0 になる
```

#### ユースケース 2: close 済み issue の除外（バグ B）

**シナリオ 1: close 配下の 03/04 は除外される**

```gherkin
Feature: close 済み issue を #4/#5 から除外する
  Scenario: close 配下にテスト観点欠落 03 と docs 更新欠落 04 がある
    Given docs/maintainer/workflow/close/<issue>/03_実装計画.md にテスト観点セクションが無い
    And docs/maintainer/workflow/close/<issue>/04_review.md に docs 更新セクションが無い
    When audit.sh をそのツリーに対して実行する
    Then #4（テスト観点未記載）も #5（docs 更新要否未記載）も当該ファイルで FAIL しない
```

**シナリオ 2: close 外の in-progress issue は従来どおり FAIL する（過剰除外なし）**

```gherkin
Feature: close 外の正当な違反は維持する
  Scenario: in-progress issue にテスト観点欠落 03 と docs 更新欠落 04 がある
    Given docs/maintainer/workflow/<issue>/03_実装計画.md にテスト観点セクションが無い
    And docs/maintainer/workflow/<issue>/04_review.md に docs 更新セクションが無い
    When audit.sh をそのツリーに対して実行する
    Then #4 と #5 が当該ファイルで FAIL する
```

### 2.3 ビジネスルール

- 監査は fail-open してはならない（環境差で SKIP に倒すのは偽陰性）。
- close 済み issue には in-progress 前提の記載要求を課さない（既存 #29/#31/#32 と一貫）。
- 既存の正しく動く監査（#29/#31/#32）のロジックは変更しない。

## 3. 非機能要件

### 3.1 パフォーマンス要件

- 監査 1 回あたりの増分は git サブコマンド 1 回・文字列一致 1 回程度で無視できる。

### 3.2 セキュリティ要件

- 新たな外部入力を扱わない。既存の GIT_RANGE 検証・注入無害化に影響しない。

### 3.3 ユーザビリティ要件

- 修正後は対象監査の実行ログ（`[audit] checking ...`）が worktree でも出力され、実行が可視化される。

### 3.4 可用性要件

- 非 git ツリー・DB 非採用環境でエラー終了しない（既存契約の維持）。

---

## 4. 外部インターフェース要件

### 4.1 API 要件

- CLI: `bash audit.sh <PROJECT_ROOT> [GIT_RANGE]`（既存 I/F 不変）。

### 4.2 データ形式要件

- 出力は既存の `FAIL:` / `[audit] ...` / `Audit passed.` 形式を踏襲する。
