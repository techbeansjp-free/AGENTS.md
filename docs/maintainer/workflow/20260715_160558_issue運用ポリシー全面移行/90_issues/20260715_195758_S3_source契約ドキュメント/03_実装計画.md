## 1. 実装概要

### 1.1 実装方針

02_設計.md が確定した C1〜C7（§2.1.1）・K1〜K7（§5.1）を、**T4 群（C1〜C4・抽象原則の契約反映）**と**T6 群（C5〜C7・汎用雛形新設）**の 2 グループに分けて実装する。両群はファイルレベルの依存を持たない（02 §2.1.3・§6.5「循環参照は存在しない」）ため、実装順序として並行実施も可能だが、**文言確定の順序には実務上の向きがある**（02 §6.5「実装順序への示唆」）:

- T4 群内: C1（正本・全文説明を持つ）を先に確定し、C2・C3 はそれへの物理リンク（ADR-S3-1）を含むため C1 確定後に着手する。C4 は C1 に非依存（02 §2.1.3）のため独立して並行可。
- T6 群内: C5（雛形本体・コピー先ファイル名の起点）を先に確定し、C6・C7 はそれを参照する使い方ガイドのため C5 確定後に着手する。

### 1.2 実装順序（推奨・単一実装者が順に行う場合）

1. T4-1（C1 文言確定）
2. T4-2（C2 追記）／T4-3（C3 追記）／T4-4（C4 追記）— 3 つとも T4-1 完了後に着手可能（T4-4 は T4-1 と並行でもよい）
3. T6-1（C5 新設）
4. T6-2（C6 追記）／T6-3（C7 追記）— T6-1 完了後に着手可能
5. X-1（非破壊・grep 突合の最終確認）
6. X-2（verify-and-close 実施・実装後レビュー → 04_review.md 作成）

> **review-docs の位置づけ（順序の明確化）**: **review-docs（実装前ドキュメントレビュー）は本実装計画の着手前に実施済みの横断的必須ゲート**であり（[`02_設計.md`](./02_設計.md) §12・PHASES §レビュー成果物の配置ルール）、その証跡は **memo＋書記（write-workflow-log）** に残し **04_review.md は作らない**。上記ステップ 6 の 04_review.md 作成は、実装後レビュー＝ verify-and-close の責務である（両者を混同しない）。

T4 群（1〜2）と T6 群（3〜4）の間に実装順の制約はない（並行実施可）。上記は依存のない部分を便宜上直列に書いたものであり、複数実装者での並行実施を妨げない。
