## 2. fixture 設計（tmp 隔離・ADR-S1-4）

### 2.1 共通セットアップ（全シナリオ）

```bash
# 本番から切り離した使い捨てリポを作る（git archive で追跡ツリーのみ抽出）。
REPO_ROOT="$(git -C "<この worktree>" rev-parse --show-toplevel)"
TMP="$(mktemp -d)"
git -C "$REPO_ROOT" archive --format=tar HEAD | tar -x -C "$TMP"
AUDIT="$TMP/.agent-skill-chain/source/enforcement/ci/audit.sh"
# 使い捨てリポ化（#34/#35/#36・#33 が git ツリー/remote を要求するため）
git -C "$TMP" init -q
git -C "$TMP" add -A && git -C "$TMP" -c user.email=t@e -c user.name=t commit -qm init
git -C "$TMP" remote add origin https://github.com/example/repo.git   # ダミー・fetch しない
trap 'rm -rf "$TMP"' EXIT
```

### 2.2 #33 FAIL 再現 fixture（close 未移動・猶予超過）

```bash
ISSUE_DIR="$TMP/docs/maintainer/workflow/20260715_000000_s1test"   # basename prefix >= cutoff(20260712_000000)
```

### 2.3 #34/#35/#36 発火 fixture（回帰・モード非依存確認用）

同一の使い捨てリポに、モードに関わらず #34/#35/#36 が**発火する**条件を仕込む（発火の有無がモードで変わらないことを見る）。

```bash
# #34/#35 を発火させる: implement-feature ログあり ＋ 00 frontmatter の github_issue/branch が欠落
GATE_ISSUE="$TMP/docs/maintainer/workflow/20260715_010000_gatetest"
mkdir -p "$GATE_ISSUE"
printf -- '---\ndocument_id: "x"\n---\n# 00\n' > "$GATE_ISSUE/00_要求定義.md"   # github_issue も branch も無い
sqlite3 "$DB" "INSERT INTO workflow_log(command,issue_path,ts_utc,summary) VALUES('implement-feature','docs/maintainer/workflow/20260715_010000_gatetest','$OLD_TS','impl');"
# #34/#35 の grandfather cutoff: #34=20260712_000000 / #35=20260713_000000。basename 20260715 は両者以降＝評価対象。
# #34 は github.com remote を要求（2.1 で origin を設定済み）。
# #36 は PR_BODY を渡したときのみ・github_issue が実 Issue のときに評価。回帰確認では別途 github_issue 入り issue を用意:
PR_ISSUE="$TMP/docs/maintainer/workflow/20260715_020000_prtest"
mkdir -p "$PR_ISSUE"
printf -- '---\ndocument_id: "y"\ngithub_issue: "#999"\nbranch: "feature/x"\n---\n# 00\n' > "$PR_ISSUE/00_要求定義.md"
# 重要（#36 の diff-range 依存）: #36 は working tree 全走査ではなく `git diff --name-only $GIT_RANGE`
#   （既定 HEAD~1..HEAD・audit.sh:1263-1332/GIT_RANGE=82 行）で「差分内 issue」だけを対象にする。§2.1 の
#   init コミットは 1 コミットのみで、PR_ISSUE を未追跡のまま残すと HEAD~1 が存在せず diff が空になり、#36 は
#   どのモードでも発火しない（回帰アサートが空振り＝#36 の被覆が無効化される）。そこで PR_ISSUE を第 2 コミット
#   として確定し、既定 GIT_RANGE=HEAD~1..HEAD が prtest を差分として拾えるようにする。#33/#34/#35 は find/DB
#   走査で working tree を見るため、この追加コミットの影響を受けない（PR_ISSUE は github_issue/branch を
#   両方持つため #34/#35 は prtest では発火せず、発火元は gatetest のまま・モード非依存を保つ）。
git -C "$TMP" add "docs/maintainer/workflow/20260715_020000_prtest"
git -C "$TMP" -c user.email=t@e -c user.name=t commit -qm prissue
```

- #34 FAIL 行: `実装前 GitHub Issue 起票ゲート未通過 ... 20260715_010000_gatetest`。
- #35 FAIL 行: `ブランチ紐づけ未記録 ... 20260715_010000_gatetest`。
- #36: `PR_BODY` に Closes/Refs を含めず実行したとき、`20260715_020000_prtest`（github_issue=#999・第 2 コミットで差分内に載る）について FAIL 行 `PR 紐づけ未記録 ... 20260715_020000_prtest`。既定 `GIT_RANGE=HEAD~1..HEAD` が第 2 コミット（prtest 追加）を差分範囲に含むため #36 が実際に発火し、モード非依存の被覆が空振りにならない。

## BDD

> 記法は Gherkin。各シナリオは §2 の fixture を前提に、audit.sh を実行し **stderr の該当行文字列の有無**でアサートする（EXIT_CODE 総体では判定しない＝他チェックの副次 FAIL がテストを汚染しないため）。

### S1-BDD-1（G1 / CO-1）: resolve = github_native

```gherkin
Feature: 実効モード解決（単体）
  Scenario: github_native かつ github.com remote あり
    Given tmp 隔離リポで origin remote に github.com を含む
    And ISSUE_TRACKING_MODE=github_native
    When resolve 関数のみを抽出し source して呼ぶ
    Then 標準出力は "local_tracked" ではなく "github_native" である
```

抽出・実行（単体テストの実装形）:

```bash
# audit.sh から resolve 関数定義だけを抽出（トップレベル閉じ括弧まで）。全走査を起動しない。
awk '/^resolve_issue_tracking_mode\(\) \{/,/^\}/' "$AUDIT" > "$TMP/_resolve.sh"
run_resolve() { ( set -e; PROJECT_ROOT="$TMP"; source "$TMP/_resolve.sh"; resolve_issue_tracking_mode ); }
out="$(ISSUE_TRACKING_MODE=github_native run_resolve)"
[[ "$out" == "github_native" ]] || { echo "FAIL S1-BDD-1: got '$out'"; exit 1; }
```

### S1-BDD-2〜5（G2 / CO-2）: resolve fail-safe → local_tracked

```gherkin
Feature: 実効モード解決（fail-safe）
  Scenario Outline: 未設定・不明値・非GitHub・非git は local_tracked
    Given <条件>
    When resolve_issue_tracking_mode を呼ぶ
    Then 標準出力は "local_tracked" である
    And 例外・非ゼロ終了で停止しない
    Examples:
      | 条件 |
      | ISSUE_TRACKING_MODE 未設定（remote に github.com あり）        |  # S1-BDD-2
      | ISSUE_TRACKING_MODE=foo（不明値・remote に github.com あり）   |  # S1-BDD-3
      | ISSUE_TRACKING_MODE=github_native だが remote に github.com 無し|  # S1-BDD-4
      | ISSUE_TRACKING_MODE=github_native だが 非 git ツリー           |  # S1-BDD-5
```

```bash
# S1-BDD-2: 未設定
[[ "$(unset ISSUE_TRACKING_MODE; run_resolve)" == "local_tracked" ]] || { echo FAIL S1-BDD-2; exit 1; }
# S1-BDD-3: 不明値
[[ "$(ISSUE_TRACKING_MODE=foo run_resolve)" == "local_tracked" ]] || { echo FAIL S1-BDD-3; exit 1; }
# S1-BDD-4: github_native だが非 GitHub remote（別 tmp で remote を非 github に）
NG="$(mktemp -d)"; git -C "$NG" init -q; git -C "$NG" remote add origin https://gitlab.com/a/b.git
out="$( ISSUE_TRACKING_MODE=github_native PROJECT_ROOT="$NG"; \
        awk '/^resolve_issue_tracking_mode\(\) \{/,/^\}/' "$AUDIT" > "$NG/_r.sh"; \
        ( set -e; PROJECT_ROOT="$NG"; source "$NG/_r.sh"; ISSUE_TRACKING_MODE=github_native resolve_issue_tracking_mode ) )"
[[ "$out" == "local_tracked" ]] || { echo "FAIL S1-BDD-4: got '$out'"; exit 1; }
# S1-BDD-5: github_native だが非 git ツリー
NOGIT="$(mktemp -d)"; awk '/^resolve_issue_tracking_mode\(\) \{/,/^\}/' "$AUDIT" > "$NOGIT/_r.sh"
out="$( set -e; PROJECT_ROOT="$NOGIT"; source "$NOGIT/_r.sh"; ISSUE_TRACKING_MODE=github_native resolve_issue_tracking_mode )"
[[ "$out" == "local_tracked" ]] || { echo "FAIL S1-BDD-5: got '$out'"; exit 1; }
rm -rf "$NG" "$NOGIT"
```

### S1-BDD-8（G5 / CO-5・回帰）: #34/#35/#36 はモード非依存

```gherkin
Feature: 他チェックの回帰保証
  Scenario: モード env を変えても #34/#35/#36 の FAIL 有無が一致
    Given §2.2＋§2.3 の fixture（#34/#35/#36 が発火する条件）
    When ISSUE_TRACKING_MODE を github_native / 未設定 / local_tracked / foo と変えて audit.sh を実行する
    Then #34（"実装前 GitHub Issue 起票ゲート未通過"）の該当行の有無が全モードで一致する
    And #35（"ブランチ紐づけ未記録"）の有無が全モードで一致する
    And #36（"PR 紐づけ未記録"）の有無が全モードで一致する（PR_BODY に Closes/Refs を含めず実行）
```

```bash
sig() {  # 3 チェックの発火有無を "0/1 0/1 0/1" に写像
  local mode="$1" e
  e="$(env ISSUE_TRACKING_MODE="$mode" PR_BODY="PR without issue ref" bash "$AUDIT" "$TMP" 2>&1 1>/dev/null || true)"
  printf '%s %s %s' \
    "$(grep -q '実装前 GitHub Issue 起票ゲート未通過' <<<"$e" && echo 1 || echo 0)" \
    "$(grep -q 'ブランチ紐づけ未記録' <<<"$e" && echo 1 || echo 0)" \
    "$(grep -q 'PR 紐づけ未記録' <<<"$e" && echo 1 || echo 0)"
}
base="$(sig local_tracked)"
for m in github_native "" foo; do
  [[ "$(sig "$m")" == "$base" ]] || { echo "FAIL S1-BDD-8: #34/#35/#36 differ for mode='$m' (got '$(sig "$m")' vs '$base')"; exit 1; }
done
```

> 注: 空文字モード（未設定と同義に扱う想定）は `env ISSUE_TRACKING_MODE=""` で渡す。`resolve` は `!= github_native` 判定のため空文字も local_tracked に落ち、#34/#35/#36 は remote/PR_BODY/差分範囲だけに依存するため全モードで発火が一致するはず。#36 は PR_BODY に有効な `Closes #n` を含めないため、§2.3 で **第 2 コミットとして確定した** `20260715_020000_prtest`（github_issue=#999）が既定 `GIT_RANGE=HEAD~1..HEAD` の差分に載り、発火する（コミットしない場合は差分が空で #36 が全モード不発＝空振りになるため、§2.3 の第 2 コミットが本シナリオ成立の前提）。`grep -q` は最初の一致で終了し出力を出さないため、`&& echo 1 || echo 0` で発火有無を 0/1 に写像できる。

### S1-BDD-9（VO-1）: resolve は副作用なし

```gherkin
Feature: Query 純粋性
  Scenario: resolve 実行で DB/FS が変化しない
    Given fixture の workflow.db と作業ツリー
    When resolve_issue_tracking_mode を複数モードで繰り返し呼ぶ
    Then workflow.db のハッシュが不変であり git status に差分が出ない
```

```bash
for m in github_native local_tracked foo ""; do ISSUE_TRACKING_MODE="$m" run_resolve >/dev/null; done
[[ "$(sha256sum "$DB")" == "$before" ]] || { echo "FAIL S1-BDD-9: DB changed"; exit 1; }
[[ "$(git -C "$TMP" status --porcelain)" == "$st_before" ]] || { echo "FAIL S1-BDD-9: worktree changed"; exit 1; }
```

### S1-BDD-10（VO-3）: 変更スコープ静的検査

```gherkin

  Scenario: diff は resolve 追加＋#33 冒頭ガードのみ
    Given feature ブランチと main
    When git diff main -- audit.sh を取る
    Then 追加ハンクは resolve_issue_tracking_mode 定義と check_close_move_pending 冒頭ガードのみ
    And #34/#35/#36/#3/#9/#29/#31/#32 の既存関数本体の行に変更（削除/改変）が無い
```

```bash

grep -qE '^\+resolve_issue_tracking_mode\(\) \{' <<<"$d" || { echo "FAIL S1-BDD-10: resolve not added"; exit 1; }
```
