## 1. 概要

### 1.1 システム概要

本サブ issue は、verify 証跡（verify-and-close / 04_review）の報告様式に関する**汎用原理**をコア（`.agents/`）へ昇格する。具体的には、(i) 仕様反映と (ii) 実経路検証を**別項目として分離記載する義務**と、**make check 緑（単体・モック代用）を (ii) 実経路検証の代替にしない誤導防止**の 2 点を明文化する。既存正本（verify(ii)・REVIEW_DUAL_LENS）と重複させず、リンクで整合させる（1 ファイル 1 責務）。

### 1.2 用語集

| 用語 | 説明 |
| ---- | ---- |
| (i) 仕様反映 | 変更内容のシステム仕様書本体への反映の有無（不要／反映済み）。verify 証跡で独立項目として記載する。汎用形は「仕様反映の有無を分離記載」とし、as-built の向き明示は含めない（system-graph 固有のためコア除外）。 |
| (ii) 実経路検証 | production・実 I/O 経路で変更が実際に動くことの実行検証（実行済み／未実行／該当なし）。verify(ii) の正本は `implement-feature.md §verify-実経路検証`。 |
| 分離記載 | (i) と (ii) を**別項目**として記し、混同・合算しないこと。一方の達成をもう一方の達成と読み替えない（誤導防止）。 |
| 緑 ≠ 実経路 | make check 等のテスト緑（単体・FakeDriver・モック代用）を (ii) 実経路検証の代替として報告してはならないという原理。 |
| 射程の見極め | 検証手段が「実経路」を確かめているのか「モック代用」に過ぎないのかを判別し、(ii) の達成可否を正しく判定すること。 |
| follow-up 起票 | 実 I/O が主題で実経路検証手段が無い場合、(ii)=未実行 とし追跡可能 issue を起票すること。その定義・正本は順 1「取りこぼし防止と既出確認のコア昇格」（S1, de775cbb-02e9-4b22-88bd-16b8fb15b8dc）で**昇格予定**の no-drop/follow-up 起票のコア原理に委譲・整合する（本サブでは重複定義せず参照のみ。S1 未昇格でも本サブの主題は独立成立）。 |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: (i)/(ii) を別項目として分離記載する義務のコア化

- **As a** verify-and-close を実行するエージェント（消費者ランタイム共通）
- **I want to** verify 証跡で (i) 仕様反映と (ii) 実経路検証を別項目として分離記載する義務がコアに定義されている状態
- **So that** 一方の達成を他方の達成と読み替える誤導を構造的に防げる

**受け入れ基準**:

- コアの該当箇所（具体配置は設計で決定）に「verify 証跡では (i) 仕様反映（不要／反映済み）と (ii) 実経路検証（実行済み／未実行／該当なし）を**別項目として分離記載**する」義務が明文化されている。
- (i) と (ii) を混同・合算しないこと（誤導防止）が明記されている。
- (i) は「仕様反映の有無を分離記載」する汎用形に留め、as-built の向き明示（system-graph 固有）はコアに含めない。

#### ストーリー 2: make check 緑 ≠ 実経路検証の誤導防止のコア化

- **As a** verify-and-close を実行するエージェント
- **I want to** テスト緑を (ii) の代替にしないこと・検証手段の射程を見極めることがコアに定義されている状態
- **So that** 「make check が緑＝実経路も検証済み」という偽装・誤導を防げる

**受け入れ基準**:

- コアに「テスト緑（make check 等の単体・モック代用）を (ii) 実経路検証の代替として報告しない」誤導防止が明文化されている。
- コアに「検証手段の射程（実経路 vs モック代用）を見極める」観点が明文化されている。
- 実 I/O が主題で実経路検証手段が無い場合、(ii)=未実行 とし follow-up を起票する（順 1「取りこぼし防止と既出確認のコア昇格」S1, de775cbb-02e9-4b22-88bd-16b8fb15b8dc で**昇格予定**の no-drop/follow-up 起票コア原理へ委譲・整合。本サブでは重複定義しない）ことが定義されている。

#### ストーリー 3: 重複なしのリンク整合（1 ファイル 1 責務）

- **As a** コア（`.agents/`）の保守者
- **I want to** (i)/(ii) 分離義務・誤導防止が既存正本と重複せずリンク委譲で整合している状態
- **So that** 定義の二重化による不整合・陳腐化を避けられる

**受け入れ基準**:

- 追記は欠落要素（分離記載義務・緑≠実経路の誤導防止）に限定され、既存の verify(ii)・`REVIEW_DUAL_LENS.md §3` の定義を 2 か所に重複させていない。
- 既存正本へはリンクで委譲している。
- 具体配置（`implement-feature.md §verify-実経路検証` 拡張か `REVIEW_DUAL_LENS.md §3` 整合か）は設計フェーズで一意に決定する（本 issue では決め打ちしない）。

### 2.2 BDD ユースケース

#### ユースケース 1: verify 証跡の分離記載義務

**シナリオ 1: (i) と (ii) を別項目で記載する**

```gherkin
Feature: verify 証跡の (i)/(ii) 分離記載義務
  Scenario: 仕様反映と実経路検証を別項目として記す
    Given verify-and-close を実行し 04_review を作成しようとしている
    When verify 証跡を記載する
    Then (i) 仕様反映（不要／反映済み）と (ii) 実経路検証（実行済み／未実行／該当なし）が別項目として分離記載される
    And (i) の達成を (ii) の達成と読み替えない（混同・合算しない）
```

**シナリオ 2: 分離記載が欠けた証跡は未完了とみなす**

```gherkin
Feature: verify 証跡の (i)/(ii) 分離記載義務
  Scenario: (i)/(ii) を合算した証跡を弾く
    Given (i) と (ii) を 1 項目に合算した verify 証跡が提出された
    When コアの verify 証跡要件に照合する
    Then 当該証跡は分離記載義務を満たさず未完了と判定できる
```

#### ユースケース 2: make check 緑 ≠ 実経路検証の誤導防止

**シナリオ 1: 緑を実経路検証の代替にしない**

```gherkin
Feature: make check 緑を実経路検証の代替にしない
  Scenario: 単体テスト緑を (ii) の代替として報告しようとする
    Given make check が緑だが実 I/O 経路の実行検証は行っていない
    When (ii) 実経路検証の結果を記載する
    Then make check 緑を (ii) の代替として報告してはならない
    And (ii) は「未実行」として記載される
```

**シナリオ 2: 実経路手段が無い場合の follow-up 起票**

```gherkin
Feature: 実経路検証手段が無い場合の follow-up
  Scenario: 実 I/O が主題だが実経路結合テストが無い
    Given 実 I/O が主題の feature で実経路検証手段が存在しない
    When verify 証跡を作成する
    Then (ii)=未実行 として記載される
    And follow-up issue を起票する（取りこぼし防止のコア原理に委譲）
```

**シナリオ 3: 検証手段の射程を見極める**

```gherkin
Feature: 検証手段の射程の見極め
  Scenario: モック代用か実経路かを判別する
    Given ある検証手段で対象を確認した
    When (ii) の達成可否を判定する
    Then 検証手段が実経路かモック代用かを見極めたうえで達成可否を判定する
```

### 2.3 ビジネスルール

- (i) と (ii) は**常に別項目**として記載し、混同・合算しない（誤導防止）。
- make check 等のテスト緑は (ii) 実経路検証の代替にしない。
- 実 I/O が主題で実経路検証手段が無い場合、(ii)=未実行 とし follow-up を起票する（順 1「取りこぼし防止と既出確認のコア昇格」S1 で**昇格予定**の no-drop/follow-up 起票コア原理へ委譲・整合し、本サブでは重複定義しない）。
- 追記は欠落要素に限定し、既存正本（verify(ii)・REVIEW_DUAL_LENS §3）の定義を重複させない（1 ファイル 1 責務）。
- as-built の向き明示（system-graph 固有）はコアに昇格しない。(i) は汎用形「仕様反映の有無を分離記載」に留める。
