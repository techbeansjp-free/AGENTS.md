# 要求定義書: ADR-6 に親 GitHub Issue 不在時の独立起票デフォルトを明記

**作成日**: 2026年07月15日
**最終更新**: 2026年07月15日

## 1. 目的・背景

### 1.1 目的（必須）

`.agent-skill-chain/project/自己拡張ワークフロー.md` の GitHub Issue 起票ゲート節にある ADR-6（「適用対象はトップレベル issue のみ。90_issues/ 配下のサブ issue は対象外。親 Issue のチェックリスト/コメントに集約する」）に、**親ワークフロー自体に対応するトップレベル GitHub Issue が存在しない場合の扱い**を追記し、将来同じ判断で迷わないようにする。

### 1.2 背景

- ADR-6 は「1 つの PR への複数レビュー指摘をサブ issue 化する」場面（PR 指摘対応）では合理的（親 issue に集約することで issue 乱立を防げる）。
- しかし「横断的な監査で見つかった、親 GitHub Issue が存在しない多数の独立した問題」というケース（例: 本リポジトリの `docs/maintainer/workflow/20260714_180751_自己点検issue群対応/`。fable による自己調査から生まれた 35 件の指摘で、そもそもこの親ワークフロー自体に対応する GitHub Issue が存在しない）には ADR-6 の文言だけでは適用できないギャップがあった。
- 実際、このワークフローの 35 件のうち、GitHub Issue 起票ゲート強化前に対応された 28 件は issue を一切作らず、強化後に対応された 4 件（#101/#102/#103/#108）は集約先（親 Issue）が無いため独立起票した、という経緯がある。この既存運用は今回追記する内容と整合する。
- ユーザーとの会話で「親 GitHub Issue が存在しない場合は独立起票をデフォルトとする」という結論が確定した。

### 1.3 期待される効果（必須: 1 件以上）

- **効果 1**: ADR-6 に親 GitHub Issue 不在時の扱いが明記され、横断的監査など親 Issue が存在しないケースでサブ issue の起票要否を都度判断せずに済む。

## 2. 機能要件

### 2.1 既存機能の維持

ADR-6 の本則（トップレベル issue のみ対象、親 Issue が存在する場合はサブ issue を集約する）自体は変更しない。

### 2.2 新規機能要件

`.agent-skill-chain/project/自己拡張ワークフロー.md` の ADR-6 該当文に、「親ワークフロー自体に対応するトップレベル GitHub Issue が存在しない場合は、集約先が無いため本ゲート（#34）の通常手順（デフォルト起票）に従い独立して起票してよい」という趣旨を追記する。

## 5. 除外要件

- ADR-6 以外の GitHub Issue 起票ゲート手順（#34 本体・declined 記録形式等）の変更は行わない。
- audit.sh 等の機械強制ロジックの変更は行わない（本タスクはドキュメント追記のみ）。

## 6. 成功基準（必須: 1 件以上）

- ADR-6 該当箇所に、親 GitHub Issue 不在時は独立起票をデフォルトとする旨が既存の文言・構造を壊さない形で追記されていること。
- 追記内容が実際の運用実績（28 件 issue なし・後発 4 件独立起票）と矛盾しないこと。
