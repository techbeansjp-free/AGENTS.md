## テスト観点

- 正例（docs 層）: システム仕様書（`docs/` かつ非 `workflow/`）が日時プレフィックス付き作業用 issue フォルダ（runtime/workflow 両系統）を参照 → FAIL。
- 負例（docs 層・誤検知しない）: close 参照・汎用ディレクトリ参照・`workflow.db` 参照・日時なしパス → 非 FAIL。
- 走査対象外（docs 層）: `docs/maintainer/workflow/` 配下の issue ドキュメント → 非 FAIL。
- SKIP（docs 層）: `docs/` 不在 → 非 FAIL（不発動）。
- 正例（code 層・追加スコープ）: ソースコードのコメントが日時プレフィックス付き作業用 issue フォルダ（非 .md ファイル・フォルダのみの参照を含む）を参照 → 検出（exit 1）。
- 負例（code 層・誤検知しない）: close 参照・日時プレフィックスなしの汎用参照 → 非検出（exit 0）。
- 非回帰: 既存 #1〜#32（および他 issue の #33〜#36）・既存 CODE_COMMENT_RULES §2/§3・既存 #26 の章節番号/追跡番号/ドキュメント名判定・既存テストが不変。

## 単体テスト

- `pat_issuefolder` を check-comment-refs.sh 経由で tmp 隔離ディレクトリに対し実行し、`<file>:<line>` 出力・終了コードを assert する（test-check-comment-refs.sh に追加）。
