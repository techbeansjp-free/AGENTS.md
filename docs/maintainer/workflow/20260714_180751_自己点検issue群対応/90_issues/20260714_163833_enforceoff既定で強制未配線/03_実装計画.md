## 1. 実装概要

### 1.1 実装方針（必須）

02_設計の柱 A（挙動）・柱 B（記述）に沿って、(1) `setup.sh`・`src/agents-md.ts` の init 経路に「新規配備（`ASC_MODE=new`）時のみ enforce on 相当を自動実行」する分岐を追加し、(2) `SETUP.md`・`enforcement/README.md` を新挙動・各層強制力区分に整合させ、(3) 回帰テストを追加する。既存の `enforceOn()` 安全策・`enforce on/off/status` 契約・allowlist は変更しない。本リポ `.claude/settings.json` への実適用は行わない（ADR-3・手動）。

### 1.2 実装順序（必須: 1 件以上）

1. **タスク 1**: `src/agents-md.ts` init 経路に新規配備時の `enforceOn()` 呼び出しを追加（柱 A・TS 側）。

3. **タスク 3**: `SETUP.md` §enforcement を「新規既定 on・opt-out 可」へ更新し復旧手順を相互参照（柱 B）。

5. **タスク 5**: 回帰テスト追加（新規=配線／既存・自己適用=不変／無効 JSON=見送り／idempotent／bash-TS パリティ）。
6. **タスク 6**: verify-and-close（04_review 作成・書記記録）。

> **スコープ確定の判断点（02 §5）**: タスク 1・2・5（柱 A）を本 issue に含めるか、別コード issue に切り出すかは進行役が確定する。柱 A を本 issue から外す場合、タスク 3・4 の記述は「新規は自動で on」ではなく**その時点の実挙動**を正確に書くこと（未実装の挙動を既定と書かない）。

## 2. タスク分解

### 2.1 タスク 1: TS init 経路の既定 on 配線（柱 A）

#### 2.1.1 概要（必須）

`src/agents-md.ts` の `init`/`upgrade` case（1220 行付近）で、新規配備相当（配備マーカー不在＝`checkPackageManifest` が `new`）のときのみ、既存 `enforceOn()`（1041 行付近）を呼んで `.claude/settings.json` に配線をマージする。`own`/`match`/abort では呼ばない。

#### 2.1.2 実装内容（必須: 1 件以上）

- init 実行時に `checkPackageManifest(projectRoot, ...)` の結果を参照し、`kind === "new"` のときのみ `enforceOn(projectRoot, ...)` を呼ぶ。
- `enforceOn()` 自体は無変更（無効 JSON 中止・`.bak`・idempotent・nonce ローテートを流用）。
- ログ出力: 新規配備で既定 on 配線した旨、または既存/自己適用で見送った旨を 1 行出す。

#### 2.1.3 テスト観点（必須）

- 新規（`new`）: 配線が入る。既存（`match`）・自己適用（`own`）: 入らない。
- 無効 JSON 新規: 配線せず警告のみ・ファイル破壊なし。
- 既に on の環境で init 再実行: 二重配線・二重 `.bak` を作らない（idempotent）。

### 2.2 タスク 2: setup.sh の new 分岐配線（柱 A・パリティ）

#### 2.2.1 概要（必須）

`setup.sh`（`ASC_MODE` は 58 行で取得済み）の new 経路で、TS 側 `enforceOn()` と同一の配線を行う。実装は「`agents-md enforce on` 相当の bash ロジックを呼ぶ」か「node CLI の enforce on を内部起動する」かのいずれか実現可能な方式を採り、TS 版とパリティを保つ。

#### 2.2.2 実装内容（必須: 1 件以上）

- `[[ "$ASC_MODE" == "new" ]]` 分岐でのみ配線処理を実行（`own`/`match` は現状どおり touch しない）。
- 無効 JSON 検出時は配線せず警告のみ（既存 enforce の安全策と同一挙動）。
- 配線処理ロジックが TS 版と乖離しないよう、共通の判定/文言を単一定義から導く（既存の package-manifest.sh パリティ方式に倣う）。

#### 2.2.3 テスト観点（必須）

- `mktemp -d` 隔離環境で `setup.sh` 新規実行 → `enforce status` が `on`。
- 本リポ（`own`）で `setup.sh` → settings.json 自動変更なし。

### 2.3 タスク 3: SETUP.md 記述更新（柱 B）

#### 2.3.1 概要（必須）

§「enforcement の opt-in（既定 off）」を「enforcement（新規セットアップ既定 on・opt-out 可）」相当へ改め、既定挙動・opt-out・ロックアウト復旧の発見性を上げる。

#### 2.3.2 実装内容（必須: 1 件以上）

- 見出しと本文の「既定 off / opt-in」表現を「新規配備（`ASC_MODE=new`）は既定 on・`enforce off` で opt-out」へ更新。
- 「既定 install では書き込まない（off）」の一文を「新規配備では既定で配線する（on）。既存再配備（`match`）・自己適用（`own`）では touch しない」へ更新。
- §enforcement 冒頭から §ロックアウトからの復旧（`!enforce off`）への相互参照（既定 on によりロックアウト発火確率が上がるため発見性を高める）。
- settings.json 保持・上書き契約表（124 行付近）の `init/upgrade` 列を「新規=配線／既存=touch しない」に整合。
- 経緯（かつて off だった 等）は書かない（現在の事実のみ）。

#### 2.3.3 テスト観点（必須）

- 差分レビューで AC-5（新規既定 on・opt-out・復旧手順）を満たすことを確認。既存の enforce on/off/status 表・安全策の記述が壊れていないこと。

### 2.4 タスク 4: enforcement/README.md 記述更新（柱 B）

4 層表・ツール別強制力マトリクス・絶対強制節・§矯正するもの §現状の実装について に、各強制点の強制力区分（新規既定 on の runtime／opt-in／advisory／CI のみ）と有効条件を明記する（02 §2.3 の区分表を正本反映）。

## テスト観点

柱 A（挙動）の回帰は `test/test-enforce-default-on.sh`（新規追加）と `test/e2e-install-uninstall.sh`（シナリオ R6 更新）で担保する。柱 B（記述）の充足は差分レビューで確認する。観点は次のとおり。

- **S1 新規=配線（AC-1）**: `.agent-skill-chain/` 未配備の隔離環境へ `init`（内部で `ASC_MODE=new`）すると `enforce status` が `on` を返し、`.claude/settings.json` に `__agentsMdEnforce` マーカー付き hook が入る。
- **S2 既存=不変（AC-2）**: 新規 init 済み環境で `enforce off` した後に `upgrade`（`ASC_MODE=match`）しても off のまま。
- **S3 自己適用=不変（AC-3）**: パッケージ複製コピー自身への setup（`ASC_MODE=own`）では `.claude/settings.json` が自動生成・自動配線されない。
- **S4 無効 JSON=安全見送り（AC-4）**: 無効 JSON の settings.json を置いた新規環境で init しても全体は完走し、無効 JSON は変更されず、他配備物（hooks 等）は生成される。
- **S5 冪等性**: 既定 on 済み環境へさらに明示 `enforce on` しても PreToolUse の managed エントリは 1 件のまま（多重配線・多重 `.bak` を作らない）。
- **bash↔TS パリティ**: TS 側 init は `runSetup()` で setup.sh へ完全委譲するため、既定 on 配線は setup.sh 1 箇所（`enforce_default_on_if_possible`）に集約され、bash/TS の分岐で挙動がドリフトしない（構造的パリティ・二重実装なし）。
- **依存欠如時の継続**: node 不在・CLI 未生成・sqlite3 不在など依存が欠ける環境では、既定 on 配線を警告のみで見送り、`init`/`setup` 全体は中断しない（安全側フォールバック）。テストランナーは依存欠如時に SKIP して継続する。
- **記述（AC-5/AC-6/AC-7）**: SETUP.md・enforcement/README.md・README.md・`docs/04_機能設計/CLI/README.md` の差分レビューで、新規既定 on・opt-out・ロックアウト復旧・各層/各ツールの強制力区分・有効条件・本リポ settings.json スコープ外の記載を確認する。
