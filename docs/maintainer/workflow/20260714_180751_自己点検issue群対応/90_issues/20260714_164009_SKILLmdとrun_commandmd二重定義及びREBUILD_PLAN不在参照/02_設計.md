## 1. 設計概要

### 1.1 設計方針

本タスクはコードを持たないドキュメント修正であり、[01_設計原則](../../../../../../.agent-skill-chain/source/spec/01_設計原則.md) のうち**単一責務・明確な境界**を適用する。「委譲の形」の定義という 1 つの責務を run_command.md 1 か所に集約し、SKILL.md はそれへの参照のみを持つ薄いエントリとする。

### 1.2 設計原則（本プロジェクトで適用するもの）

- **単一責務**: 「委譲の形」（Task/Constraints/OutputSpec）の定義という責務は run_command.md のみが持つ。SKILL.md は command 実行の入口として run_command.md・commands/{name}.md を指し示す責務のみを持つ。
- **明確な境界**: SKILL.md＝Skill エントリ（Claude Code から読み込まれる薄い入口）、run_command.md＝委譲の形・実行要領の正本、という境界を明示する。

### 2.5 横断設計判断（ADR）

#### ADR-1: REBUILD_PLAN 参照は削除する（実体作成しない）

- **コンテキスト**: source 内 5 ファイルが `REBUILD_PLAN` を参照しているが、実体ファイルが存在しない。00_要求定義.md の期待効果 2 は「削除、または実体作成のいずれかの方針が決定・実施される」としている。
- **検討した選択肢**:
  1. `REBUILD_PLAN.md` の実体を新規作成する。
  2. 参照側の文言から `REBUILD_PLAN` 言及を削除する。
- **決定**: 選択肢 2（削除）を採用する。
- **根拠**: 5 箇所の参照はいずれも「参照元の例示（親 00、03、REBUILD_PLAN 等）」という**任意の追加参照候補の列挙**であり、`REBUILD_PLAN` を必須の入力・成果物として要求している箇所はない（`grep` で確認した全 6 行の文脈確認による `existing_code` 根拠）。実体を新規作成すると、存在理由が説明できない空ファイルを増やすことになり、[01_設計原則 §UNIX 哲学](../../../../../../.agent-skill-chain/source/spec/01_設計原則.md) のシンプルさに反する。
- **帰結**: 対象 5 ファイルから `REBUILD_PLAN` 言及を削除し、「親 00、03 等」「親 00/01 等」のように一般化した表現に置き換える。

#### ADR-2: SKILL.md の「委譲の形」は run_command.md への参照のみに縮小する

- **コンテキスト**: run_command.md 冒頭は「委譲定義は本 run_command に一本化する。他に委譲の呼び方を定義するファイルは設けない」と明記しているが、SKILL.md にも同名の「委譲の形（共通）」節が Task/Constraints/OutputSpec 込みで独立に存在し、内容が一部食い違っていた（例: 証跡記述）。
- **検討した選択肢**:
  1. SKILL.md 側の記述を run_command.md に合わせて全文同期する。
  2. SKILL.md 側の重複ブロックを削除し、run_command.md への参照 1 行に置き換える。
- **決定**: 選択肢 2（参照への置き換え）を採用する。
- **根拠**: 選択肢 1 は将来の更新時に再び乖離するリスクを残す。run_command.md 自身が「一本化する」と明記しているため、SKILL.md 側は薄い入口として参照のみを持つ構成が保守性（[01_設計原則 §単一責務](../../../../../../.agent-skill-chain/source/spec/01_設計原則.md)）に合致する（`existing_code` 根拠: run_command.md 冒頭の既存宣言）。
- **帰結**: SKILL.md の「実行要領」節・「参照」節は維持しつつ、「委譲の形（共通）」節を run_command.md への参照 1 行に縮小する。
