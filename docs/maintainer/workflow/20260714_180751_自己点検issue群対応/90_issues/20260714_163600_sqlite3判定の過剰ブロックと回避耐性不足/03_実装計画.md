# 実装計画書: R6 の sqlite3 判定が部分文字列 regex で過剰ブロック・回避耐性不足

**プロジェクト名**: R6 の sqlite3 判定が部分文字列 regex で過剰ブロック・回避耐性不足
**作成日**: 2026年07月14日
**最終更新**: 2026年07月14日

---

## 1. 実装概要

### 1.1 実装方針（必須）

`PreToolUse.sh` に `is_sqlite3_invocation()` 関数を新規追加し、既存の 2 箇所の `[[ "$CMD" =~ sqlite3 ]]`（scribe 先行判定・全ロール共通判定）をこの関数呼び出しに置き換える。既存の単体テスト（`test/test-pretooluse-hook.sh`）に、過剰ブロック解消・回避耐性向上それぞれの新規シナリオ（UC12）を追加する。

### 1.2 実装順序（必須: 1 件以上）

1. `is_sqlite3_invocation()` を `PreToolUse.sh` に追加する（タスク 1）。
2. 2 箇所の R6 判定を新関数呼び出しに置き換える（タスク 1 に含める）。
3. `test/test-pretooluse-hook.sh` に UC12（過剰ブロック解消・回避耐性向上）を追加する（タスク 2）。
4. 既存テスト（`test/test-pretooluse-hook.sh`、`test/test-c4-bypass-resistance.sh`、`test/run-all.sh`）を実行し回帰がないことを確認する（タスク 3）。

## 2. タスク分解

### 2.1 タスク 1: `is_sqlite3_invocation` 関数追加と R6 判定の置き換え

#### 2.1.1 概要（必須）

コマンド名としての sqlite3 起動のみを検知する判定関数を追加し、既存 2 箇所の部分文字列一致判定を置き換える。

#### 2.1.2 実装内容（必須: 1 件以上）

- `.agent-skill-chain/source/enforcement/claude/PreToolUse.sh` の `json_get` 関数定義の直後・`parse_input` 定義の直前に `is_sqlite3_invocation()` を追加。
  - `CMD` を `;`/`&`/`|`/改行で分割し、各セグメントの先頭トークン（`VAR=val` 代入を読み飛ばし、パス付き実行はベースネーム比較）が `sqlite3` と厳密一致するかを判定。
  - `python`/`python3`/`python2` が先頭コマンドかつ `-c` を含み、`import sqlite3` または `from sqlite3 import` パターンを含む場合も検知。
- scribe 先行判定（285-292 行目付近）の `if [[ "$CMD" =~ sqlite3 ]]; then` を `if is_sqlite3_invocation "$CMD"; then` に置き換え。
- 全ロール共通判定（旧 337-341 行目付近、R6 コメントブロック）の `if [[ "$CMD" =~ sqlite3 ]]; then` を同様に置き換え。
- block 時のメッセージ文言は変更しない（既存の日英併記文言を維持）。

#### 2.1.3 テスト観点（必須）

##### 単体（本タスクの具体ケース・必須 1 件以上）

- `grep sqlite3 doc.md` → block されない（過剰ブロック解消）。
- `grep -rn "sqlite3" README.md` → block されない。
- `sqlite3 x.db "select 1"` → block される（既存検知の維持）。
- `/usr/bin/sqlite3 x.db` → block される（パス付き実行の検知）。
- `echo hi; sqlite3 x.db` → block される（セミコロン区切り後の検知）。
- `python3 -c "import sqlite3 as s; s.connect(1)"` → block される（回避耐性強化）。
- `python3 -c "from sqlite3 import connect"` → block される。
- `python3 script_using_sqlite3.py` → block されない（-c を伴わない実行はスコープ外）。
- `.agent-skill-chain/source/scripts/write-workflow-log.sh requirement-discovery x`（単独実行）→ block されない（既存動作の非劣化）。

##### 結合/API（本タスクの具体ケース・該当時は必須 1 件以上）

- `test/test-pretooluse-hook.sh` フル実行（jq 有/無の両系統）で UC1〜UC11 が全て非劣化で PASS すること。
- `test/test-c4-bypass-resistance.sh` フル実行で R6 sqlite3 回帰テストが PASS すること。
- `test/run-all.sh` フル実行で全体に新規 FAIL が発生しないこと。

##### E2E/受け入れ（本タスクの具体ケース・未達時は理由記載）

- 実際の Claude Code hooks 実行環境での確認は、ローカルに実行環境が無いため未実施（04_review.md に理由を記載）。

##### バリデーション（該当する場合の具体ケース）

- `bash -n .agent-skill-chain/source/enforcement/claude/PreToolUse.sh` で構文エラーが無いこと。

## 5. リスク管理

### 5.1 実装リスク

- **リスク**: コマンド名判定を厳密化しすぎて、既存の sqlite3 直接実行検知（既存テスト UC2/UC5/C-4 回帰）を取りこぼす可能性（00 §7.1）。
  - **対策**: 既存テスト（UC1〜UC11・C-4 回帰）を変更せずそのまま実行し、全て非劣化で PASS することを確認済み（§2.1.4）。

- **リスク**: セグメント分割・python -c 検知の簡易実装が、想定外のコマンド文字列（引用符のネスト等）で誤判定する可能性。
  - **対策**: 完全なシェル構文解析は行わず、既存の R4（複合シェル判定）と同水準の簡易判定に留める設計とした（02_設計 ADR-2）。既知の限界は 00 §7.1・01_要件定義.md §5 に明記済み。
