## 2. タスク分解

### 2.1 タスク 1: PHASE_COMMAND_MAP.md の再構造化

#### 2.1.1 概要

「本表にない command の起動は禁止」の文言にスコープ（フェーズ遷移コマンドの起動経路としての唯一性）を明示し、既存の 2 つの inline 注記（補助手順・必須ゲート）を統合した「## 横断的必須ゲート」節を新設する。

#### 2.1.2 実装内容

- Phase → Command 一覧の直後にあった 2 件の長い note（補助手順の注記、必須ゲートとしての位置づけの注記）を削除し、代わりに新設の「## 横断的必須ゲート」節へ統合する。
- Rule 節の禁止事項 1 行目「本表が phase → command の唯一の経路である。本表にない command の起動は禁止。」を、「本表は phase → command（フェーズ遷移コマンドの起動経路）の唯一の経路である。フェーズ判定後に本表にない command を選ぶことは禁止。」に修正し、新設節への参照を括弧内に残す。
- 既存のリンク先（skills/agent/run_command.md、enforcement/README.md、PHASES.md）はすべて維持する。

#### 2.1.3 テスト観点

##### 単体（本タスクの具体ケース）

- 「本表にない command の起動は禁止」という文を読んだとき、適用範囲（フェーズ遷移コマンドの起動経路）が同一文内で分かること。
- 「## 横断的必須ゲート」節を読んだとき、review-docs が表に行を持たない理由と、それが「省略可・任意」を意味しないことの両方が 1 箇所で分かること。

##### 結合/API

- 該当なし（コード実装が無いため）。

##### E2E/受け入れ

- 00_要求定義.md §6 成功基準「PHASE_COMMAND_MAP と PHASES の記述を読んだ第三者が、review-docs の位置づけを矛盾なく説明できる」を、04_review でのレビュー担当者による読み合わせで確認する（自動テスト化不可のため人手レビューで代替）。

##### バリデーション

- Markdown リンク（`[...](...)`）・見出しアンカー（`#横断的必須ゲート` 等）が実在解決すること（grep で相互参照を確認）。

#### 2.1.4 単体テスト仕様（BDD）

```gherkin
Feature: PHASE_COMMAND_MAP.md の禁止事項スコープ明示
  Scenario: 禁止事項の文を読む
    Given PHASE_COMMAND_MAP.md の禁止事項に「唯一の経路」の文がある
    When 読者がその文を読む
    Then 「フェーズ遷移コマンドの起動経路」という適用範囲が同一文内に明示されている
```

**確認方法（コード実装を伴わないため、テストコードの代わりに grep による構造確認を行う）**:

```bash
# Given: PHASE_COMMAND_MAP.md が編集済みであること
# When: 禁止事項の行を抽出する
grep -n "唯一の経路" .agent-skill-chain/source/workflow/PHASE_COMMAND_MAP.md
# Then: 「フェーズ遷移コマンドの起動経路」という語がヒットし、スコープが明示されていることを確認する
grep -n "フェーズ遷移コマンドの起動経路" .agent-skill-chain/source/workflow/PHASE_COMMAND_MAP.md
```

### 2.2 タスク 2: PHASES.md の重複記述の簡素化

#### 2.2.1 概要

§レビュー成果物の配置ルール の review-docs 該当箇所（現行 1 行だが長文）を、PHASE_COMMAND_MAP.md §横断的必須ゲート への参照中心の短い記述に置き換える。GitHub Issue 起票ゲートの記述は変更しない。

#### 2.2.2 実装内容

- 該当箇所の長文説明（「review-docs は補助手順（auxiliary）であり…」で始まる 1 行）を、PHASE_COMMAND_MAP.md の新設節への参照 1 文に短縮する。
- 「ただし review-docs は…必須ゲートであり…」の但し書き文言も、新設節に集約し、PHASES.md 側では重複させない。

#### 2.2.3 テスト観点

##### 単体（本タスクの具体ケース）

- PHASES.md の当該箇所を読んだとき、review-docs の必須性・分類の詳細説明が PHASE_COMMAND_MAP.md 側にのみ存在し、PHASES.md 側では参照のみになっていること。

##### 結合/API・E2E/受け入れ・バリデーション

- 該当なし／タスク 1 と合わせて 04_review で確認。

#### 2.2.4 単体テスト仕様（BDD）

```gherkin

    When 保守者が review-docs に関する記述を読む
    Then PHASE_COMMAND_MAP.md §横断的必須ゲート への参照が含まれている
    And PHASE_COMMAND_MAP.md と同一の長文説明が重複していない
```

#### 2.2.5 依存関係

## 5. リスク管理

### 5.1 実装リスク

- **リスク**: 表本体（Phase → Command 一覧の行）に review-docs の行を誤って追加してしまう。
  - **対策**: 00_要求定義.md の方針どおり、表本体には触れず、新設節・禁止事項の文言修正のみに変更範囲を限定する。
- **リスク**: PHASES.md 側を簡素化しすぎて、GitHub Issue 起票ゲートの記述（別項目）を誤って削除する。
  - **対策**: 差分を review-docs 関連の 1 項目のみに限定し、GitHub Issue 起票ゲートの記述は変更対象から明示的に除外する。
