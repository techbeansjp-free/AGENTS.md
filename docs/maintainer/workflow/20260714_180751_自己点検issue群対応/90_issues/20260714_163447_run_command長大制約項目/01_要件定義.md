## 1. 概要

### 1.1 システム概要

`.agent-skill-chain/source/skills/agent/run_command.md` は、メイン（orchestrator）がサブエージェントへ command 実行を委譲するときの共通 I/F（委譲パケットの Task / Constraints / OutputSpec）を定める正本ファイルである。Constraints は委譲のたびにサブエージェントへ渡す・または転記させる箇条書きであり、その 1 行 1 行が全ての委譲の都度コンテキストコストとして課金される。

### 1.2 用語集

| 用語               | 説明                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| 委譲パケット       | run_command.md の「委譲の形」に従い、メインがサブへ渡す Task/Constraints/OutputSpec の一式 |
| Constraints        | 委譲パケット内で「守るルール」を列挙するセクション（run_command.md §委譲の形） |
| 凝縮版             | AGENT_CONDUCT.md 第 3 部の、サブエージェント向けに短縮した行動規範ブロック   |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 長大な Constraints 項目の分割

- **As a** command を委譲されるサブエージェント
- **I want to** Constraints の各項目が「何を守るべきか」を簡潔に読める
- **So that** 詳細な理由・過去の観測事例を読まされることによるコンテキスト消費を避けられる

**受け入れ基準**:

- run_command.md §Constraints の「委譲タスク内の長時間コマンドはフォアグラウンド実行」項目が、禁止事項・対象範囲・フォールバック条件を本文に残したまま、理由・観測事例の詳細を外部ファイルへの参照に置き換えている。
- 分割後も、禁止事項自体（何が・いつ・なぜ対象外か）の強制力が本文だけで判読できる（外部ファイルを読まなくても「何をしてはいけないか」が分かる）。

#### ストーリー 2: AGENT_CONDUCT 凝縮版の転記義務の見直し

- **As a** command を委譲するオーケストレーター
- **I want to** 毎回の委譲パケットに AGENT_CONDUCT.md 第 3 部の全文を逐語転記する必要がない
- **So that** 委譲パケットのサイズを削減し、サブエージェントのコンテキスト消費を抑えられる

**受け入れ基準**:

- run_command.md §Constraints の「委譲時の行動規範」項目が、全文転記を必須とせず、参照リンクの記載で足りる仕様に変わっている。
- リンク先を読めないランタイム向けのフォールバック（従来どおりの全文転記）が明記されている。

### 2.2 BDD ユースケース

#### ユースケース 1: サブエージェントが委譲パケットを受け取る

**シナリオ 1: バックグラウンド実行禁止の要点が本文だけで分かる**

```gherkin
Feature: Constraints 項目の簡潔化
  Scenario: サブエージェントが背景ファイルを読まずに禁止事項を理解できる
    Given run_command.md の該当 Constraints 項目のみを読んだ
    When 「run_in_background: true 相当の長時間バックグラウンド実行」を行おうとする
    Then 禁止されていること・対象範囲・フォールバック条件が本文だけで判断できる
```

**シナリオ 2: 詳細を知りたい場合は外部ファイルを参照できる**

```gherkin
Feature: Constraints 項目の簡潔化
  Scenario: 理由や過去の観測事例を確認したい
    Given run_command.md の該当項目に外部ファイルへの参照リンクがある
    When サブエージェントがリンク先を開く
    Then 理由・観測事例・既存項目との関係の詳細が BACKGROUND_EXEC_RATIONALE.md に記載されている
```

#### ユースケース 2: 行動規範転記の省略

**シナリオ 1: 参照リンクのみで委譲パケットを構成できる**

```gherkin
Feature: AGENT_CONDUCT 凝縮版の転記義務見直し
  Scenario: オーケストレーターが委譲パケットを組み立てる
    Given run_command.md の該当項目が更新されている
    When Constraints 末尾に AGENT_CONDUCT.md 第 3 部への参照リンクのみを記載する
    Then 全文転記なしで委譲パケットの Constraints セクションが完成する
```

### 2.3 ビジネスルール

- 禁止事項自体（何が禁止か・対象範囲・フォールバック条件）は本文に残し続けること（要求定義 §7.1 リスク対策）。
- 「なぜ禁止か」の理由・過去の観測事例のみを外部ファイルへ切り出すこと。
- 164009 issue で一本化済みの「委譲の形」定義（Task/Constraints/OutputSpec の共通 I/F）には触れない。
