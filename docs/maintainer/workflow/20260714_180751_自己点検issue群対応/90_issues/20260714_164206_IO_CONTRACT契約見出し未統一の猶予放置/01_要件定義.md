## 1. 概要

### 1.1 システム概要

`.agent-skill-chain/source/IO_CONTRACT.md` の「運用」節を修正し、「新規は必須・既存は追って揃える」という猶予の**対象範囲・期限・監査基準**を明文化する。あわせて `.agent-skill-chain/source/skills/` 配下の既存 skill 全件（15 件）の契約見出し（Purpose/Inputs/Process/Outputs/Done/Forbidden）対応状況を棚卸しし、`skills/agent/SKILL.md` にのみ契約見出しを追加する、ドキュメント修正のみのタスク。コードの実行時挙動には影響しない。

### 1.2 用語集

| 用語 | 説明 |
| ---- | ---- |
| 契約見出し | IO_CONTRACT.md が定義する skill 用の 6 見出し（Purpose/Inputs/Process/Outputs/Done/Forbidden）。 |
| 猶予対象 | 契約見出しに未対応のまま、次回改修時まで見出し未整備が許容される既存 skill。 |
| 棚卸し | 既存 skill 全件について契約見出しの有無・対応状況を確認し一覧化すること。 |
| run_command（agent/SKILL.md） | Claude Code の Skill エントリ。command 実行の入口。委譲の形の詳細は run_command.md に一本化されている。 |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 猶予の対象範囲・期限・監査基準の明文化

- **As a** 本フレームワークの監査担当（review-code/verify-and-close 実行者）
- **I want to** IO_CONTRACT.md の「追って揃える」の対象・期限・判定基準を明確に読み取りたい
- **So that** どの skill が猶予対象で、いつまでに・どう判定すれば FAIL/PASS になるかを一貫して判断できる

**受け入れ基準**:

- IO_CONTRACT.md の運用節に、猶予の対象範囲（表で列挙された skill のみ）が明記されている。
- 猶予期限（次回実質改修時、の定義を含む）が明記されている。
- 機械チェック時の FAIL/PASS 判定条件が箇条書きで明記されている。

#### ストーリー 2: 既存 skill の契約見出し対応状況の棚卸し

- **As a** 本フレームワークの保守担当
- **I want to** 既存 skill 15 件それぞれの契約見出し対応状況（対応済/未対応）を一覧で確認したい
- **So that** 今後の改修時にどの skill を優先して見出しへ揃えるべきか判断できる

**受け入れ基準**:

- IO_CONTRACT.md に既存 skill 全件（`skills/agent/SKILL.md` を含む）の対応状況一覧表が存在する。
- 表の各行が「対応済」または「未対応（猶予対象）」のいずれかで判定されている。

#### ストーリー 3: `skills/agent/SKILL.md` の契約見出し追加

- **As a** run_command（agent/SKILL.md）を読む利用者
- **I want to** SKILL.md 自体が契約見出し（Purpose/Inputs/Process/Outputs/Done/Forbidden）に従っている状態を見たい
- **So that** 「必須」と明記された契約が、優先対象として名指しされたファイルで実際に守られていることを確認できる

**受け入れ基準**:

- `skills/agent/SKILL.md` に 6 見出し（`## Purpose`/`## Inputs`/`## Process`/`## Outputs`/`## Done`/`## Forbidden`）が存在する。
- 既存の「委譲の形（共通）」「実行要領」「参照」の内容・文言は変更せず、契約見出しの下に再配置する形で追加する（委譲定義の内容自体には触れない）。

### 2.2 BDD ユースケース

#### ユースケース 1: IO_CONTRACT.md の運用節是正・棚卸し・SKILL.md 是正

**シナリオ 1: 猶予の対象・期限・監査基準の明文化**

```gherkin
Feature: IO_CONTRACT.md の猶予基準明文化
  Scenario: 「必須」と「追って揃える」の関係が明確になる
    Given IO_CONTRACT.md の運用節が「既存は追って本契約の見出しに揃える」とのみ記載し対象・期限・基準が無い
    When 運用節を対象範囲・期限・監査基準の明記に修正する
    Then 運用節に「対象範囲は下表の skill のみ」「期限は次回実質改修時」「機械チェックの FAIL/PASS 条件」が明記されている
```

**シナリオ 2: 既存 skill 棚卸し表の作成**

```gherkin
Feature: 既存 skill の契約見出し対応状況棚卸し
  Scenario: 15 件全ての skill の対応状況が一覧化される
    Given .agent-skill-chain/source/skills/ 配下に SKILL.md が 15 件存在し、対応状況が未整理
    When 各 SKILL.md を grep で確認し対応状況表を作成する
    Then IO_CONTRACT.md に 15 行（全 skill 分）の対応状況表が存在する
```

**シナリオ 3: `skills/agent/SKILL.md` の契約見出し追加**

```gherkin
Feature: skills/agent/SKILL.md の契約見出し追加
  Scenario: 契約見出しが追加され既存内容は保持される
    Given skills/agent/SKILL.md に契約見出しが存在しない
    When 6 見出しを追加し既存内容をその下に再配置する
    Then grep で 6 見出し（## Purpose/## Inputs/## Process/## Outputs/## Done/## Forbidden）が全て検出される
    And 既存の「委譲の形（共通）」「実行要領」の文言がそのまま残っている
```

### 2.3 ビジネスルール

- 猶予対象は「本節策定時点（2026-07-14）で契約見出しに未対応だった既存 skill」に限定し、新規追加 skill には適用しない。
- `skills/agent/SKILL.md` 以外の既存 skill（棚卸し表で「未対応（猶予対象）」の 11 件）は本 issue のスコープ外とし、見出し追加は行わない（00 §5 除外要件）。
