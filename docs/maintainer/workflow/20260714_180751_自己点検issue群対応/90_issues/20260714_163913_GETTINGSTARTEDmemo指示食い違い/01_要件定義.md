## 1. 概要

### 1.1 システム概要

`.agent-skill-chain/source/GETTING_STARTED.md` の「1 issue を回す流れ」（ステップ 2）は、初心者が最初に読む標準手順を示す 1 ページ要約である。現状はステップ 2 の文言が「証跡を memo に書く。」と明記しており、write-workflow-log（workflow.db・本則）への言及がステップ 5（サブがやること）に留まっている。これにより、新規参入者が最初に学ぶ標準経路が非推奨の memo 運用に見えてしまう。本要件は、ステップ 2（および関連するステップ 4）の文言を、write-workflow-log を主軸とした案内に更新することを定める。

### 1.2 用語集

| 用語               | 説明                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| write-workflow-log | 実施内容・変更ファイル・完了判定を workflow.db（SQLite）に記録する capability。scribe/CONTRACT.md・ledger/schema.md の本則。 |
| memo               | workflow.db を採用しないプロジェクトの過渡的・例外運用としてのみ許容される証跡ファイル（非推奨・将来廃止予定）。      |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 初心者が GETTING_STARTED を読んで標準経路を誤解しない

- **As a** 本フレームワークを初めて使うサブエージェント（実装者）
- **I want to** GETTING_STARTED の「1 issue を回す流れ」を読んだときに、証跡記録の標準経路が write-workflow-log（workflow.db）であることを理解したい
- **So that** scribe/CONTRACT.md・ledger/schema.md が非推奨と定める memo のみ運用を、標準経路と誤解して採用しないようにする

**受け入れ基準**:

- GETTING_STARTED.md の「1 issue を回す流れ」ステップ 2 が、write-workflow-log（workflow.db・本則）を証跡記録の主経路として明記している。
- memo 運用（過渡的・例外運用）への言及は削除せず、scribe/CONTRACT.md と同じトーンで「workflow.db を採用しない場合のみ」の位置づけとして維持されている。

### 2.2 BDD ユースケース

#### ユースケース 1: GETTING_STARTED の「1 issue を回す流れ」を読む

**シナリオ 1: ステップ 2 を読んだ読者が証跡記録の標準経路を正しく理解する**

```gherkin
Feature: GETTING_STARTED の証跡運用案内
  Scenario: 初心者がステップ2を読む
    Given 初心者が .agent-skill-chain/source/GETTING_STARTED.md の「1 issue を回す流れ」を開いている
    When ステップ2（requirement-discovery 実行後の証跡記録の記述）を読む
    Then write-workflow-log（workflow.db・本則）が証跡記録の主経路として案内されている
    And memo は workflow.db を採用しない場合の過渡的・例外運用としてのみ言及されている
```

**シナリオ 2: scribe/CONTRACT.md・ledger/schema.md との整合**

```gherkin
Feature: 非推奨方針との整合
  Scenario: GETTING_STARTED と scribe/CONTRACT.md の記述を比較する
    Given scribe/CONTRACT.md が「memo のみ運用は非推奨・移行モード・将来廃止予定」と明記している
    When GETTING_STARTED.md の「1 issue を回す流れ」を読む
    Then 両ドキュメントの記述が矛盾しない
```

### 2.3 ビジネスルール

- scribe/CONTRACT.md・ledger/schema.md の既存定義（memo は非推奨・過渡的運用）は変更しない。GETTING_STARTED.md 側の案内表現のみを整合させる。
