# 設計書: CI audit の非ブロッキング化問題（最終保証層の形骸化）

**作成日**: 2026年07月14日

---

## 1. 責務

- **enforcement/README.md**: 全ツール共通の一般原則（「CI audit＝最後の砦」）の正本。**本リポジトリ固有の暫定例外の詳細は記載しない**（重複させない）。参照のみで自己拡張ワークフロー.md へ委ねる。
- **自己拡張ワークフロー.md**: 本リポジトリ固有の具体事情（暫定例外の理由・解消条件・申し送り）の正本。既存の「### 3. 本リポ CI（self-enforce.yml）への PR_BODY 配線」節は #36（PR紐づけ）に限定した記載のため、audit step 全体の非ブロッキングという、より広い論点を扱う新設節を追加する。
- **self-enforce.yml**: 実装（コード）。機能変更はしないが、コメントの説明を軽微に補強し、正本ドキュメント側の記載と平仄を合わせる。

## 2. ADR（重要判断）

### ADR-1: ブロッキング化ではなく文書整合を採る

- **決定**: 今回は `continue-on-error: true` を除去する（真のブロッキング化）のではなく、非ブロッキング運用を正本ドキュメントに「意図的な暫定状態」として明記する。
- **根拠**: `20260714_163203_workflowDB非追跡によるCI検知SKIP問題` が未解決であり、この状態でブロッキング化すると DB 系チェックの恒常的 SKIP/FAIL が顕在化し、既存 PR フローを不必要に止める可能性が高い（00 §7.1 リスク）。
- **evidence_source**: inference_only（リポジトリ内の既存ドキュメント記載・issue 00 の記述に基づく推論。外部一次情報の追加取得は行っていない）。本判断は 00 の要求定義時点でユーザーの委任（推奨方針の採用可否をエージェント裁量とする旨の指示）に基づく。
- **代替案・却下理由**: 「即時ブロッキング化」は 163203 未解決のため既存 PR フローを止めるリスクが高く却下。「audit step 自体の削除」は最終防波堤を完全に失うため却下（00 の目的に反する）。

### ADR-2: audit.sh 本体・self-enforce.yml の実行ロジックは変更しない

- **決定**: `audit.sh` のチェックロジック、および `self-enforce.yml` の `continue-on-error: true` ／呼び出しコマンドは変更しない。
- **根拠**: 00 §5 除外要件（audit.sh のチェックロジック変更は対象外）、および対応方針（ADR-1）と整合させるため機能変更は不要。

### ADR-3: self-enforce.yml のコメントは補強するが外部参照は追加しない

- **決定**: step 7 のコメントに、非ブロッキング運用が意図的な暫定状態であり workflow.db の CI 追跡状況解消後に再判断する旨を一文追記する。ただし `.github/workflows` 配下のコメント外部参照禁止（`check-comment-refs.sh`）に抵触しないよう、ドキュメント名・章節番号・issue パス・追跡番号は書かない。
- **根拠**: `check-comment-refs.sh` は `.yml` も走査対象であり、既存のコメント外部参照禁止 blocking step（#8）を壊さないため。

## 4. テスト観点

- ドキュメント変更のみ（コード実行系ではない）ため、単体テストは無い。検証は以下で行う。
  - `bash -n` 相当の YAML 構文チェック（GitHub Actions の YAML はシェルではないため、`python3 -c "import yaml"` 等での構文検証、または `actionlint` 相当が無い環境では diff レビューで代替）。
  - `.agent-skill-chain/source/enforcement/ci/audit.sh` に変更が無いことの diff 確認。
  - `.agent-skill-chain/source/enforcement/ci/check-comment-refs.sh .github/workflows` を実際に実行し、追記したコメントが blocking 検知に引っかからないことを確認する。
