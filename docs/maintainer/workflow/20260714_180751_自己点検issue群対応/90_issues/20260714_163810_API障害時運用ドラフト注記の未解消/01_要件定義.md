# 要件定義書: API 一時障害・認証失効時の運用の確定

**プロジェクト名**: API 障害時運用ドラフト注記の未解消
**作成日**: 2026 年 07 月 14 日
**最終更新**: 2026 年 07 月 14 日

> **用語**: [.agent-skill-chain/source/CONCEPTS.md §用語規約](../../../../../../.agent-skill-chain/source/CONCEPTS.md#用語規約) を参照。

---

## 1. 概要

### 1.1 システム概要

`.agent-skill-chain/project/自己拡張ワークフロー.md` §5「API 一時障害・認証失効時の運用」は、リトライ間隔・回数（30 秒間隔・最大 3 回）とエスカレーション運用を「暫定ドラフト」「実運用に適用する前に必ずユーザーの明示確認を得ること」と明記したまま残っていた。00_要求定義.md の「## ユーザー判断（記録）」節に記録済みのとおり、進行役経由でユーザーが当該具体値を正式に本採用する決定を下している。本 issue はこの決定を反映し、§5 本文から未確定を示す注記を除去し、確定ルールとして記述し直す。

### 1.2 用語集

| 用語 | 説明 |
| --- | --- |
| 一時障害 | `gh issue create` 等がネットワークエラーまたは 5xx 相当で失敗する状態。 |
| 認証失効 | `gh issue create` 等が 401/403 相当で失敗する状態。 |
| ドラフト注記 | §5 に残っていた「暫定ドラフトである」「ユーザーの明示確認を得ること」等の未確定を示す文言。 |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 確定済みルールとしての明記

- **As a** 本フレームワークの運用者・エージェント
- **I want to** §5 のリトライ・エスカレーション運用が確定済みルールであると一意に判断できること
- **So that** 実運用時にこの節へ従ってよいか迷わずに判断できる

**受け入れ基準**:

- §5 の見出しから「（要人間確認・ドラフト）」が除去され、確定を反映した見出しになっている。
- §5 本文から「暫定ドラフトである」「実運用に適用する前に、必ずユーザーの明示確認を得ること」「確定後は本節を更新し、この確認要求の注記を除去すること」に相当する未確定文言が除去されている。
- リトライ 30 秒間隔・最大 3 回、リトライを尽くしても解消しない場合のユーザーエスカレーションという具体値・運用内容自体は変更されていない。

### 2.2 BDD ユースケース

#### ユースケース 1: §5 の確定反映

**シナリオ 1: ドラフト注記が残っていないことの確認**

```gherkin
Feature: API 一時障害・認証失効時の運用の確定
  Scenario: §5 からドラフト注記が除去されている
    Given .agent-skill-chain/project/自己拡張ワークフロー.md §5 を確認する
    When 「暫定ドラフト」「明示確認を得ること」等の文言を検索する
    Then §5 の範囲内に該当する文言が存在しない
```

**シナリオ 2: 具体値が維持されていることの確認**

```gherkin
Feature: API 一時障害・認証失効時の運用の確定
  Scenario: リトライ・エスカレーション運用の具体値が維持されている
    Given .agent-skill-chain/project/自己拡張ワークフロー.md §5 を確認する
    When リトライ間隔・回数・エスカレーション条件を確認する
    Then 「30 秒間隔・最大 3 回」「リトライを尽くしても解消しない場合はユーザーへエスカレーション」の記載が維持されている
```

### 2.3 ビジネスルール

- 具体値（30 秒間隔・最大 3 回・エスカレーション運用）自体は変更しない。確定/未確定の記述状態のみを整理する。
- ユーザー判断の記録は 00_要求定義.md の「## ユーザー判断（記録）」節に既存であり、本 issue で再度確認を取り直す必要はない。
