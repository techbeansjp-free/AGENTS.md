### 2.2 実装内容の詳細（確認結果）

#### 由来判定の単一正本 + ミラー（T1・T3）

- **確認済み**: bash `is_owned_skill_dir`（`deploy-skills.sh`）が判定正本、TS `isOwnedSkillDir`（`agents-md.ts`）が同型ミラー。両者ともコメントで相互参照し drift 防止を明記（02 §2.2「単一正本 + ミラー」に一致）。
- **確認済み**: frontmatter `name` 抽出の正規化規則が bash（`_asc_skill_frontmatter_name`：先頭一致・前後トリム・引用符除去）と TS（`skillFrontmatterName`：`/^\s*name:\s*(.*)$/`・trim・引用符除去）で同一。両者とも読取り不能・欠落時は空文字→`collision`（保持側）へ fail-safe（02 §3.1.4）。
- **確認済み**: 判定優先順が仕様どおり (1)absent →(2)owned（マーカー）→(3)legacy_owned（`name` 一致）→(4)collision。

#### 破壊操作の従属（T2・T3）

- **確認済み**: `sync_skills_selective` は `owned`/`legacy_owned`/`absent` のみ `rm -rf`＋単一エントリ再配備（`deploy_skills_impl "$src" "$dest_root" "$name" 1`）＋マーカー付与。`collision` は削除も配備もせず stderr 警告のみ（fail-closed な破壊・fail-open な配備）。
- **確認済み**: TS `runUninstall` は `planSkillUninstall` の `targets`（owned/legacy_owned）のみ削除対象、`preserved`（collision）は「保持: …（非所有の同名ディレクトリ）」表示。既存の hooks/owned files 削除・空ディレクトリ後片付けロジックは不変。
- **確認済み**: `deploy_skills_impl` の追加 2 引数は省略時に従来挙動（全件・マーカー無し）を厳守。`build-adapters.sh` の 2 引数呼び出しは変更されておらず、アダプタカプセルへマーカーは混入しない（§5.2 後方互換契約）。

#### BDD インラインコメント（TEST_BDD_FORMAT）

- **確認済み**: `test-deploy-skills-owned-guard.sh` は各テストに `# シナリオ:` と `# Given:`/`# When:`/`# Then:`（必要時 `# And (Then):`）を付与。e2e C1/C2/C3 も同様。ユースケース記述はファイル冒頭コメントに記載。フォーマット準拠。

### 4.2 指摘事項

#### 指摘 1: 00/01 のスコープ記述と 02/03・実装のスコープ不一致（低・非ブロッキング）

- **重要度**: 低
- **指摘内容**: `00_要求定義.md` §5 除外要件・§6 成功基準、および `01_要件定義.md` §8 は本 issue を「調査・起票のみ／対応方針の確定・実装はスコープ外（design-feature 以降で別途）」と記述している。一方 `02_設計.md`・`03_実装計画.md` と実装は同一 issue 内で恒久対策（マーカー方式）を実装・完了しており、スコープが拡大している。00/01 がこの拡大を反映していない（spec/06「docs と実装の不整合を放置しない」の観点で軽微なドリフト）。
- **対応状況**: 未対応（本 PR のブロッカーではない）
- **対応方法**: 進行役（orchestrator）がスコープ拡大を明示的に指示した経緯であり、02/03・実装・テストは内部整合が取れている。00 の原因調査付録（evidence_source: existing_code / reproduction）は現在も有効。推奨対応は 00 §5/§6・01 §8 に「調査完了後、同一 issue 内で恒久対策の設計・実装へスコープを拡大した」旨の 1 行注記を追加すること。コード・契約・テストの正しさには影響しないため、本注記は将来の軽微な追随で足りると判断し、本 PR では未修正のまま記録する（進行役の判断に委ねる）。

#### 指摘 2: TS `isOwnedSkillDir` の 4 区分専用ユニットは無く e2e 統合で担保（低・非ブロッキング・観察）

- **重要度**: 低
- **指摘内容**: 03 T3 テスト観点は「同一 fixture で bash とクロス確認」と記すが、`isOwnedSkillDir` は非公開の内部関数のため、bash 側の 4 区分直接ユニット（`test-deploy-skills-owned-guard.sh` シナリオ 1）に対応する TS 側の 4 区分直接アサーションは存在しない。TS 経路は e2e C1（collision 保持）・C2（uninstall で collision 保持／owned 削除）・C3（legacy_owned backfill）で統合検証される。
- **対応状況**: 受容（設計上、内部関数は CLI 経由でのみ観測可能）
- **対応方法**: 同一の衝突 fixture（`name: my-totally-unrelated-skill`）を bash 単体・TS e2e の双方で用いており、両経路が同一の collision 挙動を示すことでミラーの一致は実質担保される。追加の TS 専用ユニットは任意の将来強化として記録するに留める。
