## 1. 概要

### 1.1 システム概要

本パッケージ `@techbeansjp-free/agents-md` の CLI 配布物 `bin/agents-md.js` は `src/agents-md.ts` を `tsc` でビルドした生成物である。本要件は、この生成物を **git 追跡から外して `.gitignore`** し、配布（publish）・検証（E2E・pack）・CI の各経路で bin を使う前に必ず `npm ci && npm run build` で生成する方式へ転換する。`src/agents-md.ts`（正本）は追跡を継続する。npm 慣行（生成物は追跡せず publish 直前 build で配布）へ揃えることが狙いであり、issue I の「追跡 bin ＋ CI 差分ゼロ検証（`self-enforce.yml` step #2.5）」運用を置換する。

### 1.2 用語集

| 用語 | 説明 |
| ---- | ---- |
| bin（生成物） | `bin/agents-md.js`。`src/agents-md.ts` を `tsc` でビルドした配布用 CLI 実体。本要件で非追跡化する。 |
| src（正本） | `src/agents-md.ts`。CLI の型ファースト正本。追跡を継続する。 |
| クリーンツリー | E2E が `git archive HEAD \| tar -x` で再現する作業ツリー。追跡ファイルのみを含む（bin 非追跡化後は bin を含まない）。 |
| prepack 地雷 | `npm pack --dry-run` でも `prepack` lifecycle が走り、node_modules/tsc 無しのクリーン clone で `tsc: not found` → exit 127 となり E2E を壊す既知の事象（issue I で確認済み）。 |
| step #2.5 | `self-enforce.yml` の「CLI typecheck & build diff-zero」step。追跡 bin と src の差分ゼロを検証する。bin 非追跡化で無意味化するため除去対象。 |
| publish 直前 build | publish/pack 前に明示的に `npm ci && npm run build` し、生成 bin を配布物に含める方式（prepack の代替候補）。 |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 生成物 bin の非追跡化

- **As a** パッケージ保守者
- **I want to** `bin/agents-md.js` を git 追跡から外し `.gitignore` する
- **So that** 生成物を追跡しない npm 慣行に揃い、未ビルド bin がコミットされる事故余地を原理的に消せる

**受け入れ基準**:

- `git rm --cached bin/agents-md.js` 相当で bin が非追跡になり、`git ls-files bin/` が空である（SC1）。
- `.gitignore` に `bin/agents-md.js`（または `/bin/`）が追加され、`bin/agents-md.js` が ignore 対象である（SC1）。
- `src/agents-md.ts` は追跡を継続している（`git ls-files src/agents-md.ts` が非空）。

#### ストーリー 2: 配布物への生成 bin 同梱（pack 健全性）

- **As a** パッケージ利用者（`npx`/install 経由）
- **I want to** 配布 tarball に最新の生成 `bin/agents-md.js` が確実に含まれる
- **So that** install/`npx` 時に CLI が動作し、かつ src や開発専用物（map・lock・tsconfig）が混入しない

**受け入れ基準**:

- `npm ci && npm run build` 後の `npm pack --dry-run --json` 配布物に `bin/agents-md.js` が**含まれる**（SC2）。
- 同配布物に `src/`・`tsconfig.json`・`*.map`・`package-lock.json` が**含まれない**（SC2）。
- クリーン環境での `npm pack --dry-run`（`verify-npm-pack.sh` は `--ignore-scripts`）が exit 127 等で**壊れない**（SC3。prepack 地雷の回避）。
- 配布 bin が shebang（`#!/usr/bin/env node`）・実行権限を保つ。

#### ストーリー 3: 各経路でのビルド前置（E2E・CI・release）

- **As a** パッケージ保守者
- **I want to** E2E・verify-npm-pack・CI（self-enforce / release）が bin を使う前に `npm ci && npm run build` する
- **So that** bin 非追跡化後もクリーンツリー／クリーン環境で bin が存在し、検証・配布が成立する

**受け入れ基準**:

- `bash test/e2e-install-uninstall.sh` が green（事前 build 前提を満たした上で）。E2E の `git archive` クリーンツリーに bin が無い問題が吸収されている（SC4）。
- `bash test/run-all.sh`（npm test）と `self-enforce.yml` 相当が green（SC5）。
- `release.yml` の publish 経路が publish 前に `npm ci && npm run build` し、生成 bin を含めて配布できる。

#### ストーリー 4: step #2.5 の除去と整合更新

- **As a** パッケージ保守者
- **I want to** bin 非追跡化で無意味になる `self-enforce.yml` step #2.5（差分ゼロ検証）を除去し、関連ドキュメント／CI を整合更新する
- **So that** 「追跡 bin の差分ゼロ」を前提とした記述・検証が残らず、新方式と矛盾しない

**受け入れ基準**:

- `self-enforce.yml` の step #2.5「CLI typecheck & build diff-zero」が除去されている（typecheck の存続可否は設計判断。除去後 CI が green：SC5）。
- `docs/maintainer/RELEASE.md`（特に §1.5）・`release.yml`・`self-enforce.yml`・`.agents-project/COVERAGE_EXCEPTIONS.md`（該当があれば）が新方式（bin 非追跡・使用前 build）と整合している。
- 「追跡 bin が src と差分ゼロ」を前提とした記述が残っていない。

#### ストーリー 5: 未ビルド配布の原理的排除

- **As a** パッケージ保守者
- **I want to** src を変更しても未ビルドの bin がコミットされ得ない状態にする
- **So that** 人手や CI による「再ビルドして bin を commit し直す」運用なしに配布物の健全性が保たれる

**受け入れ基準**:

- src を変更しても bin は非追跡のため commit 対象に上がらない（`git status` に bin が現れない／ignore される。SC6）。

### 2.2 BDD ユースケース

#### ユースケース 1: bin の非追跡化

bin を git 追跡から外し、src は追跡継続することを検証する。

**シナリオ 1-1: bin が非追跡で ignore 対象になる（SC1）**

```gherkin
Feature: bin の非追跡化
  Scenario: bin が git 追跡から外れ .gitignore 対象になる
    Given bin/agents-md.js が現在 git 追跡されている（git ls-files bin/ が非空）
    When git rm --cached bin/agents-md.js を行い .gitignore に bin/agents-md.js（または /bin/）を追加する
    Then git ls-files bin/ が空になる
    And git check-ignore bin/agents-md.js が bin/agents-md.js を返す（ignore 対象）
    And git ls-files src/agents-md.ts は非空のまま（src 正本は追跡継続）
```

**シナリオ 1-2: src 変更で未ビルド bin がコミットされない（SC6）**

```gherkin
Feature: bin の非追跡化
  Scenario: src を変更しても未ビルド bin が commit 対象に上がらない
    Given bin/agents-md.js が非追跡（.gitignore 済み）である
    When src/agents-md.ts を変更し git status を確認する
    Then bin/agents-md.js は git status の変更/追加対象に現れない（ignore される）
    And 「未ビルド bin がコミットされる」事象が原理的に発生しない
```

#### ユースケース 2: 配布 tarball の健全性

非追跡化後も tarball に生成 bin が含まれ、開発専用物が混入しないことを検証する。

**シナリオ 2-1: build 後の pack に bin が含まれ src/map/lock/tsconfig が含まれない（SC2）**

```gherkin
Feature: 配布 tarball の健全性
  Scenario: npm ci && npm run build 後の pack 配布物が必須物のみを含む
    Given クリーンな作業環境で npm ci && npm run build を実行し bin/agents-md.js を生成した
    When npm pack --dry-run --json で配布ファイル一覧を取得する
    Then 配布物に bin/agents-md.js が含まれる
    And 配布物に src/・tsconfig.json・*.map・package-lock.json が含まれない
    And 配布物に .agents/・AGENTS.md・CLAUDE.md・README.md・package.json・.workflow/templates/ が含まれる
```

**シナリオ 2-2: クリーン環境の pack が exit 127 で壊れない（SC3・prepack 地雷回避）**

```gherkin
Feature: 配布 tarball の健全性
  Scenario: node_modules/tsc 無し相当のクリーン環境で pack が壊れない
    Given node_modules（tsc）が無いクリーン clone（git archive ツリー相当）である
    When verify-npm-pack.sh が npm pack --dry-run --json --ignore-scripts を実行する
    Then lifecycle script（prepack 等）の tsc 起動による exit 127 が発生しない
    And pack 検査が exit 0（必須物あり・禁止物リーク無し）で合格する
```

> **設計への申し送り**: シナリオ 2-2 が成立するには、tarball への生成 bin 同梱手段が「pack `--dry-run`（`--ignore-scripts`）の経路で tsc を要求しない」必要がある。prepack を採る場合でも `verify-npm-pack.sh` は既に `--ignore-scripts` で走らせており、その経路では bin が生成されないため、pack 検査の「`bin/agents-md.js` 必須」アサート（シナリオ 2-1）との整合を設計で確定すること（例: 検査経路では事前に `npm run build` 済みを前提とする／必須物検査の対象範囲を再定義する 等）。**prepack vs publish 直前 build の論点**は設計で決着させる。

#### ユースケース 3: 各経路でのビルド前置

E2E・CI・release が bin を使う前にビルドし、bin 非追跡でも各検証が green になることを検証する。

**シナリオ 3-1: E2E がクリーンツリーの bin 欠落を吸収して green（SC4）**

```gherkin
Feature: 各経路でのビルド前置
  Scenario: E2E が事前 build 前提を満たし green になる
    Given bin/agents-md.js が非追跡で git archive HEAD | tar -x のクリーンツリーに bin が含まれない
    When E2E が bin を使う前に npm ci && npm run build で bin を生成する
    And bash test/e2e-install-uninstall.sh を実行する
    Then install/uninstall・冪等性・カプセル化の全シナリオが PASS する（FAIL=0）
```

> **設計への申し送り（E2E クリーンツリー bin 問題）**: 現状 `test/e2e-install-uninstall.sh` は `CLI="$REPO_ROOT/bin/agents-md.js"` を起動し、`make_clean_tree`（`git archive HEAD | tar -x`）は install の**ソース**としてのみ使う。bin 非追跡化で影響するのは「① REPO_ROOT の bin（CLI 起動元）」と「② クリーンツリー src 側で bin を参照する箇所（シナリオ 6 の build-adapters は bin 非依存）」の双方。`npm ci && npm run build` をどこで（CI step か E2E スクリプト先頭か）走らせて REPO_ROOT/クリーンツリーのどちらの bin を満たすかを設計で確定すること。

**シナリオ 3-2: self-enforce 相当が step #2.5 除去後も green（SC5）**

```gherkin
Feature: 各経路でのビルド前置
  Scenario: step #2.5 を除去した self-enforce 相当が green になる
    Given self-enforce.yml から step #2.5「CLI typecheck & build diff-zero」が除去されている
    When bash test/run-all.sh（npm test）と self-enforce 相当の各検証を実行する
    Then すべて green（差分ゼロ検証・pack リーク検査・E2E・カバレッジ等が PASS）
    And 「追跡 bin の差分ゼロ」を前提とした step が CI に残っていない
```

**シナリオ 3-3: release 経路が publish 前に build して配布できる**

```gherkin
Feature: 各経路でのビルド前置
  Scenario: release.yml の npm publish 経路が publish 前に build する
    Given v* タグ push 相当で npm publish ジョブが起動する
    When ジョブが publish 前に npm ci && npm run build を実行する
    Then 生成 bin/agents-md.js を含む配布物で verify-npm-pack.sh が合格する
    And 「追跡 bin 差分ゼロ検証」に依存しない publish 前提になっている
```

#### ユースケース 4: ドキュメント・設定の整合

新方式に合わせ関連ドキュメント・設定が整合更新されることを検証する。

**シナリオ 4-1: RELEASE.md / CI / 例外台帳が新方式と整合**

```gherkin
Feature: ドキュメント・設定の整合
  Scenario: 関連ドキュメント・CI が bin 非追跡・使用前 build と整合する
    Given bin が非追跡化され step #2.5 が除去された
    When docs/maintainer/RELEASE.md（§1.5）・release.yml・self-enforce.yml・COVERAGE_EXCEPTIONS.md（該当があれば）を確認する
    Then 「追跡 bin が src と差分ゼロ」を前提とした記述が残っていない
    And 各経路が「使用前に npm ci && npm run build」する新方式を正しく記述している
```

### 2.3 ビジネスルール

- bin は完全な派生物として扱い、git 追跡しない（`src/agents-md.ts` のみ正本として追跡）。
- 検証ロジックは単一正本に集約する（CI とローカルで二重化しない）。`verify-npm-pack.sh`・`test/e2e-install-uninstall.sh` を正本とし CI は呼ぶだけ、を維持する。
- prepack 地雷（`npm pack --dry-run` で tsc を要求し exit 127）を再発させない。pack 検査は `--ignore-scripts` を維持する。
- 本フェーズ（要求・要件）ではコード変更・git 操作を行わない。実測は `mktemp -d` 隔離で行い、本リポの追跡ファイル・bin・`.gitignore` を変更しない。

## 3. 非機能要件

### 3.1 パフォーマンス要件

- 各経路に追加する `npm ci && npm run build` のオーバーヘッドは、既存 CI/E2E の所要時間に対して妥当な範囲に収める。

### 3.2 セキュリティ要件

- 証跡 DB（`workflow.db*`）・リポ固有物（`.agents-project/`・`docs/maintainer/`）・`test/` が tarball に漏れない状態を維持する（`verify-npm-pack.sh` の禁止パターン維持）。

### 3.3 ユーザビリティ要件

- 利用者（`npx`/install）が配布 bin を実行でき、shebang・実行権限が保たれる。

### 3.4 可用性要件

- `NPM_TOKEN` 未設定時に publish step が skip される既存ゲートは維持し、build/検証経路は token 有無に依存せず動作する。

---

## 4. 外部インターフェース要件

### 4.1 API 要件

- CLI（`agents-md` の `init`/`uninstall`/`version`/`help` 等）のインターフェースは変更しない。

### 4.2 データ形式要件

- `npm pack --dry-run --json` の出力（`files[].path`）を検証入力とする。配布物に `bin/agents-md.js` を含み、`src/`・`*.map`・`tsconfig.json`・`package-lock.json` を含まない。

---

## 5. 制約事項

- 本フェーズは要求・要件定義のみ。コード変更・git 操作（`git rm --cached` 等）は実装フェーズで行う。
- prepack vs publish 直前 build の選択は設計フェーズで決着（地雷回避を満たすこと）。
- E2E クリーンツリーの bin 欠落吸収手段は設計フェーズで確定。
- 実測確認は `mktemp -d` 隔離で行い、本リポの追跡ファイル・bin・`.gitignore` を変更しない。
- 成果物内のリポルートへの相対リンクは現在 4 階層（`../../../../`）。
