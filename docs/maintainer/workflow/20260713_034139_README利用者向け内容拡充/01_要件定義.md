## 1. 概要

### 1.1 システム概要

本 issue は、別 issue「README 読者分離」（commit `78b3517`）で利用者向けマニュアルに特化させた [`README.md`](../../../../README.md) の**利用者向けセクションの内容を拡充**する。読者分離の構造（README＝利用者向け／[CONTRIBUTING.md](../../../../CONTRIBUTING.md)＝開発者向け／[docs/maintainer/RELEASE.md](../../RELEASE.md)＝リリース詳細）は維持したまま、利用者レビューで不足が指摘された 3 点—**①設定できること（設定一覧）②スキル一覧・アーキテクチャ説明 ③導入すると何が変わるか**—を補う。

さらに、後続レビューで**④配布物からのアップデート方法の可視化**が追加スコープとして指摘された。`README.md` は導入先へ配布されないため、既に導入済みのプロジェクトからは README を読めず、実際に配布される [`.agent-skill-chain/source/SETUP.md`](../../../../.agent-skill-chain/source/SETUP.md)・[`AGENTS.md`](../../../../AGENTS.md)・[`CLAUDE.md`](../../../../CLAUDE.md) に `init`/`upgrade`/`enforce`/`uninstall` の実行コマンド自体とそこへの導線を確保する。

拡充は全編を通じて**「README には要約＋代表例、詳細は既存正本へリンク」**方針（DRY・陳腐化耐性）で行い、既存正本（[enforcement/README.md](../../../../.agent-skill-chain/source/enforcement/README.md)・[.agent-skill-chain/source/README.md](../../../../.agent-skill-chain/source/README.md)・[CONCEPTS.md](../../../../.agent-skill-chain/source/CONCEPTS.md)・[GETTING_STARTED.md](../../../../.agent-skill-chain/source/GETTING_STARTED.md)）にある内容を新規に書き起こさず要約・参照する。

### 1.2 用語集

| 用語 | 説明 |
| ---- | ---- |
| 要約＋リンク方針 | 詳細は既存正本 1 か所に一本化し、README には要約と入口リンクのみ置く DRY パターン。既存の README §リリース手順→RELEASE.md 分離で確立済み |
| command | skill を束ねる実行単位（skill chain）。本パッケージには 6 種（requirement-discovery / design-feature / implement-feature / verify-and-close / review-docs / create-pr-review-issue）がある |
| skill（能力） | 1 目的の最小部品。`skills/{domain}/{capability}/` に配置。7 ドメイン・14 capability |
| orchestrator（進行役） | メイン。phase 判定・command 選択・委譲・証跡確認に徹し、実作業は行わない |
| enforcement opt-in | `enforce on` で PreToolUse/PostToolUse フックを配線する任意機能（既定 off） |
| ②③（並行 issue） | close 移動監査強制・GitHub Issue 起票ゲート追加。個別環境変数名は本 issue では確定情報化しない |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 設定できることの体系的な把握

- **As a** 本パッケージを採用しようとしている利用者
- **I want to** README から「導入後に調整できる設定は何か」の全体像と詳細への入口を知りたい
- **So that** 自分のプロジェクトに合わせた設定調整が可能かを README 単体で判断できる

**受け入れ基準**:

- README の利用者向けセクションに、設定の**カテゴリ＋代表例**（enforcement opt-in＝`enforce on/off` 既定 off、版のピン留め、audit 走査スコープ等の調整可能な環境変数群）が記載されている。
- 設定の全カタログは README 本体に列挙せず、詳細正本 [enforcement/README.md](../../../../.agent-skill-chain/source/enforcement/README.md) 等への入口リンクで委譲している。
- 並行 issue ②③ が追加中の個別環境変数名（`CLOSE_MOVE_*` / `GITHUB_ISSUE_GATE_*` 相当）が確定情報として README 本体に書かれていない。

#### ストーリー 2: 使えるスキル・コマンドとアーキテクチャの把握

- **As a** 本パッケージを採用しようとしている利用者
- **I want to** README から「導入すると何が使えるか」（command が何をするか・skills にどんな能力があるか）を知りたい
- **So that** このパッケージが自分のワークフローに何を提供するかを理解して導入判断できる

**受け入れ基準**:

- README に **6 つの command の役割一覧**（`requirement-discovery`＝要求/要件と BDD、`design-feature`＝設計と実装計画、`implement-feature`＝実装、`verify-and-close`＝検証/レビュー/クローズ、`review-docs`＝実装前ドキュメントレビュー、`create-pr-review-issue`＝PR 指摘対応 issue 起票）が各 1 行程度で記載されている。
- README に **skills のドメイン群**（requirements / architecture / implementation / testing / review / logging / agent）の概要が記載されている。
- 個別 capability の詳細カタログは README に全列挙せず、正本 [.agent-skill-chain/source/README.md](../../../../.agent-skill-chain/source/README.md) の索引への入口リンクで委譲している。
- 既存の「.agents 配下の構成」表（ディレクトリマップ）は維持したまま、それを補完する形で追加されている。

#### ストーリー 3: 導入後に AI の挙動がどう変わるかの把握

- **As a** 本パッケージを採用しようとしている利用者
- **I want to** README から「.agents に従わせると AI の挙動が具体的にどう変わるか」を知りたい
- **So that** 導入後の開発体験（進行の仕方・制約・証跡）を想像して導入判断できる

**受け入れ基準**:

- README に導入後の挙動変化の要約として、少なくとも次の 4 観点が記載されている: (a) 進行役（orchestrator）が実作業を必ずサブに委譲する、(b) phase gate に沿って要求→要件→設計→実装計画→実装→レビューを command で回す、(c) enforcement を opt-in すると orchestrator の直接 Write/Edit/Bash 等が制約される、(d) 証跡が workflow.db に残る。
- 思想・詳細は新規に書き起こさず、既存正本 [CONCEPTS.md](../../../../.agent-skill-chain/source/CONCEPTS.md)・[GETTING_STARTED.md](../../../../.agent-skill-chain/source/GETTING_STARTED.md) を要約し、それらへの入口リンクで委譲している。

#### ストーリー 4: 配布物からのアップデート方法の可視化

- **As a** 本パッケージを**既に導入済み**のプロジェクトの利用者
- **I want to** 導入先に配布される SETUP.md・AGENTS.md・CLAUDE.md だけを頼りに `init`/`upgrade`/`enforce`/`uninstall` の実行コマンド自体を知りたい
- **So that** README.md が配布されない導入済みプロジェクトからでも、アップデート（`upgrade`）等の操作方法を自力で調べられる

**受け入れ基準**:

- 配布される [`.agent-skill-chain/source/SETUP.md`](../../../../.agent-skill-chain/source/SETUP.md) に、`init`（バージョンピン留め含む）・`upgrade`・`enforce on/off/status`・`uninstall` の**実行コマンド自体**（`npx github:techbeansjp-free/AGENTS.md upgrade` 等）が記載されている。
- 当該コマンド例は README.md §配備後の管理（CLI）の実コマンド例と整合し、SETUP.md 単体でも読めるよう SETUP.md 内に実体を持つ（配布物単体で完結させるため、契約表からの参照のみで済ませない）。
- 配布される [`AGENTS.md`](../../../../AGENTS.md)・[`CLAUDE.md`](../../../../CLAUDE.md) から、SETUP.md の当該コマンド節へ**辿れる導線**（リンクまたは表の参照行）が存在する。

#### ストーリー 5: 読者分離構造の非後退

- **As a** 本リポジトリのメンテナ
- **I want to** 拡充作業で「README 読者分離」の成果が後戻りしないことを保証したい
- **So that** README が再び利用者向け／開発者向けの混在に戻らない

**受け入れ基準**:

- 拡充後も README には「開発者・自己拡張向け」「メンテナ向け」と読者を限定する内容が戻っていない。
- CONTRIBUTING.md・RELEASE.md の分離済み内容が README に重複コピーされていない。
- 追加は既存正本へのリンク委譲が中心で、README への詳細の書き写しによる二重管理が発生していない。

### 2.3 ビジネスルール

- **要約＋リンク方針を全拡充に適用する**: 設定の全カタログ・skills 詳細・思想は README にコピーせず、既存正本に一本化して要約＋リンクで接続する。
- **②③ の個別環境変数名を確定情報化しない**: README 本体・00・01 に `CLOSE_MOVE_*` / `GITHUB_ISSUE_GATE_*` 等の未確定変数名を書かない。「設定カテゴリ＋代表例＋正本リンク」に留める。
- **読者分離を後戻りさせない**: 開発者・メンテナ向け内容を README に戻さない。
- **歴史記述を残さない**: 「拡充した」「以前は無かった」等の経緯を README・正本に書かない（現在の事実のみ）。
- **配布物は自己完結させる**: SETUP.md・AGENTS.md・CLAUDE.md は導入先へ配布される前提で、README.md を読めない前提でも `init`/`upgrade`/`enforce`/`uninstall` の実行コマンドに到達できるようにする。

## 3. 非機能要件

### 3.1 パフォーマンス要件

- 該当なし（ドキュメント拡充のみ）。

### 3.2 セキュリティ要件

- 該当なし。

### 3.3 ユーザビリティ要件

- 追加する各節は、利用者が「設定できること／使えるもの／導入後の姿」を README 内で完結して把握でき、より深い詳細は 1 リンクで正本に到達できること。

### 3.4 可用性要件

- 拡充後もリポジトリ内の全 markdown リンクが解決する（リンク切れ 0 件）。既存の見出しアンカー・外部参照リンクを壊さない。

## 5. 制約事項

- 「README 読者分離」（commit `78b3517`）の分離構造を後戻りさせない。
- 未確定の並行 issue ②③ の個別環境変数名を確定情報として書き込まない。
- インストール／アンインストール方法の**内容**は充実済みのため変更しない（④の SETUP.md 実行コマンド節追加は既存内容の変更ではなく追加）。
