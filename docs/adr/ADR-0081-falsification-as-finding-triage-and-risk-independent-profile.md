## Context

セグメントゲートは立証（conformance）と反証（falsification）の双方に pass を要求している。立証は Issue の `SPEC.md` が確定させた有限の AC 集合に対する検査であり、全件を検査すれば終わる。反証は反例の全空間に対する探索であり、判定プロンプトは反例の探索を指示する一方で探索の停止条件を持たない。「反例が見つからなかった」は「反例が存在しない」を意味しないため、反証の pass は成果物の性質ではなく当該レビュアの当該実行における探索結果にすぎない。これを二値の合否条件に用いる限り、同一入力に対する判定は原理的に非決定的になる。

2026-08-19 の1日の運用実測では、判定プロンプトの digest が両レビュアで完全一致していたにもかかわらず判定が4回割れた。内訳は、spec で反証の pass/fail が割れた事例、implementation の round 2 で2体が別々の blocking を出した事例、validation で同一論点の severity が warning と blocking に割れた事例、validation で立証の pass/fail が割れた事例である。`strict` は独立2体のいずれか一方が blocking を出せば reject するため、停止条件を持たない探索の論理和になり、レビュア体数を増やすほど通過確率が下がる。2026-08-20 時点の open Issue 41件のうち 23件が `risk:high` であり、現行の不変条件 I8 は `risk != normal` または `autonomy == full` を strict の条件としているため、過半の Issue が自動的にこの論理和へ倒れる。

一方で、反証の探索そのものは立証観点では検出されない実欠陥を検出している。ゲートを恒久的に判定不能へ固定する機構の欠陥、終了コード0が成果物の残存を隠蔽する経路、存在しないテスト題名を pass として引用した検証結果の3件がその実例である。探索を削れば、これらは検出されなくなる。

検討したトレードオフは次のとおりである。

- **反証を判定プロンプトごと削除する案**: 非決定性は消えるが、上記3件のような実欠陥の検出経路も同時に消える。品質の維持という目的に直接反するため採らない。
- **反証を決定的にする案（探索の停止条件を与える）**: 反例の全空間に対する探索へ有限の停止条件を与えることは、探索対象の空間を有限化することと同義であり、それは反証を立証（有限の検査項目の網羅）へ変質させる。反証の価値は「あらかじめ列挙していない失敗経路を見つけること」にあるため、有限化はその価値を失わせる。採らない。
- **レビュア体数を1体へ減らし論理和を消す案**: 非決定性は残り、単に観測回数が減るだけである。コア対象で独立2体を要求する既存のレビュー方針とも衝突する。採らない。
- **blocking を進行役が事後に降格させる運用で凌ぐ案**: ISSUE-786 が導入したラウンド予算の降格機構がこれに当たる。有限性は得られるが、降格の判断が進行役の裁量に残るため「同一入力に対して同じ分類が再現される」という性質は得られない。既に導入済みの機構であり撤去しないが、本件の解決手段としては不足である。
- **`risk` を profile 決定の入力に残したまま閾値だけ緩める案（例: `high` のみ strict）**: `risk` は変更内容ではなく Issue に貼られたラベルであり、同じ変更に対して付与者ごとに異なる値を取り得る。閾値を動かしても「profile が変更内容以外の要因で変わる」という性質は残る。採らない。

収束は「反証が決定的になること」では達成できない。「gate-report だけを読む第三者が同じ分類を再現できる根拠を伴う finding しかゲートを止めないこと」によって達成する。

さらに、最終判定を導出する箇所が現状3箇所に分散している。共通の集約関数、ローカル経路の verdict 記録、GitHub 経路の証跡検証であり、後2者は共通集約の結果を事後に書き換えている。書き換えの根拠はいずれも ISSUE-786 のラウンド予算機構と light 再是正上限であり、安全側への昇格だけを行う。導出箇所が分散したままでは、`SPEC.md` が定めた順序評価が実装のどこで守られているかを機械的に確認できない。

## Decision

1. **反証観点の合否値をゲート最終判定の入力から外し、型からも削除する。** 反証は finding を産出する装置として扱う。最終判定の入力は、立証観点の合否値、blocking と分類された finding の有無、反証探索記録の有無、判定不能表明の4つに限る。ゲート結果を保持するスキーマは、反証について pass/fail/pending の合否値ではなく、探索の実施有無と探索した反例候補の列挙を保持する形へ変更する。

2. **反証観点の探索指示は削らず、探索記録の存在を承認の必要条件として機械化する。** 判定プロンプトは反例の探索を引き続き指示する。反証探索記録が無いか不完全な attempt は `approved` へ到達できない。探索の維持を「指示があること」ではなく「記録が無ければ承認されないこと」で担保するのは、指示が守られたか否かは検証できないが、記録の有無は検証できるためである。

3. **blocking への昇格を、閉じた列挙の昇格類型と、類型ごとの必須根拠に限定する。** 類型は `issue_purpose_blocked`・`existing_behavior_regression`・`data_loss_or_security`・`ci_build_failure` の4件とし、列挙外の値を受け付けない。必須根拠は各類型に1つずつ形式を定め、全類型に共通で「判定対象成果物からの逐語引用」を要求する。引用は当該 attempt の判定入力閉包へ本文を展開した成果物に対して記録側が照合する。判定入力閉包の外からの引用を認めないのは、既存のハルシネーション防止規約と同じ境界を昇格の根拠にも適用するためである。現行の判定プロンプトが用いている目的阻害性・到達可能性・責務内是正可能性の3条件は4類型の意味説明として、実証性は逐語引用の必須化として、それぞれ引き継ぐ。

4. **立証観点の AC-ID 未達・未証跡には昇格類型と必須根拠の要件を適用せず、無条件に blocking のままとする。** これは不変条件 I7（仕様⇔検証の追跡）の維持であり、緩和しない。あわせて、ISSUE-786 が導入した finding 分類record による blocking から warning への差し替えの対象を、`perspective: falsification` の finding へ限定する。限定しなければ、AC-ID 未達が最終round で warning へ差し替えられ I7 が緩む。分類record の機構自体は撤去しない。

5. **昇格しなかった finding は削除も要約もせず、severity 以外を不変のまま warning 以下として記録する。** 昇格評価の結果（成立した類型 id と引用元パス、または不成立の理由）を gate-report へ併記し、第三者が gate-report だけを読んで同じ分類を再現できる状態にする。

6. **最終判定の導出箇所を1つに統合し、既存の安全側昇格を安全側停止事実という入力として合流させる。** 導出は `SPEC.md` が定めた3規則を上から評価して確定させる。finding 分類record不正・ラウンド打ち切り閾値への到達・light 再是正上限への到達の3事実は安全側停止事実として同じ関数へ渡し、適用規則は「基礎導出が `approved` でなく、3事実のいずれかが真である → `human_required`」の1つだけとする。事実ごとに異なる例外条件を持たせる案は採らない——`approved` を除外する事実と除外しない事実が混在すると規則が非対称になり、同一入力に対する帰結が記述から一意に読めなくなるためである。この単一規則により、安全側停止事実は `approved` を新たに生むことも消すこともなく、`SPEC.md` の順序評価が事実の有無にかかわらず不変に保たれ、かつ ISSUE-786 の有限性保証が失われない。事後書き換えを残す案も採らない——導出結果を別の場所で上書きできる限り、順序評価がどこで守られているかを機械的に確認できないためである。

   この単一規則は現行実装の3つの事後上書きと1件を除いて同一の帰結を与える。異なるのは「分類recordが不正であり、かつ差し替え対象の blocking が0件で立証が pass、探索記録も揃っている」入力だけであり、現行は無条件に `human_required`、本決定では `approved` とする。差し替え対象が存在しないとき分類の不正は判定へ影響し得ず、blocking を消して安全側停止を回避する経路も存在しないためである。現行のまま据え置くと、立証 pass・blocking 0件・探索記録ありの attempt を承認とする受入条件を満たせない。不正の事実は判定理由として記録し続ける。

7. **`risk` の値を review profile 決定の入力から外し、決定を4つの入力と4つの順序規則へ書き直す。** 入力は `full` の明示オプトイン、`light` の明示オプトイン、変更差分の解決可否とコア対象の成立、過去ラウンドの strict 確定の4つに限る。規則は「`full` があれば strict」「差分解決不能・コア対象・過去ラウンド確定のいずれかなら strict とし以後も維持」「`light` があれば light」「それ以外は standard」の順とし、最後の規則に条件を置かないことで全組合せに対する帰結を一意にする。`risk` を外すのは、`risk` が変更内容ではなくラベルであり、同一の変更に対して付与者ごとに異なる値を取り得るためである。安全側の固定は変更内容だけを入力とするコア対象の経路が担う。

   除去の対象は決定関数の型だけではない。`risk` から profile を導く経路はリポジトリ内に3つ実在する——軽量レビューの可否を決めるガードレール、Issue 起票時に状態ファイルへ初期 profile を書き込む直書きの式、発行済み Check output を再構築するときにラベルから profile を導く箇所である。型を消すだけでは後2者が残るため、決定・記録を行う経路を全数として列挙し、そのすべてを新しい規則または下記8への置き換えの対象とする。Issue 起票時については、起票の時点でまだ差分が存在せず決定入力が揃わないため、初期 profile を決めること自体をやめ、状態ファイルの当該フィールドを必須から外す。

8. **これから実施する attempt の profile を決めること（live 決定）と、発行済みの記録を検証するために当時の profile を読むこと（記録済み profile の復元）を、別の責務として分離する。** live 決定は新しい規則だけを用い `risk` を入力に持たない。記録の検証・再構築は、新版の記録に対しては同じ規則で再導出して独立な改竄検知を保ち、旧版の記録に対しては当時記録された値を版付きの復号として読み、新しい規則で再導出しない。両者を同じ関数へ混ぜる案は採らない——混ぜると、`risk` を入力とする経路が実装に残らないという受入条件と、旧版で記録済みの承認を無効化しないという受入条件のどちらかを必ず破るためである。旧版の記録を新しい規則で再導出すると、`risk` 由来で strict として記録された過去の Check が standard として再構築され、正準表現の一致検査に落ちて既存の承認済み Check が検証不能になる。旧版経路で失われる独立再導出の代わりに、記録された profile と証跡の期待体数・充足数の整合、およびコア対象が成立する差分では strict であることを独立に検査する。後者は差分の内容だけを入力とし `risk` を入力としないため、コア対象で体数が下がる経路は生じない。

9. **明示オプトインは付与主体を人間と機械的に確認できた場合にだけ有効とし、`full`・`light` を同一に扱う。** 確認不能を理由に profile を昇格させない。現行は `light` にだけ付与主体の確認を課し、`full` はラベルの存在だけで strict へ倒していた。非対称を残すと、エージェントが設定できる経路の有無が2つのオプトインで食い違う。確認手段を持たないローカルモードでは、いずれのオプトインも適用されない。

10. **profile 決定結果は3値とし、既存の2値の wire 表現へ写像する。** `light` と `standard` はいずれもレビュア1体であり、両者の区別は既存の軽量レビュー記録が保持し続ける。新しい profile 値を証跡・launcher token・設定キーへ導入しないのは、投稿済み証跡の再検証・ラウンド計数・digest 照合を無効化しないためである。

11. **`schema_version` の更新は、旧版文書が新版の必須・禁止フィールドに適合しなくなる4件に限る。** 対象はゲート結果（反証の合否値を受理せず探索記録を必須とし、finding へ観点を必須追加する）、Issue 状態（初期 profile フィールドを必須から外し、反証の合否値を探索記録へ置換する）、設定（`risk` を strict の trigger として宣言するフィールドを受理しない。当該箇所は未知フィールドを許さず当該フィールドを必須とするため、削除は版を上げなければ旧版文書を不正化する）、review evidence（反証の合否値を受理せず探索記録を必須とし、finding へ観点を必須追加する）である。本変更でフィールドが変わらない他のスキーマは版を据え置く——外部契約が変わらない版更新は、利用者に移行を強いるだけで得るものが無いためである。いずれも新旧2版を受理し、旧版で記録済みの承認を無効化しない。旧版レコードの最終判定は再導出せず、記録された値をそのまま有効とする。再導出する案は採らない——新しい規則で旧版レコードを評価すると、当時は存在しなかった反証探索記録の欠落により既存の承認がすべて `human_required` へ倒れるためである。設定の当該フィールドを残して読み捨てる案は、`risk` 由来の strict 昇格経路が設定に存在しないという受入条件に反するため採らない（旧版として記録済みの設定文書に対してのみ読み捨てる）。

## Consequences

- 利点: 同一入力に対する最終判定が、レビュアの探索結果ではなく「立証の充足」「閉じた類型と必須根拠を満たす finding の有無」「探索記録の存在」という再現可能な条件だけで決まる。gate-report だけを読む第三者が分類を再現できる。
- 利点: 反証の探索が維持され、探索記録の欠落が承認を妨げる形で機械的に担保される。運用実測で検出済みの3件の実欠陥は、いずれも4類型のいずれかに該当し必須根拠を構成できるため、引き続き blocking として成立する。
- 利点: `risk` が profile を変えなくなるため、`risk:high` が過半を占める現状でも既定は1体の standard になる。strict は変更内容（コア対象）と人間の明示行為だけが生む。
- 利点: 最終判定の導出が1箇所に集まるため、順序評価の遵守が grep で確認できる。ISSUE-786 の有限性保証は安全側停止事実として残り、適用規則が1つになったことで真理表と単体テストが同時に成立する形になる。
- 利点: profile の live 決定と記録済み profile の復元を分けたため、`risk` 由来の経路を実装から全数除去しても、旧版として発行済みの Check・証跡の検証が壊れない。
- 欠点: 逐語引用の照合が厳しすぎる場合、正当な blocking が warning へ降格し得る。降格は記録に残るが、当該ラウンドではゲートを止めない。照合の下限値は既存の finding evidence 検査と同じ値を仮に採用しており、運用実測での見直しを要する可能性がある。
- 欠点: ローカルモードでは明示オプトインの付与主体を人間と確認する手段が無いため、`autonomy: full` が strict を要求しなくなる。ローカルモードで strict を要するのはコア対象の経路だけになる。付与主体確認の手段そのものの導入は本決定の対象外とする。
- 欠点: 旧版の記録を検証する経路では、profile を独立に再導出できなくなる。代替として、記録された profile と証跡の期待体数・充足数の整合、およびコア対象が成立する差分では strict であることを独立に検査する。コア対象でない Issue は新しい規則でも既定が standard であるため、記録済み値を用いることによる体数低下の余地は本決定後の規則が許す範囲を超えない。
- 欠点: 判定プロンプトと launcher digest の算出対象が変わるため、本決定の適用時点で進行中のゲート反復は、投稿済み証跡の digest が期待値と一致せずやり直しになる。やり直さない場合の判定は既存の digest 一致検査により人間判断へ倒れる。ADR-0068 が既に受け入れている帰結と同型である。
- 欠点: スキーマ4件の版更新を伴うため、切り戻し後は当該期間に新版として書かれたゲート結果が旧版スキーマ検査に適合しなくなる。ゲート結果は attempt ごとに再生成できる記録であるため、影響 Issue のゲート再実行で復旧する。
- 欠点: 昇格類型の4件と、ISSUE-786 のラウンド予算が用いる4類型は、意味は重なるが同一の列挙ではない。前者は「既存挙動の回帰」と「CI・ビルドの失敗」を分け、後者は両者を1つに束ね「前ラウンドの blocking 未解消」を別に持つ。2つの列挙を1つへ統合する案は、ラウンド予算の宣言 digest を変えて既存の宣言を無効化するため採らない。両者の対応は `DESIGN.md` が写像として明示する。
- フォローアップ: 逐語引用の照合下限値と、昇格類型の粒度は、運用実績が蓄積した段階で見直す。値の変更はコード定数の変更であり設定項目の追加を要しない。

## 本決定と既存 ADR の関係

- ADR-0068（ゲートのラウンド番号導出と反証の blocking 基準）: 反証の合否値を用いる部分だけが本決定に置き換わる。ラウンド番号の導出規則、高ラウンドの限定、打ち切り閾値、導出不能時の扱いはすべて存続する。
- ADR-0078（finding 再分類と有効 sub-verdict）: 再分類の対象が `perspective: falsification` の finding へ限定される。機構と記録形式は存続する。
- ADR-0070（verdict 集約の定足数）: slot 件数と判定確定数の検査は本決定の単一導出箇所が引き継ぐ。
