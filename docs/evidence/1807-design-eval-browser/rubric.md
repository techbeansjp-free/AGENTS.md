# 評価者向けの採点基準（モデルによる補助の採点。#1804のrubric.mdにUI-04・UI-07を加えたもの）

あなたは、生成された画面を採点する評価者である。生成した条件・方法は知らされない。各画面は乱数のID（例：`k7q2`）で示す。

## 入力

このフォルダに、依頼文（`BRIEF.md`）と、画面ごとに次のファイルがある。

- `<ID>-desktop.png`（UI-03は`<ID>-desktop.png`と`<ID>-tablet.png`）、`<ID>-mobile.png`：実際に描画した画面（外部通信なしの環境。指定した書体が無ければ代替書体で描画される）。
- `<ID>-gray.png`：desktopを白黒にした画面。
- `<ID>-notes.md`：生成者が書いた設計判断の説明。

画像はすべて自分でReadして見ること。見ていない画面を採点しない。画像を読めなかった場合は、その画面の全項目を`null`にし、理由を書く。

## 採点（各0〜2点、合計20点）

次の10項目を、画面と依頼文から観察できる事実だけで採点する。好みではなく、依頼の利用者・目的への適合で判断する。角丸・カード・グラデーション・ベージュ・特定書体などの使用自体を減点しない。既存の見た目から外れていること自体を加点しない。

| 項目 | 2点 | 1点 | 0点 |
| --- | --- | --- | --- |
| subject（題材適合） | 依頼の題材に固有の内容（UI-03：レーン・締切・遅延・対処、UI-04：部品・品番・規格・在庫と納期、UI-07：バス停・のりば・時刻・遅れと運休）が、配色・書体・構図・図形などの視覚表現に具体的に反映されている（どの要素か指摘できる） | 内容は載っているが、視覚表現は題材を問わず使える一般的なもの | 題材と矛盾する、または題材が読み取れない |
| hierarchy（情報階層） | 利用者が最初に必要とする情報（UI-03：対処が必要なもの、UI-04：検索・件数・候補の比較・選んだ部品の在庫と納期、UI-07：次の便の時刻・遅れや運休・のりば）が最も目立ち、重要度の差が自然に伝わる | 階層はあるが、重要な情報が埋もれる箇所が1つある | 重要度の差が分からない、または不要なものが最も目立つ |
| typography（書体・組版） | 書体・サイズ・太さ・行間・字間が用途に合い、日本語と英語・数字の組み合わせが読みやすい | 概ね読めるが、行長・行間・サイズ差・和欧混植のどれかに明らかな問題が1つある | 読みにくい箇所が複数ある、または文字が欠ける・重なる |
| composition（構図） | 情報と操作の関係が配置で分かり、広幅・狭幅（mobile/tablet）でも関係が保たれる | 片方の幅で関係が崩れる、または配置が単調で関係が読み取りにくい | 重なり・はみ出し・不自然な空白などで構図が破綻している |
| color（配色） | 色が意味（状態・強調）・題材・可読性と整合し、白黒画面でも状態や強調の区別が残る | 色の意味付けが一部不明瞭、またはコントラスト不足が一部にある | 色の意味が矛盾する、または読めない組合せがある |
| spacing（余白） | 余白がまとまりを示し、詰まり過ぎ・空き過ぎがない | 一部に詰まり・空き過ぎがある | 余白がまとまりを壊している |
| distinctiveness（独自性） | UI-03・UI-04・UI-07：同じ構成のまま無関係な題材（例：SaaSの紹介ページ）に差し替えても成立しない程度に、この依頼に固有の判断がある。 | UI-03・UI-04・UI-07：固有の判断は一部だけで、全体は汎用の型。 | UI-03・UI-04・UI-07：汎用の型のまま。 |
| consistency（一貫性） | 同じ役割の部品・状態が、画面内（と各幅の間）で同じ表現になっている | 不統一が1箇所ある | 不統一が複数ある |
| decoration（装飾の妥当性） | 装飾が、題材の表現か情報の理解に寄与している。装飾が無い場合も、無いことが用途に合っていれば2点 | 寄与しない装飾が一部にある | 装飾が情報や操作を妨げている |
| rationale（説明可能性） | notesの判断が画面の具体的な要素と対応し、依頼の内容・利用者に結び付いている。notesの記述と画面に矛盾がない | 対応は一部だけ、または一般論が中心 | notesが無い、画面と矛盾する、または判断の理由が無い |

## 追加の観察（UI-03だけ）

`<ID>-gray.png`（白黒）だけを見て、しきい値を超えている（対処が必要と表示されている）KPIとレーンを全て挙げる。KPIは表示名、レーンは`LANE-`で始まるIDの先頭2区切り（例：`LANE-A01`）で書く。色以外の手掛かりで読み取れたものだけを挙げる。

## 出力

最後に、次の形式のJSONだけを、1つのコードブロック（```json）で出力する。各画面について、各項目の点数と、点数の根拠となる画面要素を1文で書く。

```json
{"scores": {"<ID>": {"subject": 2, "hierarchy": 1, "typography": 2, "composition": 1, "color": 2, "spacing": 2, "distinctiveness": 1, "consistency": 2, "decoration": 2, "rationale": 1, "evidence": "…", "flaggedInGray": ["出荷遅延率", "LANE-B01"]}}}
```

`flaggedInGray`はUI-03だけ書く。全ての画面を採点すること。
