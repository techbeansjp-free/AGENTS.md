# 依頼：部品の技術資料の検索画面

産業用部品メーカー（架空）が、取引先の設計担当者向けに、部品を探して仕様と在庫を確かめる画面を1枚作りたい。データは `data.json`（同じフォルダ）にある。この画面ではデータをファイル内に埋め込んでよい（取得処理の実装は不要）。

## 利用者と使い方

- 取引先の設計担当者と購買担当者。主にPC（幅1440px程度）で、設計作業の合間に使う。外出先ではスマートフォン（幅390px程度）で在庫と納期だけを確かめることがある。
- 品番の一部・名称の語・分類で絞り込み、候補を比べ、1件の詳細（規格・在庫・納期・資料）を確かめる。

## 必ず満たすこと

- 検索欄（`<input type="search">`。品番と名称の部分一致）と、分類による絞り込みを置く。
- 一覧に、条件に合う部品の件数と、各部品の品番・名称・在庫の状態を示す。初期表示では全12件を一覧に出す。
- 初期表示で、一覧の先頭の部品の詳細（品番・名称・分類・規格・在庫の状態と数量・納期・改訂日・資料名）を示す。PCでは一覧と詳細を同時に見られるようにする。スマートフォンでは一覧から詳細へ移り、一覧へ戻れるようにする。
- 在庫の状態（在庫あり・残少・取寄せ・生産終了）を、色だけに頼らずに区別できる（文字・記号などを併用）。生産終了の部品には後継品を示す。
- 条件に合う部品が0件のとき、0件であることと、条件を解除する操作を示す。
- 長い品番でレイアウトが崩れない。

## 制約

- 単一のHTMLファイル（CSS・JavaScriptはファイル内に書く）。外部のURLから書体・スクリプト・ライブラリを読み込まない。
- 使える書体は `FONTS.md`（このフォルダ） を参照。

## 成果物

- `out/index.html`
- `out/DESIGN-NOTES.md`：主要な設計判断（情報の優先順位・配色・書体・構図など）と、それぞれをこの依頼のどの内容・利用者に対応させて選んだかを、短く書く。参考にしたものがあれば出典と、確認した範囲を書く。
