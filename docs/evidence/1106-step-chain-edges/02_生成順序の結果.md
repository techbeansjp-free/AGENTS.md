# 生成順序の結果

Issue #1106の副測度。**Step 5〜7の記録と、実装の開始が実時間でどちらが先か**を測る。

## 測り方

対象は除去試験と同じ選択基準の**63件**（full mode、到達Step 9以上、tracker重複排除）。

- **Stepの時刻**: `journal/steps.jsonl`の`recordedAt`。同じStepが複数回記録されている場合は**最初の記録**を採る
- **実装の開始**: mainのmerge commitからbranch側の範囲を取り、`src/`・`test/`・`scripts/`のいずれかを変更した**最初のcommitのauthor日時**

**H_implを使わない。** H_implはreview後の最終実装commitであり、**必ず遅い側に偏る。** 起票時の逸話（#1017）を確かめるには開始時刻が要る。

Issue番号はmerge commitのsubjectに現れるbranch名（`bugfix/1271-...`など）から引いた。**merge commitの本文にIssue番号は入らない。**

## 結果

| 観測 | 件数 |
|---|---:|
| 対象 | 63 |
| 判定できた | **59** |
| 判定不能 | 4 |
| 最初の実装commitが**Step 5の記録より後** | **47** |
| 最初の実装commitが**Step 5の記録より前** | **12** |
| 最初の実装commitが**Step 7の記録より後** | **47** |
| 最初の実装commitが**Step 7の記録より前** | **12** |

判定不能の4件は`942`・`1054`・`1204`・`1257`で、いずれもmainのmerge commitからbranch範囲を引けなかった。**内訳を隠さず記録する。**

## 差の分布

Step 5の記録から最初の実装commitまでの時間（正なら実装が後）。

| 統計 | 値 |
|---|---:|
| 中央値 | **+0.19時間**（約11分） |
| 最小 | −10.1時間 |
| 最大 | +44.2時間 |

「前」になった12件の差は次である（時間）。

`-0.05`、`-10.1`、`-0.06`、`-8.43`、`-0.19`、`-0.99`、`-9.03`、`-0.03`、`-0.21`、`-0.11`、`-0.14`、`-2.9`

**12件のうち7件は1時間未満のずれである。** 設計の記録と最初のcommitがほぼ同時刻に起きている。**大きく前後しているのは3件（8〜10時間）だけである。**

## 判定

**起票時の仮説「実装が先で文書が後」は、直近の母数では成立しない。**

- 59件中47件（**80%**）で、最初の実装commitはStep 5・Step 7の記録より後である
- 前になった12件のうち7件は1時間未満のずれであり、順序の逆転というより同時進行に近い

**起票の動機となった#1017の逸話は、母数の中では少数派である。** 逸話を一般化しなかったことが正しかった。

**ただしこの測度は「順序」しか見ていない。** 記録が先にあることは、その内容が実装の入力になったことを意味しない。**そこは除去試験が答える。**
