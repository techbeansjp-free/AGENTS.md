# Step chainの辺の除去試験 — 測定手順

> **これは検査ではなく観測である。** 合否を返さず観測値だけを残す。ここに置いたscriptを`package.json`のscriptsへ登録せず、CIからも呼ばない。**呼ぶと測定が検査に化ける。**

Issue #1106。実施日 2026-09-09。実施者はClaude Code（claude-opus-5）。

## 何を測るか

Step 0〜11は厳密なchainであり、各Stepは前Stepの完了を待つ。**「待つ」ことと「前Stepの出力を消費する」ことは別である。** 後者が成立していない辺があるなら、その待ちは費用だけを生む。

**辺が実在するかは、成果物を変えたときに後段の判定が変わるかで決める。** 印象を測度にしない。

## 判定を三分する

起票時の判定基準は「存在検査だけ」と「内容依存」の二分だった。**予備測定で二分では足りないことが分かったため三分にした。**

| 判定 | 意味 | 分離する変種 |
|---|---|---|
| 存在検査だけ | fileがあるかどうかしか見ていない | `delete`で落ち、`gut`で通る |
| 構造依存 | 節・表・IDの形は見るが、中身が当該Issueのものかは見ていない | `gut`で落ち、`swap`で通る |
| 内容依存 | 中身が当該Issueのものであることを見ている | `swap`でも落ちる |

**`gut`と`swap`の差が判定の核心である。**

## 変種

| 変種 | 操作 |
|---|---|
| `baseline` | そのまま |
| `delete` | 対象fileを消す |
| `gut` | 見出し行だけ残し、本文・表・箇条書きをすべて落とす |
| `swap` | **別Issueの同名fileと入れ替える** |

## 対象の選び方

**結果を見てから選び直さない。** 選択基準を先に固定した。

1. `.agent-skill-chain/tmp/issues/`と`.worktrees/`配下の全stagingを集める（82件）
2. `staging-record.json`の`mode`が`full`で、`journal/steps.jsonl`の到達Stepが9以上のものへ絞る
3. `tracker`（GitHub Issue番号）で重複排除し、到達Stepが大きい方を残す
4. 4成果物（00〜03）すべてを持つものへ絞る（63件）
5. **Issue番号の昇順で末尾12件**を取る（直近12件）

**要求は10件以上であり、12件はそれを満たす。** 生成順序の測定には63件すべてを使った。

## 実stagingを変更しない

**測定は複製に対してのみ行う。** 複製先は`/tmp/1106-work/trial`で、各観測の後に破棄する。`workflow record`の測定だけは`--staging`が`.agent-skill-chain/tmp/issues/`直下を要求するため、本worktree配下へ使い捨てのstagingを作り、測定後に削除した。

測定の前後で`git status --porcelain`に実stagingの変更は現れない。

## 決定性

**同じ入力で2回実行し、156観測が完全に一致することを確認した。** 比較は`observations.json`の全内容の等値比較である。

## 測定していないgate

**測った範囲を実際より広く見せない。**

| gate | 測定 | 理由 |
|---|---|---|
| `issue validate` | **した** | localで読み取りのみ。複製へ実行できる |
| `workflow record` | **した** | 使い捨てstagingを作って実行した |
| `issue sync` | **していない** | GitHubへの書き込みを伴う |
| `review round` | **していない** | git状態とreview sessionの整合を要求する |
| `pr create` | **していない** | providerとbranchの実在を要求する |
| `pr merge` | **していない** | 同上 |
| `audit:check` | **対象外** | stagingを読まない。`docs/reviews/`のartifactを読む |

**測定していないgateが内容を読んでいる可能性は否定できない。**
