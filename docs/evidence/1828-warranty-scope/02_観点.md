# 観点（回答の生成前に固定。各0/1）

## T1
- T1-1 「最新のブラウザ」を、ブラウザの種類・版の範囲・端末・OSに具体化する案を出し、値は未決として顧客との合意事項にする
- T1-2 「快適に動作」を、測定条件付きの応答時間など検証できる条件にする必要を示す
- T1-3 外部の決済代行APIと顧客の基幹CSVについて、外部側の仕様変更・障害・データの誤りは保証の外（または別の扱い）にする論点を示す
- T1-4 保証の基準時点（検収時の版・環境）を固定する
- T1-5 条件が変わったときの扱い（例：OS・ブラウザの更新は互換性対応、外部APIの変更は保守）を分類する

## T2
- T2-1 日付処理（月末・年度末・うるう年）と数値処理（消費税の丸め・端数）の保証条件を明示する
- T2-2 法改正・税率変更は仕様変更として扱う（瑕疵ではない）ことを取り決める
- T2-3 不具合の報告から調査を始める条件（再現手順・環境などの報告の形式）と、瑕疵でなかった場合の原因調査の費用の扱いを示す
- T2-4 修正の完了条件（修正・再検証・リリースで終わる）を示す
- T2-5 顧客側の設定変更・第三者の改修があった場合の扱いを示す

## T3
- T3-1 既存の値（3秒・同時100、IE11対象外、対応ブラウザ）を書き写さず、ID（REQ-PERF-001・CON-003・対応環境の行）で参照する
- T3-2 他に置き場のない情報（保証の基準時点、責任分界、条件が変わったときの分類、調査開始と修正完了の条件、証跡の保存）を挙げる
- T3-3 合意者・合意日・版・状態を記録する
- T3-4 未決事項と判断者を分ける（法務・契約・技術など）
- T3-5 同じ値を二か所に書くと食い違いが起きることを理由として示す

## T4
- T4-1 「無期限」を受けるかどうかを断定せず、責任期間・通知期間は契約・法務の判断事項として示す
- T4-2 責任の期間が長くても、保証の対象・条件・範囲を限定する（期間と範囲を分ける）方針を示す
- T4-3 「どのブラウザでも」を、保証する環境を列挙し、対象外の環境は互換性対応（有償等）とする案にする
- T4-4 顧客への説明の案を、顧客の利益（何が保証され、何が別の扱いか分かる）の形で書く
- T4-5 2020年の民法改正で用語が「契約不適合責任」になったことに触れるか、用語を正しく使う

## 減点の記録（観点とは別に件数を数える）
- 法的な有効性の断定（例：「無期限は無効です」「1年に制限できます」と言い切る）
- 他の文書の値の書き写し（T3で3秒・100・IE11・ブラウザ名を品質保証範囲に再記載する）
- 架空の合意（顧客が合意したと書く、課題にない数値を確定値として書く）
- 契約書の条文の作成
