# Phase 1 の評価計画（結果を見る前に固定、#1768）

owner 承認済み（2026-11-23、coordinator 経由）：時間と費用は合算せず別々に報告する。外部送信は行わず Host（Claude Code）だけで測る。費用上限は、非機密の局所 fixture で代表ケース数件 × 3条件 × 3回程度まで。

## 固定する条件

- Host：Claude Code（`claude -p`、`--output-format json`）。親モデルは `claude-sonnet-5-5`、委譲先は Agent tool の `model: "haiku"` 明示。権限は `dontAsk` と許可 tool の列挙（Read/Glob/Grep/Edit/Write/Agent/`npm test`/`node`）。1回あたり `--max-budget-usd 0.60`。
- fixture：決定論的に生成する14モジュールの小さな JS repo（秘密・実コードなし）。生成と実行の script は `harness/`。
- 課題：T1 検索（`fmtPrice` の呼び出し元の列挙）、T2 小変更（`fmtPrice` を小数2桁に）、T3 複数ファイル実装（呼び出し元5モジュールに割引を適用し、非呼び出し元は不変）。oracle は決定論的（答えの一致、`npm test`、挙動の検査）。
- 条件：A＝委譲せず単独（Agent tool 禁止）。B＝現行規則に沿う委譲（目的・範囲・完了条件を渡す、モデル明示）。C＝B に入力縮小（読む path・問い・返却形式だけを渡し、内容を貼らない）。D（任意 PoC）は A〜C に測定可能な不足がない限り実施しない。
- 各セル3回、順序は反復ごとに課題×条件を回す交互実行。cache 状態・provider の負荷は制御できず、ばらつきとして報告する。
- 記録：result JSON の `total_cost_usd`・`usage`・`modelUsage`・`duration_ms`・`num_turns`、wall-clock、およびローカルの session ログから親／子の usage を分けた値（子 session 数を含む）。親の再読込み・再試行は、親の assistant メッセージ数と tool 呼出し数で代理する。CI 費用は対象外（fixture のローカル検証のみ）。

## 採否の基準（評価前に固定。評価後に緩めない）

品質は、oracle の合格を3回全てで満たすことを必要条件とする。合格率が A より低い条件は、費用・時間が小さくても採用しない。

- 「改善あり」：品質の必要条件を満たしたうえで、課金費用（`total_cost_usd`）と wall-clock のどちらかで、3回の範囲（最小〜最大）が A と重ならずに小さく、もう一方が A の最大値を超えない。
- 「損」：課金費用または wall-clock の最小値が A の最大値を上回る。
- それ以外（範囲が重なる）は「差が不明」とし、採用しない。
- 採否：C または B がいずれかの課題種別で「改善あり」かつ他の課題種別で「損」でなければ、その課題種別に限った Skill の短い規則を検討する。全体で「改善あり」が出ない、または「損」が出れば、現行の `subagent-model-selection` を変更せず「実装不要（既存で十分）」または「不採用」とする。
- 独立レビューの Context は費用削減の対象にせず、本評価の条件にも含めない（レビューは全条件で同一に課す扱いで、今回は測定対象外）。

## 外挿しないこと

- 測るのは3課題・3回・1つの親／子モデル組・1つの時点の値である。他のモデル・実コード・大きな repo・cache 状態へ外挿しない。
- 価格は Host が返す `total_cost_usd` をそのまま使い、cache 割引などを推定で置き換えない。
