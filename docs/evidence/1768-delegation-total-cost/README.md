# 委譲の総費用と品質の評価：Phase 1 の結果と採否（#1768）

## 結論

**不採用（実装なし、Skill 変更なし）。** 現行の `subagent-model-selection` を変えない。 保留では終えない。Phase 1 の対照評価（Host=Claude Code、親 `claude-sonnet-5-5`、委譲先 `haiku` 明示、3課題×3条件×各3回の27件、全件 oracle 合格）を、結果を見る前に固定した [EVAL_PLAN.md](EVAL_PLAN.md) の基準で判定した。

- T1（検索）：費用は範囲が重なり差が不明、時間は委譲（B／C）の最小が単独（A）の最大を上回り「損」。
- T2（小変更）：B・C とも費用・時間の両方で「損」。
- T3（複数ファイル実装）：B・C の費用は A より低い（範囲が重ならない）が、時間は A の最大（32.8秒）を超える試行があり、基準の「改善あり」を満たさない。「損」にも当たらず、EVAL_PLAN の「それ以外」（差が不明、採用しない）として扱う。費用は範囲が重ならないが、時間が A の最大を超えるため、計画の括弧書き「範囲が重なる」には文字どおりは当たらない隙間である。
- 計画の規則「全体で『改善あり』が出ない、または『損』が出れば現行 Skill を変更せず不採用」により、不採用。小さい課題で委譲が損になることは、現行 Skill の「準備・待機・結果確認が本作業を上回るなら自分で行う」と一致する。新しい router・規則は足さない。
- 限界：3課題・n=3・単一モデル組・小さな合成 repo・1時点。cache 状態と provider 負荷は未制御（T1-A の1件目が突出して高いのは、当該試行の cache 作成が約37.6k token で他の約8〜9k より大きいため）。cache 作成（親、session ログ集計）は課題で向きが異なる：T1 は A 8.0k〜9.0k に対し B 10.2k〜11.6k・C 10.4k〜11.2k、T2 は A 8.7k〜8.9k に対し B 10.1k〜10.4k・C 10.4k〜10.9k（B／C が多い）、T3 は A 13.1k〜14.3k に対し B 12.0k〜12.4k・C 12.1k〜12.5k（A が多い）。最初の試行（T1-A-1）だけが cold cache で A に不利。これらと条件の実行順は制御しておらず、T3 の「費用は低い」にはこの差が混ざる。結論（不採用）は時間と T1／T2 の「損」に依るため変わらない。大きな repo・長い作業・他モデルへ外挿しない。「委譲が常に損」とも言わない。

- A でも haiku 系の model が `modelUsage` に現れる（約 0 USD、Host 内部の補助呼出し。委譲ではない）。

## 採否の根拠

1. 事前固定の基準（EVAL_PLAN）に当てはめた結果、T1・T2 で「損」、T3 は「改善あり」に届かず、規則どおり不採用。
2. 新機構（router・provider client・scheduler）は ADR 0005 の例外条件（対照評価で総費用の上での価値が示されること）を満たさない。
3. Phase 2（Jev 等の外部モデル）は、Phase 1 で決定論的な規則より改善できる選択の種類が特定されなかったため行わず、外部送信もしていない。

## 反証条件（この不採用を見直すとき）

- 大きな実 repo・長い作業・別モデル組で、委譲が品質を保ったまま費用と時間の両方で A の範囲を下回る反復観測が得られた場合は、課題種別に限った短い規則を再検討する。
- 特に T3 型（親が繰返し読込み・編集する作業）で、時間も改善する条件（例：並行実行できる複数の独立した子）が示された場合。
- Host が子 Agent の usage と課金額を親の起動に紐づけて標準で返すようになった場合は、計測の手間が下がるので再評価する。
- `subagent-model-selection` に従った委譲で、再試行や独立レビュー指摘の増加が反復して観測された場合は、Skill の最小是正を検討する。

### 委譲の理由の分類

#1673 の分類（検索・レビュー・実装）が既にある。本 Issue で次の区分を契約上の前提として置く。値の測定ではなく、判断の整理である。

| 区分 | 扱い |
| --- | --- |
| 独立レビュー | **費用削減を理由に廃止・非独立化できない必要条件。** 総費用の比較対象に含めるが、省く選択肢にはしない |
| 明確に独立した作業・並行できる作業 | 委譲の候補。準備・返却・再読込みが利益を上回るなら単独 |
| 広い探索 | 委譲の候補。低単価モデルでよいかは、結果を照合できるかによる |
| 判断の相談 | #1673 の規則に従う（節目だけ、必要な根拠だけを渡す） |
| 委譲しない | 小変更、準備・待機が本作業を上回る場合（既存 Skill が明記済み） |
