# 依頼：出荷オペレーションの監視画面

物流倉庫（架空）のシフト責任者が、当日の出荷の進み具合を監視し、問題のあるレーンに早く気付いて対処するための画面を1枚作りたい。データは `data.json`（同じフォルダ）にある。この画面ではデータをファイル内に埋め込んでよい（取得処理の実装は不要）。

## 利用者と使い方

- シフト責任者。PC（幅1440px程度）の常時表示と、巡回中のタブレット（幅800px程度）で見る。スマートフォンは対象外。
- 数秒で「今、対処が必要なものがあるか」を判断し、必要ならレーンの詳細（担当者・遅延件数）を見る。

## 必ず満たすこと

- `data.json`の全KPI（6項目）と全レーン（8件）を表示する。
- しきい値を超えたKPI・レーンを、色だけに頼らずに識別できる（文字・記号・位置などを併用）。
- データ取得に失敗しているデータ源（`sources`で`status: "error"`）について、失敗している事実・最後に成功した時刻・再試行の操作を示す。再試行ボタンは押せればよい（実際の再取得は不要）。
- 最終更新時刻を示す。
- 長いID（`lane.id`、`order_ref`）でレイアウトが崩れない。

## 制約

- 単一のHTMLファイル（CSS・JavaScriptはファイル内に書く）。外部のURLから書体・スクリプト・ライブラリを読み込まない。
- 使える書体は `FONTS.md`（このフォルダ） を参照。

## 成果物

- `out/index.html`
- `out/DESIGN-NOTES.md`：主要な設計判断（情報の優先順位・配色・書体・構図など）と、それぞれをこの依頼のどの内容・利用者に対応させて選んだかを、短く書く。参考にしたものがあれば出典と、確認した範囲を書く。
