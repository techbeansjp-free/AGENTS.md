# 設計メモ

## 情報の優先順位と構図（上から順に読む）
1. **対処が必要な項目のバナー（最上部）**：利用者は数秒で「今、対処が必要か」を知りたい。件数と該当項目（超過KPI・超過レーン・取得失敗のデータ源）を1か所に集約した。0件なら「対処が必要な項目はありません」を緑で出す。
2. **データ源の失敗**：バナー内に、失敗の事実・原因・最後の成功時刻（最終更新からの経過）・再試行ボタンを置いた。値が古いまま信用されるのを防ぐため。再試行は押せるだけで、押すと「再取得は行われない」旨を表示する（依頼で再取得は不要）。
3. **KPI 6項目**：1行6列（PC）、3列×2段（タブレット）。大きな数字＋目標＋しきい値を併記。
4. **レーン8件の表**：超過レーンを上に並べ替え。担当者・遅延件数・注文参照は「詳細を見る」で開く（巡回中に必要なときだけ見る使い方に合わせた）。遅延件数は一覧にも出す。

## 色以外の識別
超過は「⚠」記号、「しきい値超過／超過」の文字、太枠・左の太線、上への並び替えを併用（赤はそれらの補助）。

## 配色
白地・無彩色に近い灰＋赤（超過のみ）＋緑（異常なしのみ）。赤を超過専用にし、通常の進捗バーは青にした。赤の文字は白/薄赤背景でコントラスト比4.5以上を目安に選んだ（計算で確認はしていない）。

## 書体
Noto Sans CJK JP（日本語の可読性。常時表示のため）、ID・参照は DejaVu Sans Mono（英数字の判読）。数字は `tabular-nums` で桁を揃える。外部読み込みなし。

## 長いIDの扱い
表は `table-layout: fixed` ＋ `overflow-wrap:anywhere` で折り返し、枠外にはみ出さない。長い `LANE-B01-…`、`order_ref` で確認する想定の構造にしてある。

## しきい値の判定
KPIは `type`（min/max）に従い、下限割れ・上限超えを超過とした。レーンは `lane_delay_threshold`(8) を「超えた」（>8）もの＝B01(61)・C02(9)。判定は埋め込みデータから計算する。現時点の超過は「出荷遅延率」、B01、C02、データ源1件。

## 追加した判断
「締切超過」（最終更新時刻が締切以降で未出荷あり）の表示は依頼に無い補助情報。B01・C01が該当する。

## 参考・確認範囲
外部資料は参照していない。ブラウザーでの目視確認・実機（1440px/800px）での表示確認は**していない**。レイアウトはCSS上の想定（1100px以下でタブレット用の列構成に切替）。
