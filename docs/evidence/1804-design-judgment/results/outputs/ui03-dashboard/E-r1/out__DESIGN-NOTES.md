# 設計メモ

## 情報の優先順位（利用者：シフト責任者／「数秒で対処の要否を判断」）
1. **最上段に要対処サマリー**（「▲ 要対処 4 件」＋内訳：KPI／レーン／データ源）。依頼の「数秒で判断」に直接対応。0件なら緑の「✓ 対処が必要な項目はありません」。
2. **データ源エラー**をサマリー直下に配置。失敗の事実、エラー内容、最後に成功した時刻（最終更新からの経過時間付き）、「再試行」ボタン。冷蔵庫温度センサーの数値は古いままなので、見落とすと判断を誤るため上位に置いた。再試行は受付表示のみ（実取得なし）。
3. **KPI 6項目**：大きな数値＋目標＋しきい値を併記。
4. **レーン 8件**：しきい値超過を先頭に集め、遅延件数の多い順。詳細（担当者・遅延件数・進捗・注文参照）は常時表示し、クリック操作なしで見られる（巡回中のタブレットで操作を減らすため）。

## 色に頼らない識別
- 超過した KPI／レーンは「▲」記号＋「しきい値超過／要対処」の文字、太い枠線（KPI）・左端の太線（レーン）・先頭への並び替えを併用。正常は「✓ 範囲内」。
- 赤（#b3261e）は「超過」専用。それ以外の色は意味を持たせていない（進捗バーは青灰）。
- 判定は `data.json` のしきい値どおり：KPI は min 未満／max 超過、レーンは `lane_delay_threshold`(8) を超える遅延。結果は 出荷遅延率(12.4%>5%)、LANE-B01(61件)、LANE-C02(9件)、冷蔵庫温度センサー。出荷進捗率は目標未達だがしきい値(58%)内なので超過扱いにしていない。
- 補足として、締切を過ぎて未完のレーンに「締切超過・未完」と表示（LANE-B01）。これは依頼のしきい値ではなく、14:32 時点の締切との比較による参考表示。

## 書体
- `FONTS.md` の範囲のみ：本文は Noto Sans CJK JP（長時間の常時表示で可読性の高いゴシック）、ID・注文参照は DejaVu Sans Mono（0/O、1/l の判別がしやすい）。数値は `tabular-nums` で桁を揃える。Web Font・外部読込なし。
- 最小文字サイズは 12px（注文参照のみ）、他は 13px 以上。

## 構図・レスポンシブ
- 白カード＋薄灰背景の低装飾。強調は異常にだけ使い、異常が目立つようにした。
- 1440px：KPI 6列、レーンは表形式（1行目 ID／運送会社／遅延／進捗／状態、2行目 注文参照）。
- 800px（〜1100px）：KPI 3列×2、レーンは1件ごとのカード状に再配置。
- 長いID：等幅で `overflow-wrap:anywhere` により折り返し、グリッド子要素に `min-width:0` を指定してはみ出しを防止。

## 参考・確認範囲
