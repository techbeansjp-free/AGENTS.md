# 設計メモ

## 情報の優先順位（利用者：シフト責任者／「数秒で対処要否を判断」）
1. **総括バナー**（最上部）：しきい値超過の件数と対象名。数秒で判断する用途に直結。現データでは KPI「出荷遅延率 12.4%（>5%）」、レーン B01（遅延61件）・C02（遅延9件）の計3件。
2. **データ源エラー帯**：温度センサー取得失敗・最終成功 10:42（3時間50分前）・「再試行」ボタン。値が古い可能性は判断に影響するため、KPIより上に置いた。
3. **KPI 6項目**：大きな数字＋目標＋しきい値＋状態ラベル。PCは6列、タブレット（≤1100px）は3列×2。
4. **レーン8件**：遅延超過レーンを上、以降は遅延件数順に並べ替え。担当者・注文参照・フルIDは行を開いた詳細に置き、通常時の密度を抑えた（要件「必要なら詳細を見る」）。
5. データ源一覧・最終更新時刻（ヘッダー右）は補助情報。

## 配色
- 中立の白・グレー地に、赤（超過）と琥珀（データ源異常）の2色だけを意味に割り当て。正常は緑の文字と ✓。
- 色だけに頼らない：超過は「▲ しきい値超過／▲ 要対処」の文字、枠線の太さ、レーンは左端の太線と行の位置（上寄せ）を併用。エラーは「⚠」＋文言。
- 文字色は白/淡色地に対し十分なコントラストの濃色を使用（目視確認のみ、計測ツールでの検証は未実施）。

## 書体
- Noto Sans CJK JP（本文・数字）。IDは DejaVu Sans Mono（等幅で桁・英数字の判別が容易）。FONTS.md の範囲のみ指定、外部読込なし。
- 数字は tabular-nums で桁を揃え、更新時の見た目のずれを防ぐ。

## 構図・レイアウト
- 1カラム縦積み（総括→異常→KPI→レーン）。常時表示のPCでも巡回タブレットでも視線が上から下に流れる。
- タップ対象（再試行ボタン・レーン行）は高さ44px以上。
- 長いID：一覧では1行で省略表示（`text-overflow: ellipsis`、全文は title と詳細に表示）。詳細では `overflow-wrap:anywhere` で折り返し、レイアウトを崩さない。

## 判断の前提（要確認）
- 「しきい値を超えた」は厳密な不等号で判定（遅延 >8、max型は >、min型は <）。境界値の扱いは未確認。
- 出荷進捗率は目標（64%）未達だがしきい値（58%）内のため「正常」とした。出荷済み件数は threshold が null のため監視対象外と表示。
- 「何分前」は固定データの最終更新時刻を基準に計算（実運用では現在時刻に置換）。
