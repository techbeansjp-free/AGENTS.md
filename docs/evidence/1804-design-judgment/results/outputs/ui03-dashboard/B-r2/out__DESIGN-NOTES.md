# 設計メモ

## 前提（依頼から）
- 利用者はシフト責任者。PC常時表示（約1440px）と巡回中のタブレット（約800px）。数秒で「対処が必要か」を判断し、必要ならレーン詳細（担当・遅延件数）を見る。

## 判断と対応

| 判断 | 依頼・利用者との対応 |
|---|---|
| **最上段に「要対処 N件」を置く**。KPI・レーン・データ源の問題を1か所に集約し、各項目から該当箇所へリンクする。問題がなければ「対処が必要な項目はありません」と明示。 | 「数秒で対処の要否を判断」に直結。今回のデータでは、出荷遅延率（12.4% > 上限5.0%）、レーン B01（遅延61件）と C02（遅延9件、しきい値8件超）、冷蔵庫温度センサーの取得失敗の計4件。 |
| **情報の順序**：要対処サマリ → KPI 6項目 → レーン 8件 → データ源。 | 判断→概況→詳細の順。レーン詳細は「必要なら見る」ものなので下に置く。 |
| **色だけに頼らない識別**：「⚠ 要対処」の文字ラベル、太枠（3px）、レーン行は先頭への並び替えと左の太い帯、データ源は「取得失敗」の文言。正常側にも「✓ 範囲内／完了／通常」を出して比較できるようにした。 | 必須要件。白黒表示や色覚の違いでも、文字・記号・位置・線の太さで区別できる。 |
| **配色**：淡い青灰の地、白のパネル、濃い紺灰の文字。警告色の赤（#b3261e）は「要対処」にだけ使い、それ以外は無彩色寄りにした。 | 常時表示で目が疲れにくく、赤が出たときだけ目に入る。警告色を他の用途に使わないことで、「赤＝対処」が一貫する。 |
| **書体**：Noto Sans CJK JP（本文・数値、太さ500/700で階層化）。ID・注文参照は DejaVu Sans Mono。数値は等幅数字（tabular-nums）。 | FONTS.md の閲覧環境で確実に使える書体のみ。ID は桁が揃うと目で照合しやすいため等幅にした。 |
| **KPI の大きな数値（34px）と目標・しきい値を併記**。しきい値が `null` の「出荷済み件数」は「しきい値 なし」と表示し、判定はしない。 | 離れた位置から見ても値が読める。目標とのずれ（進捗率61.2%は目標64.0%未満だが下限58.0%以上なので範囲内）を区別して示す。 |
| **レーン表**：出荷/計画（件数・%・バー・残件数）、遅延件数（24px）、締切、担当を1行で見せる。詳細を開く操作は不要にした。 | 「必要ならレーンの詳細（担当者・遅延件数）を見る」を1画面で完結させる。クリックの手間を省く。 |
| **長いIDは折り返す**（`overflow-wrap:anywhere`、列幅は割合指定）。省略記号で切らない。 | 長いID（`LANE-B01-TOHOKU-REFRIGERATED-COLDCHAIN` など）を切り捨てると別レーンとの区別がつかなくなるため。 |
| **データ源の失敗**：枠付きで「取得失敗」、エラー内容、最後に成功した時刻（10:42、更新時刻から3時間50分前）、「再試行」ボタン（44px高）を表示。押すと受付メッセージのみ出る。正常な2件は小さく表示。 | 必須要件。値が古い可能性があることを文で伝える。 |
| **最終更新時刻**は右上に22pxの太字で表示。 | 必須要件。常時表示画面で鮮度を確認できる。 |
| **レイアウト**：1440pxはKPIが6列、800pxは3列×2段。データ源は800pxで縦積み。 | PCとタブレットの2つの閲覧環境に対応。スマートフォンは対象外のため最小幅760pxとした。 |
| **動き**は付けない。キーボードフォーカスは太い枠で可視化。 | 常時表示で動きは注意を散らす。 |

## 前提・判断を置いた点
- レーンのしきい値は「遅延件数が `lane_delay_threshold`（8）を**超える**」と解釈した（9件のC02は対象、5件のB02は対象外）。「8件ちょうど」が該当するかは依頼から読み取れない。該当するレーンはないため現状の表示には影響しないが、運用ルールの確認が必要。
- KPIのしきい値は `min` は「値が下回る」、`max` は「値が上回る」を超過とした。
- 「締切を過ぎたレーン」の強調は、依頼にないため行っていない。現在時刻の基準（最終更新時刻か実時刻か）の判断が必要になる。
- データ源（冷蔵庫温度センサー）とレーン B01（冷蔵）の関連は、データから断定できないため画面では関連付けていない。

## 参考にしたもの・確認した範囲
- 参照したのは `BRIEF.md`、`data.json`、`FONTS.md`、このフォルダの `frontend-design` スキルの指針のみ。外部の事例・資料は参照していない。
- 確認範囲：コードとデータの突き合わせ（しきい値判定の結果）を読んで確認した。**ブラウザでの表示確認（1440px/800pxの見た目、長いIDの折り返し）は行っていない。**
