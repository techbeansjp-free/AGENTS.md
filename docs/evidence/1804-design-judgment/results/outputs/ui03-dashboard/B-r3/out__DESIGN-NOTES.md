# 設計メモ

## 情報の優先順位（利用者：シフト責任者／数秒で「対処が要るか」を判断）
1. **判定バナー（最上部）**：「▲ 対処が必要: 4件」と内訳（超過KPI・遅延レーン・取得失敗・締切超過）。依頼の「数秒で判断」に対応。
2. **データ源の状態**：取得失敗は赤枠で、失敗の事実・原因・最後に成功した時刻（10:42、最終更新から3時間50分前）・「再試行する」ボタンを1か所にまとめた。失敗中の値は古い可能性があるため、KPIより上に置いた。冷蔵レーン（B01）は温度センサーの失敗と重なるため、気付きやすい位置が妥当と判断した。
3. **KPI 6項目**：並びは固定（常時表示で位置を覚えられるように）。超過は出荷遅延率のみで、赤の塗りつぶし＋「▲ しきい値超過」の文字で強調。
4. **レーン 8件**：しきい値超過（遅延件数 > 8：B01=61、C02=9）を上に、次に締切超過で未出荷が残るレーン、通常、完了の順に並べ替え。担当者・遅延件数は行内に常時表示（詳細を開く操作を省くため）。

## 色だけに頼らない識別
- 文字ラベル（▲遅延超過／◆締切超過／✔通常／出荷完了）、記号、行の左端の太線、並び順（上位）を併用。
- 赤（#b3261e）は「要対処」にだけ使用。正常側は緑の文字と記号のみで、面は塗らない。白地・赤塗り上の白文字ともコントラスト比 4.5 以上を想定した色を選んだ。
- ◆締切超過はデータのしきい値ではなく、最終更新時刻と各レーンの締切から算出した参考表示。凡例に明記した（C01は締切13:30を過ぎて9件残り、B01は14:00を過ぎて222件残り）。ただしB01は遅延超過が優先され「▲」表示になる。

## 配色
倉庫の事務所の蛍光灯下／常時表示を想定し、背景は青みのある薄いグレー（#e9edef）、文字は濃い青灰（#17252d）。赤は警告専用、緑は正常の文字のみ。装飾的なグラデーション・影は不使用。

## 書体
FONTS.md に従い Noto Sans CJK JP のみ（フォールバック DejaVu Sans / Liberation Sans）。外部読込みなし。数値は `tabular-nums` で桁を揃え、重要な数値は weight 900、補助情報は 13–14px・通常太さで階層化。遠くからの視認のため最小文字は12–13px（タブレット用の補助ラベル）に抑えた。

## 構図・レスポンシブ
- 1440px：KPI 6列横並び、レーンは「状態｜ID・運送会社・注文参照｜進捗バー｜遅延｜締切｜担当」の表形式。
- 800px（〜1100px）：KPIは3列×2、レーンは行内を2〜3段に組み替え（ヘッダー行は非表示にして各値に小ラベルを付与）。スマートフォンは対象外のため最適化していない。
- 長いID（lane.id、order_ref）は `overflow-wrap:anywhere` ＋ `word-break:break-all` で折り返し、グリッド列は `minmax(0, …)` として横あふれを防止。

## 動作
- データは `index.html` 内の定数に埋め込み。画面は定数から描画（文字は textContent で挿入）。
- 再試行ボタンは押すと、受付メッセージを表示するだけ（実際の再取得は行わない旨も表示）。aria-live で通知。
- 最終更新時刻はヘッダー右上に大きく表示。経過時間の計算は `updated_at` を「現在」として扱う（固定データのため）。

## 参考・確認範囲
- 外部の参考資料・テンプレートは使用していない。`.claude/skills/frontend-design` の指針（定型的な配色・全大文字ラベル等を避ける）のみ参照。
- **未確認**：ブラウザでの実表示（スクリーンショット・実機の幅1440/800px）は確認していない。コードの読み合わせのみ。コントラスト比も計算ツールでは測っていない。
