# 設計メモ

## 判断と対応

| 判断 | 対応する依頼内容・利用者 |
| --- | --- |
| **最上部に総括帯**「▲ 要対処 4件（KPI 1／レーン 2／データ源 1）」。0件なら「✔ 対処が必要な項目なし」 | 「数秒で、今対処が必要なものがあるか判断する」。詳細を読む前に有無と件数が分かる。 |
| **情報の順序**: 総括 → データ取得失敗 → KPI → レーン表 | 責任者の流れは「有無の判断 → どこが悪いか → 詳細」。データ源の失敗は、画面の数値が古い可能性を示すので KPI より上に置いた。 |
| **しきい値超過の表現は色＋記号＋文字＋位置**: 「▲ しきい値超過」「▲ 遅延超過」の文字ラベル、赤の太枠・左帯、レーンは表の上位に並べ替え。範囲内は「✔ 範囲内」と文字で示す | 「色だけに頼らず識別」。白黒印刷や色覚差でも、文字と位置で判別できる。常時表示の PC では、位置（上寄せ）で目を探さずに済む。 |
| **配色は低彩度の地に、赤系（異常）を1色だけ強く使う**。通常の進捗バーは灰青。琥珀色は参考情報（締切経過）のみ | 異常を目立たせるため、通常状態には彩度を使わない。常時表示で長く見ても疲れにくい。 |
| **データ源の失敗は赤い帯**に、失敗の事実・原因・最後の成功時刻（10:42、3時間50分前）・再試行ボタン（高さ44px）を1行で示す。正常な2源は画面下に小さく出す | 必須要件。「最後の成功からの経過」を併記し、巡回中のタブレットでも押しやすい大きさにした。 |
| **最終更新時刻**を右上に大きく表示（日付＋秒まで） | 必須要件。常時表示でも画面が止まっていないかを確認できる。 |
| **KPI は6枚を1段（1440px）／3×2（800px）**。値を最大の文字、下に目標としきい値の条件（「5.0%以下」）を添える | 6項目全部を一覧し、「目標との差」と「しきい値」を混同しない。しきい値のない「出荷済み件数」は「しきい値なし」と明記。 |
| **レーンは表形式**。ID／注文参照は1列にまとめ、等幅体の小さい字で任意位置で折り返す（`overflow-wrap:anywhere`、`table-layout:fixed`） | 比較しやすさと、長い ID（`LANE-B01-…COLDCHAIN`、`order_ref`）でレイアウトを崩さないため。遅延件数・担当は行内に常時表示し、操作なしで詳細まで読める。 |
| **書体は Noto Sans CJK JP**、数字は `tabular-nums`、ID は DejaVu Sans Mono | `FONTS.md` の範囲。日本語UIの可読性と、桁が揃う数字、ID の1文字ずつの判読性を優先。 |
| **「締切経過・未出荷」を参考表示として追加**（B01: 14:00 超過で222件未出荷、C01: 13:30 超過で9件未出荷） | データから導ける。しきい値判定ではないので、赤ではなく琥珀・別名称にして、注記で区別した。 |

## 判断材料と限界

- 入力は `BRIEF.md` `data.json` `FONTS.md` のみ。しきい値判定は `data.json` の値で計算（KPIは `threshold` と比較、レーンは `delayed > lane_delay_threshold`）。現在のデータでは、遅延率 12.4%（上限5.0%）、B01（61件）、C02（9件）、冷蔵庫温度センサーが該当。
- **参考にした外部の見本・文献はない**。アクセス手段がなく、近い業務画面の実物や制作資料は**未確認**（スキルが求める見本の実見は完了していない）。上の判断は依頼内容からの設計判断で、一般的な考え方（色以外の手がかり、重要情報を上に置く）によるもの。
- 実ブラウザでの表示確認（1440px／800px、実描画の書体、スクリーンリーダー）は**行っていない**。レイアウトは CSS から想定したもので、要目視確認。
- 冷蔵庫温度センサーの停止と冷凍レーン B01 の関連は、データ上は断定できないため画面では関連づけていない。
- 再試行ボタンは押下状態の模擬のみ（再取得なし）。
