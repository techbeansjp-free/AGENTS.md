# 設計メモ

## 情報の優先順位
1. **「今、対処が必要か」**（最上部のバナー）— 依頼の「数秒で判断」に対応。要対処のKPI・レーンを名前つきで列挙。異常なしの場合は緑の「✓ 異常なし」。
2. **データ取得失敗**（同じバナー領域）— 失敗の事実・エラー内容・最終成功時刻（「3時間50分前」の経過つき）・再試行ボタン。冷蔵庫温度センサーが10:42から止まっており、値が古いことを責任者が見落とさないよう上部に置いた。経過時間は実時計ではなく、データの最終更新時刻（14:32）を基準に計算。
3. **KPI 6項目** → 4. **レーン8件** → 5. **データ源一覧**（下部に常設）。

## しきい値の判定
- KPI：`threshold.type` が min なら値<しきい値、max なら値>しきい値で超過。現状の超過は「出荷遅延率 12.4%（上限5.0%）」のみ。出荷進捗率は目標未達（61.2 < 64.0）だがしきい値58.0は下回っていないので警告にしていない。
- レーン：`lane_delay_threshold`=8 を「超えた」（遅延>8件）と解釈。B01（61件）とC02（9件）が該当。8件ちょうどは超過扱いにしない（今回のデータには無い。仮置きの解釈）。

## 色だけに頼らない識別
赤＋「⚠」記号＋文言（「しきい値超過／未満」「要対処」）＋太枠・左帯＋レーンは並び順を先頭に。取得失敗は「✕」と文言。グレースケールでも判別できる。色は赤（要対処）・青灰（通常の進捗）・緑（正常）に絞り、装飾色は使わない。

## 書体
Noto Sans CJK JP（本文・見出し）。数値・ID・時刻は DejaVu Sans Mono（等幅・tabular-nums）で桁を揃え、巡回中でも読み比べやすくした。FONTS.md の範囲のみ使用。外部読込みなし。

## 構図とレスポンシブ
- PC（1440px）：KPIを6列1行、レーンは7列の表形式の行、データ源は3列。常時表示で全体が一覧できる。
- タブレット（〜1100px、800px想定）：KPIは3×2、レーンは行を折り返したカード状（ID全幅、数値は2段目）、データ源は縦積み。ボタンは高さ40px以上でタッチしやすく。
- 長いID：`overflow-wrap:anywhere`＋`min-width:0`で折り返し、レイアウトを崩さない（切り捨てないので全文が読める）。
