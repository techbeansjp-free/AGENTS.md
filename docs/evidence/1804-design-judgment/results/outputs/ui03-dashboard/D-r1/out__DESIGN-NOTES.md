# 設計メモ：出荷オペレーション監視画面

成功条件（一文）：シフト責任者が数秒で「今、対処が必要なものがあるか」を判断し、必要ならレーンの担当者・遅延件数まで辿れる。

## 主要な判断と、対応する依頼内容・利用者

| 判断 | 内容 | 対応する依頼・利用者 |
| --- | --- | --- |
| 情報の優先順位 | 上から ①対処が必要な件数の要約帯 → ②データ源の取得失敗 → ③KPI 6項目 → ④レーン8件。要約帯には超過したKPI・レーン・失敗データ源を名前付きで並べ、各項目へのページ内リンクを付けた。 | 「数秒で対処が必要か判断」。常時表示で一瞥する使い方なので、答えを最上部に置いた。 |
| 超過の示し方（色に頼らない） | 超過は赤枠＋淡赤の面に加え、「▲ しきい値超過」「▲ 要対処」の文字記号、レーンは一覧の先頭への並べ替え（位置）で示す。正常は「✓ 範囲内」「✓ 完了」。白黒印刷でも区別できる。 | 「色だけに頼らず識別」。 |
| データ取得失敗 | 黄の帯で「失敗：データ源名」「原因」「最後に成功した時刻（相対時間つき）」「古い可能性」を示し、44px高の「再試行」ボタンを帯の右に置く。`role="alert"`。押すと「再試行中…」→「まだ取得できていません（デモ）」と表示。正常なデータ源は小さく1行にまとめた。 | 「失敗の事実・最後の成功時刻・再試行」。冷蔵庫温度センサーが10:42から止まっており、冷凍レーン（B01）の遅延と併せて判断する材料になるため、KPIより上に置いた。 |
| 配色 | 地は温かい薄灰、本文は濃い墨、系列色は低彩度の青灰（進捗バー）。赤は「しきい値超過」、黄は「データ取得失敗」にだけ使い、他の意味に流用しない。 | 常時表示で長時間見るため、平常時は彩度を抑え、異常だけが目立つようにした。 |
| 書体 | 日本語は Noto Sans CJK JP（`FONTS.md` の指定書体）。数値・ID・注文参照・時刻は DejaVu Sans Mono＋tabular-nums。KPI値は34px太字。 | 桁をそろえて比較する数値と、長い英数字IDの照合には等幅が向く。ID類は小さく灰色にし、主役（遅延件数・KPI）を邪魔しない。外部フォントの読込みなし。 |
| 構図・幅 | 1440px：KPI 6列×1行、レーン4列×2行（超過2件は先頭行の左）。800px：KPI 3列×2行、レーン2列×4行。各レーンはカード1枚に、遅延件数（大）→進捗バー→担当・締切・注文参照をまとめ、詳細のために画面遷移しない。 | PC常時表示とタブレット巡回。スマホは対象外なので、狭幅は640px以下の最低限の1列対応にとどめた。 |
| 長いID | `lane.id`・`order_ref` は `overflow-wrap:anywhere` と `word-break:break-all` で折り返し、カードの `min-width:0` とグリッドの `minmax(0,1fr)` で幅を押し広げない。`title` に全文。最長は `ORD-…-COLDCHAIN-PRIORITY`（45字）。 | 「長いIDでレイアウトが崩れない」。 |
| しきい値の判定 | KPIは `min` なら値＜しきい値、`max` なら値＞しきい値で超過。レーンは遅延件数が `lane_delay_threshold`（8）**を超えた**場合（9件の北陸、61件の北日本冷凍が該当。ちょうど8件は未超過とした）。結果、超過は「出荷遅延率 12.4%（上限5%）」と上記2レーン。 | 出荷進捗率は目標64%に未達だがしきい値58%は超えていないため、超過扱いにせず目標と並べるだけにした。 |
| 最終更新 | ヘッダー右に太字で `03/08 14:32`。時刻はデータの文字列をそのまま表示し、閲覧端末のタイムゾーンに左右されない。 | 「最終更新時刻を示す」。 |

## 参考にしたものと確認した範囲

- 参照したのは、同梱の `anything-frontend-art-direction` スキル（`SKILL.md`、`references/visual-direction.md`）の手順と採用条件。余白・書体・構図の比較の観点（同時に見たい行が残る密度、ラベルと値を寄せる、色の役割を分ける、白黒でも状態が読める）を判断の確認項目として使った。
- **未確認：** スキルが挙げる外部の制作事例（CINRA、Linear 等）の実物や図は、この環境では開いていない。したがって「近い役割の見本を実見した」とは言えず、設計は上記の手順の観点とこの依頼の内容から決めたもの。
- **未実施：** 実ブラウザーでの1440px・800pxの表示確認、実描画された書体の確認、二案の比較。レイアウトは CSS の設計上の想定であり、実測していない。
- スクリーンリーダーでの確認は行っていない（`role="alert"`、`aria-live`、ボタンのフォーカス表示は実装済み）。
- 利用者本人の反応は得ていないため、好みに合ったとは記さない。
