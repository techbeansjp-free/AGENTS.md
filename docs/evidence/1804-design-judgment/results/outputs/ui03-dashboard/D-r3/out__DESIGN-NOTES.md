# 設計メモ：出荷オペレーション監視画面

## 判断と対応

| 判断 | 内容 | 対応する依頼・利用者 |
| --- | --- | --- |
| 情報の順序 | 上から「判定バナー → データ源の失敗 → KPI 6項目 → レーン8件」。バナーに要対処の一覧（KPI超過2件・レーン2件・取得失敗1件）を文字で出す。 | 「数秒で今、対処が必要かを判断」。KPIとレーンを見比べなくても、最上部で答えが読める。 |
| 識別は色＋記号＋文字＋位置 | 超過は「▲ 要対処／▲ 基準超過」の文字付きバッジ、太い枠、レーンは行頭の太線。レーンは要対処を表の上に並べ替える。正常は「✓ 基準内／通常／完了」、基準のないKPIは「– 判定なし」。 | 「色だけに頼らない」。白黒表示でも、記号・文言・位置で区別できる。 |
| 超過の判定 | KPIは `threshold` の min/max に従う（今回の超過は出荷遅延率 12.4% > 5.0% の1件）。レーンは遅延件数が `lane_delay_threshold`（8）を**超える**もの（B01=61件、C02=9件）。 | データ定義のとおり。8件ちょうどは超過にしない（今回は該当なし。要確認）。 |
| 取得失敗の表示 | 黄の枠で「失敗の事実・エラー内容・最後に成功した時刻（10:42、3時間50分前）・再試行ボタン」を出す。ボタンは44px以上で、押すと「再試行中…」の後に模擬である旨を出す。正常なデータ源は小さく1行にする。 | 失敗を赤（業務の超過）と混ぜず、別の種類として見分けられる。「3時間50分前」は画面の最終更新時刻（14:32）を基準にした。 |
| 配色 | 暗い地（#12171d）に、通常は低彩度の青灰、要対処だけ珊瑚色（#ff8a6b）、データ源の失敗だけ黄。 | 常時表示のため、広い面を暗くして眩しさを抑える。通常時に色が少ないほど、異常が目立つ。文字は暗地に対して十分なコントラストをとった（実測は未実施）。 |
| 書体 | 本文は Noto Sans CJK JP。ID・注文参照は DejaVu Sans Mono。数値は `tabular-nums`。KPI値は36px・太字。 | `FONTS.md` の範囲内。IDは 0/O や桁の照合が必要なので等幅にした。数値は更新しても桁がずれない。 |
| 構図 | 1440px は KPI を6列1行、800px 前後は3列2行。レーンは表で、狭くなると締切・担当の列を順に畳む（担当はレーン名の下に移す）。 | PC常時表示とタブレット巡回。スマートフォンは対象外にした。 |
| 長いID | 列幅を固定し、`overflow-wrap:anywhere; word-break:break-all` で折り返す。省略記号は使わず全文を表示する。 | 「長いIDでレイアウトが崩れない」。照合に使う文字列なので切り捨てない。 |
| 詳細の出し方 | 担当者・遅延件数は開閉せず行内に常時表示。 | 「必要ならレーンの詳細を見る」。8行なので、クリック操作を増やさず一覧のまま見せた。 |

## 補足

- `B01` は冷凍レーンで、温度センサーの取得も失敗している。画面上は関連づけて表示していない。データ上に対応関係がなく、推測で結びつけないため。運用側で結びつけるかは要確認。
- 画面はデータをファイル内に埋め込み、JavaScript で描画している。外部通信はない。
