# 設計メモ：請求先の編集画面

| 設計判断 | 対応する依頼 / デザインシステム |
|---|---|
| 色・余白・書体は `tokens.css` の変数だけ使用。`billing.css` にも色や書体名の直書きなし。書体は `--font-sans`（Noto Sans CJK JP）で外部読込なし | DESIGN-SYSTEM 1項、依頼「外部URLを読み込まない」、FONTS.md |
| ヘッダー・ナビは `members.html` と同じ構成。「請求先」を `aria-current="page"` にした | DESIGN-SYSTEM 5項 |
| 部品は既存の `.app-header` `.page` `.card` `.btn` `.field` `.alert` を使用。新規部品は作らず、`billing.css` は画面固有の幅・並び・読み取り専用の見た目・情報用 `.alert--info` に限定。既存ファイルは未変更 | DESIGN-SYSTEM 2項、依頼「既存ファイルを変更しない」 |
| 全項目に見える `label`。必須/任意を文言で表示（色だけに頼らない）。書式の説明は `.field__hint` | DESIGN-SYSTEM 3項、依頼の入力項目 |
| 検証は保存時に実施。誤りは項目直下の `.field__error` に「何をどう直すか」を書き、`aria-invalid` と `aria-describedby` で結び付け。最初の誤り項目にフォーカス。入力値は消さない | 依頼「誤りを項目の近くに示す・入力を消さない」、DESIGN-SYSTEM 3項 |
| 画面上部に誤り件数と一覧（各項目へ移動できるリンク）を `.alert--danger` で表示 | 依頼の検証要件（補助）、DESIGN-SYSTEM 4項 |
| 名称の50文字は `maxlength` を使わず検証で判定（入力を黙って切り捨てず、超過を文言で伝える） | 依頼「50文字以内」「入力した内容は消さない」 |
| 郵便番号は全角数字・全角ハイフンを半角に読み替えて 7桁判定。ハイフンは任意 | 依頼「7桁の数字、ハイフンは任意」 |
| 保存中はボタンを `disabled` にして文言を「保存中…」にし、二重送信も JS で防止 | 依頼「保存中は押せない状態」 |
| 成功・失敗は `.alert--success` / `.alert--danger` で、「保存しました」「保存に失敗しました」の文言で区別。`role="status"` の領域に出し、読み上げ対応。失敗時は入力が残っていることを明記 | 依頼「成功・失敗を示す」、DESIGN-SYSTEM 4項 |
| 模擬保存：1秒後に成功。メールが `fail@example.com` なら失敗 | 依頼の例 |
| `?role=viewer` で閲覧状態：理由と依頼先を上部の通知に記載、各入力を `readonly`（`disabled` と違い読めて、フォーカス可能）、保存ボタンは無効で通知と `aria-describedby` で関連付け | 依頼「編集できない理由を示した状態」 |
| 入力欄・ボタンは既存の 44px 最小高、フォーカスは既存の `--focus-ring` を使用 | components.css（既存） |
