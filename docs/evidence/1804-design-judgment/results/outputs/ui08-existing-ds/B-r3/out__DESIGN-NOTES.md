# 設計メモ：請求先の編集画面

| 判断 | 対応させたもの |
|---|---|
| `tokens.css` / `components.css` をそのまま読み込み、`billing.css` は配置（2列・ボタン行）と無効状態の見た目だけにした。色・書体・余白はすべて変数参照で、値の直書きなし | DESIGN-SYSTEM.md「変数だけを使う」「部品を作り直さない」／依頼の制約（既存ファイル不変） |
| ヘッダーとナビは `members.html` と同一構成。`billing.html` に `aria-current="page"` を付けた | DESIGN-SYSTEM.md「全画面で同じ構成」 |
| 部品は `.page` `.card` `.field` `.btn--primary` `.alert` `.badge` を使用。必須は `.badge`「必須」と文言で示す（色だけに頼らない） | DESIGN-SYSTEM.md 部品の指定／依頼の必須・任意の区別 |
| 全項目に見える `label`。誤りは `aria-invalid` と項目直下の `.field__error` で示し、`aria-describedby` でヒント・エラーと結び付けた | DESIGN-SYSTEM.md 入力欄の規約／依頼「項目の近くに示す」 |
| 誤りの文言は「何をどう直すか」を書く（例：郵便番号は7桁の数字、現在の文字数など）。入力値は消さない。ブラウザ標準検証は使わず（`novalidate`）、同じ文言体系で自前検証 | 依頼「どの項目をどう直せばよいか」「入力した内容は消さない」 |
| 検証失敗時は画面上部に件数付きの要約（項目へのリンク）を出し、最初の誤り項目へフォーカス移動 | 依頼のエラー表示、キーボード利用への配慮 |
| 郵便番号は全角数字も受け付け（NFKC正規化）、ハイフンは任意 | 依頼「7桁の数字、ハイフンは任意」 |
| 保存中はボタンを `disabled`＋「保存中…」、二重送信は変数でも防止。成功は `.alert--success`「保存しました」、失敗は `.alert--danger`「保存に失敗しました」＋再試行の案内。`role="status"`/`role="alert"` で読み上げ | 依頼の保存状態／DESIGN-SYSTEM.md「文言で区別する」 |
| 模擬保存：1秒後に成功、`fail@example.com` は失敗（失敗後も再度押せる） | 依頼の模擬仕様 |
| `?role=viewer` で全入力欄と保存を無効化し、`.alert--danger` で「編集できない理由」と次の行動（権限者へ依頼）を表示 | 依頼の閲覧専用状態 |
| 書体は `--font-sans`（Noto Sans CJK JP）のまま。外部URL・外部ライブラリなし、JSは同ファイル内 | 依頼の制約／FONTS.md |
| 狭い画面では2列を1列にし、ボタンを全幅にした（入力欄・ボタンは既存の44px以上を継承） | 既存 `.btn` / `.field__input` のタッチ目標 |

## 既知の制約・未確認
- ブラウザでの実表示確認と自動テストは行っていない（コード上の確認のみ）。
- 無効状態の入力欄の文字色は `--color-text-muted` を使用。コントラストは未計測。
- `.alert` のフォーカス表示など最小限の補助は `billing.css` に置いた。共通化が必要なら `components.css` への取り込みを別途検討。
