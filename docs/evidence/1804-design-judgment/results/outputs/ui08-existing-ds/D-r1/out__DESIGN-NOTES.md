# 設計メモ：請求先の編集画面

| 設計判断 | 対応する依頼 / デザインシステム |
|---|---|
| `tokens.css`・`components.css` をそのまま読み込み、既存ファイルは変更しない。画面専用の配置だけ `billing.css` に置き、色・書体・余白はすべて `var(--…)` で参照（色の直書きなし） | 依頼「制約」／DESIGN-SYSTEM 1行目 |
| 部品は `.app-header` `.page` `.card` `.field` `.btn--primary` `.alert` を再利用。新しい部品は作らない | DESIGN-SYSTEM 2行目 |
| ヘッダーとナビは `members.html` と同じ構成。`請求先` に `aria-current="page"` を付けた | DESIGN-SYSTEM 5行目 |
| 全項目に見える `label`。必須/任意はラベル文言に「（必須）」「（任意）」と書き、色や記号に頼らない。形式・文字数はヒント文で事前に示す | DESIGN-SYSTEM 3行目／依頼の入力項目 |
| エラーは項目直下の `.field__error` に「何をどう直すか」を書き、`aria-invalid` と `aria-describedby` で結び付ける。入力値は消さない（再描画せず値を保持） | 依頼「保存で入力を確認」／DESIGN-SYSTEM 3行目 |
| 画面上部に件数と項目別の一覧（`.alert--danger`、各項目へジャンプ）を出し、先頭に移動。項目が多く画面外のエラーに気づけるようにするため | 依頼「どの項目をどう直せばよいか」 |
| 検証は郵便番号の全角数字を許容（NFKC）、ハイフン任意。名称は50文字、メールは形式のみ確認 | 依頼の入力項目 |
| 保存中は `disabled`＋`aria-busy`、ボタン文言を「保存中…」に変更し二重送信を防止。完了後に復帰 | 依頼「保存中は押せない」 |
| 成功・失敗は `.alert--success` / `.alert--danger` で、文言（「保存しました」「保存に失敗しました」）でも区別。`role="status"` で読み上げ。模擬は1秒後成功、`fail@example.com` で失敗 | 依頼／DESIGN-SYSTEM 4行目 |
| `?role=viewer`：理由を示す `.alert` をフォーム上部に表示、入力欄は `readonly`（値は読めて、背景を弱めて編集不可を示す）、保存は `disabled`、横にも理由を文言で表示 | 依頼「閲覧権限向けの状態」 |
| 書体は `--font-sans`（Noto Sans CJK JP）のみ。外部URL・外部スクリプトなし | 依頼「制約」／FONTS.md |

## 補足・未決事項
- 閲覧状態のアラートは既存部品に警告色がないため `.alert--danger` を流用（情報部品の追加はデザインシステム側の判断事項）。
- 入力欄の`readonly`時の背景は既存トークン（`--color-bg`, `--color-text-muted`）で表現。
- エラー一覧のリンク色は `inherit`（アラート色を継承）。
- ブラウザーでの実機確認は行っていない（コード上の確認のみ）。
