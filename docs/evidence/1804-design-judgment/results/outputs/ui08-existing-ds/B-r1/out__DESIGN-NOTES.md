# 設計メモ：請求先の編集画面

| 設計判断 | 対応 |
|---|---|
| `tokens.css`・`components.css` をそのまま読み込み、`.app-header`/`.page`/`.card`/`.btn`/`.field`/`.alert` を再利用。既存ファイルは未変更 | 依頼の制約／DS「部品を作り直さない」 |
| 色・余白・書体は `var(--…)` のみ。`billing.css` に色の直値・書体名なし。外部URL読込みなし | DS「トークンだけを使う」／依頼の制約・FONTS.md |
| ヘッダーとナビは `members.html` と同じ構成。「請求先」を `aria-current="page"` に | DS「全画面で同じ構成」 |
| 全項目に見える `label`。必須/任意は色だけでなく「必須」「任意」の文字で表示。50文字以内・郵便番号の書式は `.field__hint` で入力前に提示 | 依頼の入力項目／DS「見えるlabel」 |
| 検証は「保存」時（`novalidate` で独自処理）。誤り項目に `aria-invalid` と `.field__error` を付け、`aria-describedby`で結び付け。文言は「何をどう直すか」を具体的に（例：現在62文字） | 依頼「どの項目をどう直すか」／DS入力規則 |
| 誤り時は入力値を消さず、先頭の誤り項目へフォーカス。誤り件数を `.alert--danger` でも表示 | 依頼「入力内容は消さない」 |
| 郵便番号は全角数字を半角に正規化して `^\d{3}-?\d{4}$` で判定 | 依頼「7桁、ハイフン任意」 |
| 保存中はボタンを `disabled`、ラベルを「保存中…」に、二重送信も JS で防止。`aria-busy` を付与。動きを減らす設定ではスピナー停止 | 依頼「保存中は押せない」 |
| 成功・失敗は `.alert--success`/`.alert--danger` で、文言（「保存しました」「保存に失敗しました」）でも区別。結果表示へフォーカスを移し、スクリーンリーダーにも通知（status/alert）。失敗時も入力は保持 | 依頼／DS「色だけでなく文言で区別」 |
| 模擬保存：1秒後に成功、`fail@example.com` は失敗 | 依頼 |
| `?role=viewer`：理由を示す通知を表示し、入力欄は `readonly`（`disabled`だとキーボードで読めず、内容の確認や コピーができなくなるため）、保存ボタンは無効化し `aria-describedby` で理由に結び付け | 依頼「編集できない理由を示した状態」 |
| 閲覧の通知は `.alert` に情報用の色がないため、`billing.css` に `.billing__notice` を追加（共通部品は変更しない） | DS「画面固有の見た目は画面のCSS」（components.css冒頭の注記） |
| 1カラム・最大幅640px、タップ領域は既存 `.btn`/`.field__input` の44px | DS既存部品／モバイルでも崩れにくくするため |

## 補足
- 初期値は架空のサンプル値。実運用では保存済みの請求先を差し込む。
- 電話番号は任意かつ書式指定がないため検証しない。
