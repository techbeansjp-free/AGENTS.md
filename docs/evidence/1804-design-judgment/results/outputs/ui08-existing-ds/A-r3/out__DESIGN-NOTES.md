# 設計メモ：請求先の編集画面（app/billing.html）

| 設計判断 | 対応する依頼・デザインシステム |
|---|---|
| `tokens.css` → `components.css` → `billing.css` の順に読込み。既存ファイルは未変更 | 依頼「既存ファイルは変更しない」「画面専用CSSは billing.css」 |
| ヘッダー・ナビを `members.html` と同じ構成にし、「請求先」を `aria-current="page"` にした | DESIGN-SYSTEM「ヘッダーとナビは全画面で同じ構成」 |
| 部品は `.page` `.card` `.field` `.btn--primary` `.alert` を再利用。色・余白・書体は変数のみで、色の直書きと外部読込みはなし | DESIGN-SYSTEM 1・2項、依頼「外部URLから読み込まない」、FONTS.md |
| 全項目に見える `label`。必須は「（必須）」、任意は「（任意）」と文言で示し、色だけに頼らない。形式のヒント（50文字、郵便番号の例）は `.field__hint` に置いた | 依頼の入力項目、DESIGN-SYSTEM 3項 |
| 誤りは `aria-invalid="true"` と項目直下の `.field__error` で示し、`aria-describedby` で結び付けた。文言は「どの項目をどう直すか」を書く（例：「郵便番号は7桁の数字で入力してください」） | 依頼「どの項目をどう直せばよいか項目の近くに示す」、DESIGN-SYSTEM 3項 |
| 誤りがあるとき、上部に件数と項目別リンクの `.alert--danger` を出し、最初の誤り項目へフォーカスを移す。入力値は消さない。項目を直し始めるとその項目の誤りだけ外す | 依頼「入力した内容は消さない」 |
| 検証は `novalidate` + 自前の script。全角数字・各種ハイフンも郵便番号として受理する（NFKC正規化）。名称は `maxlength` で黙って切らず、超過を文言で伝える | 依頼の検証要件 |
| 保存中はボタンを `disabled`、表記を「保存中…」に変更。二重送信は script 側でも防ぐ。1秒後に成功、`fail@example.com` で失敗する模擬処理 | 依頼「保存中は押せない」「模擬でよい」 |
| 成功は `.alert--success`（`role=status`）、失敗は `.alert--danger`（`role=alert`）。「保存しました」「保存に失敗しました」と文言でも区別。失敗時も入力内容は残し、次の行動を案内 | DESIGN-SYSTEM 4項 |
| `?role=viewer` で、画面上部に編集できない理由と依頼先を示し、全入力欄と保存ボタンを無効化。保存ボタンから理由へ `aria-describedby` で関連付け | 依頼「閲覧権限のみの状態」 |
| `billing.css` には画面固有のものだけを置いた（フォーム幅、ボタン行、閲覧専用の通知枠、無効入力欄の見た目）。`components.css` には無い「情報」用の通知枠は、既存の `.alert` に新バリアントを足さず、画面側で `--color-*` のみで作った | `components.css` 冒頭「画面固有の見た目は画面のCSSへ」 |

## 未確認・前提
- ブラウザでの目視確認は行っていない（コードの読み合わせのみ）。
- 閲覧専用の通知枠が他画面でも必要になれば、デザインシステム側への `.alert--info` 追加を別途検討してください。
- メールアドレスの形式確認は簡易的なもの（`x@y.z`形）。
