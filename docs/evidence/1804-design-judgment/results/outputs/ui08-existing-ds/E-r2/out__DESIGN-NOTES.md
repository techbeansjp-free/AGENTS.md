# 設計メモ：請求先の編集（app/billing.html）

| 設計判断 | 対応する根拠 |
|---|---|
| `tokens.css`・`components.css` をそのまま読み込み、既存ファイルは未変更。画面専用CSS（`billing.css`）は変数のみ使用し、色の値・書体名を直接書かない | 依頼「既存のデザインシステムに従う／既存ファイルは変更しない」、DS「tokensの変数だけを使う」 |
| ヘッダー・ナビは `members.html` と同じ構成。「請求先」に `aria-current="page"` | DS「ヘッダーとナビは全画面で同じ構成」 |
| 部品は `.page`/`.card`/`.field`/`.btn`/`.alert` を再利用。作り直したのは余白・並びだけ（`billing.css`） | DS「同じ役割の部品を作り直さない」 |
| 全項目に見えるラベル。必須は「*必須」、任意は「任意」を文言で併記（色だけに頼らない）。形式・文字数の条件は `.field__hint` に事前表示 | DS「見える label」、依頼の項目・必須/任意の指定 |
| 誤りは各項目の下の `.field__error` に「どう直すか」まで書き、`aria-invalid` と `aria-describedby` で結ぶ。入力値は消さない | 依頼「どの項目をどう直すか／入力内容は消さない」、DS入力欄の規約 |
| 保存失敗（入力誤り）時は上部の `.alert--danger` に項目名つきの一覧を出し、各リンクで該当欄へ移動。先頭の誤り欄にフォーカス | 依頼「どの項目を直すか」。項目数が多く画面外の誤りを見逃さないため |
| 郵便番号は全角数字・全角ハイフンも半角に直して判定（7桁、ハイフン任意） | 依頼「7桁の数字、ハイフンは任意」 |
| 保存中はボタンを `disabled`、表記を「保存中…」にし、隣に説明文。二重送信も抑止 | 依頼「保存中は押せない」、DS `.btn:disabled` |
| 結果は `.alert--success`「保存しました。」／`.alert--danger`「保存に失敗しました。…内容はそのまま残しています」。文言で区別し、`role=status/alert` で読み上げ、フォーカスを移す。`fail@example.com` で失敗を模擬 | 依頼「成功・失敗を示す」、DS「色だけでなく文言で区別」 |
| `?role=viewer`：上部に理由の `.alert`（権限が閲覧者のため／誰に依頼すべきか）、全欄は `readonly`（値は読めて、フォーカス・コピー可）、保存ボタンは無効で隣に理由を併記 | 依頼「編集できない理由を示した状態」 |
| 外部読込なし。書体は `--font-sans`（Noto Sans CJK JP）のみ。スクリプトは画面内インライン | 依頼の制約、`FONTS.md` |

## 注意・未決事項
- 閲覧者の案内は、既存DSに「情報」用の `.alert` がないため `.alert--danger` を流用した。情報用の種別をDSへ追加するかは、DS管理者の判断が必要。
- 電話番号は任意で、依頼に形式の指定がないため形式チェックはしていない。
- 保存処理は模擬で、実際の通信は行わない。
