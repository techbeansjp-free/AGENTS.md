## 試行の扱い

- **生成の停止線**：生成の試行とprobeは、台帳の累計と次の予算の和が30 USD（上限40−余裕2−Fableの順位2回分の予約8）を超えるなら起動しない。順位の予算を残すため（再レビューL-d）。
- **実行の順**：[run-order.json](run-order.json)で固定した。各条件1回の隔離の確認（probe）の後、反復を外側に、ケースはUI-03・UI-07・UI-04の順、条件は奇数回B→S・偶数回S→Bの順に18試行を1つずつ行う。[harness/run-all.mjs](harness/run-all.mjs)はこの順だけを実行し、`run-trial.mjs`は、台帳で次に予約されていない計画の試行以外を拒否する。上限で止まっても、2条件の差は1試行以内である。
- **生成の失敗**（置換えの判断。`order.mjs`の`generationFailure`。試行のdirectoryだけで決まり、実行器と採点で同じ）：`meta.json`が無い、終了が0でない、結果が`success`でない（予算上限による停止を含む）、init eventの組込みtoolが`Read,Write,Edit,Glob,Grep,Skill`とMCPの3つでないか`browser`のMCP serverが`connected`でない、`out/index.html`が無い。
- **置換え（必須）**：条件・ケースごとに、計画の試行（1〜3回目）のうちk番目の生成の失敗を、番号3+kの試行で置き換える。置換えは全ての計画の試行の後に、同じ順で、`run-all.mjs replacements`だけが実行する。置換えの試行は、結果にかかわらず再び置き換えない。採点（`decide.mjs`・`make-blind.mjs`）は同じ規則（`order.mjs`の`countedTrials`）で数える試行を決める。それ以外の追加の試行は採点に含めず、別に報告する。
- **採点での失敗**：数える試行のうち、生成の失敗に加えて、描画・goldの判定・初期表示の判定のどれかが失敗した試行（`decide.mjs`の`failed`）。描画の失敗は生成物の性質なので置き換えず、指標ではSに最悪、Bに最良の値を入れる。
- **採点に使う試行の公開**：公開する記録は派生の記録だけ（`collect.mjs`）。traceとtool logはscratchに残す。
- **名前の一致**：採点と盲検の作成の前に、台帳の測定の予約（probe・順位以外）の名前、runsの下にある試行のdirectoryの名前、採点が数える試行と置き換えられた・使わない試行の名前の3つの集合が一致することを確かめ、違えば拒否する（`decide.mjs`の`runConsistency`）。予約した試行のdirectoryを消した場合も、予約しない試行のdirectoryがある場合も拒否される。
- **固定の確認**：採点と盲検の作成の前に、固定したfileが`results/fixation.json`の最後の記録と同じで、数える全試行の`meta.json`の`fixationSha256`・`fixedAtCommit`がその記録と一致することを確かめ、違えば拒否する。
- **読まれたか**：試行ごとに、ASCの本文（`.agent-skill-chain/skills/asc/SKILL.md`）、`implementation.md`、`user-journey-acceptance`の本文、`journeys.md`を、エラーなしの`Read`で読んだかを記録する（`reads.mjs`。導入された2つの写し`skills/`・`managed-runtime/skills/`のどちらでもよい。Skill toolの呼出し・Grepは読込みに数えない）。
- **候補の文が届いた試行**：Sの試行で、本文と、`implementation.md`または`journeys.md`の少なくとも一方を読んだもの。届かなかった試行（本文を読まない、本文だけ読んでreferenceを読まない）は、条件・ケースごとに件数を分けて報告する。Bでも同じ記録を取る。

## 測れる指標（決定論）

初期表示の判定は、#1807の描画用image（`asc-1807-tools:1`、`--network none`）で[harness/first-view.mjs](harness/first-view.mjs)が行う。ケースごとの幅・高さと項目は[cases.json](cases.json)の`firstView`で固定した。判定の間は、pageの時計を`cases.json`の`fixedNow`（データの更新時刻）に固定し、reduced motionとstyleでanimation・transitionを止め、読込み・書体の読込み・500 msを待つ（独立レビューL-5）。項目は空白を除いた文字の連なりで探すが、数字と`:`・`.`だけの項目（例：「48」「07:48」）は、前後が数字・`:`・`.`でない場合だけ一致とする。

| 指標 | 定義 | 判定での使い方 |
| --- | --- | --- |
| I1 答えの初期表示（主） | 狭幅・広幅のそれぞれで、scrollしない初期表示の範囲（幅×高さ）に見える文字に、依頼の問いへの答えの項目がすべて含まれ、指定の要素（UI-04の検索欄）が範囲内に表示されている幅の数（0〜2）。条件ごとに3試行の和（0〜6） | Sの和がBより大きければ「良い」、小さければ「悪い」 |
| I2 操作なしでは見えない必須情報（副） | 広幅の読込み直後に、ページの文字（script・style等を除く）にはあるが表示の文字（`innerText`）に無い、#1807 goldの必須項目の数。展開・切替え・hover・別画面の操作でしか見えない情報。条件ごとに3試行の和 | I1が同じとき、Sの和がBより小さければ「良い」、大きければ「悪い」 |
| 非劣化 | #1807と同じ：網羅率の最小値（Bの最小値−0.05以上）、axe-coreのserious・criticalのnode数の最大値、横scrollの試行数、外部への要求のある試行数 | Sが1つでも下回れば「非劣化の失敗」 |
| 手順の実行（参考） | 生成Agentが成果物を狭幅・広幅の両方で描画したか、2つ以上のHTMLを描画したか（#1807 `core-steps.mjs`）、screenshotの回数 | 効果の判定には使わない。候補の文が手順として動いたかの記述 |
| 答えまでの画面数（参考） | 項目ごとに、上から何画面分scrollすれば見えるか（1〜8、無ければ欠測） | 記述だけ |

失敗した試行は、Sでは最悪の値（I1は0、I2は99、網羅率0）、Bでは最良の値（I1は2、I2は0、網羅率1）に置き換える（#1804・#1807と同じ）。

## 順位の手順（盲検）

1. 全ケースの描画の後、[harness/make-blind.mjs](harness/make-blind.mjs)で、回ごとに、ケースごとに数える試行のうち**失敗でない試行だけ**の画面（最大6画面）を写す（独立レビューM-4）。各画面は`out/index.html`と、それが参照するfileだけ（M-1）。写すときに、HTMLとCSSのcomment、charset・viewport・Content-Type以外の`<meta>`を消し、`<title>`を「画面 <ID>」に置き換える（再レビューM-b）。IDと見る順は、実行ごとに乱数で作る種から決め、種はkeysの木にだけ置く。作成時に、その回のkeysの木とblindの木のsha256を台帳に記録する（再レビューM-d 2・3）。
2. 評価者の閉込め（再レビューM-a）：FableとCodexの両方を`asc host-session`で、対象＝起動先を回のblindのdirectoryにして起動する（Fableは`--restricted`のRead・Glob・Grep、Codexは対象だけを読めるpermissions profile）。加えて、回の間はruns・keys・render・他の回のblindのdirectoryをmode 000にする（[harness/rank-guard.mjs](harness/rank-guard.mjs)の`lock`、終わったら`unlock`。記録fileに追記）。依頼文は[harness/rank-prompt.txt](harness/rank-prompt.txt)（#1807の再採点と同じ。画面の数は`ORDER.txt`の行数）。相互の結果を見ない。
3. 台帳（M-3、再レビューM-d 1、[harness/budget.mjs](harness/budget.mjs)）：各回は開始前に予約する（Fableは4 USD、Codexは0で「費用の報告なし」）。評価者×回の番号ごとに1回だけ。起動自体が失敗した場合（host-sessionの`status.json`が無いか完了でない）に限り、再試行を1回。終わったら、keyを開く前に（lockのまま）、host-sessionの出力を確かめて精算する：Hostとmodel、起動先と対象が回のdirectory、session id、開始が予約の後・終了が精算の前、完了。`result.txt`と`status.json`のsha256とsession idを台帳に記録する。Fableの費用は`events.jsonl`の`total_cost_usd`から取る。予約・精算は、lockが掛かっていなければ拒否する。
4. `decide.mjs`は、評価者×回の完了した回が1つでない、出力が記録のsha256と違う、精算していない予約・想定外の名前・想定外の出力directoryがある、keysかblindの木が作成時の記録と違う、予約から精算までlockが続いていない、のどれかで拒否する。

## 隔離の確認（probe）

測定の前に、各条件1回、測定と同じ起動（同じsample projectの作り方・HOME・config・tool・MCP・model）に、debugの記録を加えて、[harness/probe.mjs](harness/probe.mjs)の依頼文で行う。生成Agentの文脈に、祖先の`CLAUDE.md`・ownerのmemory・ownerの設定・ownerのSkill・repositoryの指示が無いこと、案内文のblockとASCのSkillの一覧があること、実HOMEとこのrepositoryに置いた目印fileのReadが拒否され、目印の文字列がどの記録にも無いこと、debugの記録の指示・memory・設定のpathが試行のdirectoryかprogramの場所だけであること、hookが無いこと、組込みtoolとMCPが測定と同じことを確かめる。B・Sの結果を比べ、tool・Skillの一覧・gitの件名・modelが同じことを確かめる。どれかが不合格なら測定しない。probeは各条件1回（番号1）。その条件の1回目が判定済みで不合格の場合に限り、再試行を1回（番号2）だけ行える。それ以外のprobe、および測定の試行（probe・順位以外の予約）が台帳に1件でもある後のprobeは、`run-trial.mjs`と`probe.mjs markers create`が拒否する（`probe.mjs`の`probeRefusal`）。目印fileの作成はownerの確認が要るので、統括がownerの確認を`results/probe-approval.json`に記録してcommitするまで、`probe.mjs markers create`とprobeの起動は拒否される。probeの後の是正は、`harness/probe.mjs`だけを、独立レビューを通して`fixation.mjs refix`で直せる。

## 判定の規則

ケースごと（`decide.mjs`の`caseDecision`）：

1. **評価者ごとの向き**：2回の順位の平均を画面ごとに取り、SがBより上位の組の数U（同順は0.5）を、失敗でない試行の組だけで数える。組の数をPとして、U≥ceil(8/9×P)で「改善」、U≤P−ceil(8/9×P)で「劣化」（SがBより下の組がceil(8/9×P)以上。改善と対称。再レビューL-c）、それ以外は「差なし」。P=9なら8と1で、#1807の組の規則と同じ。Pに比例させる扱い（9組未満では改善がU≥ceil(8/9×P)、劣化はその鏡像、どちらかの条件で有効な試行が2未満なら未判定）は、**ownerが承認した（2026-11-26、会話。統括の記録）**。どちらかの条件で失敗でない試行が2未満なら、そのケースの順位は「未判定」。これは、失敗した試行を盲検から除いた（独立レビューM-4：失敗の画面を最下位に置くとSに有利になり得る）ことに伴う、測定の前の具体化であり、ownerの規則（U≥8/9）と同じ割合で、組が少ないほど厳しい。
2. **再現性**：同じ評価者の1回目と2回目の順位の相関（Spearman、6画面）を記録する。0.5未満の評価者は、そのケースで「採点の揺れ」とする（#1807の分析規則の下限）。
3. **判定できるか**：どちらかの条件で失敗が2試行以上なら「保留」。Sの採点に使う3試行のうち2試行以上で候補の文が届いていなければ「未判定（候補の文が読まれていない）」。どちらかの評価者が「採点の揺れ」または順位が「未判定」なら「未判定（順位を判定に使えない）」（独立レビューL-6：効果なしではない）。「保留」と「未判定」のケースは、判定できるケースに数えない（L-2）。
4. **効果あり**：判定でき（3に当たらず）、FableとCodexの両方が「改善」、指標（I1・I2）が「悪い」でなく、非劣化の失敗が無いとき。それ以外は「効果なし」。
5. **害**：両評価者が「劣化」、指標が「悪い」、非劣化の失敗のどれかがあるケース。

全体（`overall`）：

0. **実行の完全性**：計画の18試行と必要な置換えのどれかが無いまま終わった場合は**未判定（実行が途中で止まった）**。ただし、台帳の生成とprobeの費用（順位の回の予約・費用は数えない。再レビューM-c）に1試行の予算を足すと、生成の停止線（上限40−余裕2−Fableの順位2回分の予約8＝30 USD。再レビューL-d）を超える、つまり上限に達したことが台帳で示せる場合は、この規則で止めない。この例外は、最初の測定の予約より後にprobeの予約が1件でもあれば無効とする（測定の開始後に台帳を膨らませた場合）。数える試行のうち、どれかの条件・ケースで有効な（失敗でない）試行が1つも無ければ**未判定（有効な試行の無い条件・ケース）**。
6. 「効果あり」のケースが2つ以上、害のケースが無く、生成の費用の中央値の比（S/B）が3以下（#1807の基準）なら、**効果あり（取り込む）**。
7. 判定できる（「効果あり」か「効果なし」の）ケースが2つ未満なら、**未判定（取り込まない）**。
8. それ以外は**効果なし（取り込まない）**。効果ありが1ケースだけの場合もここに入り、どの案が効いたかを分けて確かめるかはownerに報告する。

結果の報告では、指標の値、評価者ごと・回ごとの組の数、再現性、読まれた試行の数を、判定と別に必ず併記する。順位の向きと指標の向きが食い違ったケースは、そのことを明記する。

## 限界

- 各条件3回で、1ケース6画面である。Uの基準（≥8）に偶然で届く確率は、差が無くても1評価者あたり約0.1ある（6画面の並びの20通りの組合せのうち2通り）。2評価者・指標・2ケース以上を同時に求めて、偶然の採用を減らした。逆に、小さな効果は検出できない。
- 審美は人の評価ではなくモデルの順位である。#1807では、同じモデルの2回の相関が0.38〜0.96と揺れた。
- 候補3案を一括で追記した条件で、どの案が効いたかは分からない（ownerの判断：効果があれば次に分ける）。
- 生成モデルは`sonnet`だけ、Hostは Claude Code だけ。モデルの更新で結果が変わり得る。
- 初期表示の項目は、依頼文から定めた文字列の有無で判定する。別の表記（例：時刻を「あと5分」とだけ示す）は見つからない扱いになる。
- 隔離のため、組込みtoolはRead・Write・Edit・Glob・Grep・Skillだけで、Bashは無い（#1807と同じ）。利用者の環境との意図した違いである。
- 候補の文、ケースの選び方（2幅の要求、design systemなし）、指標（両幅の初期表示の答え）は同じ考え方から作った。効果が出ても、選んだケースと指標が候補に合わせてあることを割り引く。適用しない場面での害は測っていない。
- 生成Agentには削除のtoolが無いので、Sの追記「比べるために作った採らない案は、成果物に残さない。」は測定の環境では完全には守れない（別の案のfileは`out/`に残り得る。盲検には写さない）。
