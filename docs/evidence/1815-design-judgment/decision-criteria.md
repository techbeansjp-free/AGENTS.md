## 試行の扱い

- **失敗**：生成の終了が`success`でない（予算上限による停止を含む）、init eventの組込みtoolが`Read,Write,Edit,Glob,Grep,Skill`とMCPの3つでない、`browser`のMCP serverが`connected`でない、`out/index.html`が無い、描画・goldの判定・初期表示の判定のどれかが失敗した試行（`decide.mjs`の`failed`）。
- **置換え**：失敗した試行に限り、同じ条件・ケースで番号4以降の試行を1回だけ実行でき、採点では失敗の代わりに数える。それ以外の追加の試行は採点に含めず、別に報告する。
- **読まれたか**：試行ごとに、ASCの本文（`.agent-skill-chain/skills/asc/SKILL.md`）、`implementation.md`、`user-journey-acceptance`の本文、`journeys.md`を、エラーなしの`Read`で読んだかを記録する（`reads.mjs`。導入された2つの写し`skills/`・`managed-runtime/skills/`のどちらでもよい。Skill toolの呼出し・Grepは読込みに数えない）。
- **候補の文が届いた試行**：Sの試行で、本文と、`implementation.md`または`journeys.md`の少なくとも一方を読んだもの。届かなかった試行（本文を読まない、本文だけ読んでreferenceを読まない）は、条件・ケースごとに件数を分けて報告する。Bでも同じ記録を取る。

## 測れる指標（決定論）

初期表示の判定は、#1807の描画用image（`asc-1807-tools:1`、`--network none`）で[harness/first-view.mjs](harness/first-view.mjs)が行う。ケースごとの幅・高さと項目は[cases.json](cases.json)の`firstView`で固定した。

| 指標 | 定義 | 判定での使い方 |
| --- | --- | --- |
| I1 答えの初期表示（主） | 狭幅・広幅のそれぞれで、scrollしない初期表示の範囲（幅×高さ）に見える文字に、依頼の問いへの答えの項目がすべて含まれ、指定の要素（UI-04の検索欄）が範囲内に表示されている幅の数（0〜2）。条件ごとに3試行の和（0〜6） | Sの和がBより大きければ「良い」、小さければ「悪い」 |
| I2 操作なしでは見えない必須情報（副） | 広幅の読込み直後に、ページの文字（script・style等を除く）にはあるが表示の文字（`innerText`）に無い、#1807 goldの必須項目の数。展開・切替え・hover・別画面の操作でしか見えない情報。条件ごとに3試行の和 | I1が同じとき、Sの和がBより小さければ「良い」、大きければ「悪い」 |
| 非劣化 | #1807と同じ：網羅率の最小値（Bの最小値−0.05以上）、axe-coreのserious・criticalのnode数の最大値、横scrollの試行数、外部への要求のある試行数 | Sが1つでも下回れば「非劣化の失敗」 |

## 順位の手順（盲検）

1. 全ケースの描画の後、[harness/make-blind.mjs](harness/make-blind.mjs)で、ケースごとに採点に使う6画面（B・S各3）を、条件名・試行番号・DESIGN-NOTES.md・成果物以外のHTMLを除いて写す。IDと見る順は種`asc1815-round<回>`から決まり、1回目と2回目で違う。keyは作業directoryの外に置き、全員の回答の後に開く。
2. 各回で、FableとCodexが、独立した新しいContextで、読取り専用で、[harness/rank-prompt.txt](harness/rank-prompt.txt)に従い、ケースごとに6画面へ1〜6の順位を付ける（#1807の再採点と同じ依頼文を6画面にしたもの）。相互の結果を見ない。起動はASCの`host-session`（#1807と同じ）。
3. 費用：Fableの各回は開始前に台帳へ4 USDを予約し（[harness/budget.mjs](harness/budget.mjs)）、Hostの費用で精算する。Codexの費用はHostで計算されないので欠測として記録する（#1807と同じ）。

## 判定の規則

ケースごと（`decide.mjs`の`caseDecision`）：

1. **評価者ごとの向き**：2回の順位の平均を画面ごとに取り、SがBより上位の組の数U（9組、同順は0.5）を数える。U≥8で「改善」、U≤1で「劣化」、それ以外は「差なし」（#1807の組の規則）。
2. **再現性**：同じ評価者の1回目と2回目の順位の相関（Spearman、6画面）を記録する。0.5未満の評価者は、そのケースで「採点の揺れ」とし、改善・劣化の根拠に使わない（#1807の分析規則の下限）。
3. **判定できるか**：Sの採点に使う3試行のうち2試行以上で候補の文が届いていなければ「未判定（候補の文が読まれていない）」。どちらかの条件で失敗が2試行以上なら「保留」。
4. **効果あり**：判定でき、FableとCodexの両方が「改善」、指標（I1・I2）が「悪い」でなく、非劣化の失敗が無いとき。それ以外は「効果なし」。
5. **害**：両評価者が「劣化」、指標が「悪い」、非劣化の失敗のどれかがあるケース。

全体（`overall`）：

6. 「効果あり」のケースが2つ以上、害のケースが無く、生成の費用の中央値の比（S/B）が3以下（#1807の基準）なら、**効果あり（取り込む）**。
7. 判定できるケースが2つ未満なら、**未判定（取り込まない）**。候補の文が読まれないので効果を言えない。
8. それ以外は**効果なし（取り込まない）**。効果ありが1ケースだけの場合もここに入り、どの案が効いたかを分けて確かめるかはownerに報告する。

結果の報告では、指標の値、評価者ごと・回ごとの組の数、再現性、読まれた試行の数を、判定と別に必ず併記する。順位の向きと指標の向きが食い違ったケースは、そのことを明記する。

## 限界

- 各条件3回で、1ケース6画面である。Uの基準（≥8）に偶然で届く確率は、差が無くても1評価者あたり約0.1ある（6画面の並びの20通りの組合せのうち2通り）。2評価者・指標・2ケース以上を同時に求めて、偶然の採用を減らした。逆に、小さな効果は検出できない。
- 審美は人の評価ではなくモデルの順位である。#1807では、同じモデルの2回の相関が0.38〜0.96と揺れた。
- 候補3案を一括で追記した条件で、どの案が効いたかは分からない（ownerの判断：効果があれば次に分ける）。
- 生成モデルは`sonnet`だけ、Hostは Claude Code だけ。モデルの更新で結果が変わり得る。
- 初期表示の項目は、依頼文から定めた文字列の有無で判定する。別の表記（例：時刻を「あと5分」とだけ示す）は見つからない扱いになる。
- 隔離のため、組込みtoolはRead・Write・Edit・Glob・Grep・Skillだけで、Bashは無い（#1807と同じ）。利用者の環境との意図した違いである。
