# 採否基準（モデル実行の前に固定）

対象：#1783。`cases.json`の正例7件（`asc-1`〜`ma-1`）と負例2件。条件はA（ASC単体）、B（共存・予算内）、C（共存・予算超過でASCの説明文が省略される）、F（Cに既存の目的別一覧への直接参照の文例を加える）。反復はA・Bが2回、C・Fが3回。

1. 問題の有無：Cの正例の到達または手順適用が、Bより3試行以上少ない場合、または正例のいずれかがBで2/2のときCで1/3以下の場合に「予算超過による劣化あり」とする。それ以外は「劣化を観測せず」とする。
2. 劣化を観測しなければ「現行方式で十分」とし、製品を変更しない。
3. 劣化があり、Fの正例の到達と手順適用がそれぞれBとの差2試行以内に戻り、負例で過剰適用が無ければ、既存経路で回復できると判断し「利用手順の限定改善」（診断と既存文例・予算設定の案内）とする。
4. 劣化があり、Fでも回復しない場合は、決定論の一覧観測で可視性を回復できる最小の変更（description・配布処理・既存reference）を探し、他のSkillの可視性を下げないことを確認できた場合だけ「既存Skillの限定改善」とする。確認できなければ「不採用」とし、Host設定の案内に限る。
5. 実行失敗・欠測は分母から除いて別に数え、未選択や合格に変換しない。費用上限：モデル実行全体で50 USD（list価格推定）。超える見込みになった時点で止めて報告する。
6. 評価結果を見た後に、この基準・`cases.json`・条件を変えない。
