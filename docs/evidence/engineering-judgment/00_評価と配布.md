# 設計判断・見積Skillの取り込みと評価

## 目的と配布範囲

提供された83原則から、他の案件でも使える判断基準を目的・適用条件・例外に分解した。対応は[原則対応表](01_原則対応.md)を参照する。発言の引用、個人・案件の識別情報、人物像からの推論は配布しない。

`engineering-judgment`は要求、実証、単純さ、利用者負担から設計案を比較し反証する。`estimate-and-scope`は契約範囲、調査と実装の見積、費用・キー・受入の責任分担を整理する。作業調整・移行・検証・Web受入の判断は既存専門Skillへ補完した。全Skillの一括起動、固定工程、独自hook、個人環境への導入は追加しない。

配布変更は `package.json` と `src/runtime-files.json` の正本inventoryに登録し、既存の両Host向け入口生成で14 Skillを扱う。両Host登録時は276 assets、上限は280から288へ変更する。2ファイル構成の旧Skillは両Host登録込みで6 assetsを保持するため、その2世代分12 assetsの余地を確保する。無制限に増やさず、289件の既存記録と現行276＋保持13件を拒否する。本文・参照のbyte一致、リンク、既存所有者の編集保護、保持preimage込みの境界を既存テストで確認する。このEvidenceディレクトリは開発時の検証資料であり、runtimeの配布対象に含めない。

## 比較方法と限界

モデルは全生成で `gpt-6.1-sol`、reasoning effortはmedium、各条件2回、各回は会話を継承しない別Context。採点は別Contextの同モデルhigh。8依頼を各400字以内で回答し、実作業・外部操作はさせていない。生成側には課題と指定したSkillだけを渡し、rubric・他条件の回答・過去の結論は渡していない。回答を生成する前に32観点を固定した。

各生成への共通指示は「8依頼を各独立した依頼として回答。各400字以内。必要な判断と提案を行い、実作業・外部操作はしない。rubric、他run、過去評価は読まない。回答に評価条件・Skill使用の有無・実験名を書かない」。Skillあり群には該当する本文を最初に読み、必要なreferenceを使う指示を追加。なし群にはSkill本文を読まない指示を追加した。

採点者には課題・rubric・匿名回答だけを渡し、各観点0/1と理由、根拠のない断定・過剰拒否を別記録させた。条件名をランダムなIDへ置換し、回答にSkill使用の自己申告がないことを確認した。公開するkeyは採点終了後に集計へ使用する。

- [課題](comparison/cases.json) / [固定rubric](comparison/rubric.json)
- 初期比較：[匿名回答](comparison/blind-answers.json) / [採点](comparison/blind-scores.json) / [対応キー](comparison/blind-key.json)
- 初期比較はSkillなし50/64、個人版2 Skill併用61/64、縮約した汎用版55/64だった。各条件2回の合計であり、64個の独立課題ではない。個人版の認証移行の1回答に、対象を失効済みセッションまで含むと断定する軽微な指摘があった。
- この結果から見積・責任分担・切替の承認等を落とさず一般化し、最終候補を再評価した。初期の55点を最終候補の評価とは扱わない。

課題は原資料を読んだ実装者が作成し、改善にも使用したため、未見の実務課題による汎化の証明ではない。8回答を同一Context内で生成している。なし群にもHostの共通指示・Skillのcatalog metadataはあり、完全な空Contextではない。個人版は2 Skill併用なので個々の寄与は分離できない。採点者は1モデルであり、その判断も絶対の正解ではない。この比較時点では自動発火は未測定だった。後続の[暗黙選択と参照読取り](02_暗黙選択と参照読取り.md)で限定した実測を追加した。実際の導入後の訂正頻度、全83原則の実効性、課金額は未測定。過去のClaudeでの評価とモデル・環境が異なるため点数を直接比較しない。

## 最終候補

最終候補は2 Skill併用で31/32・30/32、計61/64。凍結したなし群の回答を同時に再採点し26/32・24/32、計50/64だった。[匿名回答](final/blind-answers.json)、[採点](final/blind-scores.json)、[対応キー](final/blind-key.json)、[集計](final/results.json)を保存する。採点単位の差であり、成功率・統計的優越性や個人版との同等性の証明ではない。なし群の合計は同じだが、課題B/Hの個別採点が前回と異なり、採点者のばらつきも残る。

最終候補には、存在が確認されていない前任者や既存監視を前提にした軽微な指摘が2件ある。重大問題はなかったが、「全回答が正しい」とはしない。両候補とも障害是正と常時復旧代行の分離の記載が不足するケースもあり、全観点を埋めるために個別課題の正解をSkillへ追記することは避けた。

評価時の本文は[candidate-source-hashes.json](candidate-source-hashes.json)、初期比較の対象は[指紋](comparison/source-hashes.json)で識別する。原資料と過去生成の完全な実行traceは再配布していないため、過去点数を完全再現できると主張しない。

標準品質検査の初回は494件中481成功・1失敗・12 skip。失敗は14 Skill化で旧Skillのrename保持が282 assetsとなり、280上限を超えた回帰だった。fixtureを弱めず上限の必要量を見直し、rename保持・再導入と有限上限の両方を再検証する。
