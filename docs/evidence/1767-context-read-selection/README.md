開発時の検証資料であり、配布対象に含めない。通常のASC実行時に読み込ませない。

## 結論

**保留（新機構は試作しない。Phase 1へ進まない。Issueは閉じない）。** 追加の候補ランキング、索引、確率的selector（Jev等）を要するだけの「必要情報の取りこぼし」は実測されなかった。一方、「既存手段で足りる」と言える根拠も得られていない。同一sessionでの再読込みが多く見える（下記）が、必要性を判定できず、費用への寄与も分離できないためである。外部へのrepository内容の送信、実モデル実験、費用の発生は無い。

必要情報のrecall・miss率は、実行ログだけからは測れない。測れない範囲は欠測とし、再開条件を末尾に置く。

### 適用規則の選択と、コード・根拠の内容選択は別である

`projectContext`は、変更pathのprefixと祖先の`AGENTS.md`／`CLAUDE.md`から、規約ファイルのpath・SHA256・byte数を返す決定論的な処理で、本文もコード断片も返さない。コードやテストの関連度を順位付けする機構ではなく、`authority`欄も選択が意味的遵守を示さないと明記する。したがってコード・根拠の内容選択は、現状はHostの検索と`implementation.md`の規則が担う。この責務分担は評価の前提であって、不足の証拠ではない。

`implementation.md`は、検索で位置を絞ってから必要範囲だけ読む、`gh --json/-q`で項目を絞る、巨大出力を避けて全文をworktree外へ保存する、広い調査はsubagentへ渡し結論と参照だけを返させる、を既に要求している。SKILL.md原則1も再読込みの削減を挙げている。

## Phase 1以降を実施しない理由

Phase 1の前提は「Phase 0で測定可能な実害・費用と改善余地がある場合」である。再読込みの割合という兆候はあるが、必要性の分類と費用への寄与が測れておらず、実害とは言えない。ADR 0002の機構追加審査が求める「具体的な失敗」も示されていない。ADR 0005により、実測の価値と対照評価なしに新runtimeは採用しない。そのためA/B/Cの対照評価、決定論的scorer、Jev等のshadow評価は行わない。一方、既存手段で足りるという証拠も無いため「追加実装不要」とは結論せず保留とする。何も変更しないため、Phase 2の境界（`project-context.mjs`の契約、正本性、秘密の扱い）は維持される。

| 案 | 判定 | 根拠 |
| --- | --- | --- |
| A：現行Host＋ASC | 維持 | 不足は未実測 |
| B：既存検索の順序・構成の最小改善 | 規則は既にある。変更しない | 再読込みの必要性が未分類 |
| C：優先順位付け（Jev等を含む） | 未着手 | 前提のPhase 0条件を満たさない。送信許可・費用もowner確認事項 |

## 再開条件と、ownerへの確認事項（案）

次の場合に、新しいIssueまたはこのIssueの再開で、Phase 1へ進む。
- 実セッションで、必要fileの読み落としによる手戻りが、独立に判定できる形で複数件記録された。
- または、同種の大きな読込み・再読込みが総費用の目立つ割合を占めると、tokenまたは課金の実測で示された。

測定前に固定する基準の**案**（ownerが決める。独断で確定していない）：
1. 必須根拠のrecallは100%を条件とし、security-critical（認可・検証・規約）の欠落は1件でも不採用。理由：未知の関連箇所を省くと品質ゲートの前提が崩れ、Issueも自動除外を禁じている。
2. 品質（受入条件・テスト・独立レビュー指摘）が現行のベースライン以下に落ちたら、費用が下がっても不採用。理由：「速くなったが欠陥が増えた」を採らないとIssueが定めている。
3. 費用の優位は、同条件の反復の揺れを上回る場合だけ採用候補とする。案：1ケース3回以上の反復、費用上限は評価全体で既存の#1673規模の範囲に収める。値の根拠は弱く、ownerの指定を要する。
4. 外部のselector・モデルを使う評価は、データ送信先・課金・契約の承認後にのみ行う。

ownerへの確認事項：上記の採用閾値と反復数、費用上限、Jev等の外部評価を将来行う場合の送信許可。現時点の回答は不要（実施しないため）。再開する場合に必要になる。

## 限界

- ログは1台のlocal記録で、6 sessionと標本が小さい。Codex等の別Hostは調べていない。
- 本資料は実行ログの件数集計であり、品質・費用の対照実験ではない。
- 「不足が測れなかった」ことは「不足が無い」ことを意味しない。
