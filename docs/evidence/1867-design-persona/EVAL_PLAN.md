## 判定

1. **工程が使われたか（門）：** Sの試行で、`design-creation`の`SKILL.md`が読まれ、デザインの記録に利用者の像（根拠と仮説の区別つき）と、判断と利用者の対応がある試行を数える。ケースごとに3回中2回以上なら、そのケースは判定できる。判定できるケースが3未満なら、全体を「未判定」とする。
2. **層1（機械の判定）：** #1835の層1の道具で、全試行の画面を判定する。Sの不合格の数が、ケースごとにBより多いケースがあれば記録する。axeの重大・深刻な違反が、Bより多いケースが2つ以上あれば「不採用」とする。
3. **層3（ownerの盲検の比較）：** ケースごとに、Sの3回×Bの3回の9組、計36組をownerが比べる（条件名を伏せる）。
   - ownerがSかBを選んだ組（n）で、Sを選んだ数をk、片側の二項検定（偶然0.5、α 0.05）をかける。p ≤ 0.05なら効果あり。
   - nが24未満なら「未判定」。
   - **害の確認：** 業務の画面の各ケース（ui03・ui08）で、ownerがBを選んだ組がSを選んだ組より多ければ「不採用」とする。
   - 同じ回の画面が複数の組に入るので、組は独立ではない。p値は目安として扱い、その旨を報告する。
4. **結論：** 門を通り、層1・層2で不採用にならず、層3で効果あり、かつ害が無ければ「採用」。層3で効果が無ければ「不採用」。上の未判定の条件に当たれば「未判定」。配布するかはownerが決める。

## 層2（一対比較P）：明らかな差の警報

ownerの決定で使う。Pは良い案どうしの優劣を判定できない（#1852）。一方、片方に既知の種類の明らかな劣化があれば見分ける（#1835、強い劣化10/10）。そこで、Pを「明らかな差の警報」として使う。

- ケースごとに、同じ回のSとBの組（r1・r2・r3の3組）、計12組をPに比べさせる。評価者はFableとCodex（#1835と同じ。Codexの実行中はkeyとownerの対応表を`--lock`で閉じる）。各組を2回、IDと左右を変えて比べる。
- **警報：** ある組で、両評価者が2回とも同じ側を選んだら、その組を「明らかな差」とする。
- **害の判定：** あるケースで、Bを選んだ「明らかな差」の組が3組中2組以上あれば、そのケースで害があるとして「不採用」とする。
- Sを選んだ「明らかな差」は、効果の根拠には使わない（効果は層3で判定する）。件数は報告する。
- Pの結果は、ownerが層3の回答を記録した後に開く。
