# #1852 評価計画（ownerの比較とPの実行の前に固定する）

開発時の検証資料であり、配布対象に含めない。通常のASC実行時に読み込ませない。

Issue：[#1852](https://github.com/techbeansjp-free/AGENTS.md/issues/1852)。ownerの決定は同Issueのコメント（2026-11-28。費用の上限は訂正のコメント）にある。道具は[#1835](../1835-design-eval-layers/README.md)のものを使い、設定（`config/eval.json`）だけを変える。

## 1. 問い

自然に作られた良い案どうしの組で、一対比較（P）の判断がownerの判断と偶然以上に一致するか。#1835の層3（ownerが優劣を付けた6組）では、偶然と区別できなかった。

## 2. 組（36組）

- **画面：** #1804の3ケース（ui02-exhibition・ui03-dashboard・ui08-existing-ds）。4条件（A・B・D・E）×3回＝1ケース12画面。新たに画面は作らない。
- **組の選び方：** `harness/select-pairs.mjs`（seed `18520001`）。ケースごとに、条件の6通りの組合せ（AB・AD・AE・BD・BE・DE）からそれぞれ2組を選び、1ケース12組、計36組とする。
  - 同じ条件の組合せの2組は、両側とも別の回の画面にする。
  - #1835の層3の3組（A-r1〜D-r1・A-r1〜E-r1・D-r1〜E-r1）は選ばない。ownerがすでに評価者の結果と一緒に見た組だからである。
  - 選んだ組は`config/eval.json`の`layer3.pairs`にあり、試験が`select-pairs.mjs`の出力と一致することを確かめる。
- **描画：** #1835と同じ（`run-layer1.mjs`、`asc-1807-tools:1`、2幅）。元の画面だけを描画する。

## 3. 評価者とP

- **P：** #1835と同じ方式・依頼文（`../1835-design-eval-layers/prompts/P.txt`と共通の冒頭文）。1組を1回の呼出しで答える。2回採点し、IDとA・Bの割当てを回ごとに変える。
- **評価者：** Fable（`claude -p --model fable`）とCodex（`codex exec`、`gpt-6.2-sol`）。起動・隔離・欠測の判定は#1835と同じ（#1835 EVAL_PLAN 3節・5節）。Codexの実行中は、keyとownerの対応表を`--lock`で閉じる。
- **評価の軸：** 「依頼の利用者・目的に、どちらが合っているか」（#1835と同じ）。
- **D：** 記録しない。

## 4. ownerの比較

- #1835と同じ1枚のローカルHTML（`owner-page.mjs`）。36組を乱数のIDと順序で示し、各組で「A・B・同等・判断しない」から選ぶ。条件名と評価者の判断は示さない。外部へ送らない。
- ownerは、評価者の結果を見る前に回答を記録する（回答のJSONの`recordedAt`）。比較はPの実行の前でも後でもよい。

## 5. 判定（固定の後は変えない）

- **組ごとのPの判断：** 2回の判断が一致すればその判断、割れたら「同等」とする。どちらかの回に有効な回答が無ければ欠測とし、不一致として数える（採用の側に働かない）。
- **対象の組：** ownerが「A」か「B」を選んだ組だけ（n組）。「同等」「判断しない」の組は除く。
- **検定：** 評価者ごとに、Pの判断がownerの選択と一致した組の数kで、片側の正確な二項検定（偶然0.5、有意水準0.05）を行う。P(X≥k | n, 0.5) ≤ 0.05 なら、その評価者は「採用」、そうでなければ「不採用」。
  - 例：n=24なら17組以上、n=30なら20組以上、n=36なら24組以上の一致が要る。
- **結論：**
  - **採用：** 両方の評価者で「採用」。
  - **不採用：** どちらかの評価者で「不採用」。
  - **未判定：** nが24組（計画の36組の2/3）未満。または予算で止まった（台帳の停止）。
- **組の数の見込み：** ownerが3組に1組を「同等」とすると、nは約24組になる。真の一致率が0.75なら、採用と判定される確率は約0.77、0.8なら約0.91である。#1835のui03のように1ケースの全組が「同等」でも、残る2ケースの24組でnは24に届き得る。nが24未満になった場合は組を足さず、未判定とする（結果を見た後の組の追加は、一致を水増しするため）。
- **副次の報告（判定しない）：** 再現性（2回の判断の一致）、評価者間の一致、層1で不合格の画面を含む組を除いた同じ検定。
- 結果は3ケース・36組の規模である。ownerの判断は「ASCとしての基準」の代わりであり、一般の利用者や顧客の正解ではない。

## 6. 費用

- **上限：** Fableで18 USD（Hostが計算した値）。#1835のPは1回あたり約0.21 USDで、72回で約15 USDの見込みである。台帳の合計が上限に達したら止め、残りは欠測（結論は未判定）とする。
- Codexは費用の報告が無いため、tokenと時間を記録する。
- 試行はしない。#1835で同じ方式の1回あたりの費用を測っている。

## 7. 配布物

どの結果でも、配布物（`skills/`・CLI・`src/`）は変えない（ownerの決定）。

## 8. この計画で起票者が決めたこと

ownerの決定に無い細部は、起票者（Agent）が次のように決めた。理由は、結果を見る前に固定でき、どれも採用の側に働かないからである。

- 欠測を不一致として数えること。
- 予算での停止を未判定とすること（#1835の規則と同じ）。
- 2回の判断が割れた組を「同等」とすること（ownerの回答の「割れたら同等」をそのまま使った）。
- nが24未満でも組を足さないこと。
