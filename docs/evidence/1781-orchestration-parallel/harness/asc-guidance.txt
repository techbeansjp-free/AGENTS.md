以下は ASC v0.5（main c45a8abcb1441a034f3d0b53db22644b77a9fc7f）の skills/asc/SKILL.md「進め方の原則」1・3 と skills/subagent-model-selection/SKILL.md「仕事に必要な能力を選ぶ」の抜粋である。この作業ではこれに従う。Fable は使わない。

1. **品質と速度の両立を最重要とする**：要求・受入条件を満たし、必須の実検証・独立レビューを速度のために省かない。そのうえで完了までの時間を最小にし、品質に寄与しない待機・再読込み・同じ検証の繰返し・不要な確認を削る。
3. **並行できる作業を常に探す**：計画の時点で並行できる作業を洗い出して並行化を検討し、[作業の分担](../work-coordination/SKILL.md)の条件を満たし、許可・実行環境・調整の負担を踏まえて完了までの時間を短くできる作業を同時に進める（ASCでの扱いは[調整と引継ぎ](references/coordination.md)）。CI・レビュー・長い検証の待機中は、依存しない作業を進める。並行化は委譲の許可や独立レビューの系統数を増やすものではなく、分割の費用が上回る小変更は単独で進める。


| 仕事の性質 | 選択で確かめること |
| --- | --- |
| 範囲が狭い検索・抽出・定型変更 | 出力を容易に照合できるなら、低遅延・低費用の候補で十分か確認する |
| 複数箇所にまたがる実装・原因調査 | 関連経路を保持できるcontext、利用可能なtool、対象言語・テストを扱う能力を重視する |
| 不確実な設計・反例探索・高影響なレビュー | 複数の制約や失敗経路を比較する推論能力を確保する。高価な名前だけを保証としない |
| 独立レビュー | 実装者の会話・自己評価から分離したcontextで、要求と実体を確認できる起動方法を選ぶ。別モデルだけでは独立性は成立しない |

必要な能力を満たす候補から、入力規模・予想出力・遅延・費用・再試行の見込みを比較する。工程名で高価なモデルを固定せず、最安の候補へ難しい作業を無条件に割り当てない。Hostが指定できる場合は委譲時にモデルを明示し、親の高能力モデルを継承したまま検索・抽出・照合しやすい作業に使わない。高能力のモデルは計画の確定前・完了判断の前など判断が分かれる節目の相談先に限る選択肢も比べ、相談には判断に必要な計画・制約・検証結果だけを渡す。どのモデルを使っても、判断の正しさはモデル名や自己申告ではなく、成果物と検証結果で確かめる。モデル価格やcontext上限を具体的に比較する必要がある場合は、現在のHost情報や公式情報で対象版を確認する。特定モデルの順位表や古い価格をSkillへ固定しない。
