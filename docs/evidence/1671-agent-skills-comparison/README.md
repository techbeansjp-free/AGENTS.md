# addyosmani/agent-skills との匿名比較と、user-journey-acceptance の是正（#1671）

## 判断

- addyosmani/agent-skills（MIT）の Skill のうち、ASC と領域が重なる4つを比べた。agent-skills の本文は取り込まない。Skill なしとほぼ同じ点で、ASC より低く、読む量（トークン）は多かった。
- ASC と agent-skills の両方を読ませた条件が最も高かった。そのうち `user-journey-acceptance` の範囲にある2点だけを、ASC の本文に1文ずつ足した。
  - `references/journeys.md`：開発サーバーや debug build の測定値を本番相当として扱わず、本番相当の build で測るか、差を明記する。
  - `SKILL.md`：テスト環境に本番の決済・送信等の資格情報が設定されていれば、その設定自体を問題として報告し、操作前にテスト用への切替えか許可を確認する。
- このディレクトリは開発時の検証資料で、配布対象に含めない。agent-skills の本文は再配布しない。

## 方法

- 課題：架空の12件（[cases.json](cases.json)）。観点：課題に仕込んだ事実から49観点を作り、回答の生成前に固定した（[rubric.json](rubric.json)）。範囲外の行為・実施していない確認の主張・事実と異なる主張を別に記録した。
- 生成：Claude Code のサブエージェント（sonnet）。条件ごとに2回、各回は別 Context。回答だけで、実作業はさせていない。条件は Skill なし／ASC／agent-skills／両方（組ごとに両方の本文を読む）。
- 採点：opus の別 Context 2系統に、課題・観点・匿名回答だけを渡し、対応キーは採点後に照合した。
- 匿名化：回答の Skill 名・条件名を機械的に確認した。agent-skills の1回が書いた「CONSTRAINTS.md」は条件の手掛かりになるため「規約の文書」に置き換えた。生成の依頼で各回答を600字以内とした（[prompts.md](prompts.md)）。是正1回目の1回の S1 は614字で上限を超えたが、切り詰めていない。
- 費用：各回答エージェントの完了通知に出た token 数と時間を [usage.json](usage.json) に記録した。
- 裁定：採点後に見つかった採点の誤り3件を [adjudications.json](adjudications.json) に記録した。生の採点は変えず、表の点数は裁定後の値とした（括弧内は生の採点）。
  - ASC 是正前の1回の S2-5 と K1-5 を 1→0 にした。どちらも「私の承認後にします」「私の承認を得る」で、承認する主体が曖昧なため。rubric の「曖昧なら 0」に従った。
  - 両方の1回の Y3 に fabricated を加えた。`-0` の表示が修正の前後で変わらないとしたが、実際は `¥-0` から `¥0` に変わるため。
