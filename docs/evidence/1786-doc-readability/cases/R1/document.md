# CIのテスト増加をPRごとに見えるようにする

## 目的

依頼者（プロダクト責任者、2026-11-02）：「CIが遅くて、PRを出してから確認が終わるまでの待ち時間が長い。」

テストの増加数をPRごとに報告するスクリプトを作る。

## 完了の基準

- 報告スクリプトがPRコメントにテスト数と所要時間の増減を表示する。
- 報告スクリプトのテストが通る。

## してはいけないことと対象外

- 禁止：必須checkの名前は変えない（リポジトリ管理者、2026-11-03、Issue #12のコメント）。
- 対象外：重複テストの削除やe2eの実行条件の見直しは扱わない（起票者の判断）。

## 決まっていること

- 必須checkの名前は変えない（リポジトリ管理者、2026-11-03）。
- e2eは夜間実行へ移すことをリポジトリ管理者が承認済み。

## 背景と根拠

- 確認済み：PRのCIは平均8分（直近30回の成功run）。
- 確認済み：最も遅いjobはe2eで、平均11分。

## 手段の案

要求ではない。PRごとにjunitの結果を集計し、前回のmainとの差をコメントする。

## 依存と未決

なし。
