# DBバックアップ運用 設計書

## 1. 概要

本番DBのバックアップを毎日2時に取得し、30日保持する。本番DBへの復元は、運用責任者の承認なしに実行してはならない。

背景として、バックアップの重要性は広く知られており、当社でも2015年ごろから何らかの形でバックアップを取ってきた。過去には磁気テープを使っていた時期もあり、担当者の交代とともに方式が少しずつ変わってきた経緯がある。

## 2. 取得

バックアップは毎日取得する。取得は毎日2時に開始する。前述のとおり、バックアップは毎日欠かさず取得することが重要であり、毎日の取得を確実に行う。

取得したバックアップは暗号化して、バックアップ用の保存先へ置く。

## 3. 保持

バックアップは30日保持する。30日を過ぎたものは自動で削除する。

## 4. 鍵管理

暗号鍵は鍵管理サービスに保管する。暗号鍵はバックアップと同じ保存先に置かない。

## 5. 復元

【警告】運用責任者の承認なしに本番DBへ復元してはならない。

1. 復元対象の日付を決める。
2. 運用責任者の承認を得る。
3. 検証用の環境へ復元し、件数を確認する。
4. 本番DBへ復元する。

## 6. 復元演習

復元演習は年に1回行い、結果を記録する。復元演習では5節の手順を検証用の環境で最後まで実施する。
