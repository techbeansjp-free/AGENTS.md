# 保守の依頼を品質保証範囲に照らして判定する評価

開発時の検証資料であり、配布対象に含めない。

## 方法

- 案件：[案件の資料](01_案件の資料.md)。受託の業務システム1件で、品質保証範囲は合意済み（版1.0）。未決の行（WAR-005）と適用外の行（WAR-006）を1つずつ含む。
- 依頼：[依頼](02_依頼.md)の7件。
- 生成：Claude Codeのサブエージェント（sonnet、読取りだけ）。会話を継承しない別Context。`estimate-and-scope`の本文を読ませ、本文が案内する範囲だけを読んでよいとした。
- 採点：別Context（opus）に、資料・依頼・観点・匿名の回答だけを渡した。対応キーは採点の後に照合した。

## 観点の改訂

- [初版の観点](03_観点_初版.md)は、「有償」「無償」を書くこと全般を、契約上の分類の断定として減点した。この観点では、変更前と変更後のどちらも大半の依頼で減点され、差が出なかった。
- ownerの決定（2026-11-27、#1829のcomment）で、合意済みの行で扱いも合意されていれば、「合意（WAR ID・版）に基づく扱い」として書いてよいことになった。断定しないのは、次の場合に限る。
  - 差異がまだ確かめられていない場合
  - 契約不適合の疑いがある場合
  - 該当行が未合意の場合
- これに合わせて[改訂版の観点](04_観点_改訂版.md)を作った。依頼ごとの合格は、その依頼の観点がすべて1で減点がないこととした。水準は、7件中6件以上が合格し、法的な断定が0件であること。

## 結果（改訂版の観点）

| 本文の版 | 1回目 | 2回目 |
| --- | --- | --- |
| 変更前（`6b987fd1`） | 0/7（断定1） | - |
| `db1e623d` | 5/7（断定2） | 7/7（断定0） |
| `59b1c4b2` | 6/7（断定0） | 1/7（断定2） |
| `2a3ad6fe`（提出する版） | 7/7（断定0） | 6/7（断定0） |

- 提出する版では、2回とも水準を満たした。
- 版を重ねて直したこと：
  - `59b1c4b2`：ownerの決定の文（確かめる前に約束しない）を足した。`db1e623d`の1回目で、R1（調査前の「無償対応の対象です」）とR6（調査前の「保証対象外」）が断定と判定されたため。
  - `2a3ad6fe`：「依頼ごとに根拠のWAR IDと合意の版を示す」「差異が見つかった場合に無償で直すかも権限者に残す」を足した。`59b1c4b2`の2回目で、版を書かない依頼が多く、R1・R6で差異の後の無償の修補を約束したため。
- 変更前は、根拠に品質保証範囲のIDを示さず、R1で調査の前に「不適合として無償で修補」と約束した。
- 初版の観点での結果（参考、17点満点）：変更前2、`ff065b28`は4と4。

## 限界

- 案件1件・依頼7件、版ごとに各2回の生成で、分布の推定ではない。`59b1c4b2`の2回で6/7と1/7に分かれたように、生成ごとのばらつきが大きい。
- 観点は、1回目の結果を見たownerの決定で改訂した。本文の直しは、ownerの決定の文と、採点で見えた抜け（版、差異の後の扱い）に限った。
- 提出する版の2回目でも、R1は「無償修補の方向で」と方向を示しており、境界例として0点になった。
- 隣接Skillとの選び分け（暗黙の選択）は、descriptionを変えていないので測っていない。
