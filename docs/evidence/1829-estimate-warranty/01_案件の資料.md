### 条件が変わったときの分類

社内の対応区分であり、法的な結論ではない。契約上の分類は、判定の流れの2で権限者（顧客側 ACT-01 と協議のうえ、提供側の契約担当 ACT-03）が決める。

| 区分 | 該当する状況 | 扱い |
|---|---|---|
| 瑕疵対応 | 判定の流れの2で、権限者が瑕疵対応と分類したもの | 契約書 第12条に従う |
| 互換性対応 | 保証の対象外のブラウザ・OSのアップデート後に動かない | 見積のうえ有償 |
| 保守・改修 | 外部APIの仕様変更、OSSのサポート終了 | 保守契約の範囲、未締結なら見積のうえ有償 |
| 仕様変更 | 法改正・税率の変更・業務フローの変更 | 見積のうえ有償 |
| 改善 | 想定を超えたデータ量・利用者数 | 見積のうえ有償 |
| 原因の調査が必要 | 顧客側のインフラ・設定の変更後に動かない | 調査の結果で区分を決める。調査費用は下の表 |
| 権限者の判断が必要 | 検収後に、合意した仕様・条件との差異が判明した | ACT-03 が判断する |

### 調査を始める条件と修正の完了条件

| 項目 | 合意内容 |
|---|---|
| 報告の形式 | 再現手順・環境と版・発生日時・期待した結果と実際の結果・影響 |
| 報告の窓口 | OPS-001 |
| 原因調査の範囲と費用の扱い | 差異があった場合は提供側の負担。なかった場合は1件あたり8時間までは提供側、超過分は顧客側。判定できない場合は ACT-01 と ACT-02 の協議 |
| 判定する者 | ACT-02（技術的な事実）、ACT-03（契約上の分類） |
| 修正の完了条件 | 修正・該当ACの再テスト・顧客環境への反映を ACT-01 が確認する |

判定の流れ（二段）：

```text
1. 技術的な事実（判定する者）：保証の基準時点の環境・条件で、合意した仕様・条件（この文書と参照先の正本）と差異があるか
   ある / ない / 判定できない（原因調査。費用は上の表の扱い）
2. 契約上の分類（法務・契約の権限者）：1の事実と「条件が変わったときの分類」をもとに決める。検収済みであることだけで決めない
```

## 3. 契約書の関係する条項の要約（請負契約 K-2026-031）

- 第11条（検収）：納品後14日以内に検収し、期間内に通知がなければ合格とみなす。
- 第12条（契約不適合）：検収合格後1年以内に通知された、仕様書との不適合は、提供側が無償で修補する。仕様書の定めのない事項、顧客の指示・環境の変更に起因するものは除く。
- 第13条（優先順位）：契約書と仕様書が食い違う場合は契約書を優先する。
- 第14条（保守）：納品後の保守・改修・機能追加は別途の保守契約または個別の見積による。
