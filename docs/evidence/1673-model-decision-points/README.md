# 委譲時のモデル明示と、判断の節目だけの相談（#1673）

## 判断

`subagent-model-selection` に次の文を足した。

> Hostが指定できる場合は委譲時にモデルを明示し、親の高能力モデルを継承したまま検索・抽出・照合しやすい作業に使わない。高能力のモデルは計画の確定前・完了判断の前など判断が分かれる節目の相談先に限る選択肢も比べ、相談には判断に必要な計画・制約・検証結果だけを渡す。

- 評価した2回目の文（5f7639dc）から、独立レビューの指摘で2か所を直した（最終版）。1つは「Hostが指定できる場合は」の追加で、モデルを指定できない Host では既存の記述（固定された設定で要求を満たせるならそのまま進める）と両立させるため。もう1つは「相談・委譲には」を「相談には」にしたことで、委譲時に渡すもの（目的・変更範囲・完了条件）は既存の記述が扱っているため。どちらも評価した課題の前提（指定できる Host での相談）での意味を変えないと判断し、評価し直していない（推論）。
- 着想は外部の投稿にあった構成である。実装は標準、検索・test は軽量のモデルに任せ、高能力のモデルは節目の相談だけに使う。投稿の数値と、Host 固有の機能（`--advisor` など）が実在するかは確認していない。本文に Host 固有の機能名は書いていない。
- 最初の文（1回目、fa074c8f）は「判断の節目での相談」が中心だった。実際のセッションログを集計すると、同じ失敗の繰り返しはまれだった一方で、委譲した検索まで継承した高能力のモデルが担っていた。そこで2回目の文に差し替えた。
- このディレクトリは開発時の検証資料で、配布対象に含めない。

## 受入の判定

- 回答の上では、M1-4・M5-3 の改善と、負例で不要な相談を増やさないことを確認した。
- ただし、追加文の主目的である「委譲時のモデル明示」（M5-1）は、Skill なしでも回答の上では満たしていた。一方、実際のログでは継承した高能力のモデルが使われていた。回答で述べることと実際の起動の差は、回答だけの評価では測れない。文を足したことで実際の起動が変わるかは未確認である。
- 品質の差（2回目で +3点）のうち、追加文と直接対応するのは M1-4 の +2 だけである。残りの差は各2回のばらつきの範囲と考えている（推論）。M1-5 の低下も同じ扱いとする。
- Issue が挙げた節目のうち「同じ失敗の再発時」は、ログでまれだったため本文から外した。既存の再試行の段落（同じ条件で失敗を繰り返さない）で代えられると考えている。この判断を含めて、取り込むかは repo の owner（利用者）が判断する。

## 限界

- 課題は作成者の架空のもので、各条件2回の比較にすぎない。統計的な差の証明ではない。
- 回答だけの評価で、実際のモデルの切替えによる品質・費用・時間は測っていない。
- ログの集計は、語による機械的な分類と、正規化したコマンドの一致に基づく。独立レビューの結果の重要度は、結果の形式のため集計できなかった。
- 正例で、相談と独立レビューが重なる場合の費用の増加は測っていない（1回目の是正後の1回で、完了判断の前に両方を行う回答があった）。
- 暗黙選択（Skill 名を含まない依頼で入口が選ばれるか）は測っていない。description は変えていない。
