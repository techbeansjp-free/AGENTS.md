# 判断の節目だけ高能力のモデルへ相談する（#1673）

## 判断

- `subagent-model-selection` に1文を足した：高能力のモデルを全工程に使わず、計画の確定前・同じ失敗の再発時・完了判断の前など判断が分かれる節目での相談先として使う選択肢も比べる。相談には判断に必要な計画・制約・検証結果だけを渡し、会話全体を引き継がない。
- 着想は、外部の投稿にあった構成（実装は標準モデル、検索や test は軽量モデル、高能力のモデルは節目の相談だけ）。投稿の数値と、Host 固有の機能（`--advisor` など）が実在するかは確認していない。本文には Host 固有の機能名を書いていない。
- このディレクトリは開発時の検証資料で、配布対象に含めない。

## 方法

- 課題：架空の4件（[cases.json](cases.json)）。M1 本番 DB の移行（計画から完了まで）、M2 同じ方針で2回失敗した修正、M3 軽量モデルの「完了しました」という報告（認可の変更）、M4 README の誤字1か所（負例）。
- 観点：課題の事実から14観点を作り、回答の生成前に固定した（[rubric.json](rubric.json)）。
- 生成：Claude Code のサブエージェント（sonnet）。条件は Skill なし／是正前（f1e53437）／是正後（fa074c8f）で、各2回、各回は別 Context。各回答は500字以内。回答だけで、実作業はさせていない。
- 採点：opus の別 Context 2系統に、課題・観点・匿名回答だけを渡し、対応キーは採点後に照合した。
- 費用：各回答エージェントの完了通知に出た token 数と時間を [usage.json](usage.json) に記録した。

## 受入の判定

- 節目での相談と、全工程に高価なモデルを使わないことでの改善：後者（M1-2）は全条件で 2/2 で差がない。相談に渡す内容（M1-4）は改善した。節目での相談そのもの（M1-1）は差を測れなかった。
- 負例で不要な相談・委譲を増やさない：満たした。
- 取り込むかは、repo の owner（利用者）が判断する。

## 限界

- 暗黙選択（Skill 名を含まない依頼で入口が選ばれるか）は測っていない。description は変えていない。
