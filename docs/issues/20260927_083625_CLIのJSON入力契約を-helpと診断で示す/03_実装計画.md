### 1.0 開発考慮事項の適用判定（必須）

| ID | 考慮事項 | 判定 | 理由 | 実装・検証タスク |
|---|---|---|---|---|
| DC-PRIVACY | Privacy/Security by Design | not-applicable | 変更は`--help`の静的な項目一覧と入力検証の診断文言に限られ、秘密情報・認証・信頼境界を扱わない | T02でSCN-UNIT-CLIINPUT-003が入力値を診断へ複写しないことを検査する |
| DC-OBSERVABILITY | Secure Logging・Observability・運用可能性 | not-applicable | log・metrics・保持・監視の仕組みを変えず、既存の診断出力の文言だけを変える | T02で既存のJSON診断経路だけを使うことをreviewで確認する |
| DC-UX | Human-Centered UI/UX・アクセシビリティ | not-applicable | 変更対象はNode CLIのJSON出力であり、GUIやWeb UIを提供しない | package.jsonのbinとCLI contract |
| DC-TOKENS | Design System・Design/Layout Token | not-applicable | 画面レイアウトと視覚コンポーネントを所有しない | projectKind=cli、UI sourceなし |

## 4.1 実装中発見の振り分け

本書はStep 8の計画封印後に編集しない。実装中の発見は本節へ追記しない。既定は記録せず実装を続け、契約が変わる場合だけ次の記録先へ振り分ける。

| 発見の種類 | 記録先 |
|---|---|
| 実装上の判断（関数名、分割、helper、library、test構成、file配置など） | commit履歴。追加の記録は不要 |
| 目的・受け入れ条件・不変条件・scopeの変更 | `05_計画変更.md`へ`AMD-NNN`を対象・変更・理由の3項目で追記 |
| 現在のsystem契約の変更 | `docs/specs/` |
| このIssueのscope外 | follow-up Issue |
