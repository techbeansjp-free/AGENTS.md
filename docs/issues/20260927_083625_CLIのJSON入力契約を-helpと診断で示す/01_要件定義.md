## 1. システム・変更概要

JSON入力fileを受け取る3コマンド（`workflow verification-set`、`workflow assess-discovery`、`review round`）について、`--help`へ項目一覧を載せ、入力検証の診断を1回で修正できる形へ変える。受理・拒否する入力の集合は変えない。

## 2. 用語とドメインモデル

### 2.1 ドメイン用語台帳の確定差分

| 用語ID | 標準語 | 定義 | 種別 | コンテキスト | 成立例・反例 | 類義語・禁止表現 | 根拠 | owner | 状態 | 適用版 |
|---|---|---|---|---|---|---|---|---|---|---|
| TERM-ASC-1388-01 | 入力契約（inputContract） | `--help`が示す、flagの先にあるJSON入力fileの項目一覧（必須/任意・型・受理値）と例。入力検証と同じ定義から導く | system | CLI入力契約 | 3コマンドの`--help`の`inputContract.fields`は成立。検証の受理集合と食い違う一覧は反例 | 「schema」と呼ばない | REQ-WF-009、Issue #1388 | package owner | active | v0.3.1 |

### 2.2 モデルと責務

入力契約の項目定義（field名、必須/任意、型、受理値）を検証側の単一定義として持ち、`--help`と検証の両方がそれを読む。

### 2.3 不変条件

- INV-01: 受理・拒否する入力の集合は変更前と同じである
- INV-02: `--help`の項目一覧・受理値は検証が使う定義と同じ正本から導く

### 2.4 状態遷移（該当する場合）

該当しない（状態を持たない）。

### 6.2 データ要件

保存dataを変えない。

## 7. 非機能要件

### 7.1 開発考慮事項の適用判定（必須）

| ID | 考慮事項 | 判定 | 理由 | 要件・確認証拠 |
|---|---|---|---|---|
| DC-PRIVACY | Privacy/Security by Design | not-applicable | 変更は`--help`の静的な項目一覧と入力検証の診断文言に限られ、秘密情報・認証・信頼境界を扱わない | NFR-01で診断へ入力値を複写しないことを確認する |
| DC-OBSERVABILITY | Secure Logging・Observability・運用可能性 | not-applicable | log・metrics・保持・監視の仕組みを変えず、既存の診断出力の文言だけを変える | 既存のJSON診断出力経路を使い、新しい記録先を作らないことをreviewで確認する |
| DC-UX | Human-Centered UI/UX・アクセシビリティ | not-applicable | 変更対象はNode CLIのJSON出力であり、GUIやWeb UIを提供しない | package.jsonのbinとCLI contract |
| DC-TOKENS | Design System・Design/Layout Token | not-applicable | 画面レイアウトと視覚コンポーネントを所有しない | projectKind=cli、UI sourceなし |

### 7.2 品質要件

| ID | 分類 | 要件・閾値 | 測定方法 | 対象外の場合の理由 |
|---|---|---|---|---|
| NFR-01 | 安全性 | 診断はfield名・添字・finding ID・受理値だけを示し、入力値そのものを複写しない | 診断文言のtest | - |
| NFR-02 | 性能 | 対象外 | - | 静的な項目一覧の追加であり測定対象の処理時間を変えない |
| NFR-03 | 可用性・復旧 | 対象外 | - | 状態を持たない |
| NFR-04 | 互換性 | 受理・拒否する入力集合とexit codeを変えない | 既存testの回帰確認 | - |
| NFR-05 | 保守性 | 項目定義は検証側に1つだけ置く | review | - |
| NFR-06 | 利用性・アクセシビリティ | 対象外 | - | CLIのJSON出力でありUIを持たない |

## 8. Zero Trustと権限要件

入力JSONは従来どおり厳格に検証する。権限・認証に変更は無い。

## 10. 境界値、異常、悪用、回帰

- 未知だけ・欠落だけ・両方の入力で、それぞれ正しく列挙する
- 入力値に長い文字列や制御文字を含めても診断へ複写しない
- 既存の入力拒否scenarioが引き続き落ちる

## 11. 移行と互換性

拒否の有無とexit codeは変えない。診断文言は変わるが、文言をparseする利用者は想定しない。
