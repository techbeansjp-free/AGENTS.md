# 運用保守設計

公開操作は`npx agent-skill-chain install`、`npx agent-skill-chain update`、`npx agent-skill-chain delete`、`npx agent-skill-chain doctor`で行う。`doctor`はpackage所有資産、設定、旧runtimeの残存を読み取り専用で診断する。`install`、`update`、`delete`は無指定をpreviewとし、`--apply`が明示された場合だけ書き込む。内部関数名と旧CLI aliasの`init / upgrade / uninstall`を利用手順へ公開しない。

| 事象 | 確認 | 対応 | 保持する証拠 |
|---|---|---|---|
| CI失敗 | 失敗SCN・job・HEAD SHA | 同じscopeの原因だけ修正 | workflow runとtest出力 |
| GitHub書込失敗 | 認証、repository、対象状態 | 再認証または再計画 | 伏字化済み診断 |
| update競合 | managed hashと現ファイル | 利用側変更を保持 | retained一覧 |
| finalize拒否 | dirty、push、merge、復旧参照、報告hash | 不足条件を満たして再検証 | read-only report |
| network障害 | gateごとのexternal dependency | localを継続しexternalだけpending | local証拠とpending一覧 |
| policy誤block | rule ID、risk、scope、falseBlock計測 | 独立reviewで観測・scope・diagnosticを修正しstaged移行。安全・authority境界、秘密、Git内部、identity、不可逆操作、artifact汚染、candidate自己承認のnon-override denyは弱めずfail closedを維持 | trusted policy、diagnostic、独立review、rollback history |

今回作成するPRはmerge・後片付けを行わず、branchと専用worktreeを保持する。

本repositoryはproject固有policyで通常staged追加と自己緩和拒否をdogfoodし、migrationのapply、rollback、retryを隔離projectで再現する。metrics budget超過は改善対象でありsecurity gate無効化には使わない。

新設ruleはこのcandidate自身で`active`へせず、まず`staged`のままmergeして既定branch上のtrusted setにする。既定branchでproject CI hook、反例test、誤block・検出漏れの観測が成功した後、意味、scope、enforcement、overrideを変えず`activation`だけを昇格する別PRを作り、trusted-vs-candidate比較と独立reviewを通す。初回mergeまでのbootstrap期間はcandidate所有workflowだけをauthority正本にせず、固定した`H_impl`全差分の個別監査、外部providerが観測したexact-head CI、実装者・PR authorと異なるreviewerの承認を必須とする。
