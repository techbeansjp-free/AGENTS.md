# 移行・廃止方針

v0.3は、旧harnessを意図的に削除した`renewal_v0.3.0`を基点に独立実装する。旧`.agents/`、`.workflow/`、hooks、commands、enforcementを無条件に復元せず、doctorで残存を報告するだけとする。

公開入口は`npx agent-skill-chain`とし、`install`は新規導入、`update`はpackage所有資産だけの更新、`delete`はmanaged hashが一致する資産だけの削除、`doctor`は読み取り専用診断を担う。利用側所有の仕様、project policy、変更済み品質文書、一時stagingを保持する。`update`で新しいpackage pathが追加されても、旧managed asset記録にない同名のconsumer fileは上書きせず保持する。内部関数名と旧CLI aliasの`init / upgrade / uninstall`は互換入力に限定し、新規利用手順へ公開しない。

ロールバックはv0.3実装コミットを戻し、旧harness削除済みの基点へ戻す。既存利用者への自動移行は行わない。releaseとpackage公開は手動dispatchへ限定し、通常push、version自動書換え、無承認のnpm公開は行わない。

## releaseとversion方針

製品versionはrelease用PRで`package.json`と対応するlock・policy schema資産を事前に整合させ、release workflowでは書き換えない。手動入力versionが`package.json.version`と一致し、直近の有効なrelease tagからSemVer順で単調増加し、同名tagが存在しない場合だけ本実行できる。dry-runでversion、tag、release note、npm pack対象を確認した後、別runで`dry_run=false`を明示する。

Git tag、GitHub Release、npm公開は独立した状態として扱う。途中失敗では完了済みstage以降を自動継続せず、実状態を確認する。npm未公開ならGitHub Release、続いてtagを必要な範囲だけ削除して再計画する。npm公開済みversionは削除による利用者影響を避け、`npm deprecate`で理由と代替versionを通知する。release workflow自体を戻しても既存のtag、Release、packageは消えないため、外部資産の復旧は別authorityと記録を伴う手動操作とする。

製品versionの正本は`package.json.version`とし、同じ`package.json`の`agentSkillChain`が現行・互換project policy schema versionを宣言する。今回の製品versionは`0.3.1-beta.1`、現行project policyは`v0.3.1`、互換入力は`v0.3.0`である。製品versionはSemVer 2.0.0としてpatchとnumeric prereleaseの不正な先頭ゼロ、空identifierを拒否し、build metadataを受理する。比較基点に実在する過去の誤表記`v0.3`は正式schema enumへ含めず、`deprecatedPolicySchemaAliases`のown propertyである場合だけ`v0.3.0`へ正規化するmigration専用入力として扱う。runtimeとlifecycleはpackage metadataを読み、schemaとの不一致はbuild gateで拒否する。

Project policy `v0.3.0`は互換入力として診断できる。`v0.3.1`への移行対象はpolicy、schema、runtime、CI、templateの所有pathだけに限定し、manifestへpath、kind、順序、before/after hashを固定する。各artifactは復旧内容そのものを持つdurableな`before` content snapshot、path/kind/source/after hashの参照、owner、retention期限または破棄条件を持つ。dry-runで差分とcompatibilityを確認し、applyはcall-siteのdurable journal保存関数を必須とし、最初のwriteより前に全artifactを保存できなければ何も変更しない。各write直前のbefore hash、atomicな単一file write、read-after-writeを順に記録する。複数file全体を不可分とは主張せず、partial applyやrollback中断は次回実行時に`artifacts[].before` contentを復旧正本として全targetを回復し、before/after hashは内容のintegrity検証に使うcrash-recoverable transactionとする。apply、rollback、retry、recoverはcall-siteから独立して渡されたapproved plan hash、expected revision、durable journal保存関数を必須とし、state内の同名fieldをauthorityとして再利用しない。retryはさらにtrusted/candidate/manifestから再導出したplan IDが一致する場合だけ許可する。

Project policy setは`.agent-skill-chain/project-policy.json`をentrypointとし、choices、rules、conformanceの全fragmentをmanifestへ列挙する。trusted setは既定ブランチを最初にcommit SHAへ固定し、default、manifest、全fragmentを同じSHAから読む。candidate fallback、orphan/missing fragment、duplicate JSON key、absolute/parent/symlink/gitlink/executable path、case・Unicode衝突を拒否し、manifestを含むpathとraw bytesからset hashを作る。legacy monolithはproject directoryが完全に存在しない場合だけ読み、混在を拒否する。

Fragmented setの移行manifestはentrypointと全choice/rule/conformance fragmentをcandidateのraw inventoryと完全一致させ、assembled monolithをentrypointへ書くことを拒否する。trustedまたはrootがfragmentedならplain candidateを拒否する。apply後にfilesystem loaderで全setを再読込し、candidate set hashとsemantic policy hashの両方をread-after-write gateで確認する。回復失敗は復旧に必要なjournal/manifest/artifactを保持し、別reportへdiagnosticを記録する。

未知versionと未知fieldを黙殺せず、破壊的risk不明ならapplyを拒否してstagingまでに制限する。

旧harness、旧skill、旧hook、旧enforcementは移行元runtimeとして扱わず、復元も依存もしない。
