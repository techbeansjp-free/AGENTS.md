# 課題858 要件追跡

| AC | 要件・不変条件 | 実装・enforcement point | Counterexample Gherkin | 証拠・rollback |
|---|---|---|---|---|
| AC-01 | repository rootに利用者向け`README.md`が存在する | root `README.md`、GitHubのroot Markdown表示 | SCN-INT-README-001 | 実fileとCLI・package検査の成功。README追加を戻してruntimeを維持できる |
| AC-02 | 製品目的、対象利用者、Node.js 20以上、npm、最小導入例を日本語で示す | `README.md`の概要、前提条件、導入と利用 | SCN-UNIT-README-001 | 内容検査。READMEだけを戻してCLI動作を維持できる |
| AC-03 | `install`、`update`、`delete`、`doctor`、`--root=.`、preview既定、`--apply`を現行契約と一致させる | `scripts/check_cli_contract.ts`、`PUBLIC_LIFECYCLE_COMMANDS`、`CLI_USAGE` | SCN-UNIT-README-001、SCN-UNIT-README-003 | CLI正本から全4 commandと適用条件を検査。READMEと検査を同時に戻す |
| AC-04 | Claude CodeとCodexのhost skill登録アダプターがlifecycle管理されることを示す | `README.md`のhost連携、既存lifecycle契約 | SCN-UNIT-README-004 | 両探索pathの内容検査。案内だけを戻して既存adapter管理を維持できる |
| AC-05 | READMEを非規範入口とし、中央利用案内、3規範文書、製品仕様へ有効な相対linkを持たせる | `README.md`の正本と仕様、link target実在検査 | SCN-UNIT-README-004 | README自身を正本にする自己参照とdead linkを拒否。READMEとdirectory仕様を同時に戻す |
| AC-06 | 実npm packageへREADMEを含め、project所有資産と秘密を含めない | `package.json.files`、`scripts/check_package_contents.ts`の実tarball監査 | SCN-INT-README-001 | `npm pack`のfile一覧と展開後content検査。manifestと必須収録検査を同時に戻す |
| AC-07 | READMEのcommandまたはlinkが正本からdriftした場合に品質gateを失敗させる | `scripts/check_cli_contract.ts`、README link実在検査 | SCN-INT-README-007、SCN-UNIT-README-004 | command欠落fixtureとdead link反例。正本を直して再実行する |
| AC-08 | 旧CLI aliasを推奨せずv0.3の公開commandだけを示す | `scripts/check_cli_contract.ts`の`npx` invocation検査 | SCN-UNIT-README-002 | `init`、`upgrade`、`uninstall`、`setup`の推奨形を拒否。READMEを現行commandへ戻す |

新しいドメイン用語は追加せず、既存のpackage lifecycle、host skill登録アダプター、正本の意味を変更しない。READMEは`package metadata・CLI・中央利用案内・規範・製品仕様 → README → documentation/package gate`の一方向で参照し、README自身の主張を適合証拠にしない。

実装全体のrollbackでは、root `README.md`、`package.json.files`の収録entry、CLI・package検査、対応Gherkin、directory仕様、索引、本追跡を同時に戻す。runtime、利用project所有資産、外部repository、公開済みpackageは変更しない。
