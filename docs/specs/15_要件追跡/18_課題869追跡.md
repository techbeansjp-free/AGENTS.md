# 課題869 要件追跡

| AC | 要件・不変条件 | 実装・enforcement point | Counterexample Gherkin | 証拠・rollback |
|---|---|---|---|---|
| AC-869-01 | version bump経路は`audit:check`だけを除外し、`prepack`のほかの品質gateをすべて実行する | `.github/workflows/release.yml`の`bump_version` jobで9 commandを明示実行し、`validateReleaseWorkflow`が必須gateとtest実行を検証する | SCN-INT-AUTORELEASE-003 | 実workflowのjob blockとvalidatorの成功。rollbackではbump経路を停止し、原因となった`npm run prepack`へは戻さない |
| AC-869-02 | bump経路は、PRレビュー成果物を前提とする`audit:check`を直接にも`prepack`経由にも実行しない | `validateReleaseWorkflow`が`bump_version` job内の`npm run prepack`と`npm run audit:check`を拒否する | SCN-UNIT-AUTORELEASE-007 | auditを追加した反例workflowの拒否。rollbackでは自動bumpを無効化し、監査契約自体は変更しない |
| AC-869-03 | `validate` jobと手動dispatch経路は`npm run prepack`を維持する | `.github/workflows/release.yml`の`validate` job、`validateReleaseWorkflow`のjob単位check | SCN-INT-AUTORELEASE-001、SCN-INT-AUTORELEASE-003 | 実workflowの`validate` blockとvalidatorの成功。欠落時はrelease全経路を停止して`prepack`を復元する |
| AC-869-04 | 通常PRでは`audit:check`を引き続き強制する | `.github/workflows/ci.yml`の`pull_request` triggerと「全変更fileの個別監査とGit差分path集合を照合する」step | SCN-UNIT-AUTORELEASE-007 | PR CIの`npm run audit:check`。rollbackでもCIの監査stepを変更せず、bump経路だけを停止する |

`audit:check`の判定、`package.json`のscript契約、PR CI workflowは変更しない。変更全体を戻す場合は、自動bumpを停止したうえでrelease workflow、workflow validator、反例scenario、運用保守仕様、本追跡と索引を同時に戻し、tagとGitHub Releaseの実状態を読み直す。
