# 課題861 要件追跡

| AC | 要件・不変条件 | 実装・enforcement point | Counterexample Gherkin | 証拠・rollback |
|---|---|---|---|---|
| AC-861-01 | release対象のmain mergeで人手なしにtagとGitHub Releaseを作成する | `.github/workflows/release.yml`の限定`push`、`planAutoRelease`、`tag`・`github_release` job | SCN-UNIT-AUTORELEASE-001〜004、SCN-INT-AUTORELEASE-001〜002、SCN-E2E-AUTORELEASE-001 | 実workflowとentrypoint JSON。workflowのpush triggerを停止し、外部資産を読み直す |
| AC-861-02 | tagとRelease名を`package.json.version`から導いた同じ`v${version}`へ一致させる | `scripts/plan_release.ts`の`PACKAGE_VERSION`入力、tag SHAとRelease `tagName/name`のread-after-write | SCN-UNIT-AUTORELEASE-001、SCN-INT-AUTORELEASE-001、SCN-E2E-AUTORELEASE-001 | planのversion/tagとRelease観測JSON。不一致資産を上書きせず停止する |
| AC-861-03 | 同version tagとの衝突時は0.3.x内でversionをbumpする | `planAutoRelease`のnumeric prerelease・patch規則、`isPackageVersion` gate | SCN-UNIT-AUTORELEASE-005〜006、SCN-E2E-AUTORELEASE-001 | `bump-then-release`計画。不正または解決不能versionでは外部更新せず停止する |
| AC-861-04 | version bumpをPR経由でmainへ反映し、直接pushしない | `bump_version` jobの`release/bump-v<version>`、PR作成、`gh pr merge --admin --merge` | SCN-INT-AUTORELEASE-001〜002 | branch・PR URL・merge後main SHA。失敗時はopen branch/PRを読み直して再利用する |
| AC-861-05 | bump commitが新しいrelease runを起動しない | `[skip ci]`付きcommit、job-level head message guard、`main-mutator` concurrency | SCN-UNIT-AUTORELEASE-003、SCN-INT-AUTORELEASE-001、SCN-E2E-AUTORELEASE-001 | 自動計画の`skipped`理由とworkflow validator。guardを緩めずbump経路を停止する |
| AC-861-06 | 同じversion・SHAでtagとReleaseを二重作成しない | tagの`git ls-remote --tags`、Releaseの`gh release view`、作成後のread-after-write | SCN-INT-AUTORELEASE-001、SCN-E2E-AUTORELEASE-001 | 既存資産を成功扱いするworkflow。異なるSHA・名前の衝突は上書きせず停止する |
| AC-861-07 | 自動releaseではnpm公開を行わない | `npm_publish.if`の`github.event_name == 'workflow_dispatch' && inputs.publish_npm == true` | SCN-INT-RELEASE-002、SCN-INT-AUTORELEASE-002 | validatorのnpm条件check。`publish_npm=false`または自動経路でjobをskipする |
| AC-861-08 | 文書、memo、test、workflowだけの変更ではreleaseしない | workflowの`push.paths` allowlistと`planAutoRelease`のrelease対象path判定 | SCN-UNIT-AUTORELEASE-002、SCN-INT-AUTORELEASE-002、SCN-E2E-AUTORELEASE-001 | `skipped`計画。対象pathの漏れは純関数とworkflowを同時に更新する |
| AC-861-09 | 手動dry-run・手動本実行を維持し、途中失敗の完了・未完了・復旧を日本語で示す | 既存`planRelease`、`workflow_dispatch` inputs、各jobの`$GITHUB_STEP_SUMMARY` | SCN-UNIT-RELEASE-001、006〜007、SCN-INT-RELEASE-001〜002 | dry-runとpartial結果、stage別summary。外部状態を読み直し未完了操作だけを再計画する |

unit層はrelease対象、非対象、branch、再帰、version衝突とbump境界を純関数で検証する。integration層は実workflowと無条件push・自動npm公開の反例を静的validatorで検証する。E2E層はworkflowが呼ぶ実entrypointを別processで起動し、外部更新なしのJSON結果を検証する。GitHub、npm、他worktreeへテストから書き込まない。
