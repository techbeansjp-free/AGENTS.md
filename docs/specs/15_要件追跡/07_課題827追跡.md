# 課題827 要件追跡

| AC        | 要件・不変条件                                                                                     | 実装・enforcement point                                                | Counterexample Gherkin            | 証拠・rollback                                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| AC-827-01 | `poc`指定時は全工程をquick相当の単一00成果物・最小gateで進める                                     | `classifyMode`、`createIssueStaging`、`00_要求定義_poc.md`、Step 0/1/4 | SCN-UNIT-POC-001、SCN-E2E-POC-001 | 完全な宣言だけが`poc`となり、01/02/03を生成しない。rollbackは`requestedMode`を省略して従来のquick/full判定へ戻す          |
| AC-827-02 | 目的、期間、成功・中止条件、非対象、データ・security制約、責任者、昇格・廃止条件を日本語で記録する | `PocDeclaration`、`requirementDocument`、PoC要求テンプレート           | SCN-UNIT-POC-002、SCN-INT-POC-001 | 管理情報の`モード=poc`とPoC宣言表を検査する。欠落・不明時は`full`へ戻す                                                   |
| AC-827-03 | 公開API、個人情報、機密情報、外部公開、不可逆操作と変更file失格条件はfail-closedで扱う             | `pocReasons`、`detectQuickDisqualifiers`との統合、`validateIssue`      | SCN-UNIT-POC-003〜004             | high riskの`あり`・不明・根拠なしを`full`へ単調昇格する。rollbackはPoCを停止してfull成果物を補完する                      |
| AC-827-04 | PoCを正式開発と誤認してrelease、自動merge、本番cleanupへ進めない                                   | `validateIssue`の操作gateと`blockedOperations`、PR停止の規範・skill    | SCN-INT-POC-002                   | 禁止操作要求をinvalidにし、`delivery.stopAt`とfull昇格を診断する。外部状態は変更しない                                    |
| AC-827-05 | 正式開発への昇格根拠と不足成果物を追跡する                                                         | `planPocPromotion`                                                     | SCN-INT-POC-003                   | 01要件定義、02設計、03実装計画のうち存在しない成果物と補完理由を列挙する。PoC継続へ戻す場合も期限と判断責任者を再確認する |

各反例は隔離した一時ディレクトリだけを変更し、実リモート、他worktree、release、merge、cleanupを実行しない。PoCの昇格は`poc → full`だけを許可し、`full → poc`への途中降格を証拠として受理しない。
