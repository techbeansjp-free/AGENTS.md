# 課題831 要件追跡

| AC | 要件・不変条件 | 実装・enforcement point | Counterexample Gherkin | 証拠・rollback |
|---|---|---|---|---|
| AC-831-01 | 通常worktreeをrepositoryの`.worktrees/`直下へ規定名で作成する | `Policy.worktree`、project policy schema・runtime validator、`validateWorktreePlacement`、`createWorktree`、`worktree create` CLI | SCN-UNIT-WTPLACE-001、003〜004、008、SCN-INT-WTPLACE-001、SCN-E2E-WTPLACE-001 | optional policyの後方互換と安全側既定値を検証する。作成失敗時は既存pathとbranchを保持する |
| AC-831-02 | 規定外path、nested path、親参照、symlink脱出、制御文字、非NFC、case・Unicode衝突を作成前に拒否する | 純粋な文字列検証、canonical `.worktrees` root、Git common directory境界、登録済みworktree照合 | SCN-UNIT-WTPLACE-002、005〜006、SCN-INT-WTPLACE-004 | 非0診断と未作成pathを証拠にし、入力だけを修正して再実行する |
| AC-831-03 | branch名をIssue番号、slug、project policyの許可typeへ拘束する | branch pattern解析、Issue・slug一致、`allowedBranchTypes`照合 | SCN-UNIT-WTPLACE-003〜004、SCN-E2E-WTPLACE-001 | 不正branchは作らず、許可typeと規定名へ戻す |
| AC-831-04 | baseを検証済みremote default branch SHAへ拘束する | `origin/HEAD`、`refs/remotes/origin/<default>`、40桁SHA、`rev-parse <base>^{commit}`の完全一致 | SCN-INT-WTPLACE-002、SCN-E2E-WTPLACE-001 | 不一致では副作用前に停止し、remote default branchを取得して新しいSHAで再実行する |
| AC-831-05 | dirtyな作成元worktreeの状態を変更しない | 作成直前・直後の`git status --porcelain=v1 --untracked-files=all`完全一致 | SCN-INT-WTPLACE-003、SCN-INT-WORKTREE-001 | 不一致では自動cleanupせず両worktreeを保持し、status差分から復旧する |
| AC-831-06 | testは実repositoryと他worktreeを変更しない | `WorkflowWorld.temp()`による`mktemp`隔離repository、`.git/info/exclude`のfixture限定設定 | SCN-INT-WTPLACE-001〜004、SCN-E2E-WTPLACE-001 | test終了時に隔離directoryだけを除去し、製品`.worktrees/`を対象にしない |
| AC-831-07 | merge後cleanupを対象PR専用worktreeへ限定する | `matchesTargetWorktree`のcanonical path・branch完全一致 | SCN-UNIT-WTPLACE-007 | prefix・case-insensitive一致を拒否し、他worktree・branch・metadataを保持する |
| AC-831-08 | `.worktrees/`をGit管理・npm配布対象外にする | `.gitignore`と`package.json.files`許可list、package contents検査 | SCN-E2E-WTPLACE-001、`npm run package:check` | `.worktrees/`を追跡・配布せず、混入時はpackageを公開しない |

unitは文字列だけを扱う純関数で境界反例を検証する。integrationとE2EはOSの`mktemp`配下に作成した隔離repositoryだけを使い、実repositoryの`.worktrees/`、他Issue・他agentのworktree、branch、prunable metadataへ触れない。検査結果は同じ実装HEADへ結び、sandboxが子プロセスを拒否する環境では`EPERM`を未実行証拠として分離し、権限のある同一HEAD環境で再実行する。
