# 課題833 要件追跡

| AC | 要件・不変条件 | 実装・enforcement point | Counterexample Gherkin | 証拠・rollback |
|---|---|---|---|---|
| AC-833-01 | previewは外部writeなしで全候補のpath、理由、owner、削除可否と除外理由を返す | `src/domain/hygiene.ts`の`previewWorkspaceHygiene`、`src/cli.ts`の`worktree hygiene` | SCN-UNIT-HYGIENE-001、SCN-E2E-HYGIENE-001 | 決定的なJSON reportとSHA-256。applyを付けず再previewする |
| AC-833-02 | Git common directory、object、ref、reflog、worktree metadataは空でもoverride不能な対象外とする | `repositoryIdentity`、`scanDirectory`のGit境界打ち切り | SCN-UNIT-HYGIENE-002 | `.git`と偽`.git`を含む隔離fixture。候補化された場合はapplyせず実装をrollbackする |
| AC-833-03 | repository root、home、filesystem root、親参照、未解決env、glob、symlink、root外pathを拒否する | `repositoryIdentity`、`hasUnsafeMeta`、`isContained`、`lstatSync` | SCN-UNIT-HYGIENE-003〜004 | 副作用前の例外とremove 0回。境界不明時はrootと対象を保持する |
| AC-833-04 | 内容のある`memo/`、他project資産、`node_modules`を保持し、空の`memo/` directoryだけを深い側から候補にする | `scanDirectory`のmemo判定とpackage manager境界 | SCN-UNIT-HYGIENE-005、SCN-INT-HYGIENE-001 | Unicodeを含む隔離fixtureの保持確認。誤候補時はapplyせず新しいpreviewを取得する |
| AC-833-05 | applyは64桁承認hash、repository同一性、全候補再preview、明示operationを満たすまでremoveを呼ばない | `applyWorkspaceHygiene`の副作用前gate | SCN-UNIT-HYGIENE-006〜007、SCN-E2E-HYGIENE-002 | hash不一致・stale・TOCTOUでremove 0回。状態変更後は旧reportを破棄する |
| AC-833-06 | 削除はfileと空directoryの非再帰処理だけとし、部分失敗を成功と報告しない | CLI remove callback、`applyWorkspaceHygiene`の停止・復旧診断 | SCN-INT-HYGIENE-001〜002 | permission failure fixtureの削除済み・未処理・復旧方法。backup復元とdirectory再作成後に再previewする |
| AC-833-07 | 登録済みworktreeと未登録の空containerを分離し、登録済みworktree本体はGit公式command専用とする | `registeredWorktrees`、`scanWorktreeContainers`、既存`worktree finalize` | SCN-INT-HYGIENE-003 | `git worktree list --porcelain`を使う隔離fixture。登録済みworktreeは保持し別の完了処理へ戻す |
| AC-833-08 | apply後のGit HEAD、refs、repository root、worktree listは不変、statusは対象一時生成物の消失だけとする | `snapshot`、`expectedStatus`、apply後read-after-write照合 | SCN-INT-HYGIENE-004 | 同一fixtureの前後Git観測。不一致時は成功を返さずGit状態と削除済みpathを確認して復旧する |

すべての反例は`test/support/world.ts`の`temp()`と`initRepo()`で作る隔離repositoryだけを変更する。実repository、実remote、他worktreeをfixtureまたは削除対象にせず、sandboxが子processを拒否する環境では静的検査と実行可能なtag・name指定範囲の結果を分けて記録する。
