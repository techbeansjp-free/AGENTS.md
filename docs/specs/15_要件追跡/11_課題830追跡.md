# 課題830 要件追跡

| AC | 要件・不変条件 | 実装・enforcement point | Counterexample Gherkin | 証拠・rollback |
|---|---|---|---|---|
| AC-830-01 | coordinatorは進行管理だけを行う | `DEFAULT_ROLE_CONTRACTS`、`validateRoleOperation` | SCN-UNIT-ROLE-001 | product実装禁止診断。独立implementerへ再割当 |
| AC-830-02 | implementerと最終reviewerは異なるidentity・contextである | `validateRoleAssignment`、`routing roles` | SCN-UNIT-ROLE-002〜003、SCN-E2E-ROLE-001 | 非0の日本語診断。独立contextを作り直す |
| AC-830-03 | 6 roleの許可path・操作・禁止操作・必要証拠を一致させる | `role.ts`、project choice schema・runtime validator | SCN-UNIT-ROLE-004、SCN-INT-ROLE-001〜002 | role証拠不明では終端拒否。契約を安全な既定へ戻す |
| AC-830-04 | risk、mode、scope、finding重大度から必要tierを単調決定する | `requiredTier`、`validateTierSelection`、`routing tier` | SCN-UNIT-TIER-001〜003 | tier不足・mapping不明を拒否。scope縮小またはmapping更新 |
| AC-830-05 | model tierと操作authorityを分離する | `validateTierSelection`と既存enforcementの独立呼出し | SCN-UNIT-TIER-004 | criticalでも禁止操作を拒否。authorityを別途取得 |
| AC-830-06 | Codex high、Claude Opusを自律選択上限にする | `PROVIDER_AUTONOMOUS_CEILINGS`、`routing ceiling` | SCN-UNIT-CEILING-001、005 | alias・自動routingを拒否して上限内へ戻す |
| AC-830-07 | 上限超過をscope拘束の人間overrideだけに限定する | `validateProviderSelection` | SCN-UNIT-CEILING-002〜004 | 別Issue・別scope・失効・自己発行を拒否して人間へ移管 |
| AC-830-08 | candidateによるrole・tier弱化を拒否する | `classifyProjectChoiceDiff` | SCN-INT-ROLE-003 | 禁止操作削除とtier引下げを取消し、強化だけを許可 |
| AC-830-09 | role実行log、fixture、model mapping秘密値を配布しない | package allowlist・配布物検査 | SCN-INT-ROLE-001、`npm run package:check` | 開発専用資産を配布対象外へ戻す |

本変更は前方互換なschema、runtime、CLI、文書、templateの第1段階である。`.agent-skill-chain/project/choices/development.json`へのdogfooding設定適用は、本変更がdefault branchのtrusted validatorになった後の別PRで行う。同一PRで未知fieldを追加してcandidate自身のauthorityへ使用しない。

反例は対象scenarioの失敗から最小実装へ追跡する。role・tier・override証拠が不明な場合は成果物や外部状態を変更せず、独立した担当割当、trusted mapping、人間authorityのいずれかを再取得する。
