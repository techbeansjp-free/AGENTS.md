## project rule coverageとorphan拒否

conformance検査は`.agent-skill-chain/project-policy.json`の`ruleFiles`とrules directoryを完全一致させ、各ruleの安定ID、目的、所有者、scope、enforcement、証拠を検証する。拡張メタデータを持つruleは`packageDefault`、`projectOverride`、`changeAuthority`の3fieldを同時に持つ。

rule coverage matrixはrule IDごとに規範文書、schema、runtime、CIへの出現を真偽値で保持する。規範は3正本、schemaは`.agent-skill-chain/schemas/`、runtimeは`src/`、CIは`.github/workflows/`を走査する。次をorphanとしてfail closedで拒否する。

- rule fileに定義済みだがruntimeにもCIにもenforcement pointがない。
- 規範文書にIDがあるがproject policyへ定義されていない。
- CIだけにIDがある暗黙ruleである。
- schemaにIDがあるがruntimeで検証されていない。

同じ検査で品質CIの`pull_request`単独triggerとread-only permission、npm以外のlockfile不在、`package-lock.json`と`npm ci`、package engineとCI Node.jsの互換性、必須品質command、trusted default branch policy、npm配布境界を検証する。candidate policyはPR base SHAのvalidatorで評価し、同じPRがmerge・review・release条件を緩和して自己承認することを許可しない。
