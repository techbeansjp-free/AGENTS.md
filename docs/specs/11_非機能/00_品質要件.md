# 品質要件

| 品質特性 | 合格基準 | 確認方法 |
|---|---|---|
| 安全性 | 不明なmode、権限、remote、証拠、最新状態を拒否する | 悪用・失敗Gherkin |
| 原子性 | 失敗時に既存内容と正本を変更せず、partial状態を公開しない | collision・途中失敗テスト |
| 可読性 | 人が読む文書と全テスト起票を日本語にする | 日本語文書・Gherkin形式検査 |
| 追跡性 | 要件、SCN ID、テスト結果、実装、HEAD SHAを対応付ける | 追跡検証とPR証拠 |
| 移植性 | Node.js 20以上でESMとして動作する | typecheck、build、CI |
| 配布品質 | 開発専用資産と`memo/`をnpm packageへ含めない | 実際の`npm pack`内容検査 |
| 復旧性 | worktree完了前に到達可能な上流branchを保持する | finalize結合テスト |
| 開発速度 | local feedbackとPR gateのbudgetをproject policyで設定可能 | gateWaitMsとbudget超過診断 |
| policy品質 | 重複、誤block、override、rollback、検出漏れを観測可能 | metrics集計とdogfood E2E |
| 型安全性 | 製品実装はTypeScript strictで検査し、明示・暗黙の`any`を許可しない | `npm run lint`、`npm run typecheck`、source quality反例 |
| 形式品質 | ソース・JSON・設定を非破壊的な整形検査で固定し、書き込み整形は明示操作に分離する | `npm run format:check`、`npm run format:write` |
| 入力安全性 | 外部から取り込むJSON・policy・CLI入力は`unknown`から開始し、policy、manifest、state、evidence等の入力種別ごとに実行時検証してから型を確定する。未知field・未知version・型不正を黙殺しない | schema、入力種別別validator、SCN-UNIT-QUALITY-010 |
| 品質契約更新性 | candidateによる品質gateの自己緩和を拒否しながら、baseへ事前登録した版付きproposalとbyte/hashが完全一致する強化だけを次PRで有効化できる | `qualityContractVersion`、trusted proposal registry、SCN-UNIT-QUALITY-006、008〜009 |
| Privacy/Security | 秘密・個人情報・識別子の収集を最小化し、診断・ログ・例外への混入を防ぐ | redaction・悪用BDD、review |
| 運用可能性 | ログ・metrics・traceの目的、アクセス、改ざん防止、保持、rotation/容量上限、削除、監視、alertを境界ごとに設計する | 運用設計、失敗BDD、review |
| UI/UX契約 | UIを追加する場合は利用者中心設計、アクセシビリティ、Design/Layout Tokenを必須とする。現在のCLIは理由・証拠付きで非適用 | project choice、開発契約の適用判断 |
| NFR-836-01 安全性 | routing evidenceと診断に保存許可list外のfieldが0件であり、providerのstderr本文をログ、診断、例外、evidenceへ転記しない | SCN-INT-ROUTING-004、SCN-UNIT-ROUTING-012 |
| NFR-836-02 性能 | 実装開始前の外部観測をavailability観測と実行直前の再検証の合計2回以内にする | SCN-UNIT-ROUTING-009の観測回数検査 |
| NFR-836-03 可用性・復旧 | provider停止時は実装を開始せず、scopeを保持した再開可能なfail-closed診断を返す | SCN-E2E-ROUTING-001 |
| NFR-836-04 互換性 | `modelMapping`未設定の既存projectは読み込みに成功し、routingを行わない既存動作と終了codeを維持する | SCN-INT-ROUTING-006の既存fixture回帰 |
| NFR-836-05 保守性 | 汎用package資産に個別model slugを必須値として保持しない | SCN-UNIT-ROUTING-002、SCN-INT-ROUTING-005、conformance検査 |
| NFR-836-06 利用性・アクセシビリティ | routing診断はrule ID、目的、リスク、根拠、次の操作、必要authority、rollbackの7項目を空値なく持つ。画面部品を持たないため支援技術と視覚要素の基準は対象外 | SCN-UNIT-ROUTING-010 |

性能の数値SLOは、対話型のローカルCLIで外部API時間が支配的なためv0.3では定めない。CIは15分でtimeoutする。

Targeted検証は差分・risk・証拠fingerprintが同一の成功だけをdeduplicateする。最終gateは常にsecurity、受け入れ条件、独立review、full testを実行する。
