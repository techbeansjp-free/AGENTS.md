# 信頼境界

- パス、Unicode、シンボリックリンク、Git remote、repository、branch、HEAD SHA、認証、認可、外部観測状態を信頼しない。
- 読み取り結果だけに依存せず、書き込み・削除直前に対象と状態を再検証する。
- 候補PR内のpolicy変更は当該PRのmerge判断に使用しない。
- review、test、spec証拠は同じHEAD SHAへ結び付ける。
- merge、Issue close、branch削除、release、cleanupを別操作として認可する。

| 脅威 | 予防 | 検知・復旧 |
|---|---|---|
| パス走査・Unicode偽装 | NFC正規化、基準内解決、制御文字拒否 | 副作用前に拒否 |
| repository誤認 | URL構文解析とowner/name完全一致 | 外部書込を行わず診断 |
| 部分書込 | 隣接一時領域と原子的rename | 未公開一時物を除去し既存状態を保持 |
| TOCTOU | 適用直前の再検証と最新状態hash | 不一致時に拒否し再計画 |
| 秘密混入 | 引数配列、伏字化、配布許可リスト | CIの配布物検査 |
| 候補policy自己緩和 | default branchのtrusted ruleと強度・activation・overrideを比較 | ASC-TRUST-001でnon-override拒否しcandidate差分をrollback |
| override逸脱 | Issue、scope、actor、理由、期限、SHAの完全一致 | 監査記録なしで拒否しowner authorityを診断 |
| trusted ref不明 | origin/HEADをcommit SHAへ固定できなければauthority operationを停止。PR CIはGitHub eventの明示base SHAと40hex・一致・commit実在を検証 | candidate/worktree/package install元floorへfallbackせずremote構成またはexplicit base入力を修復 |

Non-override対象は秘密保護、Git内部領域、remote/worktree同一性、不可逆操作、成果物汚染、候補自身の承認防止である。環境変数や無期限flagはoverride authorityにならない。
