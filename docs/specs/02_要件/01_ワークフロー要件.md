# ワークフロー要件

### REQ-WF-001 モードを安全側に判定する

Q-01〜Q-08を全件根拠付きで満たす場合だけquickとする。不明、根拠なし、公開契約・data・security・依存・不可逆操作への影響があればfullへ単調昇格する。明示PoCは専用宣言とhigh risk不在を必要とする。

- 受け入れ条件: AC-WF-001
- 根拠: Issue #824、#827
- 実装: `src/domain/mode.ts`

### REQ-WF-002 Issue計画を原子的に同期する

Issue stagingを隣接一時領域で完成後に公開し、成果物inventoryとdigestを保持する。quick・pocはStep 4、fullはStep 8の耐久トラッカー書込後再読取一致だけを`sync-verified`とする。

- 受け入れ条件: AC-WF-002
- 根拠: Issue #824、#860
- 実装: `src/domain/issue.ts`

### REQ-WF-003 PoCを正式開発から隔離する

PoCは目的、期間、成功・中止条件、非対象、data・security制約、責任者、昇格・廃止条件を必須とし、release・自動merge・本番cleanupを拒否する。正式化では不足する01要件、02設計、03計画を補完し、fullからpocへ降格しない。

- 受け入れ条件: AC-WF-003
- 根拠: Issue #827
- 実装: `src/domain/issue.ts`

### REQ-WF-004 Step順序とjournalを機械検証する

Step 0〜11、mode別列、staging成果物path、共通staging検査を`src/domain/workflow.ts`の単一正本で定義する。journalは行順、必須成果物、evidence、mode単調昇格を検証し、PR作成前にStep 4・10・同期状態を含むStep 10までを要求する。モード判定成果物は`changedFiles`を保存し、再分類でも同じhigh risk判定を再現する。欠落overrideはIssue・scope・主体・理由・期限へ拘束し、承認元をcandidate管理下から分離する。

- 受け入れ条件: AC-WF-004
- 根拠: Issue #877
- 実装: `src/domain/workflow.ts`

### REQ-WF-005 reviewと証拠を独立させる

reviewは肯定・敵対の全観点を最大3ラウンドで評価する。製品・仕様・testを固定した`H_impl`とreview artifactだけを加えた`H_final`を分離し、実装者・PR authorから独立した同一HEADのapprovalと成功CIだけを承認証拠とする。

- 受け入れ条件: AC-WF-005
- 根拠: Issue #824、#834
- 実装: `src/domain/review.ts`

- 受け入れ条件: AC-WF-006

### REQ-WF-007 role・model・tierと独立性を解決する

- 受け入れ条件: AC-WF-007

- 受け入れ条件: AC-WF-008
- 根拠: Issue #834、#837
- 実装: `src/domain/conformance.ts`

### REQ-WF-009 CLIの必須入力とusageを1回の実行で提示する

subcommandごとの要約、必須flag、条件付きflag、任意flagと既定値、実行例を`src/cli-usage.ts`の単一正本で定義する。`--help`は必須flag検証より先に評価してusageを返す。不足している必須flagは1件ずつではなく1回の実行で全件を`reasons`へ列挙する。値をとるflagの空白区切り指定は無言の未指定扱いにせず、`--flag=値`形式を求める専用診断で拒否する。trusted boundary評価は必須flag検証より先に行う。usage正本と`src/cli.ts`の実装が読むflagの一致は`scripts/check_cli_usage.ts`が双方向に検証する。

- 受け入れ条件: AC-WF-009
- 根拠: Issue #886
配布文書は`--help`の存在、値をとるflagが空白区切りを受理しないこと、不足flagを1回で全件返すことを述べる。**同じ事実を二度書かない。** `.agent-skill-chain/00_利用案内.md`とREADMEの該当区画は`scripts/generate_cli_usage_guide.ts`が`src/cli-usage.ts`のusage正本から生成し、`scripts/check_cli_usage.ts`は生成区画が正本の描画結果と一致することだけを検証する。一致しない場合は生成commandの実行を求める。

- 実装: `src/cli-usage.ts`、`src/cli.ts`、`scripts/check_cli_usage.ts`、`scripts/generate_cli_usage_guide.ts`、`.agent-skill-chain/00_利用案内.md`、`README.md`
