# 要件一覧

要件IDはIssue番号ではなく、変更頻度と所有責務が安定している境界づけられたコンテキストを表す。**この体系は配布templateにも適用する。** `.agent-skill-chain/templates/specs/`の要件ID・受け入れ条件IDは`REQ-{domain}-{3桁}`・`AC-{domain}-{同じ3桁}`とし、domainはplaceholderとして利用projectが定義する。製品が配る型を製品自身が使う。`REQ-WF`は開発ワークフロー、`REQ-LC`はローカル資産ライフサイクル、`REQ-GH`はGitHub・release連携、`REQ-SQ`は仕様・安全・品質管理である。末尾の3桁連番は各コンテキスト内の安定番号であり、廃止時も再利用しない。

## 共通既定値

- `高速に`、`適切に`等の判定不能な表現だけで要件を完了させない。
- 必須要件の変更、Critical/High risk受容、不可逆操作、相反する事業判断には新しい人間権限を要求する。
- この一覧と`01_`〜`04_`の要件見出しは異なる構文・異なるfileから独立列挙し、`trace:check`で双方向一致を検査する。同じ`docs/specs/02_要件/`を列挙源とするため、directory全体の同時欠落は両手段とも検知できない限界がある。必須file検査とGit差分reviewで補完する。
