# プロジェクトライフサイクル要件

### REQ-LC-001 package資産を安全に導入・更新・削除する

`install`、`update`、`delete`はpreviewを既定とし、`--apply`時だけpackage所有の通常fileを変更する。利用者文書、project policy、仕様、staging、他tool、symlink、変更済み資産を保持し、hash・containment・TOCTOUを各write前に検証する。部分失敗はremoved・pending・recoveryを返す。**repository直下のhost入口は、hostごとに常時読まれるfile名が違うため複数を展開する。** Codexは`AGENTS.md`、Claude Codeは`CLAUDE.md`を読む。片方だけを配ると、もう片方のhostでは規範文書へ到達する常時の入口が存在しない。**host skillは呼び出されたときに読まれる登録口であり、常時の入口の代替にならない。** 展開対象の一覧を正本とし、record検証がfile名を別に持たない。

**強制点hookは本体だけを配り、登録は配らない**（Issue #1105）。hookはhostのtool呼び出し前に**利用者の操作なしに毎回走る**点でskillと責務が違う。**正本は`.agent-skill-chain/hooks/`に1つだけ置き、`install`と`update`が`.claude/hooks/`と`.codex/hooks/`へ展開する。** 展開先は`HOST_SKILL_TARGETS`とは別の定数に分ける。**共通のloopへまとめない。** まとめると展開先の一覧を消す変異がskillとhookの両方を同時に消し、片方だけを壊す変異を検出できない。**展開先を`isPackageOwnedPath`へも足す。** 足さないと展開はされるがmanaged record検証で拒否され`update`と`delete`が使えなくなる。**実行bitを保つ。** 実行できないhookは強制点にならない。**`install`はhostが所有する設定fileへ書き込まない。** 書き込みは`install`の権限を「packageの資産を置く」から「以後のtool callごとに自動実行されるcodeを登録する」へ広げる。**登録状態は`doctor`が報告するだけにとどめ、`healthy`を変えない。** 本体の欠落・改変はmanaged assetの診断として`healthy`へ入るが、登録は利用者による有効化状態でありpackageのinstall健全性ではない。**診断は「hookが無効です」と断定しない。** project-localの設定だけを見ており、global・managed・plugin経由の有効化状態は見えない。**発火を実測していないhostについて対応したと称さない。** Codex CLIのhook契約は設定探索path・event名・matcher対象tool名・標準入力schema・path変数のいずれも確認できておらず、隔離環境での発火試験は不発だった。**したがってCodex用の設定fileを配らない。** **強制するのは`SCN-INT-LIFECYCLE-010`（正本と2つの展開先の配置）、`SCN-INT-LIFECYCLE-011`（実行bit）、`SCN-INT-LIFECYCLE-012`（消えた展開先の復元）、`SCN-INT-LIFECYCLE-013`（利用者が変更したhookの保持）、`SCN-INT-LIFECYCLE-014`（host設定fileの不変）、`SCN-UNIT-PACKAGE-028`（配布物の必須asset）、`SCN-UNIT-PACKAGE-029`（案内がCodex側の未確認を述べること）、`SCN-UNIT-DOCTORHOOK-001`〜`003`（登録の3状態と断定しない診断）である。**

- 受け入れ条件: AC-LC-001
- 根拠: Issue #828
- 実装: `src/domain/lifecycle.ts`

### REQ-LC-002 host skill adapterを管理する

共通`asc-step`正本をClaude CodeとCodexの所定pathへ配置しmanaged hashへ登録する。未管理で正本とbyte一致するfileは採用し、異なる利用者fileと他skillは保持する。doctorはfrontmatter、正本link、hash、配置を検証する。正本はStep skill一覧への相対linkを持ち、そのlinkは正本と配置先のすべてから一覧正本へ解決する。正本の`description`は各Stepの開始を示す語を含む単一行とし、正本はStep skillの実名も対応表も複製しない。この内容契約はpackageの受け入れtestが強制する。doctorの診断範囲は上記のfrontmatter・正本link・hash・配置に留まり、内容契約まで広げない。

- 受け入れ条件: AC-LC-002
- 根拠: Issue #847

### REQ-LC-008 worktreeを読み取り専用で走査する

登録済みworktreeをprimary、in-progress、cleanup-ready、retainへ順序付き分類し、保持理由を全件日本語で返す。不正entryを分離して正常entryの判定を継続し、候補の存在だけで非0にせず、走査・doctor・削除の責務を分離する。

**detached HEADは正当な観測であり、分類から落とさない。** HEADの付着状態は`git worktree list --porcelain`の明示marker（`branch refs/heads/…`と`detached`）だけを根拠にし、**branch行の欠落をdetachedと推測しない。** attachedは空でないbranch名、detachedは`branch: null`を持ち、両方ある・両方ない観測、attachedで空、detachedでbranchあり、`headState`が列挙外の観測は不正として分離する。**不正観測のerrorはraw添字だけでなくpathを含める。** 添字はraw観測の位置であり、どのworktreeかを示さないためである。detachedは分類を自動でretainへ変える理由ではなく、REQ-LC-010の先例どおり「HEADがdetachedです。現行のfinalizeは対象branchを要求するため、この経路では後片付けできません」を理由へ加える。理由が残る限りcleanup-readyへ進まない。text形式はbranch欄へ`(detached)`を表示する。**この不変条件を強制するのは`SCN-UNIT-WTSURVEY-023`から`SCN-UNIT-WTSURVEY-026`と`SCN-INT-WTSURVEY-014`から`SCN-INT-WTSURVEY-015`である。** finalizeの対象同一性をHEAD SHAへ拡張してdetachedを後片付け可能にすることは、不可逆操作の認可条件に触れるため本条項の対象外である（Issue #1251）。

**分類はrepositoryのobject formatに依存しない。** HEAD SHAとして受理するのはGitのobject formatが定める桁数の小文字hexであり、SHA-1の40桁とSHA-256の64桁の2値に閉じる。**これは字句形式の検証であって、object IDの実在確認でも、repositoryの実際のobject formatとの照合でもない。** null OIDのような実在しない値も字句としては受理する。**任意長のhexを受理しない。** 誤長の文字列が分類へ混入するためである。**大文字を小文字へ畳み込まない。** `git worktree list --porcelain`の出力は小文字であり、大文字の到来は観測経路の異常を意味するため、正規化はその異常を隠す。

**HEAD観測の解析と判定はdomainが単独で所有する。** porcelain出力の解析は`parseWorktreeHeads`が、桁数の判定は`isWorktreeHeadSha`が持ち、CLI層の責務はgitの起動と出力の受け渡しだけである。**CLI層へ解析を置かない。** 実gitは正しい桁数の小文字しか出力しないため、CLI層に解析があると異常なporcelainを与える経路が無く、正規化を挟む変更が全scenario緑のまま通る。

**受理範囲の限定性は信頼する入力元に依存する。** 本条項が想定する入力は、成功した実Gitの`git worktree list --porcelain`だけである。Gitは内部のobject IDを出力するため、字句検証で足りる。**domain APIへ直接与える合成入力は信頼境界の外にある。** また`worktree survey`は報告だけを行い、削除は`worktree finalize`が対象を独立に再検証する。**この2点が成り立たない構成では、字句検証だけでは不足する。**

**この不変条件を強制するのは`SCN-UNIT-WTSURVEY-027`から`SCN-UNIT-WTSURVEY-032`と`SCN-INT-WTSURVEY-016`から`SCN-INT-WTSURVEY-017`である。** repositoryの実際のobject formatと桁数の整合を確認することは本条項の対象外である。**理由は目的との整合ではなく費用と前提である。** 照合には`git rev-parse --show-object-format`の追加観測が要り、compatibility formatを持つrepositoryでは単純な桁数対応が成り立たない。上の信頼する入力元の前提が成り立つ限り、追加観測に見合う検出力が無い（Issue #1255）。

- 受け入れ条件: AC-LC-008
- 根拠: Issue #883
- 実装: `src/domain/worktree-survey.ts`

### REQ-LC-009 ignore対象を安全に判定してworktreeを後片付けする

finalize ignore allowlistはpackage既定の`node_modules/`と`dist/`、およびtrusted project policyの安全なdirectory prefixだけを受理し、schemaとruntimeで同じ入力集合を検証する。候補側は削除可能範囲の拡大を自己承認できない。surveyとfinalizeは同じ純粋な安全判定を使い、allowlist内のignore対象だけを再生成可能として保持理由から除く。allowlist外・種別不明のignore対象はpathと日本語理由を返し、未commitの追跡対象file、未追跡file、stash、未push・到達不能commit、remote branch不明、PR未merge、復旧不能、`.worktrees/`の直接の子でない配置を従来どおり拒否する。**復旧可能性はupstream refの一致だけでなく、既定branchからのHEAD到達でも成立する。** 既定branchは`refs/remotes/origin/HEAD`から解決し、解決不能とmerge-base判定不能はいずれも到達不成立として扱う。**既定branchからの到達を`reachableFromDefaultBranch`として独立に観測し、それが真であると観測できたときだけ、upstream ref由来の拒否理由（未pushのcommit件数、push未実施、remote branch不在、復旧参照不在）を免除する。** 同fieldが不明なら免除しない。`pushed`・`remoteBranch`・`recoveryRef`の意味は変えない。作業tree由来の拒否は到達可能性にかかわらず維持する。cleanup計画の配列・boolean観測が不正または不明な場合は、他の観測から安全状態を推定せずretainとする。buildとgateで生成したallowlist内資産は、survey、finalize preview、authority・digest付きapplyの順で後片付けする。
**保持理由は、その領域を所有するcommandが存在する場合それを示す。** `.agent-skill-chain/tmp/issues/`配下のblocking資産の保持理由へ、`issue staging`が所有する領域である旨を末尾へ加える。**案内は安全判定と資産分類を変えない。** allowlist判定の後に生成し、`safe`にも`allowedIgnoredArtifacts`にも`blockingIgnoredArtifacts`にも影響しない。REQ-LC-011の「報告するがhealthyを変えない」と同じ形である。**ただし診断出力の契約は意図的に変える。** `reasons`の文字列は戻り値とCLI出力へ露出しており観測可能な契約である。**「契約を一切変えない」ではない。** 変えないのは判定の契約であり、変えるのは診断の契約である。**案内はpath文字列だけから決め、filesystemを読まない。** `assessWorktreeRemovalSafety`が純関数であり`survey`と`finalize`が同じ判定を使うことを維持するためである。**接頭辞は末尾`/`を含み、`.agent-skill-chain/tmp/issues`そのものと`.agent-skill-chain/tmp/issues-other/`配下へは案内を出さない。** **大小文字を畳み込まない。** Gitのpathはcase-sensitiveであり、畳み込むと`.AGENT-SKILL-CHAIN/TMP/ISSUES/x`のような別pathを所有領域と誤認する。**案内側で正規化しない。** 空segment、`.`、`..`、絶対path、`\`、制御文字、非NFCは`validArtifactPath`が案内より前で不正観測へ分離するため、末尾slash形や`tmp/issues/../runtime/x`は案内へ届かない。**`STAGING_LIFECYCLE_AREAS`を案内へ流用しない。** 同配列は「真なら保護する」ライフサイクル分類の正本であり`.agent-skill-chain/tmp`全体を含む。分類の正本を案内へ流用すると、将来その配列へ領域を追加したとき誤った案内が出る。**強制主体を条項ごとに分ける。** 案内の出現範囲は`SCN-UNIT-FINALIGN-035`と`SCN-UNIT-FINALIGN-036`が、案内が判定を変えないことは`SCN-UNIT-FINALIGN-037`が担う。**`role-log`、`metrics`、`runtime`には案内が無い。** それらに所有commandが存在するかは確認していない。過剰な案内より無い方が安全側である（Issue #1290）。

- 受け入れ条件: AC-LC-009
- 根拠: Issue #894
- 実装: `src/domain/worktree-removal-safety.ts`、`src/domain/finalize.ts`、`src/domain/worktree-survey.ts`、`src/domain/worktree.ts`、`src/domain/policy.ts`、`src/cli.ts`、`.agent-skill-chain/schemas/project-policy-manifest.schema.json`、`.agent-skill-chain/schemas/project-policy.schema.json`

### REQ-LC-010 worktree名の時刻と作成後の命名整合性を検証する

`worktree create`はCLI層で取得した現在時刻をdomainへ必須入力として渡す。directory名の`YYYYMMDD_HHMMSS`をlocal timeとして解釈し、未来または現在時刻から10分を超えて古いtimestampを副作用前に拒否する。明示pathではGit内部侵入などのtrusted boundaryをdirectory名・timestamp・Issue番号・slugより先に評価する。`--path`省略時は同じ現在時刻、Issue番号、slugから`.worktrees/{timestamp}-{issueNumber}-{slug}`を構成する。現在時刻の未指定・不正値はtimestamp検証を省略せず拒否する。`worktree survey`はdirectory名とbranch名のIssue番号・slugの不一致を`reasons`へ報告するが、分類または削除判断を変更せず、既存directoryを改名しない。

worktree作成契約は配布物の`.agent-skill-chain/docs/01_開発ワークフロー.md`へも届ける。**同じ事実を二度書かない。** 正本は`src/domain/worktree.ts`の`WORKTREE_NAME_FORMAT`と`WORKTREE_TIMESTAMP_MAX_AGE_MINUTES`であり、配布文書の該当区画は`scripts/generate_worktree_contract.ts`が正本から生成する。`conformance:check`は生成区画が正本の描画結果と一致することだけを検証し、一致しない場合は生成commandの実行を求める。正本が述べる書式をruntimeの`WORKTREE_NAME`が受理することも同時に検証する。

- 受け入れ条件: AC-LC-010
- 根拠: Issue #893
- 実装: `src/domain/worktree.ts`、`src/domain/worktree-survey.ts`、`src/cli.ts`

### REQ-LC-011 製品自身のlifecycle健全性をCIで検証する

CIは`build`の後に製品自身のrepositoryへ`install --apply`でhost skill登録アダプターを展開し、`doctor`が`healthy: true`かつ`installed: true`を返すことを要求する。`healthy: false`はCIを失敗させる。展開先の`.claude/`と`.agents/`、および`.agent-skill-chain/managed-assets.json`は`.gitignore`の対象とし、展開後も`git status --porcelain`が空であることを同じCIで確認する。`doctor`は既定branchへmerge済みで後片付け可能なworktreeを件数と個別pathで報告するが、削除は行わず`healthy`も変えない。削除は`worktree finalize`と`worktree hygiene`のpreview・承認hash経路に限る。`.codex/`はhost skill登録アダプターの対象ではない。Codexの登録口は`.agents/skills/asc-step/SKILL.md`である。

**`doctor`は契約を満たしたまま未完で止まっているstagingを、件数と個別pathとStep位置で報告する。** 未完のstagingには「契約を満たさない記録を持つもの」と「単に途中で止まっているもの」が混ざり、どちらも`valid: false`へ潰れると手を入れるべきものを選べない。実測では28件中9件が後者だった（Issue #954）。**worktreeの後片付け報告と同じく、削除も是正も行わず`healthy`も変えない。** 報告の分離だけを行う。**この不変条件を強制するのは`SCN-UNIT-WFPATH-003`から`SCN-UNIT-WFPATH-005`である。**

- 受け入れ条件: AC-LC-011
- 根拠: Issue #882、#847、#856、#883
- 実装: `.github/workflows/ci.yml`、`.gitignore`、`src/domain/lifecycle.ts`
