# グラフ投影要件

## 文書の責務

本書は、agent skill chain（ASC）がGit管理された要求、受入条件、設計、実装、test、review、Evidenceおよびproviderから耐久化済みの事実を横断して追跡するための、Semantic Graphの要求、system要件、受け入れ条件を所有する。GraphDB製品の一般説明、実装手順、test code、運用commandの重複説明は所有しない。

`REQ-GR`は「Graph Projection」境界づけられたコンテキストを表す。Requirement IDは`REQ-GR-{3桁}`、対応する受け入れ条件IDは`AC-GR-{同じ3桁}`とする。廃止した番号は再利用しない。

## 要求

ASCは、開発を速く進めるために、要求から実装・検証・review・mergeまでの関係を毎回全文探索やAI推論だけで復元せず、問い合わせ可能なSemantic Graphとして利用できなければならない。同時に、Graphの導入が新しい編集正本、新しい長期観測待ち、worktree間の共有状態、またはGraph障害時の人間承認待ちを生んではならない。

この要求を成立させる上位条件は次のとおりである。

1. Git管理されたtext、source code、test、policy、workflow、Evidence manifest、およびproviderから既存の耐久stateへ記録された事実を正本とする。
2. GraphDBは削除可能かつ完全再構築可能な派生Read Modelであり、GraphDB binaryをGit管理しない。
3. 各worktreeは独立した投影を持ち、別worktreeの未確定変更を観測しない。
4. AI推論は候補探索に使えるが、Gate判定は決定論的・再現可能なGraph Evidenceと他のEvidenceを組み合わせる。
5. 探索は決定論的かつhard bound付きとし、大きい・循環する・不正なGraphでも無制限に実行しない。
6. Full、Quick、PoCは別のworkflow modeとして維持し、Graphを理由に一律にFull化しない。
7. 実日数を待つ観測期間ではなく、隔離した疑似projectのユースケースと反例を実行して成立性を判定する。

## 共通語彙と境界

| 用語 | 本書での意味 |
|---|---|
| Source of Truth | Git管理された意味情報と、Gitまたはproviderを正本として既存の耐久stateへ記録された事実。GraphDBは含まない |
| Semantic Graph | Source of Truthから構築したtyped node・edgeの論理Graph |
| Projection | Source of Truthを問い合わせ用に変換した、破棄・再構築可能なRead Model |
| GraphStorePort | Domainがstorage製品へ依存しないための`replace/read/close`境界 |
| exact Graph Evidence | 現在source、schema、builder、extension、manifest、実投影hashがすべて一致したGraphから得た決定論的証拠 |
| candidate | 推論edge、stale Graph、不完全探索等から得た、Gate PASSへ単独利用できない候補 |
| drift | 現在のSource of Truthと投影、または投影を読むための契約が一致しない状態 |
| hard budget | depth、訪問node数、訪問edge数、結果数、operation数の事前上限。wall clock timeoutだけで代用しない |

## 要件

### REQ-GR-001 Source of Truthと派生投影を分離する

要求、受入条件、設計、ADR、code、test、policy、workflow、review・test Evidenceの正本をGit管理可能な意味情報または既存の耐久Evidence Storeに置く。GitHub等のprovider事実はproviderまたはproviderから再読取して固定した耐久stateを正本とし、Graph Builderが外部状態を推測して生成してはならない。

GraphQLite database、current pointer、generation、cacheおよび一時構築物は、`.agent-skill-chain/runtime/graph/`配下のGit管理外runtime projectionとする。これらを全削除しても正本を失わず、完全再構築で復旧できなければならない。Graph間またはbranch間でdatabase binaryをmergeしない。

GraphDBだけにRequirement、Finding、Evidenceまたはprovider状態を書き込むcommandを公開しない。Graphのwrite APIはcanonical snapshotの置換に限定し、利用者がGraphを第二の編集正本として使える汎用CRUDを提供しない。

- 受け入れ条件: AC-GR-001
- 検証Evidence: runtime pathのignore検査、Graph削除後の完全再構築、Source of Truth無変更の確認
- 実装: `.gitignore`、`src/adapters/repository-graph.ts`、`src/adapters/graphqlite.ts`

#### AC-GR-001

- Given Git管理された同じproject sourceがある、When Graph runtime一式を削除して再構築する、Then削除前後のcanonical Graph content hashが一致し、Git管理fileは変更されない。
- Given GraphDB binaryをGitへ追加しようとする、When package conformanceを検査する、Then runtime projectionを正本として扱う変更は拒否される。
- Given review Findingまたはprovider事実がGraphにだけ存在する、WhenGraphを削除する、Then再構築不能な情報としてGateは失敗し、Graphだけを正本に昇格しない。

### REQ-GR-002 Graph storageをPortと固定GraphQLite adapterへ分離する

Domain modelと探索アルゴリズムはGraphQLite、SQLite SQLまたはCypherへ依存せず、`GraphStorePort`だけへ依存する。Primary adapterは`colliery-io/graphqlite` v0.6.1、commit `a1c65adcc1cc261f9bf9fd0a059f2cfb4b955d13`の公式release assetとする。version、platform・architecture別asset名、byte size、SHA-256をsourceに固定し、`latest`、未検証mirror、path探索で見つけた共有libraryを利用しない。

GraphQLite extensionの取得はpreview既定・`--apply`明示のinstall operationに分離する。取得時はHTTPSの公式release URL、固定size、固定SHA-256を検証してworktree内runtimeへ原子的に配置する。既存fileがsymlink、通常file以外、sizeまたはdigest不一致なら上書きせずfail closedとする。unsupported platform・architectureは代替binaryを推測しない。

Graph subcommandは`node:sqlite`の`DatabaseSync.loadExtension(path, entryPoint)`を使用し、entry point `sqlite3_graphqlite_init`を明示する。extensionを読み込んだ直後に追加extension loadingを無効化する。Graph機能の最低versionは、`loadExtension`と`enableLoadExtension`が利用でき、`node:sqlite`がflag不要になったNode.js 22.13.0以上とする。package全体はNode.js 20以上の非Graph CLIを維持し、GraphQLite adapterをdynamic importに限定する。Node 22.13.0未満のGraph commandはadapter load、network、filesystem writeの前に理由付きで拒否する。

- 受け入れ条件: AC-GR-002
- 検証Evidence: platform asset tableのexact照合、digest不一致反例、Node 22.13境界、Portのsource dependency検査
- 実装: `src/domain/semantic-graph.ts`、`src/adapters/graphqlite.ts`、`src/cli.ts`

#### AC-GR-002

- Given対応platform上にextensionがない、When`graph install --dry-run`を実行する、Then予定URL・version・size・digest・配置先だけを返しnetwork writeを行わない。
- Given公式assetと一致するcontentを取得した、When`graph install --apply`を実行する、Then原子的に通常fileとして配置して再読取digestを検証する。
- Givendigest不一致、symlinkまたはunsupported platformである、Whenadapterを初期化する、Thendatabaseを開く前に理由付きで拒否する。
- GivenNode 22.13.0未満である、Whengraph commandを実行する、Thenadapter import、network、filesystem writeの前に理由付きで拒否する。
- GivenNode 20以上22.13.0未満である、When非Graph commandを実行する、ThenGraphQLite adapterを読み込まず従来どおり実行する。
- GivenNode.js 20で非Graph commandを実行する、When配布CLIを起動する、ThenGraphQLite adapterをloadせず従来機能が動作する。
- GivenDomain sourceを静的検査する、WhenGraphQLite固有import・Cypher・SQLを探索する、Thenそれらはadapter層にだけ存在する。

### REQ-GR-003 同じ意味sourceから決定論的なGraphを完全再構築する

Builderはrepository rootを境界とし、Gitのtracked fileおよびignoreされていない対象fileを、NFC正規化したrepository相対pathの辞書順で有限走査する。絶対path、`..`、backslash、制御文字、symlink先のcontent、上限を超える単一file・source集合を意味Graphへ取り込まない。

snapshotは明示的な`graphSchemaVersion`と`graphBuilderVersion`を持つ。同じ意味source、同じschema、同じbuilderからは、入力列挙順、実行者、Agent、worktree絶対path、build timestampに依存せず同じcanonical node・edge列と`graphContentHash`を得なければならない。hashから`builtAt`、worktree identity、HEAD等の配置・観測metadataを除外し、node、edge、propertiesを安定順に正規化する。

一方、manifestはrepository、worktree、HEAD、tree、dirty flag、全sourceのcontent digestをSource Identityとして保持する。構築前後に同じSource Identityを観測し、途中変更を検出した場合は投影を公開しない。incremental updateまたはBase Graphは最適化であり、完全再構築との意味的同値性を決定論的に証明できるまで既定経路にしない。

- 受け入れ条件: AC-GR-003
- 検証Evidence: 入力順差分のproperty test、clean clone間のhash一致、構築中source変更反例
- 実装: `src/domain/semantic-graph.ts`、`src/adapters/repository-graph.ts`

#### AC-GR-003

- Given同じnode・edge・propertiesを異なる順序と異なるworktree identityで持つsnapshot、Whencanonical hashを計算する、Thenhashは一致し入力を変更しない。
- Given同じclean commitを別worktreeへcheckoutした、When双方で完全再構築する、ThenGraph content hash、node数、edge数が一致する。
- Given構築のsource読取中にfileが変更された、When公開前のSource Identityを再観測する、Thenpending generationをcurrentへ切り替えず再実行を要求する。

### REQ-GR-004 worktreeごとにGraph runtimeを隔離する

各worktreeは自身の`.agent-skill-chain/runtime/graph/v1/`だけにextension、immutable generation database、manifest、current pointerを持つ。worktree identityはcanonical rootとabsolute Git directoryから求めたdigestとし、同じbranch名、同じHEAD、似たpath名だけで同一視しない。

Graph operationは指定rootが当該worktreeのrepository rootであること、runtime pathがそのreal rootに包含されること、database・extension・pointerがsymlinkでないことを副作用前に検証する。他worktree、親repository、shared cache、任意環境変数のpathへfallbackしない。

あるworktreeのdirty sourceまたはprojectionが、別worktreeのGraph freshness、impact結果またはGateを変えてはならない。branch mergeではGraphDBをmergeせず、merge後sourceから対象worktreeのprojectionを再構築する。

- 受け入れ条件: AC-GR-004
- 検証Evidence: 同一HEADの2 worktree、片方だけdirtyにする隔離scenario、wrong-worktree manifest反例
- 実装: `src/adapters/repository-graph.ts`、`src/adapters/graphqlite.ts`

#### AC-GR-004

- Given同じHEADを持つworktree AとB、WhenAだけのsourceを変更してAを再構築する、ThenBのruntime file、manifest、freshness、query結果は変わらない。
- GivenAのmanifestをBで読ませる、Whenfreshnessを評価する、Then`wrong-worktree`としてexact Evidenceを禁止し、Bでのrebuildだけを復旧手段にする。
- Givenroot外またはsymlink経由のruntime path、Wheninstallまたはrebuildを適用する、Then外部write前に拒否する。

### REQ-GR-005 typed schema、provenance、certaintyを検証する

Semantic Graphは少なくともrepository、commit、requirement、acceptance criteria、design、ADR、file、symbol、scenario、test、review、finding、evidence、pull request、merge、workflow run、capability、worktreeを拡張可能なnode kindとして表現できる。edgeはcontains、depends-on、imports、references、has-acceptance-criteria、designed-by、decided-by、verified-by、satisfied-by、produces-evidence、reviewed-by、produced-finding、affects、violates、supported-by、merged-asをtyped relationとして表現できる。

この一覧はDomain schemaの**語彙**であり、各projectorが現在すべてを投影するという機能主張ではない。Repository Projectorはmachine-readableな固定capabilityをexportし、現行builderがmaterializeするnode kindをrepository、commit、requirement、acceptance criteria、design、file、scenario、review、worktree、edge kindをcontains、imports、references、has-acceptance-criteria、verified-by、satisfied-by、supported-byに限定する。ADR、symbol、test、finding、evidence、provider由来node等は、対応する正本parserとprovenanceを実装・検証するまでschema語彙に留め、投影済みと表示しない。

各node・edgeはstable ID、kind、source path、任意のsource line、scalar property、`deterministic`または`inferred`のcertaintyを持つ。inferred要素は0以上1以下のconfidenceを必須とし、deterministic要素へconfidenceを付けない。edge endpoint未解決、重複ID、未知kind、負・非有限weight、不正path・line・property、malformed Source Identityを例外的に無視せず検証Evidenceとして全件報告する。

特にtrace tableが参照するFeatureまたはImplementation pathがsource集合に存在しない場合、projectorはそのpathをfilterして正常なGraphに見せず、source path・line・不足endpointを含むstable diagnosticで完全構築をfail closedにする。

Gateと既定impact queryはdeterministic edgeだけを対象とする。inferred edgeを含める操作は明示optionとcandidate表示を必要とし、その結果だけでexact GateをPASSしない。GraphRAG、Embedding、similarity search、時系列telemetryは本コンテキストの責務外とし、将来必要なら別Port・Storeへ分離する。

- 受け入れ条件: AC-GR-005
- 検証Evidence: schema validator反例、inferred exclusion、unknown kind・endpoint・weight検査
- 実装: `src/domain/semantic-graph.ts`、`src/adapters/repository-graph.ts`

#### AC-GR-005

- Given重複node、未解決endpoint、負weight、不正provenanceを持つsnapshot、Whenvalidateまたはqueryする、Then黙って空Graphへ変換せずstableなinvalid reasonsを全件返す。
- Givendeterministicとinferred edgeが同じnodeへ到達する、When既定impact queryを実行する、Thendeterministic edgeだけを結果に含める。
- Giveninferred edgeを明示的に含める、When結果をEvidenceへ変換する、Thencandidateであること、confidence、sourceを保持しexact Gateの単独根拠にしない。
- GivenDomain schemaに将来用kindが存在する、WhenRepository Projector capabilityを観測する、Then現行builderが実際にmaterializeするkindだけを返し、未実装kindを投影済みと主張しない。
- Giventrace tableが存在しないFeatureまたはImplementation pathを参照する、When完全投影する、Then不足endpointを黙って削除せずstable diagnosticでfail closedになる。

### REQ-GR-006 manifestと実投影を照合してdriftを制御する

公開済みgenerationは、manifest version、Graph schema version、Builder version、GraphQLite version・asset digest、Source Identity、Graph content hash、node・edge count、単調増加generation、`complete`状態、canonical UTC build timestampを持つ。database内manifest、current pointer、databaseから再読取して再計算したsnapshot hash・件数を照合する。

freshnessは少なくとも`missing`、`corrupt`、`incomplete`、`schema-mismatch`、`builder-mismatch`、`extension-mismatch`、`wrong-worktree`、`source-ahead`、`projection-unverified`、`projection-drift`を区別し、複数理由をstable順で返す。manifestだけが一致し、実Graphを再読取していない場合は`projection-unverified`である。

1件でもdriftがあればexact Graph Evidenceを禁止する。Source of Truthと固定extensionが健全で完全再構築により復旧可能なら、通常経路は人間へ質問せずrebuildするか、書き込みauthorityがないread-only操作では具体的なrebuild commandを返す。破損databaseのbackupを正本保護に必須化しない。

- 受け入れ条件: AC-GR-006
- 検証Evidence: 各drift分類、複合drift、database read-back、rebuild収束
- 実装: `src/domain/semantic-graph.ts`、`src/adapters/graphqlite.ts`、`src/cli.ts`

#### AC-GR-006

- GivenSource Identity、version、digest、manifest、実snapshot hash・件数が完全一致する、Whenstatusを評価する、Then`fresh=true`かつ`exactEvidenceAllowed=true`になる。
- Givenmanifestは一致するが実snapshot hashを未観測である、Whenstatusを評価する、Then`projection-unverified`となりexact Evidenceを禁止する。
- Given複数のversion・worktree・source・projection driftがある、Whenstatusを評価する、Then全理由を決定論的順序で返し、成功と誤報しない。
- Givenmissingまたはcorruptなprojection、Whenapply authorityを持つ回復経路を実行する、Then正本から新generationを構築・read-backした後だけcurrent pointerを原子的に切り替える。

### REQ-GR-007 変更影響を決定論的なbounded BFSで探索する

unweightedな到達可能性と変更影響はbreadth-first searchを使用する。複数start node、edge kind、incoming・outgoing方向、inferred edge包含可否を明示入力とし、start nodeと隣接edgeをstable IDの辞書順で処理する。同じ意味Graphとqueryからは、挿入順に依存せず同じ部分結果、counter、理由を返す。

探索は`maxDepth`、`maxVisitedNodes`、`maxVisitedEdges`、`maxResults`、`maxOperations`の全hard budgetを持つ。start集合自体もbudgetへ算入し、depth上限に達した先に未訪問nodeがある場合を`complete`としない。上限到達時は例外や無制限拡張ではなく`budget-exceeded`、上限以内のcanonical部分結果、実測counter、到達上限理由を返す。

freshでないGraph、存在しないstart、不正snapshot、不正budgetでは探索せず`invalid`またはstale statusを返す。不完全探索結果を「影響なし」のEvidenceに使用しない。

- 受け入れ条件: AC-GR-007
- 検証Evidence: `SCN-UNIT-SEMGRAPH-002`、`003`、`015`、`016`、入力順differential test
- 実装: `src/domain/semantic-graph.ts`、`src/cli.ts`

#### AC-GR-007

- Given同値Graphを異なる挿入順で構築した、When同じbounded BFSを実行する、Thennode順、counter、status、reasonsが一致する。
- Given各hard budgetの境界反例、When探索する、Thenいずれも指定上限を1件も超えず`budget-exceeded`を返す。
- Givenmax depthの先に未訪問edgeがある、When探索する、Then部分結果を返しつつ`complete`または「影響なし」と判定しない。

### REQ-GR-008 依存順序とcycleをKahn法とiterative Tarjan法で判定する

順序制約は対象edge kindを明示してKahnのtopological sortで処理する。indegree計算を含む全operationをbudgetへ算入し、ready nodeはmin-heap等によりstable IDの辞書順で選択する。GraphがDAGならすべてのnodeを一度だけ含む、edge制約を満たすcanonical orderを返す。

未処理nodeが残る場合はiterative Tarjan法でstrongly connected componentを求める。再帰call stackへGraph深度を委ねず、component内のIDとcomponent列をcanonical順にする。2 node以上のcomponentに加えself loopを1 node cycleとして報告する。node、edge、result、operationのhard budgetを守り、不完全なcycle分析を完全結果にしない。

Kahn法は依存順序とcycle検出に限定し、business priorityや実装担当割当を勝手に推論しない。cycleはEvidenceであり、解消方法は設計判断として別に記録する。

- 受け入れ条件: AC-GR-008
- 検証Evidence: `SCN-UNIT-SEMGRAPH-004`〜`007`、`018`、`019`
- 実装: `src/domain/semantic-graph.ts`、`src/cli.ts`

#### AC-GR-008

- Given複数ready nodeと合流点を持つDAG、When順序を計算する、Then全edge制約を満たす辞書順tie-breakの完全orderを返す。
- Givencycleとself loopを含むGraph、When順序を計算する、ThenDAGと誤認せずcanonical SCCを返す。
- Givendeepまたはdense Graphと各hard budget反例、WhenSCCとorderを計算する、Thencall stackを枯渇させずbudget内のstatusと部分Evidenceを返す。

### REQ-GR-009 説明経路をbounded BFSまたはDijkstra法で求める

すべての対象edgeが無重みなら最短hop数のBFS、1件でもweightを持つならnon-negative weighted graphに対するDijkstra法を選ぶ。負値、NaN、Infinityおよび不正weightを事前検証で拒否し、負辺用algorithmへ暗黙fallbackしない。

同距離の候補はnode IDとedge IDから成るcanonical path keyでtie-breakする。Dijkstraのpriority queueはdistance、path key、node IDの順で決定し、入力挿入順へ依存しない。BFSとDijkstraの双方がdepth、訪問node、訪問edge、result、operationのhard budgetを守る。

到達不能は`complete`かつ空pathと明示理由、不正入力は`invalid`、上限到達は`budget-exceeded`と区別する。pathが得られないことと影響がないことを同一視しない。

- 受け入れ条件: AC-GR-009
- 検証Evidence: `SCN-UNIT-SEMGRAPH-008`、`009`、負weight反例、異順序differential test
- 実装: `src/domain/semantic-graph.ts`、`src/cli.ts`

#### AC-GR-009

- Given同距離の複数経路を異なる挿入順で持つGraph、Whenshortest pathを求める、Then同じcanonical pathを返す。
- Given無重みGraphと重み付きGraph、Whenqueryする、Then前者はBFS、後者はDijkstraを使用したことを結果に示す。
- Given負weightまたはいずれかのhard budget超過、Whenqueryする、Then不正または不完全を明示し、もっともらしい完全pathを返さない。

### REQ-GR-010 Graph EvidenceをGateへ安全に利用する

Graph query resultは、Graph freshness、source identity、graph content hash、query種別、query入力、budget、status、counter、deterministic・inferred区分と結び付ける。Gate PASSへ単独利用できるのは、freshかつexact evidence allowedのGraphに対する、deterministic edge限定かつ`complete`な結果だけである。

Graph Evidenceのauthorityは常に`none`、`mergeAuthorization`と`modeAuthorization`は常に`false`である。freshかつcompleteでもworkflow modeの決定・昇降格、provider操作、releaseまたはmergeを許可せず、既存のmode・delivery・provider authority Gateへ構造Evidenceとして入力されるだけとする。

Graphはtraceability、impact candidate、dependency order、orphan・cycle・未解決endpoint等の構造的conformanceを証明する。意味的妥当性、security判断、runtime behavior、provider上の最新状態をGraphだけで証明しない。BDD acceptance test、type・static analysis、build、runtime validation、CI、独立review等からChange Typeとriskに応じたEvidence Setを組み合わせる。

AIが生成したedge、impact、root causeまたはcounterexampleはcandidateとして保存できるが、その推論自体をGraphへ`deterministic`として昇格しない。推論しか利用できない事項はconfidence、source、反証結果を明示する。

- 受け入れ条件: AC-GR-010
- 検証Evidence: Gate decision table、stale・inferred・budget-exceeded反例、exact-head照合
- 実装: `src/domain/semantic-graph.ts`、`src/domain/agile-verification.ts`、`src/cli.ts`

#### AC-GR-010

- Givenfreshかつ完全なdeterministic query result、When構造Gateを評価する、ThenGraph identityとquery Evidenceを保存して他の必須Evidenceとともに判定できる。
- Givenstale、inferred、invalidまたはbudget-exceeded result、WhenGateを評価する、Then単独PASSを拒否し、rebuild、budget見直しまたは別Evidenceという具体的remediationを返す。
- GivenGraph上はRequirementからtestへ到達できる、Whenruntime behaviorの正しさを判定する、Then到達可能性だけでPASSせず対応するExecutable Evidenceを要求する。
- GivenfreshかつcompleteなGraph Evidence、Whenmodeまたはmerge可否を判定する、ThenGraph自身はauthorityを付与せず既存workflow Gateの結果を変更しない。

### REQ-GR-011 Graph operationを小さいCLI commandへ分離する

公開CLIは少なくとも`graph install`、`graph rebuild`、`graph status`、`graph impact`、`graph path`、`graph order`を分離する。install・rebuildは`--dry-run`または`--apply`を必須とし、status・impact・path・orderはread-onlyとする。read-only commandが暗黙download、rebuild、current pointer更新を行わない。

CLIはJSONでmachine-readableなstatus、identity、result、counter、reason、remediationを返し、stderrや例外へsource本文、secret、任意Cypherを複製しない。利用者入力をSQL・Cypher構造へ連結せず、adapter内の固定queryへparameter bindingする。GraphQLite builtin traversal・CSR cacheの結果は、ASCのdeterminism・hard budget契約を満たすことが別Evidenceで証明されない限りGate algorithmに使用しない。

queryはfreshnessを先に検査する。read-only時にrebuildが必要なら失敗理由と明示的commandを返し、長期pollingまたは対話質問を開始しない。apply authorityを持つ自走経路では、安全な完全rebuild後に同じqueryを1回再試行できる。

- 受け入れ条件: AC-GR-011
- 検証Evidence: CLI usage contract、write boundary、parameter binding、stale recovery scenario
- 実装: `src/cli-contract.ts`、`src/cli-usage.ts`、`src/cli.ts`、`scripts/check_cli_contract.ts`

#### AC-GR-011

- Given各subcommandの必須flagが不足する、WhenCLIを実行する、Thenusageと不足flagを1回で全件返し副作用を起こさない。
- Given利用者がnode IDへSQL・Cypher断片を含める、Whenqueryする、Then固定queryとbound parameterとして扱い、query構造を変更しない。
- Givenstale Graphでread-only queryする、Whenfreshness checkが失敗する、Then暗黙writeせずrebuild commandとdrift reasonを返す。

### REQ-GR-012 隔離疑似projectで待機なしに成立性を観測する

導入後に実日数の観測期間を置いて成否を先送りしない。test runnerが作る一時directory内へ、Full、Quick、PoC、DAG、cycle、dirty source、複数worktree、drift、破損、budget境界を表す最小疑似projectを構築し、同じ実行で入力、操作、期待結果、実測Evidenceを完結させる。

疑似projectは実repository、実remote、他worktree、利用者のGraph runtimeを変更しない。fixtureは実時計、実repositoryの可変状態、network availabilityへ依存せず、固定instant、local Git repository、注入したfetch・extension pathを使う。actual GraphQLite compatibilityは、公式asset digestを検証した隔離integrationまたは明示した環境条件付きtestで別に観測し、通常unit suiteをnetwork必須にしない。

観測は成功例だけでなく、反例を意図的に注入し、検出されたことをEvidenceにする。経過日数ではなく、定義済みscenario全件PASS、反例全件拒否、同一入力の再実行一致、利用者workspace非変更を完了条件にする。

- 受け入れ条件: AC-GR-012
- 検証Evidence: 隔離scenario matrix、再実行hash、workspace clean差分、GraphQLite実adapter smoke test
- 実装: `test/features/unit/semantic-graph.feature`、`test/features/integration/semantic-graph-observation.feature`、`test/steps/semantic-graph.steps.ts`、`test/steps/semantic-graph-observation.steps.ts`

#### AC-GR-012

- Given一時directoryに作ったFull・Quick・PoC疑似project、Whenbuild・rebuild・query・Gateを実行する、Then実日数を待たず各modeの期待したEvidenceと制約を観測できる。
- Given2つの隔離worktreeとdirty・corrupt・schema mismatch・budget超過の反例、Whenscenario suiteを実行する、Then各反例を所定のreasonで拒否し他fixtureを変更しない。
- Given同じfixtureと固定instant、Whensuiteを繰り返す、Thencanonical hashと順序付きquery resultが一致し、実repositoryの追跡・未追跡fileに差分を残さない。

### REQ-GR-013 Full、Quick、PoCを別modeとしてGraphへ反映する

Graph機能の存在だけを理由に全作業へ同じ成果物・Gate・rebuildを強制しない。Fullは要求、要件、設計、実装計画、BDD、実装、Evidence、review、deliveryの完全traceabilityを対象とする。Quickは低risk変更の集約要求・受入条件と実装・検証を追跡し、公開契約、data、security、依存、基盤等の失格条件が見つかった場合だけFullへ単調昇格する。

PoCはQuickの省略版ではなく、学習仮説、成功・中止条件、非対象、data・security制約、廃止・昇格条件を追跡する独立modeとする。PoC Graphは正式仕様充足、releaseまたは自動mergeのEvidenceとして使用せず、正式化時は同じGraphDBを昇格・mergeせず、補完したSource of TruthからFull projectionを再構築する。

modeはGraph snapshotから決定しない。Git ignoreされたtransient stagingのmodeを探索・推測してsnapshotへ付加せず、Quickに存在しないFull専用成果物nodeを合成しない。mode正本と昇格判断は既存workflow契約が所有し、Graphはその決定後に存在する正本だけを投影する。PoCからFullへ昇格するときは旧PoC manifestを新Full sourceに対してstaleとし、補完した要求・要件・設計・実装計画から完全再構築した別generationだけをFull Evidence候補にする。

実装中の発見でGraph schema・builder・Source of Truth契約を変えないものはdiscovery recordへ記録し、影響実装とtestを前向きに更新する。目的、scope、AC、security境界または不可逆操作を変える発見だけを既存mode規約に従い局所再確定し、Graph driftだけで要求から全工程を再起動しない。

- 受け入れ条件: AC-GR-013
- 検証Evidence: mode別疑似project、PoC非昇格反例、Quick失格時のFull昇格、discovery前向き処理
- 実装: `src/domain/agile-verification.ts`、`src/adapters/repository-graph.ts`、`src/cli.ts`

#### AC-GR-013

- Given低risk Quick変更、WhenGraphを構築する、Then存在しないFull専用成果物を捏造せず、Quickの集約契約から実装・testへの追跡を返す。
- GivenPoC変更、WhenGraph Evidenceをdelivery Gateへ渡す、ThenPoC成功を正式仕様充足またはmerge許可へ読み替えない。
- GivenQuickまたはPoCでmode失格条件を発見する、When既存discovery評価を行う、ThenQuickはFullへ単調昇格し、PoCは停止または明示Full昇格し、同じGraphDBを正式projectへmergeしない。
- Givenignored stagingに別modeが記録されている、WhenRepository Projectorを実行する、Thenstaging modeをsnapshotへ捏造せずGit管理された対象sourceだけを投影する。
- GivenfreshなPoC Graphとautomatic merge条件、When既存delivery Gateと合成する、ThenGraph freshnessに関係なく`stop-at-pr`となる。
- GivenPoCをFullへ明示昇格する、WhenFull正本成果物を補完する、Then旧PoC投影は`source-ahead`として拒否し、補完正本から完全再構築する。

### REQ-GR-014 可用性・性能・保守性・安全性を最低限の強制で担保する

GraphはASCの自走を助ける派生機能であり、再構築可能な障害を恒久停止にしない。generation databaseを完全構築し、transaction commit、`quick_check`、manifestとsnapshotのread-back、hash・件数照合を終えた後だけatomic current pointerを更新する。失敗中のpending generationをcurrentとして公開しない。queryはread-only connectionを使用し、構造write後のstale in-memory cacheへ依存しない。

投影は既定で200,000 node、1,000,000 edge、source file 4 MiB、source集合128 MiBの有限上限を持ち、探索は共通hard budgetを持つ。数値は安全上限であって性能達成の推測値ではない。実際の初期rebuild、status、impact、path、orderは隔離fixtureとASC自身で計測してEvidenceへ記録し、最適化は計測でbottleneckが確認された後に行う。

資源制御は二層に分ける。第一層のinput/projection envelopeは共通Domain定数200,000 node・1,000,000 edgeを使用し、すべての公開Domain入口とStore writeでraw `length`をO(1)確認する。上限超過はiterator、validation、canonicalization、hash、adjacency構築より前に拒否する。第二層のquery budgetはedge kind・certaintyをfilterした後、実際に訪問するnode・adjacencyへ適用する。BFS・Dijkstraのunsorted adjacency indexは第一層に拘束された入力を一度だけ`O(E)`で分類し、訪問listが残budget内の場合だけcanonical sortする。Graph全体を対象とするKahn・Tarjanはeligible node・edgeのindex前処理をoperationへ算入する。

full rebuild、Port、typed schema、固定version・digest、canonical orderingを保守性・再利用性の基盤とする。incremental update、Base Graph cache、別Graph adapter、GraphRAG、Vector Storeは将来拡張可能だが、現在の正しさやmergeの成立条件へしない。最適化を導入する場合も完全再構築をfallback・differential oracleとして残す。

- 受け入れ条件: AC-GR-014
- 検証Evidence: crash point fault injection、上限境界、read-only query、full rebuild differential、計測記録
- 実装: `src/adapters/graphqlite.ts`、`src/domain/semantic-graph.ts`、`test/steps/semantic-graph.steps.ts`

#### AC-GR-014

- Givendatabase構築、transaction、検証、rename、pointer更新の各地点で失敗を注入する、When再実行する、Then最後に検証済みのcomplete generationだけを読め、Source of Truthを失わない。
- Givennode・edge・source・query budgetの境界値と超過値、Whenbuildまたはqueryする、Then境界内は処理し、超過は上限を越えて資源消費する前に拒否または不完全状態を返す。
- Given将来のincremental builder、When完全rebuildとのdifferential testを行う、Thencanonical hash・node・edgeが一致しない実装を有効化しない。

## Gate判定表

| Graph状態 | query状態 | certainty | Gateへの利用 |
|---|---|---|---|
| fresh・実投影照合済み | complete | deterministicのみ | 構造的Evidenceとして利用可能。変更riskに応じた非Graph Evidenceは別に必要 |
| fresh・実投影照合済み | complete | inferredを含む | candidateとしてのみ利用可能 |
| fresh | budget-exceeded | 任意 | 不完全Evidence。影響なし・cycleなし・到達不能の証明に利用不可 |
| fresh | invalid | 任意 | 利用不可。入力またはGraphを修復する |
| stale・unverified・corrupt | 任意 | 任意 | exact Evidence利用不可。完全rebuildまたは別の決定論的Evidenceが必要 |
| missing | 任意 | 任意 | 正本からrebuild。GraphDB backupを要求しない |

## Algorithm契約

| 問い | algorithm | 決定性 | 計算量の基準 | hard bound |
|---|---|---|---|---|
| 影響・到達可能性 | BFS | start・隣接edgeをstable ID順 | `O(V + E)` | depth、node、edge、result、operation |
| 依存順序 | Kahn + min-heap | ready nodeをstable ID順 | `O((V + E) log V)` | node、edge、result、operation |
| cycle・SCC | iterative Tarjan | component内外をstable ID順 | `O(V + E)` | node、edge、result、operation |
| 無重み説明経路 | BFS | canonical predecessor tie-break | `O(V + E)` | depth、node、edge、result、operation |
| 非負重み説明経路 | Dijkstra + min-heap | distance、path key、node ID順 | `O((V + E) log V)` | depth、node、edge、result、operation |

ここで`V`と`E`はqueryが対象とするnodeとedgeであり、budget到達時は理論上の完全性より資源上限を優先して不完全状態を明示する。

## 対象外

- GraphDB binaryの共有・Git merge・長期backupを正本保護とすること
- GraphQLiteへ任意Cypherを通す汎用database console
- GraphQLite builtin algorithmを検証なしでGateの正本algorithmにすること
- GraphRAG、Embedding、Vector similarity、全文検索をGraphStoreへ混在させること
- 大量runtime telemetryを無差別にGraphへ投影すること
- performance数値を根拠なく約束すること
- Graph導入を理由にすべてのQuick・PoCをFullへ昇格すること
- 実日数の経過を待ってから受け入れ可否を決めること
