# GitHub連携要件

### REQ-GH-001 GitHub操作を単一adapterと再読取で制御する

Issue同期、PR作成、review証拠、policy authority、mergeは完全repository同一性・base/head SHA・認証・権限を事前検証し、適用直前に再検証し、適用後に再読取する。candidate policy、自己申告metadata、stale/failed証拠をauthorityにしない。

- 受け入れ条件: AC-GH-001
- 根拠: Issue #824、#829、#834
- 実装: `src/adapters/github.ts`

### REQ-GH-002 手動releaseを段階制御する

手動dispatchはversion一致・単調増加・tag不在・既定branch・必須gateを検証し、dry-runを安全な既定値とする。tag、GitHub Release、npm公開を独立stage・authority・再読取へ分離し、途中失敗の完了範囲と復旧を返す。npm公開は明示入力、保護environment、provenanceを要求する。

- 受け入れ条件: AC-GH-002
- 根拠: Issue #826
- 実装: `src/domain/release.ts`

### REQ-GH-003 配布digestで自動releaseを判定する

`npm pack --dry-run --json --ignore-scripts`のpathとversionだけを正規化した内容hashから配布digestを算出し、現在version tag内容の再計算値と比較する。差分時だけtag・Releaseを冪等作成し、version衝突はPR経由でbumpする。自動経路はnpm公開せず、bump経路も`audit:check`以外の品質gateを実行する。

- 受け入れ条件: AC-GH-003
- 根拠: Issue #861、#869、#879
- 実装: `src/domain/release.ts`

### REQ-GH-004 branch関係からmerge方式を解決する

base branchに一致する`branchMethods`全entryのmethods積集合を使い、global許可を拡大しない。base/head双方が長命branchならmergeだけを許可し、squash/rebaseを診断付きで拒否する。短命branchから長命branchへのsquashは解決済み許可内で利用できる。

- 受け入れ条件: AC-GH-004
- 根拠: Issue #875
- 実装: `src/domain/delivery.ts`

### REQ-GH-005 Git履歴からreview境界を監査する

review artifactはfile名順でなくcommit構造と差分path 1件から選び、推定`H_impl`と本文SHAを二重確認する。正規release bumpはsubject、変更path、`package.json.version`限定の3条件を全て満たす場合だけ監査差分から除外し、直線・merge履歴の通常変更を除外しない。

- 受け入れ条件: AC-GH-005
- 根拠: Issue #873、#892
- 実装: `scripts/check_file_audit.ts`
