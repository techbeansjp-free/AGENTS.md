# テスト標準

単体、結合、E2Eの全テストを`test/features/`配下へ日本語の説明で起票し、各Scenarioへ一意のSCN IDを付ける。構造keywordの方言はproject choiceの`gherkinDialect`を正本とし、このrepositoryは`en`を選ぶ。TypeScriptのstep定義は実行実装であり、起票の正本ではない。step/supportもstrict型検査と`any`禁止の対象に含める。

期待する失敗を先に確認してから最小実装を行う。正常、失敗、境界、悪用、ロールバックに加え、パス走査、Unicode、原子性、リモート誤認、秘密情報、TOCTOUを該当境界で確認する。実workspace、実remote、他worktreeをテストから変更・削除しない。

CIはpull requestだけで発火し、lint、ソース整形、strict型検査、source quality、日本語文書、Gherkin形式、build、配布物、単体、結合、E2Eを検証する。ソース整形と日本語文書・Gherkinの形式は別のgateであり、一方の合格をもう一方の証拠に代用しない。

Risk比例policyはunitでrule強度、diagnostic、自己緩和、override、offline、dedupe、metricsを検証し、integrationでmigrationとpackage境界、E2Eで通常拡張、安全拒否、rollback retryをdogfoodする。Targeted実行の重複抑止後もCIの最終full suiteは維持する。

成果物統制語彙は、正本に必要語と正方向があること、要求・要件・設計・計画・レビュー・システム仕様templateが正本を参照すること、関連Step skillが開始前に読むことをunitで検証する。単なる語句出現ではなく、少なくとも1語を欠落させた反例がbuild gateで拒否されることを証明する。

ドメイン用語台帳は、要求の候補差分、要件の確定差分、実装後の耐久台帳で責務別の必須列を検証する。関連Step skillの開始前読取と、用語ID・business rule・コンテキスト・例と反例・根拠・owner・状態・適用版・置換先の欠落を拒否する反例を持つ。
