# ディレクトリ構成

- `README.md`: GitHub、npm、clone直後の利用者へ目的、現行CLI、正本linkを示すpackage所有の非規範的な公開入口。
- `AGENTS.md`: リポジトリ直下の短い入口。規約を重複定義しない。
- `.agent-skill-chain/00_利用案内.md`: package資産と利用project資産のowner、入口、利用順を示す非規範的な索引。
- `.agent-skill-chain/docs/`: パッケージ所有の連番付き規範文書。
- `.agent-skill-chain/skills/`: パッケージ所有のステップ0〜11契約とhost共通`asc-step`正本。
- `.claude/skills/asc-step/SKILL.md`: lifecycleが管理するClaude Code用host skill登録アダプター。
- `.agents/skills/asc-step/SKILL.md`: lifecycleが管理するCodex用host skill登録アダプター。旧`.agents` harnessとは区別する。
- `.codex/`: host skill登録アダプターの対象ではない。Codexの登録口は`.agents/skills/asc-step/SKILL.md`であり、repository rootへ`.codex/`を作らない。
- `.agent-skill-chain/templates/`: パッケージ所有のIssue・仕様・共通設計テンプレート。
- `.agent-skill-chain/schemas/`と`policy/`: ポリシー検証契約、既定値、記入例。
- `.agent-skill-chain/project/`: このrepositoryが所有するchoices、rules、conformanceの完全JSON inventory。Markdownを混在させず、この仕様から説明する。
- `.agent-skill-chain/tmp/`: Git管理外の一時ステージング。耐久的な正本にはしない。
- `src/domain/`: 境界づけられたコンテキストの不変条件。`workflow.ts`はStep正本とjournal・モード判定の純関数、`staging.ts`は一時stagingの検査・計画・適用判定、`worktree-survey.ts`は観測配列の副作用のない安全側分類を担う。
- `src/adapters/`: 外部プロバイダーとfilesystem境界。`workflow-journal.ts`は安全なstaging内への追記・再読取digest、`gh`を呼べる`github.ts`はGitHub操作だけを担う。
- `src/lib/`: 小さく再利用可能な共通部品。
- `bin/`: CLI起点。
- `docs/specs/`: 利用側所有の耐久的なパッケージ仕様。
- `docs/reviews/`: tracked review artifactを置く平坦なdirectory。file名の連番は人が履歴を読むための整理であり、`audit:check`は番号や辞書順で成果物を選ばず、review headと推定`H_impl`の差分1件から選ぶ。既存artifactは採番衝突の解消目的でrenameしない。
- `test/features/`: 日本語Gherkinによる単体・結合・E2Eの起票。`unit/worktree-survey.feature`と`integration/worktree-survey.feature`は後片付け走査の分類・CLI・read-only性を検証する。
- `test/steps/`と`test/support/`: 開発用ステップ定義とフィクスチャー。配布物へ含めない。

rootの人向けMarkdownは短い`README.md`と`AGENTS.md`を非規範的な入口とし、規範本文は`.agent-skill-chain/docs/`へ集約する。npm、TypeScript、formatter、lint、test runner、Gitなど外部toolがroot配置を契約とする`package.json`、lockfile、`tsconfig*.json`、`eslint.config.mjs`、`cucumber.mjs`、ignore fileは明示例外であり、重複する人向け規範文書ではない。Issue #834ではnpm CLIの製品version正本をroot `package.json.version`、project policy schema対応versionを同じpackage metadataに置き、buildでlockfile・schema・runtimeとの一致を検証する。rootへ`POLICY.md / WORKFLOW.md / QUALITY.md`を重複配置しない。

package所有の主要directoryは短い利用案内を持ち、そこから実fileへリンクする。Step directoryは`SKILL.md`、仕様category directoryは`00_*`を入口とする。新規directoryに入口がない状態、未知directory、利用案内のリンク切れはbuildで拒否する。`project/`だけはmanifestと全fragmentを完全照合するauthority inputなので案内fileを置かず、`.agent-skill-chain/00_利用案内.md`と本仕様から参照する。

## project資産の所有権と配布境界

| パス | 単一責務 | 所有者 | Git追跡 | npm配布 | 境界 |
|---|---|---|---|---|---|
| `README.md` | 利用者向けの非規範的な公開入口 | package owner | する | 含める | CLI、中央利用案内、規範、製品仕様を参照し、独立した正本にしない |
| `memo/` | 個人用の一時メモ | 作業者 | しない | 除外 | 正本・証拠にしない |
| root `issues/` | 旧形式のIssue置場 | repository maintainer | 新規追跡しない | 除外 | 新規成果物は`.agent-skill-chain/tmp/issues/`へ置く |
| `.worktrees/` | 分離worktreeのcontainer | workspace owner | しない | 除外 | repository資産にしない |
| `test/` | Gherkin、step、fixture | test owner | する | 除外 | unit・integration・E2Eの開発証拠 |
| `.github/` | CI、release、trusted authority | repository maintainer | する | 除外 | candidateが同じPRのtrusted条件を緩和できない |
| `scripts/` | 開発・品質・build検査 | repository maintainer | する | 除外 | 製品runtimeの`dist/src/`と分離する |
| `.agent-skill-chain/project-policy.json` | project policy manifest正本 | project owner | する | 除外 | 全fragmentの完全inventoryを持つ |
| `.agent-skill-chain/project/` | choice・rule・binding・provider mapping | project owner | する | 除外 | JSONだけを置きmanifestに全件列挙する |
| `.agent-skill-chain/role-log/` | role実行記録 | runtime・change owner | しない | 除外 | 正本または公開証拠にしない |
| `.agent-skill-chain/metrics/` | project運用観測値 | runtime・project owner | しない | 除外 | 秘密を含めず容量・保持を制限する |
| `.agent-skill-chain/tmp/issues/*/staging-record.json` | mode、成果物、同期証拠、cleanup状態の機械可読記録 | runtime・project owner | しない | 除外 | 対応schemaで未知fieldを拒否し、耐久的な正本にはしない |
| `.agent-skill-chain/tmp/issues/*/00_モード判定.json` | Step 0の根拠付きモード判定成果物 | runtime・change owner | しない | 除外 | 対応schemaで全Q回答とPoC条件を検証する |
| `.agent-skill-chain/tmp/issues/*/journal/steps.jsonl` | Step実施順、成果物、証拠、限定HumanOverrideの追記記録 | runtime・change owner | しない | 除外 | 行順で検証し、無条件bypassを記録しない |
| `src/domain/workflow.ts` | Step定義、mode列、journal・モード判定の純関数正本 | package owner | する | 含める | 現在時刻・乱数・filesystemを参照しない |
| `src/adapters/workflow-journal.ts` | journal追記、再読取digest、staging検査 | package owner | する | 含める | domain判定を再実装せずstaging外へ書かない |
| `scripts/check_workflow_steps.ts` | 規範文書とコード正本の完全一致検査 | repository maintainer | する | 除外 | 規範表・mode列を変更せず解釈しない |
| `.agent-skill-chain/schemas/workflow-*.schema.json` | モード判定成果物とjournal entryの構造契約 | package owner | する | 含める | 未知fieldを許可しない |
| 秘密・秘密fixture | credentialと悪用反例入力 | security owner | しない | 除外 | 実秘密をfixture・log・packageへ保存しない |

`package.json.files`はpackage所有資産だけのallowlistとし、上表の配布除外path、その親directory、秘密を含む広域entryを列挙しない。実際の`npm pack`内容検査も併用し、宣言と成果物の両境界で拒否する。
