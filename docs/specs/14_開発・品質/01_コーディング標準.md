# コーディング標準

Node.js 20以上のESMとTypeScript strictを使い、`node:sqlite`を使うGraph subcommandだけはNode.js 22.13.0以上を要求する。GraphQLite adapterはGraph commandのversion guard後にdynamic importし、非Graph CLIのNode 20起動を壊さない。明示的な`any`、型推論の結果としての暗黙の`any`、`@ts-ignore`、`@ts-nocheck`は禁止し、未知の外部入力は`unknown`のまま受けて型ガードとドメインvalidatorで絞り込む。ドメイン関数は入力・出力を明示し、テストではアダプターを注入する。NFC正規化を行い、制御文字とパストラバーサルを拒否し、複数ファイル状態を原子的に公開し、診断から秘密・個人情報を伏字化し、信頼できない値をシェル文字列へ展開しない。

JSON readerは構文上のJSON値を`unknown`として返すだけとし、generic type parameterや無条件castでdomain型を付与しない。CLI境界はassessment、review、policy、operation、migration manifest/state、conformance/finalize/PR evidenceごとのvalidatorで未知fieldと型を拒否してからdomain関数へ渡す。

Semantic GraphのDomain model、validator、canonical hash、drift判定、bounded BFS・Kahn・iterative Tarjan・DijkstraはGraphQLite、`node:sqlite`、SQL、Cypherをimportせず`GraphStorePort`だけに依存する。storage固有処理はadapterへ閉じ、固定queryとbound parameterを使う。任意Cypher API、再帰にGraph深度を委ねるSCC、入力順に依存するtie-break、hard budgetの事後checkを禁止する。

## 検査とコマンド

| 検査 | コマンド | 合格条件 |
|---|---|---|
| 静的検査 | `npm run lint` | 違反0件 |
| 整形 | `npm run format:check` | 差分なし |
| 型検査 | `npm run typecheck` | エラー0件 |
| source品質 | `npm run source:check` | 対象外source・禁止型0件 |
| 構築 | `npm run build` | 終了値0 |
| 単体test | `npm run test:unit` | 失敗0件 |
| 結合test | `npm run test:integration` | 失敗0件 |
| E2E test | `npm run test:e2e` | 失敗0件 |
| test一式 | `npm test` | 失敗0件 |
| 配布物 | `npm run package:check` | 開発専用資産0件 |

**この表は各検査の合格条件を持つだけであり、実行順は次段落が所有する。** `構築`は順序連鎖の外で実行される。CIは独立したstepとして`npm run build`を実行し、`prepack`は`npm run build`そのものである。

`npm run lint`、`npm run format:check`、`npm run typecheck`、`npm run source:check`、`npm run test:unit`、`npm run test:integration`、`npm run test:e2e`、`npm test`、`npm run package:check`を独立したgateとして実行する。`format:check`はPrettierによる非破壊検査、`format:write`は開発者が明示実行する整形であり、日本語文書検査やGherkin形式検査と責務を混ぜない。CIと`prepack`は`lint → format:check → typecheck → source:check → test`の順で実行する。

このrepositoryではPythonとshellは製品実装・検査スクリプトとも非適用とし、必要な検査はTypeScriptに統合する。`source:check`は一時ライフサイクル領域を除くrepository内で`.py`・`.sh`の再混入と禁止型を拒否する。将来補助言語を導入する場合はproject choiceを更新し、PythonならRuff・mypy、shellならShellCheck・shfmtと同等の検査を同一変更で追加する。テストはOSの一時ディレクトリまたは模擬コールバックだけを使い、実GitHubリモートを呼ばない。安全性に関わる変更には正常系以上の失敗系を用意する。

npm配布物には、リポジトリ開発専用の`test/`、`.github/`、`scripts/`、`docs/specs/`、Cucumber・TypeScript設定、`node_modules/`、`memo/`を含めない。

品質契約のprotected fileとpackage fieldはcandidateとtrusted baseのbyte/hash完全一致を既定とする。変更時は`.github/trusted-quality-proposals.json`に版付きtargetを前PRで登録し、次PRでexact targetだけを有効化する。candidate側だけに存在するproposalを自身の変更authorityとして使用しない。

品質契約14は`test`の直列Cucumber形と`npm run compile --silent && node --import tsx scripts/run_cucumber_shards.ts`形を受理する。`scripts/run_cucumber_shards.ts`も保護対象であり、未登録の本文変更を拒否する。新しい保護対象へ加えるときは、その本文がtrusted baseとbyte一致しなければならない。

## Step 9内部の実装支援

配布する[Coding Engineering Skill](../../../.agent-skill-chain/skills/coding-engineering/SKILL.md)は、必要なcontextだけの探索、既存実装の再利用、変更に応じたLens選択、実装中のtargeted feedback、自律修正、差分中心の自己確認を支援する。Lensは判断材料であり独立工程・Gateではない。最終Verification Set、Step 9開始・停止・完了条件、Step 10の独立review、PR・merge、project policyの所有責務は変わらない。評価は既存logまたは隔離fixtureを用い、未計測値と実taskでの改善未立証を区別する。
