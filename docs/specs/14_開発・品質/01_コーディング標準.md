# コーディング標準

Node.js 20以上のESMとTypeScript strictを使う。明示的な`any`、型推論の結果としての暗黙の`any`、`@ts-ignore`、`@ts-nocheck`は禁止し、未知の外部入力は`unknown`のまま受けて型ガードとドメインvalidatorで絞り込む。ドメイン関数は入力・出力を明示し、テストではアダプターを注入する。NFC正規化を行い、制御文字とパストラバーサルを拒否し、複数ファイル状態を原子的に公開し、診断から秘密・個人情報を伏字化し、信頼できない値をシェル文字列へ展開しない。

`npm run lint`、`npm run format:check`、`npm run typecheck`、`npm run source:check`、`npm run test:unit`、`npm run test:integration`、`npm run test:e2e`、`npm test`、`npm run package:check`を独立したgateとして実行する。`format:check`はPrettierによる非破壊検査、`format:write`は開発者が明示実行する整形であり、日本語文書検査やGherkin形式検査と責務を混ぜない。CIと`prepack`は`lint → format:check → typecheck → source:check → test`の順で実行する。

このrepositoryではPythonとshellは製品実装・検査スクリプトとも非適用とし、必要な検査はTypeScriptに統合する。`source:check`は`.py`・`.sh`の再混入と禁止型を拒否する。将来補助言語を導入する場合はproject choiceを更新し、PythonならRuff・mypy、shellならShellCheck・shfmtと同等の検査を同一変更で追加する。テストはOSの一時ディレクトリまたは模擬コールバックだけを使い、実GitHubリモートを呼ばない。安全性に関わる変更には正常系以上の失敗系を用意する。

npm配布物には、リポジトリ開発専用の`test/`、`.github/`、`scripts/`、`docs/specs/`、Cucumber・TypeScript設定、`node_modules/`、`memo/`を含めない。
