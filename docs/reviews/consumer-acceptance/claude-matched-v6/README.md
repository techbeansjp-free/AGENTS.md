## 結果

10試行すべてで固定oracle・独立レビュー・Draft PR117–126/CI・全Contextの取得usage照合が成功した。[集計](summary.json)は不合格。時間中央値80.75→113.53秒、tokens中央値394,530→395,875で、両指標削減は成立しなかった。最大tokensは572,224→472,662に減ったが、最大時間は88.85→121.19秒へ増加した。最大値だけで改善とは扱わない。

候補の1試行ではAgentのdescriptionをsubagent_typeにも指定し、存在しない種別として拒否された後にgeneral-purposeで再依頼した。別の候補では進行役がReviewer用詳細を先に読み、既知のファイル読取りやGit確認を分割していた。手順参照を省略した候補でも元要求・commit・変更範囲・実テストは独立確認され、当fixtureの品質oracleは成立した。参照文字列の有無だけを品質の代理にしない。

CI待ちとモデル側処理を分けた値は各観測に残す。API時間の変動も含まれるため、全文指示の配置だけを遅延の唯一原因とは断定しない。単発の追試や過去v5から有利な試行を混ぜず、この比較はここで閉じる。性能未達を製品全体の完了へ読み替えない。

後続変更では、既存の独立読取り一括化の指示をプロジェクト固有設定節から通常実装の入口へ移し、Reviewer用詳細の進行役による重複読取りを抑制した。配布更新テスト1件と限定独立レビューは成功。これは本比較の後の変更であり、時間・tokens改善は未実測。新しいGate・Agent・権限変更はない。
