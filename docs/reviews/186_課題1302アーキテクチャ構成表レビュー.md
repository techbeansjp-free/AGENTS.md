## 4. 敵対的評価

### 4.1 表に創作した依存関係が混ざっていないか

**混ざっていない。** `domain`の禁止依存「`adapter`層への依存」は「外部観測からdomainへの逆依存を認めない」に、`graph_domain`の禁止依存「GraphQLite固有import、SQL、Cypher」は「GraphQLite固有import・SQL・CypherをDomainへ逆依存させず」に、`graph_port`の禁止依存「任意Cypher APIの公開」は「任意Cypher APIを公開しない」に、それぞれ既存記述が対応する。

### 4.2 新規採番が紛れ込んでいないか

**紛れ込んでいない。** mermaid blockからnode idを抽出し、**表ID差集合mermaid node ID**が空であることを確認した。**向きが重要である。** 逆向きの mermaid node ID差集合表ID は10件であり（§4.3）、本artifactは網羅を主張していない。**この検査は機械的に再現できる。**

### 4.3 mermaidのnodeを表が網羅していないことは欠陥か

**欠陥ではない。** mermaidのnodeは20件で、表は10件である。差の10件（`user`、`files`、`github`、`provider`、`workflow`、`routing_inputs`、`evidence`、`projector`、`sources`、`graph_runtime`）は**外部actorまたはデータ資産であってコンポーネントではない。** templateの列（責務・入力・出力・許可依存・禁止依存）はコード上の責務単位に対して意味を持つ。**網羅を主張していない。**

### 4.4 「依存方向」節と表が二重管理にならないか

**なる。** 同じ事実が散文と表の2箇所に載った。ただし**表は散文の要約であり、散文が正本である。** 片方だけ直す事故は起こりうる。**現時点でそれを検出する機構は無い**（#938 slice Dが扱う範囲）。この限定を明記しておく。

### 4.5 そもそもこの変更を出すべきか

**出すべきである。** 製品が自分の配る型に従っていない状態は#938の欠陥であり、本変更で必須仕様20件すべてが表を持つ。**強制点を1つも増やさずに解消している。**
