## 経緯

Issue #928の配布物影響調査で検出した。**Issue #886でruntimeへ実装した機能が、配布物側で一切案内されていなかった。**

#886が解こうとした問題は「利用者は仕様書を開かないと必須flagを知れない」であった。runtimeは解決したが、**その解決手段の存在自体が利用者へ伝わらない。** 本packageの主たる利用者はAI進行役であり、`--help`があると知らなければ従来どおり1件ずつ試行錯誤する。

## 対処

配布物の`.agent-skill-chain/00_利用案内.md`とREADMEへ次を記述した。

- 任意のcommandとsubcommandへ`--help`を付けるとusageをJSONで返すこと
- usageが要約、必須flag、条件付きflagとその条件、任意flagと既定値、位置引数、実行例を含むこと
- 不足する必須flagを1回の実行で全件返すこと
- 値をとるflagは`--flag=値`形式であり、空白区切りは受理せず専用診断で拒否すること
- trusted boundaryの評価が必須flag検証より先であること

## 設計判断の是正

**初回の実装は二重管理であった。** usage正本の内容を配布文書へ人が書き写し、検査が突合する形にした。

repository ownerの指摘により作り直した。**照合機構を足しても、正本が2つある事実は消えない。** 本repositoryが繰り返し戦ってきた「同じ事実を2箇所に持ち、突合していない」欠陥を、是正の名目で新たに作っていた。

| 役割 | 実体 |
|---|---|
| 正本 | `src/cli-usage.ts`の`COMMAND_USAGE` |
| 導出 | `scripts/generate_cli_usage_guide.ts`が利用案内とREADMEの生成区画を描画する |
| 検査 | `checkCliUsageDocuments`は生成区画が正本の描画結果と一致するかだけを見る |

**人が同じ事実を二度書く箇所は無い。** 不足flagの一覧も、READMEが述べる件数も、`missingRequiredFlags`の結果から描画する。

実測。生成区画から`--remote-default-sha=...が必要です`の1行を削ると拒否される。

```
.agent-skill-chain/00_利用案内.mdの自動生成区画が正本と一致しません。
node --import tsx scripts/generate_cli_usage_guide.tsを実行して差分をcommitしてください
```

生成を適用すると再び合格する。SCN-UNIT-CLIDOC-005でこの往復を固定した。
