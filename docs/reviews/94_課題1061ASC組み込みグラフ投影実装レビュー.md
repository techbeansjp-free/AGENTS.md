## 3. 設計・アルゴリズム評価

- Graph DBは却下していない。GraphQLiteをadapter境界に置き、DomainはGraphQLiteへ依存しないため、正本・探索契約を維持したままStoreを交換できる。
- reachabilityとimpactはbounded BFS、非負weightのshortest pathは明示weightがあればDijkstra、依存順序はKahn、cycle証明は再帰stackを使わないiterative Tarjanを使用する。
- 局所BFS・Dijkstraはfilter後に実際に訪れたadjacencyだけをquery counterへ算入する。全Graphを対象とするKahn・Tarjanはindex構築もoperationへ算入する。
- input envelopeはnode 200000、edge 1000000を`.length`またはDB countで列挙前に拒否する。query budgetと役割を混ぜず、DoS耐性と小変更のthroughputを両立する。
- exact edgeとinferred edgeを分離し、inferred経路はconfidence・source・candidate edgeを保持するがGate authorityを持たない。
- generation DBを完全構築・readbackし、rename後のgeneration directoryをfsyncしてからcurrent pointerを原子的に切り替え、pointer directoryのfsyncでdurable commitとする。pointer公開後のfaultでは参照中DBを消さず、公開前だけcandidateをrollbackする。
- ECMAScript依存はTypeScript 5.9.3 compiler ASTで抽出する。static・dynamic options・type import・export・literal requireを扱い、shadow、ambient/type-only binding、with、direct eval、再代入は実行時解決を偽ってdeterministic edgeにしない。
- compilerはruntime dependencyにせず、固定version・SHA-256を検証したcompiler、LICENSE、ThirdPartyNoticeを`dist/vendor`へ同梱し、空cacheのoffline consumerでも同じparserを使用する。
- Node公開APIでdirectory metadataのdurable順序を立証できないWindowsは対応済みと偽らず、GraphQLite asset catalogから除外して副作用前にfail closeする。Linux x64/arm64とmacOS x64/arm64を明示対応境界とする。

## 9. 対象外と延期ではない境界

- GraphRAG、Embedding、Vector Store、incremental update、Base Graph共有cache、任意Cypher APIは今回の受け入れ条件に必要ないため対象外であり、組み込みGraph DBの却下・撤回ではない。
- Windows Graph runtimeは延期された対応済み機能ではない。ordered directory metadata durabilityを立証できないplatformとして明示的にunsupportedとし、対応を主張しない。
- 未実装語彙のsymbol、test、finding、provider node等を実装済みcapabilityとして主張しない。将来追加時はsource adapterと受け入れ例を別変更で追加する。
- Graphはmode、merge、release、provider writeのauthorityを持たない。fresh exact Graphも既存Gate Evidenceの代替にはならない。
- 非Graph CLIのNode 20契約、新npm runtime dependency、GUI・Web UI、releaseは変更しない。Graph commandの下限だけNode 22.13以上とする。

## 10. 独立reviewの成立

実装担当とは分離したread-only reviewerが、二層budget、公開Domain入口、Storeのdurability順序、BFS・Dijkstra・Kahn・Tarjan、compiler ASTのscope・ambient・dynamic resolution、固定vendorのoffline配布、セキュリティ境界を確認し、blocker 0 / High 0と判定した。外部CIとrepository上のimmutable reviewはpush後のexact headで取得し、このartifact自身をmerge authorityとして扱わない。

## 11. 総合判定と再開地点

判定: `candidate-verified / pending-external-attestation`。

- 未解決Critical・High: 0件
- 組み込みGraph DB: 採用・実装済み
- drift・探索algorithm・resource bound: 実装・反例検証済み
- main統合: rebase済み、既存trusted proposal・PoC・review・delivery契約を保持
- 再開地点: H_finalのaudit、force-with-lease push、PR exact-head CI、通常merge

H_finalは本review artifactだけを加えるcommitとし、以後このtracked artifactを更新しない。
