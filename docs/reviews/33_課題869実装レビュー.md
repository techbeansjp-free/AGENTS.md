## 真因

`scripts/check_file_audit.ts`は`H_impl..current`の差分が最新のreview artifact 1件だけであることを要求する。

version bump branchのHEADは「mainの最新review artifact commit＋機械生成のbump commit」であり、`package.json`と`package-lock.json`が差分へ加わる。したがって**構造的に必ず失敗する。**

run [32807629742](https://github.com/techbeansjp-free/AGENTS.md/actions/runs/32807629742)では、test 459件とconformanceは合格し、`audit:check`だけが失敗した。

`audit:check`はPRレビューの契約であり、`H_impl`（製品・仕様・testを固定したcommit）と`H_final`（review artifactだけを加えたcommit）を分離して変更file集合と監査表の一致を保証する。**review artifactを持たない機械生成のbump commitへ課すのは契約の適用対象を誤っている。**

## bump経路のgate構成

reviewerが実workflowで確認した。`prepack`から`audit:check`だけを除いた構成である。

```
npm run project:quality
npm run quality            # lint → format:check → typecheck → source:check → npm test
npm run build
npm run docs:format
npm run test:format
npm run trace:check
npm run architecture:check
npm run conformance:check
npm run package:check
```

## 監査強度が下がらない根拠

`audit:check`は`.github/workflows/ci.yml`（trigger `pull_request`）の`全変更fileの個別監査とGit差分path集合を照合する` stepで引き続き実行される。同fileは本PRで変更していない。したがって**人のreviewを伴う全PRで従来どおり強制される。**

`validate` jobと手動dispatch経路は`npm run prepack`のままであり、検証内容は変わらない。

### 敵対観点の残論点

bump commitはPRを経由するため、`ci.yml`の`pull_request` CIも同時に走る。そちらでは`audit:check`が実行され、bump PRに対して失敗する可能性がある。ただしbump PRは`gh pr merge --admin`でmergeされるため、check失敗はmergeを阻害しない。**admin bypassに依存する点は設計上の弱点として記録する。** bump PRを`audit:check`の対象外とする、またはbump commitへ最小のreview artifactを持たせる強化は別Issueの対象とする。
