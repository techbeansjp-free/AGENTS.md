### 対象外として記録する反例

次の2件は諮問で挙がったが、本PRの対象外とした。

- **取り込み先が既定branch以外のPR。** `比較基点`の定義を取り込み先相対にしたため導出自体は
  正しく働くが、旧来の文言（「取り込んだ既定branchのtip」）どおり申告した既存artifactは
  拒否される。**既定branch宛て以外のPRでは監査契約そのものが未定義**であり、契約の定義は
  #966の対象内ではない。
- **squash/rebaseで取り込むproject。** 取り込み先branch上のcommitが親1個になり、取り込み先側で
  この確認は成立しない。取り込み前のmerge refでの確認だけが働く。配布規範文書へ明記した。

### 対象外（親1個）でfail-closedにしなかった理由

境界commitが親1個のとき、つまり**候補branch上でreview artifact commitをHEADにして`npm run audit:check`を回すとき**、既定branch側が構造から決まらない。この場合に停止するか、申告値のまま通すかを決める必要があった。**通す側にした。**

- **gateが効く場所では常に導出できる。** CIは`pull_request`で`refs/pull/<N>/merge`をcheckoutし、`prepack`が走る既定branch上ではHEADがPR mergeである。**縮小した申告はPRを通過できない。**
- **停止しても防げる不可逆な行為が無い。** 運用ポリシーの門の置き方（「止めた場合に残る状態が復旧可能であり、かつ止めることで不可逆な行為を防げるところにだけ置く」）に照らすと、ローカル実行の停止はどちらも満たさない。
- **警告も出していない。** 導出できないのはartifactの欠陥ではなく実行場所の性質であり、開発者が取れる行動が無い。毎回出る警告は信号ではなく雑音になる。
- 既定branch参照（`origin/main`）へ迂回する案は採らなかった。新しい入力と「どのbranchが既定か」という新しい決定を増やすうえ、**gateが効く場所では不要**である。

**この限界はSCN-UNIT-AUDITSEL-010として固定し、仕様3か所へ明記している。**黙って通していない。

### #1004との関係

`inferReviewBoundary`は境界commitの`.at(-1)`親をreview headとする。**既定branch追随merge（親が`[候補head, 既定branch]`）では順序が逆で、review headの推定が既定branch側へ入る**という別欠陥を#1004として起票済みである。その形では本変更の導出も同時に誤るが、**その場合はreview head推定の時点で既に監査が失敗する**ため、誤った導出値が合格を生むことはない。#1004の是正は本PRの対象外とした。
