## 真因（Major）

**契約が人の注意力に依存していた。** `src/domain/`は「現在時刻を取得しない」契約を持ち機械検証されるが、同じ契約がtest fixtureへ拡張されていなかった。

検出が遅れる理由も記録されている。implementer環境ではsandbox制約による別の失敗が先に起き、真因が隠れる。

## 対処

### 実時計・乱数

`test/steps/`配下での`Date.now()`、引数なしの`new Date()`、`Math.random()`をTypeScript ASTで検出し拒否する。時刻を要するfixtureは`test/support/fixture-instant.ts`を使う。

```
fixtureInstant({ hoursAgo: 1 })
fixtureInstant({ daysAhead: 1 })
```

基準時刻は**module読み込み時に1度だけ**確定し、`ASC_FIXTURE_BASE_INSTANT`で注入できる。#866で導入した`RELEASE_CURRENT_VERSION`と同じ注入方式である。

既存の該当箇所は`test/steps/workflow-step-enforcement.steps.ts`の1件で、helperへ置換した。

### 実repository状態

`package.json`、`package-lock.json`、`.agent-skill-chain/project/`配下への相対path accessを拒否する。**全ての相対path accessを禁じてはいない。** Issue #888が名指しした3対象へ限定した。

dogfoodingとして実値が必要なものは、理由を添えて`REPOSITORY_READ_EXCEPTIONS`へ宣言する。**宣言が使われなくなった場合も拒否する。** 台帳が実態から乖離したまま残ることを防ぐ。

初回実行で10件の宣言対象を検出し、いずれも製品自身の設定をdogfoodingで検証する箇所であった。

## 検査の配置

`prepack`の`EXPECTED_SCRIPTS`はbase側の定数であり、candidateからscriptを増やしても有効にならない。したがって新規gateを増やさず、既存の`test:format`（`scripts/check_gherkin_format.ts`）から呼ぶ。

`scripts/check_source_quality.ts`は`PROTECTED_FILES`であり、変更にはversioned staged proposalの2段階が要る。**test品質検査のためだけに品質契約versionを上げるのは釣り合わない**と判断し、protectedでない`check_gherkin_format.ts`を選んだ。
