## 経緯

Issue #886は`worktree create`の実測として**5回の試行**を記録している。1回の実行につき不足flagが1件しか判明せず、`--flag 値`の空白区切りは無言で未指定として扱われ、subcommand単位の`--help`も無かった。

本作業でも同じ現象を3回再現した。

| 実行 | 返答 |
|---|---|
| `worktree survey` | `--root=...が必要です` |
| `worktree finalize` | `書き込み可能なコマンドには--dry-runまたは--applyが必要です` |
| `worktree finalize --dry-run` | `--path=...が必要です` |
| `worktree finalize --dry-run --path=...` | `--evidence=...が必要です` |

## 真因（Major）

**必須入力の集合がどこにも表現されていない。** `required(flags, "x")`は実行時に1件ずつ例外を投げるだけであり、subcommandの必須入力を集合として保持する場所が無かった。そのため次が同時に成立しない。

- 不足を全件報告する
- validationより先にusageを返す
- 値をとるflagと真偽flagを区別して空白区切りを診断する

`bin/agent-skill-chain.ts`は`reasons`を`[error.message]`の1件で構成しており、**複数件を返す器はあったが1件で塞がれていた。**

## 対処

`src/cli-usage.ts`へ34 subcommandのusageを単一正本として定義した。`main`はcommandとsubcommandを解決した直後にこの定義を引き、`--help`、空白区切り拒否、trusted boundary preflight、不足flagの全件報告をこの順で評価する。

`CliValidationError`は`reasons`と`next`を保持し、`bin/agent-skill-chain.ts`がそれを`ASC-CLI-VALIDATION-001`診断へそのまま載せる。既存の診断構造は変えていない。

## 同型の洗い出し

本repositoryで繰り返している「同じ事実を2箇所に持ち、突合していない」を新たに作らないため、usage正本と実装の一致を`scripts/check_cli_usage.ts`が双方向に検証する。TypeScript ASTで`src/cli.ts`のdispatchを走査し、次の4点を確認する。

1. 実装が`required`で要求するflagがusageの必須・条件付きにある
2. usageが必須・条件付きと宣言したflagを実装が読んでいる
3. 実装が読む全flagがusageに記載されている
4. 全dispatchにusage定義がある

この検査は初回実行で**手書きしたusage表の誤り3件を検出した。**

| 検出 | 内容 |
|---|---|
| `routing evidence` | `--implementation-head`をusageへ書き漏らしていた |
| `workflow record` | `--artifact`は`flags`ではなく`artifacts`経路で受けるため、例外条件の明示が必要だった |
| `workflow` | subcommand無しのdispatchはthrowのみで、usage対象から除外する必要があった |

さらに全testを実行して**usage表の誤り1件と順序回帰1件を検出した。**

| 検出 | 内容 |
|---|---|
| `worktree hygiene` | `--approved-hash`を必須と宣言したが実際は`--apply`時のみ必要であり、preview実行が終了code 1へ回帰した |
| `worktree create` | 必須flag検証がtrusted boundary評価を先取りし、`ASC-GIT-INTERNAL-001`が隠れた |

**後者はIssue #831・#893と同型の回帰である。** 新しい検査を追加すると既存の安全側評価より前に割り込む。対処として`enforceTrustedWorktreeBoundary`の呼び出しを`worktree create` blockから`USAGE_PREFLIGHT`へ移し、実装側の重複を残さずに順序を固定した。
