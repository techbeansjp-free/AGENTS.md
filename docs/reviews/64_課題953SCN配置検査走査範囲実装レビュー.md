## 経緯

`issue validate`はstaging成果物に`Scenario: SCN-`の存在を要求する。テンプレート契約も`00_要求定義_quick.md`で最小Gherkinを必須とする。一方でSCN配置検査は所定location外のSCN定義を拒否する。**両方を同時に満たすことができなかった。**

repository rootで`npm run trace:check`を実行すると、staging 8件・38箇所が違反として報告され続けていた。

### なぜ長期間検出されなかったか

`.agent-skill-chain/tmp/`はgitignore対象である。したがって実装用worktreeには存在せず、CIはclean checkoutで走る。**repository rootで実行したときだけ落ちる。** 2026-08-25作成のstagingが既に該当しており、少なくとも1日以上検出されていなかった。

## 設計

検査の目的は「テスト定義を`test/features/`の外に置かせない」ことである。一時ステージングのGherkinは受け入れ例の下書きであってテスト定義ではない。したがって走査範囲から除く。

**除外は`.agent-skill-chain/tmp/issues/`に限る。** 既存の`isStagingLifecyclePath`は流用しない。同関数は`role-log/`と`metrics/`も真とするが、この2領域は`.gitignore`に無く追跡され得る。

```text
.agent-skill-chain/tmp/issues/x.md    ignored
.agent-skill-chain/role-log/x.md      TRACKED (not ignored)
.agent-skill-chain/metrics/x.md       TRACKED (not ignored)
```

流用していれば、**追跡対象の2領域を検査から黙って外していた。**
