# Issue 1576: 同条件に寄せた隔離比較（2026-10-14）

## 判定と条件

性能受入は未達。単発の探索比較であり、一般的な改善率を証明しない。修正版の追加試行も初回新ASCを置き換えず別に残す。正式な数値とHEAD、GitHubのCheck結果、共通oracle、欠測、失敗試行は[集計JSON](1576_matched_20261014.json)を参照する。

全方式は同じprivate dummyのbaseline `fabdfaae0c7d854b7b8336d3ed22288d0b283b66`から開始し、greetingの`Helo`を`Hello`へ変更する。同じモデル`gpt-5.6-sol`、effort high、承認profile、独立したGit clone、lock済み依存、共通oracle、fresh独立review、Draft PR/CIを使用する。GraphDBは用いない。旧・新ASCはpackage.files相当の配布物のみを使用し、ASCのsource/test/review文書を参照できない。比較用の計測wrapperはprovider package内に置き、製品のsandbox probeを変えていない。

新ASCのpromptは実装先行を明示するため、自動選択率の試験ではない。ASCなしにも共通のテスト・独立review・PR/CIを課すが、Planning Sealやjournalまで同等とは主張しない。外部サービスの揺らぎとhost負荷は統制しきれていない。

要求dispatchから提出HEADの最後の成功CIまでをwall timeとする。Agent使用量は終了報告までを含むため、CI到達までのtokensとは呼ばない。inputはcache readを内包し、processedはinput + cache write + output、freshはinput - cache read + cache write + output。reasoningはoutput内なので再加算しない。

Host承認処理の内部usage、起動列挙の完全性、請求額、context high-water markは確定できない。全Agent総量は`null`、観測できたtask Agentの合計は下限値として扱う。phase時刻はAgentの記録であり、独立再構築したcritical pathとは扱わない。

## 観測した固定費と最小修正

初回新ASCではCandidateのモデル実行は約25.5秒と34.8秒だったが、依存復元、候補worktree境界の誤使用、Step 1の形式補完、Step 9の再dispatch、review準備、Evidence、Deliveryが残った。Step 1 fresh Workerを省略しても、E2E短縮は保証されない。

Step 9ではsandboxのGit起動EPERM、存在しないCLI入口の推測、再びEPERMという失敗が続いた。`workflowAgentDispatch()`へ実行可能な`previewArgv`を加え、同じread-only観測の正式なHost承認付き再実行と、HEAD/workUnit境界不一致による停止を区別した。権限拒否の迂回は認めず、作業単位の照合も維持する。修正版を追加試行で評価した。ただしAgentが選んだ経路も異なるため、このコード変更だけの因果効果は分離できない。

初回新ASCは実装先行入口からPR/CIまで到達したが、通常のStep 9 Workerを経由し、後の`candidate-adopt`は遷移済みとして拒否された。Candidate正式採用による省略経路の性能成功とは扱わない。

追加新ASCは採用前独立reviewから正式Candidate採用、full検証、Deliveryへ到達し、再実装Workerを起動しなかった。最初のreviewは依存不足とPython bytecode生成により無効化し、復元後にfresh reviewを再実行した。review・staging・Git refsの前後一致と提出HEADの共通oracleを確認した。初回の通常Step 9経由を含め、全試行を残す。

## 品質と保証の境界

共通oracleは提出HEADを別の一時ディレクトリへ展開し、full fixture test、正しい返り値、`Hello`を`Helo`へ戻した変異で回帰テストが失敗することを確認する。認可、他言語、migration、policy等の既存ファイルが不変であることも比較する。追加docsを許すoracleであり、ASCの全安全契約の証明ではない。

Reviewerはfresh contextで読み取り専用を指示し、Git HEAD/status/diffの前後一致を確認する。この一致だけでignored staging全体の無変更を証明したとはしない。観測したreviewコマンドの確認も補助証拠とする。

製品側では同HEADのAMD追加による古いreview再利用を拒否する修正と敵対テストを追加した。詳細は[計画拘束の検証](1576_review_planning_binding.md)。外部編集者による元Issue本文の開始時snapshot不変性は新たに実装していない。

## 失敗試行と次の判断

v2はorigin/HEADの開始条件不一致、v3はwrapper配置によるsandbox runtime探索の変化を検出し、比較から除外した。v3旧ASCのread-only sandbox停止、v3 ASCなしの完走も記録を残す。v4のCLI誤用、依存再配置、sandbox拒否、provider再試行、CI待機を総時間から差し引かない。

現時点で大規模な新制御機構は追加しない。実行入口の推測を除く最小修正の結果を示し、残るCoordinatorのCLI探索・正式成果物補完・配送準備を、実測に基づく次候補として扱う。性能受入、全Agent総tokens削減、一次要求の外部改変保証を達成済みにしない。PR #1577はDraftを維持する。
