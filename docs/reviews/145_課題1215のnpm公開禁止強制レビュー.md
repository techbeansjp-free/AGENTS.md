## 3. 肯定的評価

- **「拒否されること」を確かめる経路を設計した。** `--dry-run` はprivate検査を通過し、未認証では `ENEEDAUTH` が先に落ちる。**dummy認証つきの実publishでしか観測できない。** 2回失敗してから経路を作り直した。
- **強制点を1点に絞った。** owner決裁が「強制力があってもいい」と明示していても、外部2者への諮問で他候補を棄却し、npm自身の門だけにした。
- **conformanceを重複門にしなかった。** 見るのは宣言の存在だけである。
- **巻き添えを避けて分離した。** `npm_publish` job を消すと consumer acceptance gate が消える。**実測してから対象外にした。**
- **分離の過程で別の欠陥を見つけた。** その job は直近3 run すべて skipped で、**#1024 の「必須gate」が成立していない**（#1216）。
