# CLOSEOUT.md — クローズアウト（欠落工程の補完）の抽象形正本

**責務**: implement-feature 完了の検知で起動する不変クローズアウトの**欠落工程（抽象形）**の正本を 1 か所に持つ。既存の重複工程（verify 必須・指摘 0 反復・04_review・90_issues）は**ここに再記述せず**、既存正本（[REVIEW_RULE.md](REVIEW_RULE.md) / [run_command.md §Constraints](skills/agent/run_command.md) / [RULES.md](RULES.md)）へリンクで委譲する（CORE.md §境界）。本ファイルは工程の**抽象形**のみを定め、ブランチ名・CI コマンド・トレーラ等の具体値は `.agents-project/` に委ねる。

## commit ステップ

- 1 サブ issue = 1 論理コミットを基本とする。
- 既定ブランチ（main 等）上で作業している場合は feature ブランチを切ってからコミットする。
- **push はユーザーが明示したときのみ**行う（高リスク操作。[RULES.md](RULES.md) §高リスク操作 参照）。

- **1 feature = 1 コンテキスト**を保つ。feature の区切りで /clear し、無関係な文脈を持ち越さない（safe-clear invariant: clear して安全な境界でのみ clear する）。

## fresh サブ分割

- 工程は必要に応じて fresh なサブへ分割する。分割しても**収束を保証**するため、**却下済みの指摘とその理由**を後続サブへ継承し、同じ指摘の蒸し返し・無限反復を防ぐ。
- 収束保証に**加えて**、退行を防ぐため **must-preserve リスト（不変条件）も後続サブへ継承**する。文脈をリセットしても、収束保証と退行防止の両方が維持される。
- **対構造**: ここで継承する 2 つは **収束保証（却下済み指摘＋理由）⇔ 退行防止（must-preserve）の対**である。退行防止側の原則本文（ラウンド継承で退行検知）は [REVIEW_DUAL_LENS.md §6 反復ループへの must-preserve 継承](REVIEW_DUAL_LENS.md#6-反復ループへの-must-preserve-継承退行検知) に、must-preserve リストの定義は [REVIEW_DUAL_LENS.md §3 証跡要求](REVIEW_DUAL_LENS.md#3-証跡要求) に委譲する（ここでは継承物に加える事実のみを置き、退行検知の原則本文・定義は再記述しない）。

## 停止耐性チェックポイント

- **phase 完了ごとのチェックポイント義務**: 進行役は 00〜03（要求・要件・設計・実装計画）および実装の各 phase を完了するたびに、次 phase へ遷移する前に (a) 書記（write-workflow-log）への記録、(b) 再開プロンプト（次に何をどこから始めるかの短文）の更新、の 2 点を完了させてから遷移する。セッション中断・`/clear` が phase 境界の直後に起きても、直前の phase までの成果と再開手順が失われない状態を常に保つ。
- **既存節との整合**: 本チェックポイントは [§fresh サブ分割](#fresh-サブ分割) が定める「後続サブへの継承物（却下済み指摘とその理由、must-preserve リスト）」の前提条件である。フレッシュなサブへ分割する時点でチェックポイントが未完了だと継承物自体が失われるため、fresh 分割の**前**に必ずチェックポイントを完了させる。
- **§別セッション引継ぎとの関係**: [§別セッション引継ぎ](#別セッション引継ぎ) が定める引継ぎ記録・再開プロンプトは、セッション終了時に限らず、本チェックポイントにより phase 完了の都度更新される（引継ぎ発生を待たない点が差分）。
- **実値の委譲**: 再開プロンプトの具体書式・記録項目のテンプレートは `.agents-project/` へ委譲する（本節は「更新義務」という抽象原則のみを定める）。

## verify-実経路検証

- verify(ii) として、変更が**実際の経路で動く**ことを検証する（机上確認だけで完了としない）。検証様式は [REVIEW_DUAL_LENS.md §3 証跡要求](REVIEW_DUAL_LENS.md#3-証跡要求) の両リストと整合させる。

### verify 報告様式（分離記載・誤導防止）

verify 証跡の**報告様式**の規範を定める（(ii) 実経路検証そのものの定義は上記の正本に従い、ここでは再定義しない）。

- **(i)/(ii) の分離記載義務**: verify 証跡では **(i) 仕様反映**（不要／反映済み）と **(ii) 実経路検証**（実行済み／未実行／該当なし）を**別項目として分離記載**し、混同・合算しない（一方の達成を他方の達成と読み替えない）。(i) は「仕様反映の有無を分離記載」の**汎用形**に留め、実装と仕様のどちらを正とするか等の同期方向の指定や PF 固有色は含めない（具体運用は `.agents-project/` に委ねる）。
- **緑 ≠ 実経路（射程の見極め）**: テスト緑（make check 等の単体・モック代用）を **(ii) 実経路検証の代替として報告しない**。検証手段の**射程（実経路 vs モック代用）を見極めて** (ii) の達成可否を判定する。この射程の見極めは、敵対的観点（境界・前提崩れを攻める）と整合する（[REVIEW_DUAL_LENS.md §3 証跡要求](REVIEW_DUAL_LENS.md#3-証跡要求) の両リストと併せて記載する）。
- **(ii)=未実行 時の追跡**: 実 I/O が主題で実経路検証手段が無い場合は **(ii)=未実行** とし、follow-up を必ず追跡可能な issue に落とす。follow-up 起票の原則の定義は [§取りこぼし0と既出確認（no-drop / dedup）](#取りこぼし0と既出確認no-drop--dedup) に従う（ここでは再定義しない）。

## 取りこぼし0と既出確認（no-drop / dedup）

クローズ/起票時のフォローアップ追跡に関する**対の原則**を抽象形で定める。具体 grep コマンド・90_issues パス・タグ運用等の固有値はコアに置かず `.agents-project/` に委ねる。

- **取りこぼし0（no-drop）**: クローズ/起票時に挙がったフォローアップ・残件は、必ず**追跡可能な issue/サブ issue** に落とす。散文・memo 言及だけで終えることは no-drop 違反とする。親 issue がある場合の 90_issues 反映等の具体的帰結は既存の出力要件（[implement-feature.md §クローズアウト](commands/implement-feature.md)）に従い、ここでは再定義しない。
- **既出確認（dedup）**: 起票前に issue ツリーの**先祖・兄弟・子孫**の三系統を機械的に走査する。三系統のいずれかの走査欠落は網羅性違反とする。既出（追跡可能 issue が存在）なら新規起票せず**既存へ紐付ける**。**記述はあるが追跡可能 issue 化されていない場合は、出自パスを参照に明記して起票してよい**（出自参照の例外分岐）。
- **対の原則**: no-drop（落とし忘れ防止）と dedup（起票しすぎ防止）は緊張関係にある**対**であり、片方のみを強化すると churn（過剰起票／取りこぼし）を招く。この対構造は churn/退行防止の二観点と同型である（根拠は [REVIEW_DUAL_LENS.md §1 目的](REVIEW_DUAL_LENS.md#1-目的churn退行防止) へリンク委譲）。

## 委譲ツール発行の malformed 自己検証

- **受理確認手順**: 進行役は委譲ツール（run_command 経由のサブエージェント起動等）を発行した直後、当該呼び出しが**正しい記法で受理されたか**（エラー・入力検証失敗を伴わずサブが起動したか）を自己確認する。委譲パケットの形式は [skills/agent/run_command.md §Constraints](skills/agent/run_command.md#constraints) の Task/Constraints/OutputSpec に従う。
- **malformed 検知時のフォールバック**: 発行した委譲がエラーで拒否された（malformed と判定される）場合、**同一記法での再試行を禁止**する。エラー内容を読み、記法・パラメータの誤りを特定してから修正した呼び出しで再発行する。原因を特定せずに同じ呼び出しを繰り返すことは、単なる再試行のループであり収束を保証しない。
- **位置づけ**: 本節は「即行動の実証」（発行した行動が実際に効果を持ったかの自己検証）の代理指標として機能する。思考プロセスの質そのものを機構的に強制することはできないため、少なくとも委譲ツール呼び出しという物理的操作の受理確認は自己検証で担保する。

## 課題の責任完遂

クローズアウト中に発見した課題（現 issue の主題内・主題外を問わない）について、**起票は必要条件であるが十分条件ではない**という原則を定める。起票のみで完了とみなし、その後の扱いが宙に浮く状態（起票して放置）を禁止する。

- **起票義務そのもの**: 追跡可能な issue/サブ issue へ落とす義務の定義は [§取りこぼし0と既出確認（no-drop / dedup）](#取りこぼし0と既出確認no-drop--dedup) に従う（本節では再定義しない）。
- **起票後の判定確定（本節が補完する内容）**: 起票した課題は、以下のいずれかへ**必ず**判定を落とす。判定未確定のまま起票のみで終えることを禁止する。
  1. **責任スレッドが拾う順送り**: 現在進行中の責任スレッド（同一 issue の後続 phase、または既存の担当スレッド）が当該課題を引き継ぐことが明確な場合、その旨を起票先に明記して順送りする。
  2. **明確な理由を伴う繰延**: 直ちに着手しない場合は、**繰延の理由**（優先度・依存関係・スコープ外等）を起票先に明記する。理由を伴わない放置的な繰延は禁止する。
- **実値の委譲**: 繰延理由の具体的なカテゴリ表・繰延の判定基準の具体閾値は `.agents-project/` へ委譲する（本節は「判定確定義務」という抽象原則のみを定める）。
