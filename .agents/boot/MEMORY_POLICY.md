# MEMORY_POLICY - 記憶の 2 層・スコープ・サニタイズ

> **AI 向け**: 長期記憶はモデル内部に保持されない。**外部ストア（memory/*.md や ledger）** に置き、必要なときに取り出して「今回のコンテキストに再投入」して初めて効く。memory を増やすほど古い方針・例外の一般化・強い言い回しに引っ張られやすいので、**memory は「人格」より「参照用ログ」**として扱い、規則は rules/ にのみ置く。

---

## 1. 記憶のスコープ（取り違え防止）

| スコープ | パス | 用途 |
|----------|------|------|
| **user** | `memory/user/` | ユーザー固有の記憶。 |
| **project** | `memory/project/` | プロジェクト（issue/リポジトリ）固有の記憶。 |
| **global** | `memory/global/` | 汎用・横断の記憶。 |

スコープを分けておくことで、どの記憶をいつ使うかの取り違えを防ぐ。各スコープ配下に raw/ と curated/ を置いてよい（例: `memory/project/curated/`）。

---

## 2. 2 層の役割（raw / curated）

| 層 | 役割 | 保持 |
|----|------|------|
| **raw** | 会話ログに近い一次メモ（**事実ログ**）。サブの成果物の写しなど。 | 短期。未サニタイズ。 |
| **curated** | サニタイズ済み・再利用前提の確定記憶（**決定事項ログ**に近い整理済み）。人格の読み込みに参照として使う。 | 長期。要約・抽象化・PII 除去済み。 |

パス例: `memory/{user,project,global}/raw/` と `memory/{user,project,global}/curated/`。従来の `memory/raw/` と `memory/curated/` のみでも可（スコープ未導入時）。

---

## 3. ルール

- **MUST**: サブの成果物や会話由来の情報を **memory に昇格させる前にサニタイズする**（要約・抽象化・PII 除去）。
- **MUST**: サブの成果はまず **raw** にのみ書く。メインがレビューし、サニタイズした上で **curated** に昇格させる。
- **MUST NOT**: raw の内容をそのまま curated にコピーしない。必ずサニタイズを挟む。
- 人格の「過去の記憶」として読み込むのは **curated** のみ。LOAD_POLICY で memory を参照する場合は本ポリシーに従う。

---

## 4. memory は規則にしない・更新ルール

- **規則は rules/ にしか置かない**。memory には「事実・決定のログ」だけを置き、**振る舞いを強制する規則は書かない**。規則が必要になったら rules/ または CORE / AGENTS に移す。
- **最新優先**: 同一キー・同一テーマの記述が複数ある場合は **最新のもののみを有効**とする。または有効期限を設け、期限切れは参照しない運用にする。
