# MVP 6 人格：サブエージェント定義（IN/OUT 固定）

> **AI 向け**: 常時ロード廃止 issue の MVP で採用した **6 人格** の定義一覧。各人格は Task / Constraints / OutputSpec で委譲し、入出力を **入出力固定（壁打ち・フェーズI/O）**（常時ロード廃止 issue の memo）および **意思決定用 2d** に合わせる。共通 I/F は [EXECUTION_CONTRACT](../boot/EXECUTION_CONTRACT.md) を参照。

**6 人格と delegate_to_sub の 5 role の対応**: 委譲の入口である [delegate_to_sub](../skills/agent/delegate_to_sub.md) の固定 JSON では role が implementer | reviewer | tester | auditor | scribe の 5 値。本 6 人格との対応は 要件BDDリード・総合レビューリード → reviewer、実装者 → implementer、テスト者 → tester、監査者 → auditor、書記 → scribe。同一の対応が [LOAD_POLICY 4](../boot/LOAD_POLICY.md) に明記されている。

**原則**: サブには ① AGENTS（CORE 含む）＋ ③ TOOLS のみ渡す。**例外はロールに閉じる** — 役割が明確なサブだけ、追加の最小コンテキストをホワイトリストで固定する。アドホックに「今回は渡す」にしない。

---

## サブに渡してよい情報のホワイトリスト

| 人格 | 基本（全員） | 追加してよいもの（このロールだけ） |
|------|--------------|------------------------------------|
| 要件BDDリード・総合レビューリード・実装者・テスト者・監査者 | ① AGENTS（CORE）＋ ③ TOOLS ＋ そのタスクの作業契約 | なし（作業契約のみ） |
| **書記** | ① ＋ ③ | **ログ仕様・保存先のみ**（[書記役とログ委譲](../scribe/書記役とログ委譲.md)、[ledger/README](../ledger/README.md)、[ワークフローログ_SQLiteスキーマ](../ledger/ワークフローログ_SQLiteスキーマ.md)） |
| 監査者（必要時のみ） | ① ＋ ③ | [監査者用工程フロー](../rules/監査者用工程フロー.md)・[監査者用チェックリスト](../rules/監査者用チェックリスト.md)。セキュリティ観点・ドメイン用語集など追加する場合は**ユーザー個人情報は含めない**。 |

新規ロールを増やすときは、この表に「追加してよいもの」を 1 行で定義し、例外を増やしすぎない。

---

## 一覧と IN/OUT（フェーズ単位）

| 人格 | フェーズ | IN（Task/Constraints に含めるもの） | OUT（OutputSpec で求めるもの） |
|------|----------|--------------------------------------|--------------------------------|
| 要件/BDDリード | 01 | issue 目的、制約、既存仕様 | BDD シナリオ、受け渡し契約（成果物一覧） |
| 総合レビューリード | 壁打ち・04 | 01 の成果物（壁打ち時）。全成果物（04 時） | 指摘・要約・02 へ進む条件（壁打ち）。最終 GO/NG（04） |
| 実装者 | 02 | BDD、受け渡し契約、壁打ち結果要約（任意） | 実装成果物、変更ファイル一覧 |
| テスト者 | 02 | BDD、受け渡し契約、実装成果物参照 | テストコード・実行結果・カバレッジ観点 |
| 監査者 | 03 | 実装・テスト・結果 | 指摘一覧、修正要求、GO/NG |
| 書記 | 全フェーズ | ログ項目（issue_id, agent_id, action_type, ...） | 確認メッセージ（ログ 1 件記録済み）。成果物は SQLite または logs/ |

## 配置

- **定義ファイル**: 本 `workers/` 配下の `01_要件BDDリード.md` 〜 `06_書記.md`。
- **実運用**: 採用先プロジェクトの **プロジェクトルート直下**の `.cursor/agents/` または `.claude/agents/` に配置する（プロジェクト内完結。ユーザーホーム等リポジトリ外へはコピーしない）。必要に応じてパス・プロンプトを調整する。書記は [書記役とログ委譲](../scribe/書記役とログ委譲.md) および [ワークフローログ_SQLiteスキーマ](../ledger/ワークフローログ_SQLiteスキーマ.md) を参照。

## 受け入れ条件（実装時に満たすこと）

- **workflow.db の .gitignore**: SQLite を採用するため、**初回セットアップまたは書記サブ導入タスクの受け入れ条件として「`.gitignore` に `workflow.db` を追加済みであること」を明示する。** 漏れ防止のため、本 README および [ワークフローログ_SQLiteスキーマ](../ledger/ワークフローログ_SQLiteスキーマ.md) の前提にも同じ条件を記載する。
