# Platform Adapter: Claude Code

> **責務**: **claude_code.md = Claude Code 実行時の差分仕様**。root の CLAUDE.md は利用者向けの入口・導線・セットアップ。本ファイルはツール・委譲・注意点等の実行差分のみを記載する。**定義しない**: 共通仕様（boot）、入口・セットアップ説明（CLAUDE.md）。

## 目的

この実行基盤で、共通仕様（boot の CORE / LOAD_POLICY / EXECUTION_CONTRACT 等）を壊さずに動かす。

## 前提

- **利用可能**: サブエージェント・ツール制御（Bash/Read/検索等）との相性が良い。構造化された委譲と相性が良い。
- **利用の注意**: ツール使用の癖（呼び出し順・引数の渡し方）が製品ごとにあり、共通契約だけでは揺れが出ることがある。
- **文脈保持**: Bash/Read 前提の設計と馴染みやすい。ファイルベースの成果物と相性が良い。

## 必須ルール

共通仕様は boot（CORE / LOAD_POLICY / EXECUTION_CONTRACT）に従う。Claude Code では AGENTS.md および .agents へのパスを明示するとよい。

## 注意点

- **破綻しやすいポイント**: ツールを多用しすぎると「何が必須読了か」が薄れる。実行前契約の 4 ファイル読了を省略しないこと。
- **長文化しやすい箇所**: 依頼文に経緯を書くとサブにそのまま渡しがち。Constraints は禁止・必須・参照・前提（最大 5 行）に限定する。
- **コンテキスト漏れ**: 委譲時に SUBAGENT の注入順序を守り、worker 1 つと契約だけを渡す。

## 実行時の差分

- **サブエージェント相当**: Claude Code のサブエージェント/タスク起動では、共通契約の JSON（Task/Constraints/OutputSpec）をそのまま渡す。role は implementer | reviewer | tester | auditor | scribe のいずれか。
- **ツール呼び出し**: Bash/Read/ファイル操作が主。規約で禁止している操作（書記以外のログ作成・許可されていない Write 等）は行わない。
- **ファイル編集**: 実ファイルの編集・作成。.workflow 配下はテンプレートをコピーして作成し、必須セクションを維持する。書記向きの実行基盤としてログ記録フローを組みやすい。
