# Platform Adapter: Cursor

## 目的

この実行基盤で、共通仕様（boot の CORE / LOAD_POLICY / EXECUTION_CONTRACT 等）を壊さずに動かす。

## 前提

- **利用可能**: エージェント・ルール・プロジェクト文脈の統合、実ファイル編集（Read/Edit/Write）、ターミナル、検索。ワークスペースパスに基づく参照。
- **利用の注意**: 暗黙のコンテキストが膨らみやすい。ルールと AGENTS.md の参照順が重要。
- **文脈保持**: プロジェクトルート・開いているファイル・ルールファイルの注入順が効く。長文を最初に読ませる設計と相性が良い。

## 必須ルール

- **最初に読む順序**: boot の実行前契約どおり（CORE → LOAD_POLICY → WORKFLOW → CONCEPTS）。Cursor では .cursor/rules や AGENTS.md 経由でこれらが参照されるため、参照先パスを壊さないこと。
- **委譲の表現**: サブエージェントは mcp_task 等の機構で表現。Task/Constraints/OutputSpec は共通契約のまま渡す。
- **ログ記録**: 書記サブに委譲。workflow.db への記録は書記のみ。memo 暫定記録は CONTRACT §5 準拠。
- **出力制約**: SILENT MODE・ファイル名 YYYYMMDD_HHMMSS_ プレフィックス・frontmatter は CORE のまま。Cursor 固有の出力長制限は特になし。

## 注意点

- **破綻しやすいポイント**: コンテキストに CORE 以外の長文を載せすぎると、何が絶対制約か曖昧になる。boot の 4 ファイルを「最初に読む」ことを守ること。
- **長文化しやすい箇所**: ユーザー指示に背景を長く書くと、委譲時にそのままサブに渡しがち。Constraints は最大 5 行・背景は原則書かないを守る。
- **コンテキスト漏れ**: サブに渡すときは SUBAGENT の注入順序を守り、対象 worker の 1 つだけを渡す。

## 実行時の差分

- **サブエージェント相当**: mcp_task 等で role に応じた委譲。intent は結果述語 1 文。Cursor 側のツールで「サブエージェント」を起動する場合は、共通契約の JSON をそのまま渡す。
- **ツール呼び出し**: ファイル編集・検索・ターミナルは Cursor 標準。規約で禁止している操作（書記以外のログ作成等）は行わない。
- **ファイル編集**: 実ファイルの編集が主。.workflow 配下の成果物はテンプレートをコピーして作成し、必須セクション・フォーマットを維持する。
