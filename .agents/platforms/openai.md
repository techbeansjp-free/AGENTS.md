# Platform Adapter: OpenAI

## 目的

この実行基盤で、共通仕様（boot の CORE / LOAD_POLICY / EXECUTION_CONTRACT 等）を壊さずに動かす。

## 前提

- **利用可能**: 会話主体のインタラクション、構造化された出力の指定。環境によって API・ツール・コンテキストの持ち方が異なる。
- **利用の注意**: 「何を最初に読むか」のガードが特に重要。環境依存差が大きいため、参照するファイルパス・読了順序を明示した方が安全。
- **文脈保持**: 会話履歴と注入したコンテキストに依存。長文を一度に渡しすぎると境界が曖昧になりやすい。

## 必須ルール

- **最初に読む順序**: boot の実行前契約どおり（CORE → LOAD_POLICY → WORKFLOW → CONCEPTS）。OpenAI 利用時は「最初に読む 4 ファイル」を明示し、読了するまでワークフロー開始・委譲・成果物作成を禁止する旨を守る。
- **委譲の表現**: サブエージェント相当の呼び出しがある場合、Task/Constraints/OutputSpec を共通契約の形式で渡す。背景・経緯は載せない。
- **ログ記録**: 書記サブに委譲。workflow.db への記録は書記のみ。CONTRACT §5 の暫定記録を守る。
- **出力制約**: SILENT MODE・ファイル名 YYYYMMDD_HHMMSS_ プレフィックス・成果物の必須項目は CORE のまま。環境ごとの出力長制限に注意する。

## 注意点

- **破綻しやすいポイント**: 最初に読むファイルを省略したり順序を変えると、規約の強制力が弱まる。実行前契約の 4 ファイル読了を必須とする。
- **長文化しやすい箇所**: 会話で説明を足しがち。委譲時は結果述語 1 文＋Constraints 最大 5 行に抑える。
- **コンテキスト漏れ**: 環境によってはファイル参照の方法が異なる。参照してよいパスを Constraints で明示する。

## 実行時の差分

- **サブエージェント相当**: 製品によってサブ呼び出しの有無・形式が異なる。ある場合は共通契約の Task/Constraints/OutputSpec を渡す。要件BDDリード・レビュー・監査など、会話的な役割との相性が良い。
- **ツール呼び出し**: 環境依存。利用可能なツールが限られる場合は、成果物の形式（Markdown・パス・必須項目）を OutputSpec で固定する。
- **ファイル編集**: 環境により Read/Write の有無が異なる。編集できない場合は「成果物の内容を出力し、人間がファイルに反映する」運用にする。
