# capability: refactor-safely

**目的**: 実装後にリファクタが必要な場合に、安全にリファクタし責務の整理・重複削除・可読性向上を行う。振る舞いは変えない。

---

## 手順

1. 入力（実装済みコード。02_設計・03_実装計画）を読む。
2. リファクタ対象（重複・責務混在・名前の不明瞭さ）を特定する。
3. 変更範囲を小さく区切り、1 区切りごとにテストが通ることを確認する。
4. リファクタを実施する（抽出・リネーム・分割等）。02 の責務・境界を崩さない。
5. 変更後のコードと 02 の整合を確認する。証跡に「何をどうリファクタしたか」を 1 行で残す。

---

## 制約・禁止

- 振る舞いを変えない。テストが通る状態を維持する。
- 単一責任を崩さない。02_設計の責務と矛盾する分割をしない。
- 必要以上にやりすぎない。YAGNI。本 issue の目的に直結しないリファクタは別 issue にする。

---

## 成果物の形式

- **OUT**: リファクタ後のコード。振る舞い同一。可読性・責務の改善がされていること。
- 変更内容の短文メモ（04_review または memo）。
