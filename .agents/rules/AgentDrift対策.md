# Agent Drift 対策（用語・概念）

本ドキュメントは、AGENTS 規約において Agent Drift（意図からの逸脱）を理解し、運用・点検に活かすための用語と概念を定義する。

---

## 参考資料の注記

**根拠: arXiv:2601.04170。** 知見は論文内シミュレーション結果に基づくものであり、実運用ログの実測ではない。

---

## 3 種類のドリフト

| 用語 | 説明 |
| -------- | ------ |
| **Semantic Drift** | 出力は文法的に正しいが、タスクの意図から静かに逸れるドリフト。例: 金融分析エージェントがリスク重視→機会強調にシフト。 |
| **Coordination Drift** | マルチエージェント間の役割分担が崩れるドリフト。例: ルーターが特定サブエージェントにタスクを偏らせる。 |
| **Behavioral Drift** | 初期設定にない行動パターンが出現するドリフト。例: 指定メモリツールを使わずチャット履歴にキャッシュ。 |

---

## 3 メカニズム

| 用語 | 説明 |
| -------- | ------ |
| **Context Window Pollution** | 初期のやり取りで溜まった不要データが有用情報を埋もれさせる。Context Rot と同じ構造。 |
| **Distributional Shift** | 運用が進むにつれ入力分布が訓練時と乖離する。 |
| **Autoregressive Reinforcement** | 出力の小さなエラーが次の入力になり、ずれが雪だるま式に累積する。 |

---

## 3 緩和策

| 用語 | 説明 |
| -------- | ------ |
| **エピソードメモリ統合** | 一定ターンごとに要約エージェントで過去やり取りを整理・圧縮する緩和策。 |
| **ドリフト認識ルーティング** | 安定性スコアを監視し、ドリフトしたエージェントを検知してタスクの振り先を変更する緩和策。 |
| **適応的行動アンカリング** | 初期の正常挙動を例示として保持し、ドリフトが進むほど強くアンカリングをかける緩和策。論文では単一戦略で最も有効と報告。 |

## 記憶の整理（緩和策 1: エピソードメモリ統合）

### 説明

**エピソードメモリ統合**は、一定ターンごとに過去のやり取りを要約・圧縮し、Context Window Pollution（有用情報が不要データに埋もれる現象）を緩和する対策である。要約・圧縮によりコンテキストを整理し、長期運用時のドリフトを抑える。

### ルール・チェック項目

- **いつ点検するか**: フェーズ区切り・一定ターン経過時、または監査者がドリフト対策観点で確認するタイミングで、「記憶の整理」の実施有無を点検する。
- **何を点検するか**:
  - 要約・圧縮（またはそれに相当する整理）の手順・参照が定義されているか。
  - 実施有無を確認できる証跡または参照先があるか。
- **既存ルールとの関係**: ログ・記録の整理や要約を行う場合でも、書記役（scribe）の役割を侵さない。ログ記録は [書記役とログ委譲](../scribe/書記役とログ委譲.md) に従い、書記サブへの委譲のみとし、書記以外が `.workflow/**/logs/` や `workflow.db` に直接書かない。

## 異常の検知（緩和策 2: ドリフト認識ルーティング）

### 説明

**ドリフト認識ルーティング**は、安定性スコアを監視し、ドリフトしたエージェントを検知した場合にタスクの振り先を変更する対策である。Distributional Shift や Autoregressive Reinforcement の影響を抑える。※安定性スコア計算の自動化は本 issue の範囲外であり、点検は手順・参照の確認レベルとする。

### ルール・チェック項目

- **いつ点検するか**: サブ実行の前後・フェーズ区切り、または監査者がドリフト対策観点で確認するタイミングで、「異常の検知」の実施有無を点検する。
- **何を点検するか**:
  - 安定性スコア（またはそれに相当するドリフト指標）の監視手順・参照が定義されているか。
  - ドリフト検知時の振り先変更（ルーティング変更）の手順・参照が定義されているか。
  - 上記の実施有無を確認できる証跡または参照先があるか。
- **既存ルールとの関係**: サブエージェント・ルーターの既存定義（[workers/README](../workers/README.md)、[boot/LOAD_POLICY](../boot/LOAD_POLICY.md) 等）は変更しない。本項は点検項目・参照としての記載にとどめる。

## 基準への立ち戻り（緩和策 3: 適応的行動アンカリング）

### 説明

**適応的行動アンカリング**は、初期の正常挙動を例示として保持し、ドリフトが進むほど強くその例示（アンカー）を参照させる対策である。論文では単一戦略で最も有効と報告されている。基準となるドキュメント・ルールを「アンカー」として明示し、運用時に参照可能にしておく。

### ルール・チェック項目

- **いつ点検するか**: フェーズ開始時・タスク委譲前、または監査者がドリフト対策観点で確認するタイミングで、「基準への立ち戻り」の参照が有効かどうかを点検する。
- **何を点検するか**:
  - アンカーとして参照すべき基準（AGENTS 規約・CORE・ルール）が明示されているか。
  - 正常挙動の例示または参照先（[AGENTS 規約](../../AGENTS.md)、[CORE](../boot/CORE.md)、本 rules 配下のルール等）が有効に参照可能か。
  - ドリフトが疑われる場合に、上記アンカーを参照して立ち戻る手順・参照が定義されているか。
- **既存ルールとの関係**: [AGENTS 規約](../../AGENTS.md)・[CORE](../boot/CORE.md) および本 rules 配下のルールを「基準（アンカー）」としての位置づけを侵さず、それらを参照する形で記述する。
