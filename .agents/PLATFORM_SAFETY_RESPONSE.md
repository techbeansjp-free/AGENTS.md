# PLATFORM_SAFETY_RESPONSE.md — プラットフォーム安全機構ブロック時の AI 対応プレイブック（抽象原則）

**責務**: Claude Code の auto mode classifier 相当の、**本パッケージの enforcement とは別レイヤーの**プラットフォーム側安全機構にツール呼び出しをブロックされた際の AI 対応原則の**抽象原則のみ**を規定する。具体的な検知手段・ログ文言・ランタイム固有 API は**コアに置かず** `.agents-project/` に委ねる（PF 中立性・CORE.md §ルールの優先順位）。

---

## 1 適用条件

本ファイルの原則は、**プラットフォーム側に auto mode classifier 相当の安全機構が存在するランタイムで、当該機構にツール呼び出しがブロックされたときのみ**適用する（[MODEL_SELECTION.md §1 適用条件](MODEL_SELECTION.md#1-適用条件)・[EFFORT_POLICY.md §1 適用条件](EFFORT_POLICY.md#1-適用条件)と同型のフォールバック構造）。

---

## 2 対象外フォールバック

当該安全機構が存在しない、またはブロックの発火自体を観測できないランタイムは**対象外環境**であり、その場合は本ファイルの強制は発火せず、そのランタイムの既定動作にそのまま従う（エラーにしない）。プラットフォーム側安全機構の発火自体は本パッケージの管理外であり、対象外環境で本原則の遵守を人為的に模擬する必要はない。

---

## 3 4 原則

ブロックを検知した場合、AI は次の 4 原則を**この順で**適用する。

### (a) 回避絶対禁止

別ツール・別の言い回し・別経路での**迂回を一切試みない**。ブロックは「今回はこの言い方が悪かった」という表現上の失敗ではなく、安全機構が意図的に発火した判断として扱う。

### (b) 即座停止と透明な説明

迂回を試みず**直ちに停止**し、ユーザーへ次を説明する。

- 何を実行しようとしたか
- 推定される拒否理由
- 次にどうしたいか（提案）

説明の後は、ユーザーの応答を待つ。

### (c) ユーザー本人の明示的承認

「進めてよい」「大丈夫」等の**一般的な同意のみ**では前進しない。ユーザー自身の言葉で**具体的な対象（ツール名・パス・コマンド）**が明示されるまで、実行に進まない。一般的同意と具体的対象明示の二者を混同しない。

### (d) サブエージェント自己報告の独立検証

サブエージェントが「プラットフォーム安全機構にブロックされた」と自己報告した場合、進行役はその自己報告を**鵜呑みにしない**。何がどうブロックされたかを**独立に検証**してから、(b) の説明・(c) の明示的承認の手続きに進む。独立検証を経ずに自己報告のまま次の対応（説明・承認取得・再試行）へ進んではならない。

---

## 4 enforcement との別レイヤー明記

本ファイルが扱う「プラットフォーム側安全機構」は、本パッケージ自身の enforcement（[enforcement/README.md](enforcement/README.md)。Layer1〜4 の物理／契約／配備／完了強制）とは**別レイヤー**である。

- 本パッケージの enforcement は、**本パッケージが定義した規約**（orchestrator が実作業をしない等）への違反を、本パッケージ自身の hooks・CI が検知・矯正する仕組みである。
- 本ファイルが扱うプラットフォーム側安全機構は、**プラットフォーム提供者側が定義した安全判断**（auto mode classifier 相当）であり、本パッケージの規約とは無関係に、本パッケージの外側から発火する。

両者は責務が異なり、混同しない。プラットフォーム側安全機構のブロックを「本パッケージの enforcement の誤検知」として扱ってはならず、逆に本パッケージの enforcement の拒否を「プラットフォーム側安全機構のブロック」として本ファイルの手続きに読み替えてもならない。
