# プロジェクト固有ルール（.agents/unique-rule/）

このディレクトリには、**プロジェクトごとの固有ルール**を配置する。

## 目的

- **テンプレートはそのまま使う**: `.agents/` 配下の規約ファイル（実行ルール.md、コーディングルール.md 等）は汎用テンプレートとして変更せず、コピーしたまま利用する。
- **固有ルールはここに追加**: プロジェクト固有の規約（開発環境の起動方法、テスト実行方法、フレームワークのベストプラクティス、命名規則など）は、この `unique-rule/` 配下にファイルとして作成する。
- **運用を楽にする**: テンプレートの更新を取り込んでも、プロジェクト固有の記述がテンプレートに混ざらないようにする。

## 優先順位

**`.agents/unique-rule/` 配下のルールが `.agents/` のルールより優先される。**

- 同名または同目的のルールがある場合: **`.agents/unique-rule/` のファイルを採用**する。
- `.agents/unique-rule/` に該当ファイルがない場合: `.agents/` の標準ルールに従う。

参照順序の例:

1. まず `.agents/unique-rule/` に該当するファイルがあるか確認する。
2. あればその内容に従う。
3. なければ `.agents/` の標準ルール（実行ルール.md 等）に従う。

## 配置例

採用先プロジェクトで次のようなファイルを用意する場合、このディレクトリに置く。

- `プロジェクト固有.md` - プロジェクト固有の規約（開発環境の起動方法、テスト実行方法、ディレクトリ構成など）
- `フレームワークベストプラクティス.md` - 使用フレームワークのベストプラクティス（Laravel / Next.js / Astro 等）

ファイル名は `.agents/` の規約ファイル名と揃えてもよいし、プロジェクト独自の名前でもよい。エージェントは「同目的のルール」がある場合に unique-rule を優先する。

## 注意

- この README は汎用パックに含まれる。採用先で `unique-rule/` を使う場合のみ、このディレクトリにファイルを追加する。
- 空の `unique-rule/` のままでも問題ない（その場合は常に `.agents/` の標準ルールが使われる）。
