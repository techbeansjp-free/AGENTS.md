# 設計判断の優先順位

本プロジェクトで設計判断に迷った場合は、以下の優先順位に従う。

## 優先順位

1. 可読性
2. 単一責務
3. 仕様との整合性
4. 変更容易性
5. 保守性
6. 再利用性
7. 実装効率

## 原則

- 再利用のために責務を曖昧にしてはならない
- 一時的な都合で shared を肥大化させてはならない
- query に副作用を書いてはならない
- docs と実装の不整合を放置してはならない
- イベント駆動は拡張性のために使うが、単純な同期処理で十分な場合は無理に導入しない

## 判断に迷った場合

以下を優先する。

- 短期的な実装容易性より、長期的な可読性
- 抽象化より、意図の明確さ
- 再利用性より、責務の明確さ
- テクニックより、構造の一貫性
