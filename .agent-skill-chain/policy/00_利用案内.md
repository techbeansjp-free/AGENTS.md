# policy利用案内

## 目的

このdirectoryはpackageが提供する汎用policy入力を置く。利用project固有の値を収容する場所ではない。

## ownerと編集

packageが所有し、schema・runtime・testと同じ変更単位で編集する。利用projectはこのfile群を直接書き換えて固有規則を表現せず、`.agent-skill-chain/project-policy.json`が列挙する`project/`のJSONを所有する。

## 使い方

| file | 用途 |
|---|---|
| [default.json](default.json) | 現行schema versionの安全なpackage既定値 |
| [sample.json](sample.json) | 単一入力を診断するときの記入例。projectの正本ではない |
| [conformance.json](conformance.json) | package不変条件のID、enforcement point、反例、証拠、rollback catalog |

入力を変更する前に[schemas利用案内](../schemas/00_利用案内.md)から対応schemaを確認する。利用projectのfragment setは中央の[ディレクトリ利用案内](../00_利用案内.md)に従う。

## merge.branchesの記入例

**`merge.branches`は3役を兼ねる。** 役割は[開発ワークフロー](../docs/01_開発ワークフロー.md)が所有する。[sample.json](sample.json)がそのまま雛形である。

**`methods`は`["merge"]`だけにする。** squashとrebaseは取り込み先branch上のcommitの親を1個にするため、`audit:check`が`比較基点..H_impl`と`H_impl..H_final`の2区間を導出できなくなり、取り込み先での監査が成立しない。**squash専用の構成は配らない。**

**`branches`へ短命branchのpatternに加えて長命branchを完全一致で列挙する。** 短命branchのpatternは`worktree.allowedBranchTypes`と揃える。長命branchを列挙すると、その2つの間のsquashとrebaseが`methods`とは独立にもう一段拒否される（`src/domain/delivery.ts`の長命branchペア判定）。**`methods`を`["merge"]`にするだけで短命branchからの取り込みも拒否されるため、この列挙は二重化である。**

**製品側の強制だけでは足りない。** web UIや`gh pr merge`は`pr merge`を経由しないため、**GitHubのrepository設定でsquash mergingを無効化する。**

## 置かないもの

repository固有のpackage manager、runtime、CI、表示言語、命名、test layer、release方式、rule IDを置かない。秘密情報、実行証拠、migration snapshotも置かない。

## 正本

JSON構造は`.agent-skill-chain/schemas/`、製品とpolicy schemaの現行versionは`package.json`、利用projectの選択値とruleはproject manifestが列挙するfragmentを正本とする。
