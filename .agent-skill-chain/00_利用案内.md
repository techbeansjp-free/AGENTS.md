## 導入・更新・削除

利用者向けの公開入口はpackage runnerの`npx`である。**本packageはnpm registryへ公開しておらず、`npx`は本package自体をregistryから解決せず、Git remoteの指定でGitHubから直接取得して実行する。**

**registryを完全に使わないわけではない。** Git取得時は`prepare`が`npm run build`を実行するため、その過程でdevDependenciesをregistryから取得する。

| 用途 | command |
| ---- | ------- |
| 最新を使う | `npx github:techbeansjp-free/AGENTS.md doctor --root=.` |
| 版を固定する | `npx github:techbeansjp-free/AGENTS.md#<tag> doctor --root=.` |

`<tag>`にはreleaseのtag（`v0.3.1-beta.83`のような形）を指定する。**以降に現れる`npx agent-skill-chain <command>`は、この`npx github:techbeansjp-free/AGENTS.md <command>`の短縮表記である。**

**利用project側のpackage manager scriptを経由しない。** `package.json`の`scripts`へ登録して`npm run`や`pnpm run`から呼ぶと、package managerが本CLIへ到達する前に利用project自身の依存解決を走らせる。**その失敗は本CLIとは無関係に起動を止める。** 実際に、依存が552 packageあるprojectで`pnpm run`経由の起動だけが失敗し、同じ環境で直接起動は成功した。**本CLIはNodeとGitだけで動き、runtime依存を持たない。** 起動口は上表のcommandを直接実行する。

対象directoryを省略した場合は現在directoryを使い、`install`、`update`、`delete`は何も書き換えないpreviewを既定とする。preview結果を確認した後、同じcommandへ`--apply`を付けた場合だけ変更する。

| 操作 | preview                                  | 適用                                             |
| ---- | ---------------------------------------- | ------------------------------------------------ |
| 導入 | `npx agent-skill-chain install --root=.` | `npx agent-skill-chain install --root=. --apply` |
| 更新 | `npx agent-skill-chain update --root=.`  | `npx agent-skill-chain update --root=. --apply`  |
| 削除 | `npx agent-skill-chain delete --root=.`  | `npx agent-skill-chain delete --root=. --apply`  |
| 診断 | `npx agent-skill-chain doctor --root=.`  | 読み取り専用のため非該当                         |

`delete`はmanaged asset recordとhashが一致するpackage所有fileだけを削除し、利用project所有fileと変更済みfileを保持する。再現性のためversionを固定するときはGit remoteの指定へrelease tagを付けて`github:techbeansjp-free/AGENTS.md#<tag>`とする。**`agent-skill-chain@<version>`はnpm registry上のpackage名とversionの解決であり、本packageは未公開のため成立しない。**内部関数名と旧CLI aliasの`init / upgrade / uninstall`は新しい手順・文書・自動化へ使用しない。

**`.agent-skill-chain/managed-assets.json`（managed asset record）を失った場合は`update --recover-record`で復旧する。** **`--recover-record`を付けない`update`は、recordが無ければ1 fileも書かずに拒否する。** 誤った`--root`や作業directoryでの実行を防ぐためであり、**製品はfilesystemから「かつて導入した」ことを推測しない。**

復旧すると、正本と一致する展開済み資産を採用してrecordを再固定し、**正本と異なる資産は上書きせず`retained`として報告する。** 報告された資産は内容を確認し、正本へ戻したい場合だけ当該fileを削除して再実行する。**`--recover-record`は未導入のdirectoryでも展開対象を配置する。** 対象directoryを確認してから付ける。dangling symlinkのrecordと壊れたrecordは不在扱いにせず拒否するため、先に当該pathを解消する。

`install`と`update`は、Claude Code用`.claude/skills/asc-step/SKILL.md`とCodex用`.agents/skills/asc-step/SKILL.md`も管理する。両fileは`.agent-skill-chain/skills/asc-step/SKILL.md`と同じ内容で、hostからWorkflow・Step skill正本へ入るための登録口である。`doctor`で配置・hash・frontmatter・正本linkを確認できる。

## commandの調べ方

**必須flagを1件ずつ試す必要はない。** 任意のcommandとsubcommandへ`--help`を付けると、必須flag検証より先にusageをJSONで返す。

```
npx agent-skill-chain worktree create --help
```

usageは要約、必須flag、条件付きflagとその条件、任意flagと既定値、位置引数、実行例を含む。

必須flagが不足したまま実行した場合も、**不足を1回の実行ですべて`reasons`へ列挙する。** 1件ずつ返さない。

```
$ npx agent-skill-chain worktree create
reasons: --issue=...が必要です / --branch=...が必要です / --slug=...が必要です / --base=...が必要です / --remote-default-branch=...が必要です / --remote-default-sha=...が必要です
```

値をとるflagは`--flag=値`の形式で指定する。**空白区切りは受理しない。** 無言で未指定として扱わず、専用の診断で拒否する。

```
$ npx agent-skill-chain worktree create --branch 値
reasons: --branchは空白区切りでは受理しません。--branch=値の形式で指定してください
```

trusted boundaryの評価は必須flag検証より先に行う。境界を侵すpathを渡した場合、不足flagではなく境界違反として拒否する。

## 使い方

1. 最初にrepository直下の[AGENTS.md](../AGENTS.md)と、この索引を読む。
2. 作業規則は`docs/`、実行するStepは`skills/`、成果物の書式は`templates/`からたどる。
3. policy入力を変更するときは`schemas/`で構造を確認し、package既定値とproject選択値を分離する。
4. 仕様を作るときは[仕様template利用案内](templates/specs/00_利用案内.md)から適用categoryを選ぶ。

各Step directoryの入口はそのdirectoryの`SKILL.md`、各仕様category directoryの入口はそのdirectoryの`00_*`文書である。新しいdirectoryを追加するときは、用途を重複定義しない入口文書とdirectory案内検査の対応を同じ変更に含める。

## 補助レビュー

### 進行役からローカルLLMへのreview委譲

Step 03/07/10の進行役は、下記の`local/supplemental-review.json`が`enabled: true`なら、その設定のローカルLLMをreviewerとして呼び出す。ユーザー共通設定は`$XDG_CONFIG_HOME/agent-skill-chain/supplemental-review.json`（未指定時は`~/.config/agent-skill-chain/supplemental-review.json`）に同じJSONを置く。対象worktreeのローカル設定、主worktreeのローカル設定、ユーザー共通設定の順に採用する。先に見つかった`{"enabled":false}`は後続の設定を抑止する。どれも無ければ既存のreview経路を使い、LLMは起動しない。`--root`には対象stagingと同じworktreeのrootを指定する。

```
npx agent-skill-chain routing delegated-review-staging --root=<対象worktreeのroot> --step=3 --staging=<対象staging>
npx agent-skill-chain routing delegated-review-staging --root=<対象worktreeのroot> --step=7 --staging=<対象staging>
npx agent-skill-chain routing delegated-review-diff --root=<対象worktreeのroot> --base=<比較基点SHA> --head=<H_impl SHA> --staging=<対象staging>
```

結果は`disabled`、`degraded`、`reviewed`のいずれか。`reviewed`には肯定・敵対の評価、対象内finding、差分外指摘の除外件数、判定、入力・出力digest、modelを含む。設定済みで`degraded`ならreview完了として扱わない。これは進行役のreviewer委譲であり、個人設定だけでprojectのtrusted policyやmerge権限を変えない。従来の`routing supplemental-review-*`コマンドは追加の指摘を得る互換経路として残る。

Step 03/07/10実施時に、ローカルLLM（Ollama）へdiffまたはstaging文書を渡し、判定には使わない追加の指摘を得られる任意機能である（TERM-ASC-124）。CodeRabbit相当以上の観点（バグ・セキュリティ・パフォーマンス・保守性・機能性）でレビューするようpromptを設計している。

**Issue #1425の`modelMapping.roles.reviewer`との違い**: `modelMapping.roles.reviewer`はgit管理下・project全体共有のreviewer役割宣言であり、`mode: "supplement"`でも共有設定の上書きが必須になる。本機能はエンジニア個別のGit管理外設定であり、`modelMapping.roles.reviewer`を一切読み書きしないため、他エンジニアや`pr create`/`pr merge`/`review round`の判定に影響しない。

有効化するには、`.agent-skill-chain/local/supplemental-review.json`（既定path）を作成する。

```json
{
  "enabled": true,
  "provider": "ollama",
  "model": "qwen2.5-coder:32b",
  "endpoint": "http://localhost:11434",
  "timeoutMs": 300000,
  "profile": "chill"
}
```

`profile`は`chill`（Critical/Highだけ表示）または`assertive`（全severityを表示）を指定できる。省略時は従来互換の`assertive`である。表示から隠した候補は`suppressedFindings`に残り、差分reviewの第二passでも検証する。`firstPassFindings`が全候補の元の順序を保持し、第二passの`findingIndex`はその配列に対応する。進行役は表示候補と隠れた候補の両方を確認する。findingの`effort`は`Quick win`、`Moderate`、`Heavy lift`から選ぶ修正工数の目安である。

`endpoint`はloopback（`127.0.0.1`/`localhost`）だけを受理する。`.agent-skill-chain/local/`は本packageの`install`/`update`が管理する対象namespace（`docs`・`skills`・`templates`・`schemas`・`policy`・`hooks`）に含まれないため、**`update`を実行してもこの設定fileは上書き・削除されない。** 追加で`.gitignore`へ登録する必要はない（本packageの配布物に含まれる`.gitignore`が`.agent-skill-chain/local/`を既に除外している）。利用projectが独自の`.gitignore`を持つ場合は、同じprefixを追記する。

CLIの呼び出し方は次のとおりである。設定が無効・不正な場合はエラーにせず`{"state": "disabled"}`を返して正常終了する。

```
# Step 10相当: exact-head diffと関連ファイルをレビューする
npx agent-skill-chain routing supplemental-review-diff --root=. --base=<比較基点SHA> --head=<対象SHA>

# Step 03/07相当: staging内の要求・要件・設計文書をレビューする
npx agent-skill-chain routing supplemental-review-staging --root=. --staging=<staging path>
```

指摘は`{"state": "findings", "findings": [...], "ignoredOutOfScopeCount": 0}`のJSONで返る。差分外の別taskへの指摘は採用せず、除外件数だけを残す。 連結worktreeから既定の補助review設定を使う場合、対象worktreeに設定が無ければ主worktreeのローカル設定を参照する。`--config-path`で明示したpathにはこのfallbackを適用しない。`supplemental-review-diff`の関連file収集では、拡張子なしdotfileを検索対象から外し、変更file名のstemが10件を超えるfileに現れた場合は汎用名として関連候補を採用しない。Ollama未起動・timeout時は`{"state": "degraded", "reason": "..."}`を返し、呼び出し元（Step 03/07/10の既存実施）を妨げない。より詳細な契約（起動境界・endpoint検証・安全側への倒し方）は、利用projectが`docs/specs/`配下に持つ信頼境界仕様（本package自身の例: `docs/specs/10_セキュリティ/01_信頼境界.md`の「補助レビュー起動の境界」節）を確認する。

## 置かないもの

- package所有directoryへrepository固有のpackage manager、CI、言語、命名、release値を置かない。
- `project/`へpackageの汎用規則、Markdown、未列挙fileを置かない。
- templateへ完成済みproject値や実装証拠を置かない。
- `.agent-skill-chain/tmp/`、`role-log/`、`metrics/`、`local/`を正本または配布物にしない。
