# agent-skill-chainディレクトリ利用案内

## 目的

この文書は`.agent-skill-chain/`配下で「何を、誰が、どの順で使うか」を探すための非規範的な索引である。規則やproject固有値をここへ複製せず、各正本へ案内する。

## ownerと編集

| directory | owner | 入口文書 | 用途 |
|---|---|---|---|
| `.agent-skill-chain/docs/` | package | [00_運用ポリシー.md](docs/00_運用ポリシー.md) | 権限・所有、開発フロー、品質基準の3規範文書 |
| `.agent-skill-chain/policy/` | package | [00_利用案内.md](policy/00_利用案内.md) | 安全な既定値、記入例、不変条件catalog |
| `.agent-skill-chain/schemas/` | package | [00_利用案内.md](schemas/00_利用案内.md) | policy入力とconformance入力の機械検証契約 |
| `.agent-skill-chain/skills/` | package | [00_利用案内.md](skills/00_利用案内.md) | Step 0〜11の実行契約 |
| `.agent-skill-chain/templates/` | package | [00_利用案内.md](templates/00_利用案内.md) | Issue成果物、仕様、共通設計の雛形 |
| `.agent-skill-chain/project/` | 利用project | この表とproject自身の仕様 | 利用projectが選択した値、rule、conformance binding |
| `.agent-skill-chain/project/choices/` | 利用project | project manifestと対応schema | 開発方式、言語、test層、runner等の選択値 |
| `.agent-skill-chain/project/rules/` | 利用project | project manifestと対応schema | project固有ruleの分割定義 |
| `.agent-skill-chain/project/conformance/` | 利用project | project manifestと対応schema | package不変条件とproject証拠のbinding |
| `.agent-skill-chain/tmp/` | runtime・利用project | この索引 | Git管理外の一時staging。子directoryも耐久的な正本ではない |
| `.agent-skill-chain/role-log/` | runtime・利用project | この索引 | 配布外のrole実行記録 |
| `.agent-skill-chain/metrics/` | runtime・利用project | この索引 | 配布外の観測値 |

`project/`はmanifestに列挙したJSONだけから成る完全inventoryであり、案内Markdownを混在させない。利用project固有の説明は、そのprojectが所有する`docs/specs/`から参照する。

## 使い方

1. 最初にrepository直下の[AGENTS.md](../AGENTS.md)と、この索引を読む。
2. 作業規則は`docs/`、実行するStepは`skills/`、成果物の書式は`templates/`からたどる。
3. policy入力を変更するときは`schemas/`で構造を確認し、package既定値とproject選択値を分離する。
4. 仕様を作るときは[仕様template利用案内](templates/specs/00_利用案内.md)から適用categoryを選ぶ。

各Step directoryの入口はそのdirectoryの`SKILL.md`、各仕様category directoryの入口はそのdirectoryの`00_*`文書である。新しいdirectoryを追加するときは、用途を重複定義しない入口文書とdirectory案内検査の対応を同じ変更に含める。

## 置かないもの

- package所有directoryへrepository固有のpackage manager、CI、言語、命名、release値を置かない。
- `project/`へpackageの汎用規則、Markdown、未列挙fileを置かない。
- templateへ完成済みproject値や実装証拠を置かない。
- `.agent-skill-chain/tmp/`、`role-log/`、`metrics/`を正本または配布物にしない。

## 正本

権限と所有は[00_運用ポリシー.md](docs/00_運用ポリシー.md)、Step順序は[01_開発ワークフロー.md](docs/01_開発ワークフロー.md)、品質gateは[02_品質基準.md](docs/02_品質基準.md)、構造は各schema、projectの選択値はproject manifestが列挙するJSONを正本とする。この案内との不一致では、それぞれの正本を優先する。
