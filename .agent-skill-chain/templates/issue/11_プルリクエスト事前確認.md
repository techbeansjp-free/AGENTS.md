## 1. 要件と変更

- [ ] 対象内の要求・要件がすべて実装済み

## 2. テストと品質

- [ ] project policy選択の言語・runnerと汎用の安定SCN IDで受け入れ例を追跡している
- [ ] 変更種別・risk・影響境界・ACから選んだVerification Setに再現可能なEvidenceがある

- [ ] 開発専用資産が配布物へ混入していない
- [ ] 秘密情報検査が合格

## 3. レビューと仕様

- [ ] 全ラウンドで肯定・敵対の両観点を確認
- [ ] 実装中発見の事実・影響・判断・対処・検証・仕様更新が最終reviewに含まれる
- [ ] ラウンド3で全指摘を分類
- [ ] 未解決Critical/Highがない、または別権限者の条件付き受容がある
- [ ] `docs/specs/`を更新し、要件・変更・SCN・テストを追跡
- [ ] dependency/authority/evidence graphのcycle反例とdetectorが合格
- [ ] 基準SHAとの差分に含まれる全ファイルを1ファイル1行でowner・target layer・責務・依存・仕様・test・安全性まで個別監査し、path集合が完全一致
- [ ] `H_impl`が`H_final`のancestorで、その差分がreview artifactだけ
- [ ] 既定branch追随を行った場合、取り込みはreview artifact commitより前にあり、artifactが最終commitである
- [ ] 既定branch追随を行った場合、`比較基点`が取り込んだ既定branch tipを指し、`H_impl`がartifact直前の最新commitを指す
- [ ] 既定branch追随を行った場合、個別監査表を`比較基点..H_impl`から再生成した
- [ ] trusted providerが観測したPR head、成功CI head、独立review commitが`H_final`へexact一致
- [ ] repository、PR、Actions run、immutable review IDが一致し、runの関連PR番号が対象PRだけを指す
- [ ] reviewerはPR authorとprovider観測済み`H_impl` commit authorのどちらとも異なる
- [ ] `no-spec-impact`の場合は限定的根拠がある

## 4. Git・GitHub・権限

- [ ] 正確なリポジトリ、既定ブランチ、基点・先頭SHAを再確認
- [ ] すべてのコミットを対象ブランチへpush済み
- [ ] PR本文のIssue参照が[開発ワークフロー](../../docs/01_開発ワークフロー.md)の規約に従う
- [ ] PR作成の操作authorityがあり、automaticの場合はtrusted policyをcandidate自身が変更していない
- [ ] マージ、Issue終了、ブランチ削除、release、公開、finalize、cleanupを連鎖しない
