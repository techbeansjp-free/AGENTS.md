# 03 実装計画

> 設計を、riskに比例したEvidenceで完了を判定できる小さな実装単位へ分解する。`成果物用語と責務境界`は`.agent-skill-chain/docs/01_開発ワークフロー.md`を正本とする。実装中の発見は前工程を自動再起動せず、事実と対処を本書へ追記する。目的・scope・受け入れ条件・security境界・不可逆操作の契約が変わる場合だけ影響する上流成果物を再確定する。

> **量を判断へ比例させる。** 本文書で機械検査が要求するのは、fileの存在、開発考慮事項の4行の表、未解決placeholderの不在、`Scenario: SCN-...`の行が成果物全体で1つ以上あることの4点だけである。**節構造は検査されない。** 判断のある節は具体的に書き、判断の無い節は書式を埋めるために語を増やさない。**同じ理由で対象外になる節が複数あるなら、節名を列挙した1行へまとめる。** 節ごとに同じ文を書き直さない。

## 11. 実装中の発見と対処

発見記録は4.1節を正本とする。契約変更が`なし`なら実装を継続する。契約変更がある場合もIssueや変更のない上流文書からやり直さず、影響する00〜03だけを再確定する。

## 12. risk比例検証hook

差分・risk・成功証拠でtargeted検証を選び、最終full gateと独立reviewを維持する。project固有budgetと計測はproject policyを参照する。
