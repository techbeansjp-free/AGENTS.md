## 1. 入力証拠

レビュー証拠は二段階で完成させる。製品・仕様・testを固定した`H_impl`の後、Phase Aではtracked review artifactだけを加えた`H_final`を作る。`H_impl`は`H_final`のancestor、commit間差分はproject policyが選ぶevidence-only pathだけとし、artifact path、SHA-256、Git blob OIDを観測する。trusted providerから`H_impl` commit SHA/author ID、repository、PR number/current head/author ID、Actions run ID/event/head/conclusion/関連PR番号、immutable review ID/commit/user ID/submittedAt/stateを実観測する。PR・成功CI・承認reviewは`H_final`へ一致させ、reviewerはPR authorとobserved implementation commit authorのどちらとも異なることを要求する。caller申告actor、任意JSON、別PRのrun、COMMENTED、未完了CI、自己reviewは承認証拠にしない。tracked文書へ自身のcommit SHAを書かず、H_final後はartifactを更新しない。完了はtrusted providerの外部attestationだけで記録し、head変更時は外部証拠を作り直す。

| 証拠 | 参照先 | 観測結果 | 根拠種別 |
|---|---|---|---|
| 要求・受け入れ条件 | （URL・ID） | （要約） | 人間判断 / 実行観測 / 既存コード / 一次資料 / テスト出力 / 推論 |
| 差分 | （SHA・URL） | （要約） | 既存コード |
| テスト | （コマンド・CI） | （件数） | テスト出力 |
| 仕様 | （更新先） | updated / no-spec-impact | 既存文書 |
| commit前candidate | （path manifest） | （candidate tree SHA） | Git index |
| Phase A artifact | （evidence-only path） | （SHA-256 / blob OID / H_impl..H_final paths） | Git観測 |
| commit後external | （trusted providerのPR / CI run / immutable review ID） | （repository、H_final、event、run/review ID、actor ID、提出日時、verdict） | 外部のimmutable証拠 |

重要判断を推論だけで承認しない。新しい権限が必要な場合は、対象操作と決定権者を明示する。

- dependency/authority/evidence graphにcycle、self-loop、unknown node、candidate自己評価、tracked artifact自己SHAがない:
- `H_impl`が`H_final`のancestorで、その差分がreview artifactだけであり、trusted providerが観測したPR/CI/reviewが`H_final`へ一致している:
- reviewer stable IDがPR author/provider観測済み`H_impl` author stable IDと異なる:

### 1.1 変更ファイル個別監査

追加・変更・削除した全ファイルを省略せず1ファイル1行で記録する。まとめ行、directory単位の一括承認、test成功だけによる代替を認めない。

| path | 変更種別 | owner | target layer | 単一責務・配置根拠 | 依存方向・循環 | 仕様・AC・SCN | 安全・rollback | 個別判定 |
|---|---|---|---|---|---|---|---|---|
| （repository相対path） | add / modify / delete | （owner） | package / project / spec / evidence | （根拠） | pass / finding（根拠） | （追跡先） | （境界・復旧） | pass / finding |

- 基準SHAとの差分path集合と表のpath集合が完全一致する:
- package層へproject固有値、project層へ汎用機構、spec/evidence層へ実行authorityを混入していない:
- 個別findingを修正した場合、そのファイルと隣接依存だけを再監査した:
