# hooks（強制点）

このdirectoryは、hostのtool呼び出し前に自動実行される**強制点**の正本を持つ。

## skillとの違い

**skillは呼び出されたときに読まれる登録口である。** hookは**利用者の操作なしに毎回走る。** 同じ配布機構で配るが責務が違う。

## 配られるもの

`install`と`update`は本体だけを配る。

| path | 内容 |
|---|---|
| `.agent-skill-chain/hooks/asc-contract-citation.mjs` | 正本 |
| `.claude/hooks/asc-contract-citation.mjs` | 正本からの展開 |
| `.codex/hooks/asc-contract-citation.mjs` | 同上 |
| `.agent-skill-chain/hooks/asc-host-observer.mjs` | host observerの正本（Issue #1566） |
| `.claude/hooks/asc-host-observer.mjs` | 正本からの展開。登録entryが指す実行対象 |

**`asc-contract-citation.mjs`の登録は配らない。** hostの設定fileへの書き込みは、`install`の権限を「packageの資産を置く」から「以後のtool callごとに自動実行されるcodeを登録する」へ広げる。**利用者が明示的に登録する。**

`doctor`はproject-localの設定に期待するentryがあるかを**報告する**。**`healthy`は変えない。**

## asc-contract-citation.mjs が何をするか

`codex exec`を含むcommandを検査する。commandが参照する`.md`または`.txt`のfileに**範囲を狭める語**（だけ・のみ・対象外・外す・限る・含めない・実行しない）があるのに、`## 規範の引用`節の中に要件IDと`> `で始まる原文引用の両方が無ければ、起動を`deny`で拒否する。

**節の外に置いた引用やIDは数えない。**

**Node.jsで実行する。** `package.json`の`engines`が要求するNode.js 20以上で動く。**`bash`と`jq`は必要としない。**

## Claude Codeへの登録

`.claude/settings.local.json`へ次を加える。**既存の設定を消さないこと。**

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR/.claude/hooks/asc-contract-citation.mjs\"",
            "timeout": 15
          }
        ]
      }
    ]
  }
}
```

**この形式は本repositoryで実際に動作している。**

## host observer（Issue #1566）

`asc-host-observer.mjs`はClaude Codeの`PreToolUse`（tool `SendMessage`）だけで起動するstatelessな観測器である。**警告するだけで止めない。** 送信本文にfresh contextを要するASC handoffがあればfresh mismatch、宛先subagent transcriptの最初のuser行（dispatch prompt）にterminalのASC handoffがあればterminal reuseのadvisory警告を返し、それ以外は何も返さない。常にexit 0で終了し、toolの許可・拒否・保留を返さず、fileを書かず状態を持たない。workflow・review・deliveryの判定と`doctor`全体の`healthy`には入らない。入出力・判定条件・Capability Matrixの正本は、本packageのrepositoryの`docs/specs/06_外部インターフェース/02_ホスト観測契約.md`（契約ID `HOOK-001`）である。

**登録は`install --apply`・`update --apply`が管理する。** `.claude/settings.local.json`の`hooks.PreToolUse`へ次のASC所有entryを1件だけ置く。shellを介さない形式であり、Windowsでも`node`を直接起動する。

```json
{
  "matcher": "SendMessage",
  "hooks": [
    {
      "type": "command",
      "command": "node",
      "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/asc-host-observer.mjs"],
      "timeout": 10
    }
  ]
}
```

- 所有は`command`と`args`の完全一致だけで判定する。`timeout`・matcher・追加fieldを変えても所有は移らず、次の`update`で正規形1件へ収束する。利用者のhook・permissions・env・同groupの他commandは保持する。
- 登録は新しいClaude Code sessionから有効になる。`doctor`の`hooks.hostObserver`が登録・資産・検証済みversion（`2.1.282`）を報告する。
- 無効化は`delete --apply`、またはこのentryの手動削除で行う。observerは状態を残さないため後片付けは要らない。ただし手動削除したentryは次の`update`で再び登録される。
- record復旧（`update --recover-record --apply`）はこのentryを追加も削除もしない。host設定fileを変えないためである。復旧後の次の通常の`update --apply`で登録される。
- 検証済みversion以外でhook errorが表示されても、toolは実行される。

## 変更したい場合

**展開先ではなく正本を変える。** 展開先を書き換えると、`update`は利用者の変更として保持し、`delete`は削除しない。**正本と展開先が食い違ったまま残る。**

本repositoryでは実際にdriftが起きた。`.claude`側だけがIssue #1233の是正を受け、`.codex`側は古い判定のまま残っていた（2026-09-09に観測）。

## Agent Lifecycle / Handoff（Issue #1546）

常時観測を廃止した。`asc-agent-lifecycle.mjs`は旧host登録との互換入口としてだけ配布し、標準入力は解析・保存せずEOFまで読み捨て、実行時JSON・lockを読み書きせず正常終了する。session・agent・toolの記録、予約、操作拒否は行わない。残留記録の解除やownerの停止確認は作業再開の条件ではない。

`install/update --apply`はcanonical command `node "$CLAUDE_PROJECT_DIR/.claude/hooks/asc-agent-lifecycle.mjs"`に一致するASC所有entryを削除する。同じgroupの他command、利用者のpermissions、無関係なhook・envは保持する。任意のラッパーをASC所有とは推測しない。`delete`も同じ所有境界を使う。

旧`--report`は観測廃止を返し、`--recover-session`は復旧不要を返す。旧`--trusted-workflow-read`はCLIを起動せず廃止を報告するため、ASC CLIを直接実行する。これらの互換入口は過去の記録を変更しない。doctorはlifecycle登録を要求せず、managed assetsの整合性は従来どおり検査する。

担当起動と引き継ぎには`workflow advance`の出力とGit・Issue・staging・review sessionを使う。hostの権限確認や明示CLIの検証は常時観測とは別に保持する。`asc-contract-citation.mjs`など他のhookはこの廃止の対象に含めない。
