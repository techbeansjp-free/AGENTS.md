# COVERAGE_AND_EXCEPTIONS.md — カバレッジ 100% と例外運用（汎用正本）

本ファイルは **本パッケージの配布物の一部**として、カバレッジ **100% を目標に CI で矯正する**運用と、**合理的に計測対象から外す例外**をどう管理するかの**正本**を定義する。対象言語の例: **Python / Node.js（TypeScript 含む）/ Go / PHP**（フロントエンドは下記 1.2 を参照）。

**「100%」の推奨定義**: 単体に限らず、**採用プロジェクトが README / CI で宣言した自動テストジョブ**（例: 単体・結合・API ブラックボックス・必要に応じ E2E）の結果を **公式手順でカバレッジデータにマージ**し、その **マージ後のレポート**に対して `--fail-under=100` 等を掛ける。どのジョブをマージ対象に入れるかはチームで固定し、**閾値を下げず**運用する。

**採用先プロジェクト**では、本文の方針に従い、下記 **第3章の例外台帳（レジャー）テンプレート** を `docs/COVERAGE_EXCEPTIONS.md` または **`.agent-skill-chain/project/COVERAGE_EXCEPTIONS.md`** に**コピー**して実データを運用する。台帳の**規約・列定義・言語別マーカの説明**は本ファイルを参照し、採用先で重複定義しない（DRY）。

---

## 1. 方針

- **デフォルト 100%**: CI の閾値（例: `--fail-under=100`）は下げない。不足は **テスト追加**か**例外登録**の二択とする。
- **例外の意味（閾値と分母）**: 例外は **閾値を緩めることではない**。**台帳＋ツール上の除外**で「計測に含める行・ファイル」を絞ったうえで、**残りの計測対象に対して 100% を強制**する。
- **除外の二重化**: (A) ツールが理解する **マーカまたは設定**、(B) 人間が読む **例外台帳**。**A だけ・B だけは不可**。
- **Go の制約**: 標準ツールチェーンに **Python の `pragma: no cover` 相当の公式な行単位無視は無い**。ファイル単位・ビルドタグ・`cover.out` 後処理などで扱う。

### 1.2 ブラウザ・Canvas / WebGL など「再現が難しい」UI 層

同一ピクセル・同一 GPU 挙動まで **CI で完全再現できない**コードは起こりうる。次を **この順で**検討し、それでも合理的に困難な **極薄の層だけ** 台帳付きで計測から外す。

1. **ロジックと I/O の分離**: 座標変換・状態機械などを Canvas / `getContext` から切り離し、**純粋な部分は通常どおり 100%** を目指す。
2. **行実行の取得**: `canvas` のモック、headless 互換実装、jsdom ＋ mock 等で **該当行がテストで実行される**ようにし、マージカバレッジに乗せる（**見た目の正しさの証明にはならない**場合がある）。
3. **見た目・統合の担保**: スクリーンショット比較・ビジュアルリグレッション・Playwright 等の E2E を **マージ対象ジョブに含める**場合、**代替保証**にジョブ名・参照画像・更新手順を台帳へ明記する。
4. **最後の手段**: 上記でもコストが見合わない **薄いアダプタのみ** を認定基準 4 に沿って除外する。

認定基準 4 の「結合テスト等」には、**HTTP 層のブラックボックス**に限らず、**上記 3 のブラウザ自動化**を含めてよい（採用プロジェクトのマージ定義に合わせる）。

### 1.1 禁止する回避パターン

| 禁止 | 理由 |
|------|------|
| 手書きの意味あるコードを「とりあえず `src/` 全体 ignore」 | 矯正が形骸化する |
| 台帳なしの `# pragma: no cover` のみ | 説明責任が追えない |
| 本番で実行されうるエラーハンドリングの網羅的除外 | 品質リスクが高すぎる |

## 2. 例外の認定基準

次のいずれかに該当し、**テストコストが成果に見合わない**ことをレビューで説明できる場合のみ例外とする。

1. **機械生成コード**（コミットする場合も含む）で、人手で意味のあるテストを書かない方針としたもの。
2. **到達不能だが型・リンタのために残す分岐**（例: `default` で `never` / exhaustive check）。
3. **本番では実行されないデバッグ・診断専用**（feature flag で無効化されるパス等）。※本番到達の可能性がある場合は例外にしない。
4. **外部環境依存で再現困難**かつ **別の自動テストで代替**しているもの（例: 契約テスト・結合テスト・API ブラックボックス・**スクリーンショット／E2E** 等。単体だけでは計測困難な場合。代替の**ジョブ名・パス・参照先**を台帳に書く）。**Canvas / WebGL** 等は 1.2 を先に適用する。

## 3. 例外台帳（レジャー）— 必須列

採用先の台帳ファイル（コピー先）に、次の列を満たす表を置く。

| 列 | 内容 |
|----|------|
| ID | 連番または UUID |
| 対象 | リポジトリ相対パス、可能なら関数名・行範囲 |
| カテゴリ | 上記第2章の 1〜4 のいずれか |
| 理由 | 1〜3 文で「なぜ**計測対象の** 100% に含めないか」（単体に限らない） |
| 代替保証 | 結合・契約・ブラックボックス・E2E／ビジュアル・静的解析・監査ログ等（**具体的なジョブ名や成果物パス**） |
| 適用手段 | pragma / 設定キー / ビルドタグ / 後処理スクリプト名 等 |
| 承認 | PR リンクまたはレビュアー名と日付 |
| 有効期限 | 任意（リファクタで解消予定の場合） |

### 3.1 台帳に含めるサンプル行（運用開始時に削除）

| ID | 対象 | カテゴリ | 理由 | 代替保証 | 適用手段 | 承認 | 有効期限 |
|----|------|----------|------|----------|----------|------|----------|
| SAMPLE-001 | （最初の実例外へ差し替え） | 1 | 書式例示用。運用開始時に本行を削除する。 | 不要（サンプル） | なし | テンプレート同梱 | 運用開始時削除 |

## 4. 言語別: 100% 矯正下での除外手段（代表例）

プロジェクトで別ツールを使う場合は、**言語あたり 1 系統**に統一し README に記載する。

### 4.1 Python（coverage.py）

| 手段 | 用途 | 備考 |
|------|------|------|
| `# pragma: no cover` | 行・分岐の除外 | 台帳とセット。 |
| `[tool.coverage.run] omit` / `source` | パス単位 | **生成物ディレクトリ**等。台帳と一致。 |
| `[tool.coverage.report] exclude_lines` | 正規表現パターン | `if TYPE_CHECKING:` 等。濫用注意。 |

**参照**: [Coverage.py — Excluding code from coverage.py](https://coverage.readthedocs.io/)

### 4.2 Node.js / TypeScript（c8 / Istanbul / Vitest / Jest）

| 手段 | 用途 | 備考 |
|------|------|------|
| `/* c8 ignore next */` 等 | 行単位 | ツール依存。 |
| `/* istanbul ignore next */` | nyc / Istanbul 系 | 既存コードで多い。 |
| `coveragePathIgnorePatterns`（Jest） | パス除外 | **生成物・e2e スタブ**等に限定。 |
| `coverage.exclude`（Vitest） | パス除外 | 設定で明示。 |

Vitest は `coverage.provider` が `v8` と `istanbul` で**無視コメントの扱いが異なる**ことがある。プロバイダを 1 つに固定し、**効く記法を README に 1 例**載せる。

**参照**: 各ツールの公式 Coverage 節（c8 / Vitest / Jest）。

### 4.3 Go

| 手段 | 用途 | 備考 |
|------|------|------|
| ビルドタグ（`//go:build`） | ファイル単位 | 運用コスト高。 |
| 生成コードの別パッケージ化 | `go test -coverpkg=...` から外す | **説明しやすい**。 |
| `cover.out` の **後処理** | 生成行の除去 | 標準外。実務で使用。 |
| `//nolint` 等 | **カバレッジ除外ではない** | 混同禁止。 |

### 4.4 PHP（PHPUnit + Xdebug / PCOV）

| 手段 | 用途 | 備考 |
|------|------|------|
| `@codeCoverageIgnore` | クラス・メソッド | PHPUnit 公式。 |
| `@codeCoverageIgnoreStart` / `End` | 範囲 | |
| PHPUnit の `<exclude>` / `<include>` | パス | 生成物とセットで台帳に記載。 |
| PCOV `pcov.exclude`（ini） | グローバル除外 | **生成物パスに限定**推奨。 |

**参照**: [PHPUnit — Code Coverage](https://docs.phpunit.de/en/11.5/code-coverage.html)（バージョンに合わせ URL を読み替え）
