# BACKGROUND_EXEC_RATIONALE — 委譲タスク内バックグラウンド実行禁止の背景

**正本の切り分け**: 禁止事項そのもの（何が禁止か・対象範囲・フォールバック条件）は [run_command.md §Constraints「委譲タスク内の長時間コマンドはフォアグラウンド実行」](run_command.md) 本文が正本。本ファイルは**理由・観測事例の詳細のみ**を補足する参照先であり、本文の再定義は行わない。

---

## 理由（なぜ禁止か）

入れ子で委譲されたサブエージェント自身が起動したバックグラウンドタスクの完了通知（task-notification）は、その起動元＝コマンドを起動したサブエージェント自身の会話コンテキストに届く仕組みである。しかし、サブエージェントが応答を終了すると Agent 呼び出しが完了扱いとなり再開されないため、その通知を受け取れない。

そのため「完了通知を待つ」と言い残して応答を終了すると、処理が停滞する。オーケストレーター側にもこの完了は自動通知されず、手動での確認・再開が必要になる。

## 観測事例

同一サブエージェントで 2 回、応答終了後に完了通知を受け取れず処理が停滞する事象を観測済み。

## 判断基準の補足

対象外とする条件を実行時間の長短（秒数などの閾値）に置かない。判断の分かれ目は「`run_in_background` を使う可能性があるか」に置く。

## フォールバックの根拠

この前提（入れ子委譲では、起動したバックグラウンドタスクの完了通知を、応答を終了したサブエージェント自身が受け取って再開することはできない）が成立しないランタイムでは、通知欠落という事象自体が起きないため、本項は自然に無害化される（ロックアウトしない）。

## 既存項目との関係

本項は既存の各ゲート・書記依頼の強制とは非交差の独立項目であり、既存項目を置換・弱化しない。
