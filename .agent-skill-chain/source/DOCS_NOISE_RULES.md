# DOCS_NOISE_RULES.md — システム仕様書のノイズ排除規約

**責務**: システム仕様書（`docs/`）における**ノイズ禁止パターン**を定義する唯一の正本。「システム仕様書が常に最新かつ正しい」を保つため、実装と矛盾する・陳腐化した・重複した・壊れやすい記述を排除する基準を 1 か所に集約する。[DOCS_RULES.md](DOCS_RULES.md) からはこのファイルへの参照のみを行い、本ファイルの内容を複製しない。

---

## コード層との境界（[CODE_COMMENT_RULES.md](CODE_COMMENT_RULES.md) との対称）

- **本ファイル（docs 層）が対象とするもの**: `docs/` 配下のシステム仕様書（01_システム概要〜99_ID命名規則と管理・00_review 等）の記述内容のノイズ。
- **[CODE_COMMENT_RULES.md](CODE_COMMENT_RULES.md)（code 層）が対象とするもの**: ソースコードのコメント・docstring からの外部参照（仕様名・章節番号・PR/issue/タスク番号）の禁止。
- 両者は「陳腐化しやすい記述を排除する」という同じ思想を、**docs 層**と**code 層**それぞれの独立した正本で担う（責務は重複しない・相互に再定義しない）。

---

## 禁止パターン（4 種）

システム仕様書に次の 4 パターンの記述をしてはならない。

### (i) 実装と矛盾する記述

- **定義**: 記載内容が現在の実装と食い違っている記述。
- **判定基準**: 実装ファイル・実行結果と突合し、一致しないもの。
- **是正方法**: 実装に合わせて記述を修正するか、実装側を仕様に合わせて修正する（as-built 同期。継続追随ゲートは [DOCS_RULES.md §継続追随ゲート](DOCS_RULES.md) を参照）。

### (ii) 陳腐化した記述

- **定義**: 過去には正しかったが、その後の変更で実態と乖離した記述（削除済み機能の記載・旧仕様のまま残った説明等）。
- **判定基準**: 現状の実装・運用と照合し、既に存在しない対象を指しているもの。
- **是正方法**: 該当記述を削除するか、現状に合わせて更新する。

### (iii) 正本が別にある内容の重複記述

- **定義**: 別ファイルに既に正本がある内容を、そのまま複製して書いている記述。
- **判定基準**: 同一内容が複数ファイルに存在し、更新時に同期が必要になっているもの。
- **是正方法**: 正本 1 か所に内容を残し、他の箇所は正本への `§節参照` または `#見出しアンカー` の**参照 1 行**へ張り替える（正本一元化。[CORE.md §境界](boot/CORE.md)）。

### (iv) 壊れやすい参照

- **定義**: 行番号直リンク（`<file>.md:NNN`）等、ファイルの編集で容易に陳腐化する参照形式。
- **判定基準**: 既存の [DOCS_RULES.md §行番号直リンク禁止](DOCS_RULES.md) の定義を包含参照する（本ファイルでは再定義しない）。
- **是正方法**: `§<節名>` または `#<見出しアンカー>` の安定参照へ張り替える。

## 機械検証と意味的検証の役割分担

上記のうち (iv) 壊れやすい参照は形式的パターン（行番号直リンクの文字列）であり、enforcement（`enforcement/ci/audit.sh` の grep 検出）で機械的に検出できる。一方、(i) 実装と矛盾する記述・(ii) 陳腐化した記述・(iii) 正本重複は「実装や他ファイルとの意味的な一致」を要する判定であり、機械検証だけでは十分でないため、[DOCS_RULES.md §継続追随ゲート](DOCS_RULES.md) が定める R-5 のレビュー反復（指摘 0 件まで）が意味的検証を担う。両者は二段構えで補完し合い、どちらか一方に依存しない。
