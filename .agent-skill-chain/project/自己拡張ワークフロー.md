# 自己拡張ワークフロー（このリポジトリ固有・最優先）

**目的**: 本リポジトリは「パッケージの正本」かつ「自己拡張（ドッグフーディング）する消費者」の二役を兼ねる。両者は git の扱いが逆になるため、名前空間を分離して二重管理・配布物汚染を防ぐ。

このファイルは `.agent-skill-chain/project/` 配下にあり、**`.agent-skill-chain/source/` および CLAUDE.md の標準フローより優先**される（[../.agent-skill-chain/project/README.md](README.md) §優先順位）。

## issue の作成場所（標準フローの上書き）

CLAUDE.md / `.agent-skill-chain/source/` の標準では issue を `.agent-skill-chain/runtime/<timestamp>_<title>/` に作るが、**本リポジトリでは下記に作成する**。

| 種別 | 作成場所 |
|------|----------|
| 単一 issue | `docs/maintainer/workflow/<timestamp>_<title>/` |
| サブ issue（PR 指摘対応等） | `docs/maintainer/workflow/{parent}/90_issues/{ディレクトリ名}/` |

- `<timestamp>` は実行環境の現在時刻（JST）。例: `TZ=Asia/Tokyo date +%Y%m%d_%H%M%S`。
- ファイルセット（`00_要求定義.md`・`01_要件定義.md`・`02_設計.md`・`03_実装計画.md`・`04_review.md` 等）は `.agent-skill-chain/runtime/templates/` の標準テンプレートに従う。
- これらは **git 追跡対象**であり、自己拡張の開発記録として残す。

## memo の作成場所（標準フローの上書き）

CLAUDE.md / `.agent-skill-chain/source/`（[../.agent-skill-chain/source/skills/agent/run_command.md](../.agent-skill-chain/source/skills/agent/run_command.md):57・[../.agent-skill-chain/source/workflow/TEMPLATES.md](../.agent-skill-chain/source/workflow/TEMPLATES.md):12-13）の標準では memo を `.agent-skill-chain/runtime/{issue}/memo/` に作るが、これは**消費者ランタイムの既定**である。**本リポジトリの自己拡張 issue では下記に作成する**（issue 本体と同一名前空間に置き、記録分裂を防ぐ）。

| 種別 | 作成場所 |
|------|----------|
| 自己拡張 issue の memo | `docs/maintainer/workflow/<issue>/memo/`（`close` 後は `docs/maintainer/workflow/close/<issue>/memo/`） |

- ファイル名のプレフィックス（`YYYYMMDD_HHMMSS_`・JST）の取得規約（`TZ=Asia/Tokyo date +%Y%m%d_%H%M%S` または `.agent-skill-chain/source/scripts/memo-prefix.sh` の実行）は配布物側の正本（上記 run_command.md:57）に従う（重複再定義しない）。
- これらは **非追跡（transient）** であり（ルート `.gitignore` の `**/memo/*` で無視される）、**置き場所のみ** issue 本体と同一名前空間に置く（記録分裂を防ぐため）。追跡可否の決定はルート `.gitignore`（`**/memo/*`）が単一情報源であり、本宣言はそれを上書きしない。
- memo は**過渡的スクラッチで正本ではない**。レビュー（review-docs 等）の**本則証跡は `workflow.db`**（消費者ランタイム生成物・`.gitignore` 対象）に残る。**git 追跡する成果物は issue ドキュメント（`00`〜`04`）のみ**である（memo は含まない）。

## 完了 issue の close 移動（上書き）

汎用ルールの**宣言は [../.agent-skill-chain/source/boot/CORE.md](../.agent-skill-chain/source/boot/CORE.md) §完了 issue の close 分離**、**ライフサイクル詳細は [../.agent-skill-chain/source/workflow/PHASES.md](../.agent-skill-chain/source/workflow/PHASES.md) §完了 issue の close 移動**にある。本リポでは**配置先のみ上書き**する（トリガー条件・完了判定の定義は重複させず上記を参照）。

| 種別 | 移動先 |
|------|--------|
| 完了したトップレベル issue（配下のサブ issue 含む） | `docs/maintainer/workflow/close/<issue>/` |

- 移動は**トップレベル issue が完了したときのみ**（PHASES のトリガー・完了定義に従う。サブ issue 単独完了では移動しない）。
- close 後も git 追跡対象（自己拡張の開発記録）として残す。04_review.md・workflow.db ログ等の証跡は移動後もそのまま保持する。

### close 移動時の相対リンク補正（必須手順・移動前に完結）

本節は [../.agent-skill-chain/source/workflow/PHASES.md](../.agent-skill-chain/source/workflow/PHASES.md) §完了 issue の close 移動 の「移動に伴う相対リンクの深度補正」原則の**本リポ向け具体化**である（原則・検証タイミングの正本はコア、本節は具体手順）。

`docs/maintainer/workflow/<issue>/` はリポジトリルートから **4 階層下**（`docs`/`maintainer`/`workflow`/`<issue>`）だが、`close/<issue>/` へ移動すると **5 階層下**（`docs`/`maintainer`/`workflow`/`close`/`<issue>`）になる。issue ディレクトリの**外**（`.agent-skill-chain/source/`・`.agent-skill-chain/project/`・`.github/`・`README.md`・`docs/maintainer/RELEASE.md` 等リポジトリルート配下）を指す相対リンクは 1 階層深くなるため補正する。**検証・補正はすべて移動前（`docs/maintainer/workflow/<issue>/`＝読み取り制限のかからない場所）で完結させること。** `.claude/settings.json` は `close/` 配下への Read/Grep/Glob を deny しており、移動後検証に依存する手順は必ずブロックされる。

**手順（この順で厳守）**:

1. **列挙**: 元の場所（未移動）で、対象 issue 内の全ファイルの相対リンクを列挙する。例: `grep -rEon '\]\(\.\./' docs/maintainer/workflow/<issue>/`。
2. **分類**: 各リンクを次に分類する。
   - **(a) issue ディレクトリの外を指す参照**（`.agent-skill-chain/source/`・`.agent-skill-chain/project/`・`.github/`・`README.md`・`docs/maintainer/RELEASE.md` 等、リポジトリルート配下）→ **深度 +1 が必要**。
   - **(b) 同一 issue ディレクトリ内の兄弟ファイル・配下 memo への参照**（例: `./00_要求定義.md`・`./memo/...`）→ **補正不要**（深さ変更なし）。
   - **(c) 同時に close へ移動する別 issue への参照**（例: `../20260712_XXXXXX_.../00_要求定義.md`）→ 参照先も同じ深さで一緒に移動するため**補正不要**（両者の相対位置は不変）。
3. **編集**: **(a) のみ**、`../` を 1 つ追加する形で、**元の場所にいるうちに**編集する（例: `../../../../.agent-skill-chain/source/CONCEPTS.md` → `../../../../../.agent-skill-chain/source/CONCEPTS.md`）。**markdown リンク構文 `](...)` を伴わないバッククォート内・本文中の `../` の言及（過去レビュー証跡・例示等）は改変しない**（実リンクのみ対象）。
4. **移動前検証**: **元の場所にいる状態のまま**妥当性を検証する。**`close/` という文字列を含むパスを Bash コマンドの引数に一切使わない**方法で行う: 編集前のリンクと編集後のリンクを比較し、「`../` の数がちょうど 1 つ増えている」「ターゲットのファイル名部分が変化していない」ことをテキスト上で確認する（実ファイルシステムへの再アクセスは不要）。深度 +1 は移動という操作の定義そのものであり、**編集前のリンクが実在解決していれば**深度 +1 後のリンクも移動後に正しく解決することは構造的に保証される。念のため、編集前（未移動）のリンクが実在解決することを通常の Read/Grep/Glob（deny 対象外の元の場所）または `realpath -m` で確認しておくこと。**編集前のリンクが解決しない**（元から深度不足等の不備がある）場合は、単純な +1 では移動後も解決しないため、移動後に 5 階層上（`](../../../../../`）で正しく解決する深度へ**是正**してから移動する。
5. **移動**: 編集・検証が完了し確認が取れた後にのみ、`git mv`（追跡ファイル）／`mv`（`memo/` 等の非追跡ファイル）でディレクトリを `close/<issue>/` へ移動する。
6. **移動後の禁止事項**: 移動後は、`close/` 配下のファイルに対して Read/Grep/Glob（Bash 経由の `cat`/`grep`/`realpath` 等を含む）を**一切行わない**。移動成否の確認は `git status`（パス一覧のみで内容は読まない）・`git log --stat`（コミット対象パス一覧のみ）等、**ファイル内容を読まない手段**に限定する。

この手順により、以後の close で同じリンク切れ（深さ不足）が再発せず、かつ移動後の `close/` 配下への読み取りに依存しないため、環境の deny 設定（`.claude/settings.json`）に抵触しない。

## テストの tmp 隔離（必須）

何かをテスト/検証するときは、**一時ディレクトリ（`mktemp -d`）を作成してその中で検証**する。**いきなり自己インストール（本リポへの `setup.sh` 実行等）や本番ファイルへの実行をしてはならない。**

- **理由**: 破壊的影響の回避と、既存生成物との混同による「本当に正しいか分からない」状態の防止。
- **具体運用**: install / uninstall / setup / build 等の検証は `mktemp -d` ＋ `git archive HEAD | tar -x`（クリーン clone の再現）等で隔離環境を作って行う。本リポの `.agent-skill-chain/source/` `.claude/` `.cursor/` `.agent-skill-chain/runtime/` `workflow.db` を**変更・破壊しない**こと。検証後は一時環境を片付ける（`rm -rf` 等）。
- 汎用のテスト方針は [../.agent-skill-chain/source/RULES.md](../.agent-skill-chain/source/RULES.md) §テスト隔離 を参照（重複させず相互参照）。

## 理由（名前空間の役割分担）

| パス | 役割 | git |
|------|------|-----|
| `.agent-skill-chain/source/`、`AGENTS.md`、`CLAUDE.md`、`.agent-skill-chain/runtime/templates/`、`.claude-plugin/`、`.agent-skill-chain/source/scripts/` | パッケージ正本（配布物） | 追跡する |
| `test/` | 保守者自己テスト（自リポ検証用の runner / coverage / E2E / 各 test-*.sh。**非配布**＝`package.json` の `files` allowlist 外。`verify-npm-pack.sh` でも pack 混入を検知） | 追跡する |
| `docs/maintainer/workflow/` | 自己拡張 issue（保守者の開発記録）。「追跡する」は **issue 本体ドキュメント（`00`〜`04`）を指す** | 追跡する（※ `memo/` は例外＝**非追跡**） |
| `.agent-skill-chain/runtime/<issue>`、`.agent-skill-chain/runtime/workflow.db*` | 消費者ランタイム生成物 | **無視**（`.gitignore`） |
| `.claude/`、`.adapters/` | setup / build による各ツール向け生成物 | **無視**（`.gitignore`） |

> **※ `docs/maintainer/workflow/` 配下の追跡範囲（誤読防止）**: 上表の「追跡する」は **issue 本体ドキュメント（`00_要求定義.md`〜`04_review.md`）** を指す。同一ディレクトリ配下にある **`memo/` は例外であり非追跡（transient）** で、ルート `.gitignore` の `**/memo/*` で無視される（§memo・§issue の作成場所 を参照）。「`docs/maintainer/workflow/` 配下なら何でも一括追跡」ではない。memo の追跡可否の決定はルート `.gitignore` が単一情報源であり、本表・本ファイルの宣言はそれを上書きしない。

参照: [../docs/maintainer/workflow/README.md](../docs/maintainer/workflow/README.md)、[../.agent-skill-chain/source/SETUP.md](../.agent-skill-chain/source/SETUP.md)、ルート `.gitignore`。
