# OPERATING_PRINCIPLES.md — AI駆動開発の基本運用原則の強化（本リポ固有）

**責務**: AI駆動システム開発全般に適用する本リポジトリ固有の基本運用原則の強化（リソース意識・責務境界意識・進行役表示最小化）を、コア `.agent-skill-chain/source/` の抽象原則への参照とともに 1 か所に集約する。各節は「本リポでの位置づけ」を述べるのみで、既存原則の本文は複製しない。

サブ委譲時のモデルティア選定（役割→ティア対応表）の正本は本ファイルではなく [MODEL_TIER_TABLE.md](MODEL_TIER_TABLE.md) を参照（索引のみ・定義は複製しない）。

## (b) リソース（トークン・コンテキスト）意識

本リポでは、issue 起票局面に限らず**AI 駆動システム開発全般**でトークン・コンテキストへの配慮を基本姿勢とする。設計・実装・レビュー等いずれの作業局面でも、不要な文脈肥大化を避けることを常に意識する。

具体機構（issue-persist 境界・仕様 inventory の索引化＋スライス渡し・fresh サブの構造化ハンドオフ）は引き続き issue 起票局面に特化したものとして [../source/CONTEXT_EFFICIENCY.md §適用のスケーリング](../source/CONTEXT_EFFICIENCY.md#適用のスケーリング) に定める。単一/少数 issue の軽量運用（過剰適用回避）はそこで維持され、本節の一般原則化によって軽量作業に全機構が新たに強制されることはない。

## (c) 責務・境界意識

責務・境界を意識することは、設計フェーズに限らず**全工程**（要求定義・実装・レビュー・issue 起票等を含む）で当たり前に適用される基本姿勢である。

原則の本文は新規に定義せず、既存の [../source/spec/01_設計原則.md §単一責務・§明確な境界](../source/spec/01_設計原則.md) と [../source/spec/06_設計判断の優先順位.md](../source/spec/06_設計判断の優先順位.md) を正本として参照する。

## (d) 進行役表示最小化

進行役（オーケストレータ）自身の応答・表示は、ユーザーが進捗を確認できる程度に留めてよい。

**論拠**: 詳細情報は要求定義・要件定義・設計・実装計画・レビュー（`00`〜`04`）に残り、かつ git 管理下にあるため、進行役自身の応答を最小化しても情報は失われない。

**対象範囲の違い**: 本節は**進行役（オーケストレータ）自身**の表示量を扱う。[../source/AGENT_CONDUCT.md](../source/AGENT_CONDUCT.md) はサブエージェント向けの報告規範（結論先行・進捗の実証等）であり対象が異なる。[../source/boot/CORE.md §応答ルール](../source/boot/CORE.md#応答ルール) は進行役が説明すべき手順の**型**（phase 判定→command 選択→run_command→結果確認）を定めるのみで表示量には触れない。本節はその型を保ったまま、表示**量**の最小化のみを付け加えるものであり、両者と二重定義・混同にはならない。
