# 運用ポリシー

ASCの目的は、要求に適合する変更を安全かつ効率的に提供することである。固定Step、文書量、Agent数、テスト件数自体を成果にしない。

ユーザーのGoal・受入条件・変更範囲・権限を正本とする。Agentが自分の変更範囲や権限を拡張してはならない。秘密情報、他Issue、他worktreeの成果を保護する。Hostの拒否を迂回しない。

Git管理済みrepoでは専用worktreeを標準とし、命名と実体確認は[実行手順](../../v05/USAGE.md)に従う。Git未管理フォルダーではworktreeを要求しない。残留session記録や別worktreeの正常な作業を理由とする一律拒否を導入しない。

push、PR、merge、releaseは別の操作権限である。[Owner契約](../../v05/OWNER_APPROVAL.md)に従い、未承認操作は行わない。移行時は利用者固有の設定・契約を保護する。

実行結果、失敗、skip、欠測を区別する。未検証を合格として記録しない。
