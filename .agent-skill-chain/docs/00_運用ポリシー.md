# 運用ポリシー

## 権限

パッケージ既定値は`delivery.stopAt=pull_request`である。ローカル計画にGitHubリモートは不要だが、一時ステージングを耐久化済み、同期済み、別セッションから再開可能とは報告しない。外部への書き込みには、事前表示、リポジトリ同一性、認証・権限・状態、操作単位の承認、書き込み直前の再検証を要求する。

プロジェクトのマージ方針は既定ブランチで追跡し、`disabled / assisted / automatic`から選ぶ。`assisted`は対象PR単位の承認を要求する。`automatic`は既定ブランチ上の信頼済みポリシーを耐久的な承認として扱う。対象PR自身が追加・緩和したポリシーで自己承認できない。ホストとGitHubの制御を迂回しない。

マージ承認が許可するのは`pr.merge`だけである。ブランチ削除、Issue終了、リリース、パッケージ公開、完了処理、後片付けは別の権限を要求する。

## 所有権

パッケージ所有資産は、この案内、3つの規範文書、テンプレート、ステップ0〜11のスキル契約、スキーマ、既定ポリシー、CLI、検証器、アダプターである。利用側所有資産は、プロジェクト規約・テストコマンド、`.agent-skill-chain/tmp/issues/`、`.agent-skill-chain/project-policy.json`、`docs/specs/`、将来の`docs/adr/`である。更新・アンインストールは利用側所有資産と変更済み資産を保持する。

## role分離とmodel tier

同一scopeの工程責務は`coordinator / analyst / implementer / reviewer / verifier / finalizer`へ分離する。coordinatorはIssue分解、依存関係、割当、状態遷移、証拠集約だけを行い、product code・test・specを実装しない。implementerと最終reviewerは異なるagent identityかつ異なるcontextとし、独立性が不明ならPR、merge、finalizeをfail-closedで停止する。各roleの許可path、許可操作、禁止操作、必要証拠はproject choiceで宣言し、package既定契約より弱い変更をcandidate自身の承認へ使わない。

能力tierは`routine / standard / advanced / critical`とし、risk、mode、scope、finding重大度から単調に必要tierを決める。model mapping未定義、tier不足、根拠なし降格、silent fallbackは拒否する。能力tierはfilesystem、GitHub、merge、releaseのauthorityを付与せず、操作authorityを別の信頼境界で検証する。

provider別の自律選択上限として、Codexの推論レベルは`high`まで、Claudeのmodelは`Opus`までとする。上限超過にはprovider、選択値、Issue、scope、指示者、指示日時、失効日時が完全一致する人間overrideを要求する。roleまたはAI agentによる自己発行、別Issue・別scope・失効済み証拠、alias・自動routing・fallbackによる上限回避を拒否する。人間の事業判断とrisk受容は能力tierから推測しない。

## fail-closed不変条件

- モードの根拠が不明なら`full`を選ぶ。
- リポジトリ、リモート、SHA、保護設定、検査、レビュー、仕様影響、復旧方法、権限が不明なら、それに依存する書き込みを拒否する。
- 暗黙のstash、reset、checkout、clean、worktree削除、マージ、終了、削除、リリース、公開を行わない。
- 事前確認と適用を分離する。完了処理の適用には、承認済みの最新報告ハッシュを要求する。
- アーカイブ済みハーネス、SQLite台帳、リース、UUIDによる作業調整、サブエージェント強制、無制限レビューループへ実行時依存しない。

依存、authority、evidenceは有向非循環graphとして扱う。candidateによる自己評価、tracked artifactへの自己commit SHA、相互参照で成立する承認・証拠を禁止する。rollback/retryだけは、単調なrevision、実行上限、終了条件を持つ明示的な状態遷移として許可する。

ポリシースキーマと安全な既定値は`.agent-skill-chain/schemas/`と`.agent-skill-chain/policy/`に置く。利用側による上書きは、有効で追跡済みのポリシーだけに許可し、パッケージ既定値は常に安全側とする。

## risk比例型rule

強制強度は具体的なrisk、可逆性、影響範囲、authority境界に比例させる。安全・authority境界以外を一律にdenyせず、拒否時は行動可能な根拠、安全な次の行動、必要authority、rollbackを返す。candidate変更は自身へ適用するtrusted条件を緩和して自己承認できない。構造の機械正本はschema、製品仕様と追跡は`docs/specs/`、projectの選択値はproject policyへ分離する。
