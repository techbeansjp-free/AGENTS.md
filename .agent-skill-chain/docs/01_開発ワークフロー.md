# Goal・Evidence駆動の実行

固定Step 0〜11は実行しない。Goal、受入条件、リスク、依存関係、有効なEvidenceから必要な作業を選ぶ。詳細は[Goal実行](../../v05/GOAL_EXECUTION.md)を参照する。

実装Agentが必要な設計・コード・テスト・文書を扱い、別ContextのReviewerが元要求と実差分を独立に確認する。決定論的なGit確認・検証・権限確認には専用Agentを起動しない。

並列化は変更範囲と依存関係が分離できる場合に行う。失敗・中断後は有効なEvidenceから再開し、影響する作業だけを再実行する。不明な影響は確認範囲を広げる。予算・権限・停止条件を守る。

Issue参照の`Closes #`はmerge時に閉じる意図がある場合だけ使い、参照だけなら`Relates to #`を使う。PR作成をIssue完了やreleaseと混同しない。
