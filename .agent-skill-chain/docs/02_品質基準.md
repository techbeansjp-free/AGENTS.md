# 品質基準

変更範囲、権限、秘密保護、独立レビュー、要求・実装・検証・提出対象の一致は常時維持する。実テスト成功だけで要求適合や安全性を証明したと扱わない。

Reviewerは元要求、実差分、関連経路、プロジェクト契約、テスト、文書の整合性を確認する。修正後はEvidenceの有効性を再評価する。実装者の自己評価を独立レビューとして受理しない。

Gherkin、DDD、UNIX思想、再利用性、保守性、冪等性、デザイン規約は変更内容とプロジェクトの明示契約に従って適用する。必要な保証を黙って省略せず、不要な文書・専用Agentは増やさない。ADRは将来の判断に必要な理由が既存資料にない場合に限り、重複生成しない。

製品の標準検証は`npm run quality`。配布物は`npm run package:check`。Linux隔離・実E2E・移行の受入状況は[受入記録](../../v05/RELEASE_READINESS.json)で確認する。試験件数を旧版と合算しない。

性能は時間・Agent起動・tokens・再試行・欠測を品質と同時に評価する。同条件でない観測値から改善率を断定しない。変更で無効にならない検証を形式的に繰り返さない。
