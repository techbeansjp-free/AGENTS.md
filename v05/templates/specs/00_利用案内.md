# 任意の仕様書テンプレート

既存プロジェクトの書式・配置・用語・IDを優先する。以下は書式がない場合の出発点であり、全ファイルの生成・読込みを要求しない。必要な節だけ既存文書へ取り込んでもよい。番号は分類であり実行順序ではない。

| 必要な内容 | 雛形 |
|---|---|
| 目的・対象範囲・元要求 | [要求定義](01_要求定義.md) |
| 検証可能な条件・不変条件 | [要件定義](02_要件定義.md) |
| 責務・依存関係・設計判断 | [基本設計](03_基本設計.md) |
| API・データ・処理・例外 | [詳細設計](04_詳細設計.md) |
| 画面・操作・状態・アクセシビリティ | [画面仕様](05_画面仕様.md) |
| 検証方法・運用・移行 | [検証・運用設計](06_検証・運用設計.md) |

利用時は選んだ雛形をプロジェクトが認めた場所へコピーし、以後はプロジェクトが所有する。既存文書を上書きしない。配布先は `node_modules/agent-skill-chain/v05/templates/specs/`。自動生成・自動読込み・専用Agent起動は行わない。

`{...}`は記入例のplaceholder。未確定事項は未決として、確認先と影響を記す。提案・承認済み・実装済み・検証済みを区別し、実装に合わせて元要求を変えない。雛形を埋めたことは承認・検証Evidenceではない。

既存Issue・OpenAPI・テスト・設計資料が正本なら参照し、重複記述を避ける。不要な節は省略できるが、適用される契約は省略しない。仕様変更時は関連文書を更新し、独立レビューで元要求・実差分・文書を照合する。変更不要の専用報告書は作らない。

Gherkin・DDD・層構造・採番規則はプロジェクト契約に従う。ADRは長期的な判断理由が既存資料に残らない場合だけ使用する。旧Step・Seal・Journalは必要ない。
