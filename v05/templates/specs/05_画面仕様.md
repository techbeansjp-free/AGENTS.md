# 画面仕様（入口）

> 値を書かない入口。書く内容ごとに`details/`の正本を示す。置き場の規則は[利用案内](00_利用案内.md#置き場の表)、書き方は[同じく](00_利用案内.md#書き方)に従う。小さな変更は、Issue・PRに要求と受入条件を書けば足りる。仕様書は作らない。

UIがない変更には使わない。

| 書く内容 | 書く場所 |
|---|---|
| 利用者の目的、関連要件・業務シナリオ | [個別画面仕様](details/05_画面/02_個別画面テンプレート.md)。主体は[システム概要](details/01_システム概要/00_概要.md)「利用者・関係者」に書き、個別画面仕様にはACT IDだけを書く。権限は[信頼境界・認証認可](details/10_セキュリティ/01_信頼境界・認証認可.md) |
| 画面・操作フロー | [画面遷移](details/05_画面/01_画面遷移.md)、[業務・利用者フロー](details/01_システム概要/01_業務・利用者フロー.md) |
| 表示状態（初期・読込中・空・成功・エラー・権限不足）と操作、入力・バリデーション、API・データとの対応、アクセシビリティ、レスポンシブ | [個別画面仕様](details/05_画面/02_個別画面テンプレート.md) |
| 既存コンポーネント・トークン | [デザイントークン](details/17_デザイン/00_デザイントークン.md)、[レイアウトトークン](details/18_レイアウト/00_レイアウトトークン.md) |
| デザインの状態（案／承認済み、確認者と根拠） | 文書の冒頭の1行（[利用案内](00_利用案内.md#書き方)） |
| 受入条件 | [受け入れ条件](details/02_要件/01_受け入れ条件.md) |

必要なワイヤーフレームや操作案は未承認であることを明示する。
