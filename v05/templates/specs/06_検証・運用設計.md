# 検証・運用設計（入口）

> 値を書かない入口。書く内容ごとに`details/`の正本を示す。置き場の規則は[利用案内](00_利用案内.md#置き場の表)に従う。小さな変更は、Issue・PRに要求と受入条件を書けば足りる。仕様書は作らない。

| 書く内容 | 書く場所 |
|---|---|
| 要求・リスクごとの検証対象・方法・合格条件、正常・失敗・反例 | 合格条件は[受け入れ条件](details/02_要件/01_受け入れ条件.md)、テストとの対応は[要件追跡表](details/15_要件追跡/00_追跡表.md) |
| 検証環境・データ（隔離、秘密を含めないfixture）、統合の検証 | [テスト標準](details/14_開発・品質/02_テスト標準.md) |
| 性能（条件・時間・処理量・予算・欠測の扱い） | [性能・容量・可用性](details/11_非機能/01_性能・容量・可用性.md)の「測定」 |
| 運用（監視・障害時の判断・復旧・権限） | [運用設計](details/12_運用保守/00_運用設計.md)、[監視・障害対応](details/12_運用保守/01_監視・障害対応.md) |
| 移行・廃止（対象・検証・中止条件・復旧） | [移行計画](details/13_移行・廃止/00_移行計画.md)、[互換・廃止](details/13_移行・廃止/01_互換・廃止.md) |
| 実行結果の所在（対象commit・設定・結果） | [要件追跡表](details/15_要件追跡/00_追跡表.md)の「結果・HEAD SHA」。実績がCI等にある場合は参照だけを書く |

予定と実績を区別する。未実行・失敗・skip・欠測を成功扱いしない。
