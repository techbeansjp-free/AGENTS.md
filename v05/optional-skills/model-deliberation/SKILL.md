# 明示依頼に限る複数モデル協議

利用者が今回の協議を明示的に依頼していなければ、この手順でAgentを起動しない。問いが難しい、質問前である、Skillが参照されたという理由だけでは起動しない。協議自体の許可と、モデル・Host・外部操作の許可は別に扱う。

判断したい問い、元要求・制約、必要な入力、許可済みで実際に利用可能なモデルを確かめる。Fable・Astraはその利用をユーザーが明示指定した場合だけ選ぶ。協議依頼をモデル指定と解釈しない。別Hostの導入を必須にせず、利用中Hostの選択機能を使う。選択できるモデルが不足・利用不能ならその事実を示し、同一モデルの別Contextを「複数モデル」と呼ばない。禁止モデルや別Hostへ自動fallbackしない。

各独立Contextへ同じ問い・根拠の参照・制約を渡す。進行役の予想や他者の結論を最初の意見へ混ぜない。必要な成果は推奨、根拠、反例、未確認と判断を覆す条件。入力や成果に秘密を複製せず、検討のために外部への変更を許可しない。

進行役は独立意見を受け取り、一次資料・実証・推論の区別、矛盾する前提、反例が今の対象で成立するかを確認する。重要な不一致が残る場合だけその問いへ追加検証を限定する。人数や全員一致を正しさの証拠にしない。合意形成のためだけに同じ問答を反復せず、未解決と検証方法を残す。

既存Issue・仕様・PR等に、採用理由と重要な不採用理由を残す。利用者には推奨を一つ、理由、残る重要な不確実性と利用者が決める点を返す。協議の結論は独立レビュー、owner判断、mergeや外部操作の承認を代替しない。
